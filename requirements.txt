pdfplumber>=0.11

# ── UI 서버 (F4-1 · 결정 `docs/decisions/0038-fastapi-for-the-ui-server.md`)
#
# 왜 서버가 필요한가 — **계산기가 파이썬에 있어서다.** 정적 페이지로 가려면 계산기를
# JS 로 다시 쓰거나(계산이 두 군데 → 두 답. `problem.md` §7 이 막는다) 미리 계산해야
# 하는데, 은행권 12개월만 질문 15개 × 예/아니오/모름이라 3^15 = 1,435만 상태다.
# 서버는 **이미 있는 계산 함수를 HTTP 로 감싼 것**이고 상태를 저장하지 않는다(무상태).

# 엔드포인트를 정의하고 요청·응답을 검증한다.
#   `http.server`(표준 라이브러리)로도 충분했다 — 로컬 단일 사용자에 엔드포인트가 둘이다.
#   그런데 (1) 사람이 써 보고 싶다고 했고(이 저장소는 "근거 없음 — 판단" 을 그대로 적는다)
#   (2) Pydantic 이 뷰 모델 계약의 일부를 타입에 박는다 — 화면 계약 assert 앞에 스키마
#   검증이 한 겹 생긴다(다만 assert 를 대체하지 않는다) (3) OpenAPI 문서가 자동으로
#   나온다. **의존성을 늘리는 쪽을 골랐다는 것을 여기 명시한다.**
#   FastAPI·Pydantic 은 MIT, Starlette 은 BSD-3-Clause.
fastapi>=0.115

# ASGI 서버 — FastAPI 앱을 실제로 띄운다.
#   `python -m uvicorn src.web.app:app --host 127.0.0.1 --port 8000`
#   **127.0.0.1 에만 묶는다** — 로컬 전용이고, `0037` 이 "공개는 깃 단위에서 끝날
#   가능성이 높다" 를 전제로 선다. BSD-3-Clause.
uvicorn>=0.30

# HTML 템플릿 (F4-2 에서 쓴다. 여기서 함께 선언한다)
#   화면을 **서버 렌더**로 두는 이유는 계약이다 — HTML 이 서버에서 나오면 렌더 겹 검사가
#   CLI·리포트에 붙은 것과 같은 모양으로 붙는다(`0039`). 클라이언트 렌더로 가면 계약
#   검사를 파이썬에서 못 돌리고 헤드리스 브라우저·JS 테스트 러너가 들어온다.
#
#   표준 라이브러리(f-string + `html.escape()`)로도 되지만 두 가지 때문에 기각했다.
#   (1) HTML 분량이 **예측된다** — 같은 내용의 텍스트 렌더러가 이미 `report.render`
#   241줄 + 최종 화면 50줄이다. 태그가 붙으면 몇 배가 되고 f-string 안의 HTML 은 그
#   규모에서 못 읽는다. (2) 데이터에 `&` 와 `"` 가 **실제로 있다**(상품명·기관명·공시
#   문구 1,831개 중 3개) — 손으로 거는 이스케이프는 빠뜨리는 게 기본값이다.
#   BSD-3-Clause.
#
#   **템플릿에 판정을 넣지 않는다** — `{% if %}` 가 화면 계약을 판정하면 계약이 뷰 모델
#   밖으로 샌다. 판정은 `view.build()` 가 하고 템플릿은 꽂기만 한다(`0038` 반증 조건).
jinja2>=3.1
