# 0019 · 조건이 아닌 문구를 걸러내고, 조건불명은 은행에 물어보라고 말한다

2026-08-27 · 이슈 [#2](https://github.com/hyos0415/fineprint/issues/2) ·
사전등록 [`../spec/prereg-06-matching-and-judgment.md`](../spec/prereg-06-matching-and-judgment.md) §1.8 · §2.3(1)

## Decision

사람이 표본을 직접 읽다가(`START-HERE` 1번) 나온 셋을 고친다.

```
1  조건이 아닌 문구를 조건으로 세던 것을 규칙으로 걸러낸다      13건
2  그중 "항상 충족"으로 계산되던 것을 판정 불가로 옮긴다        4건
3  금액 임계를 띄어쓰기 없으면 못 잡던 버그를 고친다           36건
```

**규칙 — 문구를 하드코딩하지 않는다.** 근거 문구에서 숫자와 껍데기 말(우대이율·최대·
이상·연·개월…)을 걷어내고 **아무것도 안 남으면 조건이 아니다.** 금액·횟수 임계가
붙은 것은 먼저 뺀다(`"1천만원 이상"`은 숫자를 걷어내면 비지만 진짜 조건이다).

```
"우대이율 6개월 이상 2.20%"  ->  ""              조건 아님
"계약기간 24개월 이상"        ->  ""              조건 아님
"소중한 날"                 ->  "소중한날"        조건이다. 묻는다
"아파트관리비 이체"           ->  "아파트관리비이체"  조건이다
```

걸러낸 것을 **금리 표기 유무로 둘로 가른다.**

| | 무엇 | 어떻게 | 왜 |
|---|---|---|---|
| **제외** | 금리도 조건도 없다 (`"계약기간 24개월 이상"`) | 항목에서 뺀다 | 애초에 항목이 아니다. `applies_to_term`이 처리할 자리다 |
| **조건불명** | 금액은 있는데 조건이 없다 (`"우대이율 6개월 이상 2.20%"`) | 금리는 남기고 **판정 불가**로 못 박는다 | 빼면 "공시가 2.20%를 준다고 했다"는 정보가 사라진다 |

`조건불명`은 질문을 만들지 않는다. **물어봐야 소용없다 — 공시가 안 적은 것이지
사용자가 모르는 게 아니다.** 대신 사유를 문장으로 보여주고, **갈 곳을 알려주며 끝낸다.**

> 우대금리 금액은 공시에 있는데 무슨 조건을 채워야 받는지는 나와 있지 않습니다.
> 표시된 최대 금리를 실제로 받을 수 있는지 **은행에 전화해 확인해 보세요**

마지막 문장은 사람 지시다 — *"이건 진짜 은행에 전화해서 확인해보라는 안내가 마지막에
꼭 있어야할 거 같아."* 우리가 대신 추측하지 않는 대신 **사용자를 막다른 길에
세워두지도 않는다.**

## Evidence

### 가장 나쁜 케이스 — 아무것도 안 물어도 2.20%p를 준 것으로 계산했다

부산은행 **부산이라 좋다 Big적금**의 조건문은 이 한 줄이 전부다.

```
*우대이율 6개월 미만 최대2.00%, 6개월 이상 2.20%
```

무슨 조건인지 한 글자도 없다. 그런데 추출기가 이걸 `무조건_특판_이벤트`로 분류했고,
그 유형은 코드에서 **항상 충족**(`ALWAYS_MET`)이다.

```
고치기 전   6개월 상품이 4.80% 로 보인다          사용자 입력 0개
고친 뒤     2.60~4.80% · 사유 "조건불명"          은행에 전화해 확인하라고 말한다
```

`problem.md`가 인용한 피해 사례가 *"최고금리를 보고 가입했으나 우대금리를 적용받지
못했다"*인데, **우리가 그 사례를 재생산하고 있었다.** 같은 구조가 부산은행에 3건 더
있다(`펫 적금` 0.55 · `BNK내맘대로 적금` 0.15 · `LIVE정기예금`).

### 규칙이 정확히 맞는다 — 넘치지도 모자라지도 않는다

`기타` 40건 중 **13건**을 집어낸다. 사람이 읽고 나눈 결과와 정확히 일치한다.
그리고 `기타` **밖에서 4건을 더 찾았다** — 위 `무조건_특판_이벤트` 2건과
`비대면_채널가입` 2건(페퍼저축 기본금리 서술)이다. 사람이 `기타`만 봤으면 놓쳤을 것들이다.

**재추출이 필요 없다.** 판정 단계의 규칙이라 비용은 $0이다.

### 임계 미탐 36건 — `prereg-06` §1.1과 같은 종류의 두 번째 구멍

```
"1천만원 이상"  ->  임계로 인식        ✅
"1천만원이상"   ->  인식 못 함         ❌   광주 27 · 안양 6 · 경남 3 = 36건 (3.4%)
```

`(?![가-힣])` 부정 예측이 `"1천만원이상"`의 `이`에 걸려 매칭을 막았다. 방향이 나쁘다 —
**임계인 줄 모르면 사용자 "예" 답을 그대로 충족으로 세어 과대 진술이 된다.**
§1.1이 `천만원` 단위 누락으로 겪은 것과 같은 실패다.

### 기준선이 움직였고, 예고한 방향 그대로였다

셋 다 **확정률을 낮추는 방향**이라고 고치기 **전에** 적었다(`prereg-06` §2.3(1)).

| | 커버리지 | 예산 12개 시점 확정 | 폭 평균 |
|---|---|---|---|
| 은행권 · 전 | 81.0% (64/79) | 47/64 (73.4%) | 0.096%p |
| 은행권 · 후 | **79.7%** (63/79) | **37/63 (58.7%)** | **0.170%p** |
| 저축은행 · 전 | 36.7% (109/297) | 91/109 (83.5%) | 0.239%p |
| 저축은행 · 후 | **36.7%** (109/297) | **89/109 (81.7%)** | **0.241%p** |

**전부 나빠졌다. 그게 맞다.** 옛 확정률 73.4%에는 *"조건이 뭔지 모르는데 사용자가
`기타=예`라고 답하면 확정"*과 *"1천만원 임계를 안 보고 확정"*이 섞여 있었다.

기준선은 **은행권 79.7% · 저축은행 36.7%**로 재등록한다. 질문 예산 K=12와
우선순위 규칙(`0018`)은 건드리지 않는다 — 바뀐 것은 숫자 하나뿐이다.

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| A | 그대로 둔다 | 부산은행 상품이 계속 "아무 조건 없이 4.80%"로 보인다. **막으려던 피해를 우리가 만든다** |
| B | 걸러낸 13건을 **전부 뺀다** | 은행권 커버리지 78.5%로 **게이트 불통과**. 부산 상품이 `계산불가`가 되는데, 실제로는 "뽑았는데 조건이 아니었다"라 층 라벨이 틀린 말을 한다 |
| C | 13건을 **전부 판정불가로** | 게이트는 통과하지만 `"계약기간 24개월 이상"`까지 금리 항목으로 남는다. 그건 기간이지 우대금리가 아니다 |
| D | 문구 목록을 코드에 박는다 | 다음 달 공시에 새 문구가 오면 그대로 샌다. **월 1회 갱신되는 데이터에 하드코딩은 맞지 않는다**(`0010`) |
| E | 재추출해서 스키마에 `조건불명` 유형을 넣는다 | $1 + 스키마 변경. **규칙으로 $0에 되는데 값어치가 없다**(`0013`과 같은 판단) |

## Why rejected

B와 C가 갈린 자리가 이 결정의 핵심이다. 걸러낸 13건이 **한 종류가 아니었다** —
`"계약기간 24개월 이상"`은 정보가 없어서 빼도 잃을 게 없지만,
`"우대이율 6개월 이상 2.20%"`는 **공시가 알려준 유일한 숫자**라 빼면 사용자가
"이 상품 최고 4.80%"라는 사실 자체를 못 본다. 그래서 금리 표기 유무로 갈랐다.

D는 이 프로젝트가 반복해서 거부해 온 방향이다(`정규화(별칭 사전) 경로로 가지 않는다` —
`CLAUDE.md`). 해법은 목록을 늘리는 것이 아니라 **형태로 판정하는 것**이다.

## 반증 조건

- **`제외`로 빠진 항목 때문에 닫힘률이 떨어지면** — 지금은 6건뿐이라 영향이 없다.
  다음 달 공시에서 이 규칙이 진짜 조건을 빼기 시작하면 규칙이 너무 넓은 것이다
- **껍데기 단어 목록을 늘려야 하는 일이 계속 생기면** — 그건 D(하드코딩)로 가는
  뒷문이다. 목록이 아니라 판정 방식을 다시 봐야 한다
- **`조건불명` 상품을 사용자가 그냥 넘겨버리면** — 은행에 전화하라는 안내가
  실제로는 "이 상품은 포기하라"로 읽히는 것이다. 그때는 문장이 아니라 화면에서
  이 상품들을 어디에 놓을지를 다시 정한다
- **임계 정규식을 또 고쳐야 하는 형태가 나오면** — 두 번 고쳤다(단위 누락 · 띄어쓰기).
  세 번째가 나오면 정규식이 아니라 **추출 시점에 숫자를 뽑는 쪽**으로 옮겨야 한다
