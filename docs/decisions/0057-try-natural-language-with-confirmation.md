# 0057 · 자연어로 조건 답을 **제안**한다 — 확인 없이 들어가는 값은 0 · 기각되면 그것도 결론

2026-09-04 · 로드맵 D8(R2) · 이슈 [#73](https://github.com/hyos0415/fineprint/issues/73) ·
개정 대상 `0042` D3·D6 · 앞선 결정 `0024` P2 · `0026`(질문 수를 협상하지 않는다) · `0030`(옮긴 값을 보여주고 고치게 한다) ·
`0056`(검색은 보류 — AI 가 남은 자리는 추출 하나)

**사전등록이 없다 — 방향 결정이다.** 실험 설계(`prereg-27`)는 월요일(2026-09-07)에 측정 전에 쓴다.

## Decision

**사람이 정했다.** *"일단 자연어 붙여서 이것저것 해보고 기각이 되면 그거 나름대로도 결론이 의미가 있는 부분이니깐"* (2026-09-04).

```
D1  R2 의 범위를 넓힌다 — `0042` D3 의 화이트리스트(기관·상품군·기간·금액 넷)에 **조건 답 후보**를 더한다.
    자연어에서 "이 조건에 이 답" 후보를 뽑되, 뽑는 대상은 **유형 질문 키**(`kind` · `kind@company`)와 목록 질문
    (`_거래은행`)뿐이다. **문구 단위 질문(`#` 키)은 채우지 않는다** — 사용자가 공시 문구를 읽어야 답할 수 있다
D2  **확인 없이 상태에 들어가는 값은 0 이다.** 후보는 화면에 **근거 문장과 함께 항목별로** 보이고, 사용자가
    예/아니오/모름/채우지 않음을 직접 고른 뒤에만 `state` 에 들어간다. `0042` D6("자연어로 조건 답을 확정하지 않는다")
    은 이 뜻으로 **유지**된다 — 확정은 사용자가 하고 모델은 제안만 한다. `0030` 이 가중치에 대해 한 것과 같은 모양
D3  `0042` 의 나머지는 그대로다 — **로컬 모델(llama.cpp)** · 원문은 구조화 직후 버리고 로그에 안 남긴다 · 외부 API 로
    보내지 않는다. 자연어 상자는 **선택**이고 비우면 지금과 같다(점진적 향상 · `0038`)
D4  **기각 관문을 먼저 적는다** — 사람이 쓴 문장 표본에 손 라벨을 붙이고, **잘못 채운 답 0** 이 아니면 화면에 넣지 않는다.
    질문 수가 얼마나 줄든 이 관문이 먼저다. 기각되면 "자연어 선채움은 이 문제에서 정확도가 부족하다" 가 결론이고
    그것을 기록한다 — `0056` 이 검색에 대해 남긴 것과 같은 종류의 음성 결과다
D5  이 자리는 **이 프로젝트에서 LLM 이 사용자와 직접 만나는 유일한 지점**이다(추출은 공시 원문만 본다). 그래서 실험
    결과가 무엇이든 "AI 가 어디에 필요한가" 의 답에 들어간다
```

## Evidence

- 오늘 하루의 결론(`0056` · 사람 말): *"결국 llm 이 쓰일 곳의 모호함을 없애고자 구조화와 입력폼으로 다 해결해버렸어."*
  남은 AI 자리는 추출 하나이고, 사용자와 만나는 자연어 자리는 없다. 그 자리를 **한 번은 재 봐야** "필요 없다" 도 결론이 된다
- 폼(권역·기간·은행·금액·선호)은 30초면 채우므로 `0042` 원안(폼 네 칸만 자연어로)은 얻는 것이 작다. 질문 수를 줄이는 것은
  후보 집합이지 자연어가 아니다. 유일하게 줄일 수 있는 것은 **사용자 본인의 말로 조건 답을 미리 채우는 것**이고,
  그것은 시스템의 추측이 아니라 사용자의 진술이다 — 단, 확인을 거칠 때만(D2)
- 위험은 과대 진술이다 — "카드 안 써" 를 "카드 실적 예" 로 채우면 이 프로젝트가 가장 막는 실패다. 그래서 D4 의 관문이
  "질문 몇 개 줄었나" 보다 앞선다

## Alternative

- **A. `0042` 그대로 — 폼 네 칸만** — 안전하지만 보상이 작고, 로컬 서빙 비용이 보상보다 클 수 있다. 사람이 B 를 골랐다
- **C. 제안 없이 확인도 없이 채운다** — `0042` D6 위반 · `0016` 추측. 기각
- **D. 외부 API(Haiku)로 파싱한다** — 급여·주거래·카드 같은 금융 상태가 외부로 나간다. `0042` D1 이 막은 자리. 기각
- **E. 문구 단위 질문까지 채운다** — 문구는 사용자가 읽고 대조해야 답이 있다(`0027`). 모델이 문구를 대신 읽으면 `0019` 가
  막은 "남의 낱말에 뜻 지어내기" 로 들어간다. 기각

## Why rejected

위에 같이 적었다.

## 반증 조건

- **표본에서 잘못 채운 답이 1개라도 나오면** — D4 관문 불통과. 화면에 넣지 않고 원인(모델 · 문장 · 키 매핑)을 적는다.
  두 번 실험해도 0 이 안 되면 **기각을 결론으로 기록**한다
- **확인 화면에서 사용자가 제안을 그대로 다 통과시키면(고친 것 0 · 여러 세션)** — 확인이 형식이 된 것이다. 제안을 기본
  선택으로 두지 말고 빈 상태에서 고르게 바꾼다
- **8GB 에 올릴 모델이 한국어 문장을 못 읽으면(라벨 정확도 < 80%)** — 로컬 전제가 이 과업에서 안 서는 것이다. 외부 API 로
  가지 않는다 — 기각이 결론이다
- **사용자 문장에 원문 보관이 필요한 상황이 생기면**(디버깅 등) — `0042` D3 의 "원문은 버린다" 와 충돌한다. 합성 문장으로만
  디버깅한다
