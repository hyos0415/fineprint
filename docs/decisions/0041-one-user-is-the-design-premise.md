# 0041 · 사용자는 한 명이다 — 사용자 수를 설계 전제로 못 박는다

> 날짜: 2026-09-01 · 상태: 유효

앞선 결정 `0037`(링크만 · 수익화 없음) · `0040`(무상태 · DB 없음) · `0026`(개인정보 최소수집) ·
`0038`(FastAPI + Jinja2)

**사전등록이 없다.** 범위 결정이다.

## Decision

**사용자는 만든 사람 한 명이다.** 이 전제를 다른 결정들이 기대는 자리에 명시한다.

```
D1  **계정·인증을 만들지 않는다.** 따라서 DB 도 없다(`0040`)
D2  **멀티유저 인프라를 만들지 않는다** — 배포·HTTPS·레이트리밋·관측
D3  **바인딩은 127.0.0.1 고정**이다
D4  **화면 계약(A1~A13)은 그대로 남는다.** 사용자 수와 무관하다 — 아래 Evidence
```

사람의 말이 근거다.

> 일단 어차피 개인단위 레포로 끝낼 생각이라서, 사용자 수는 나 개인 하나로 상정하고 끝내야겠다.

## Evidence

### 무엇이 무엇을 강제하는지 갈라 보니 사슬이 이랬다

```
멀티유저 자체     → 배포 · HTTPS · 레이트리밋 · 관측
                  **DB 는 아직 필요 없다** — 답을 브라우저에 두면 무상태로 다수를 받는다
                  계산이 16ms · 스냅샷이 워커당 800KB 라 동시성 자체는 쉬운 쪽이다
계정을 만들면     → **DB + 인증 + 개인정보보호법**. `0026` 의 반증 조건이 발동한다
서비스로 공개하면  → **`0037` 이 다시 열린다** (그 결정의 반증 조건에 박아 뒀다)
R2·R4 를 켜면    → LLM 서빙 (`0042`)
```

**순서가 "멀티유저 → DB" 가 아니라 "계정 → DB" 다.** 그리고 계정이 오는 순간 새로
들어오는 것은 광고 규제가 아니라 **개인정보보호법**이다 — 급여이체·카드실적·자격 같은
우대조건 답이 쌓이면 그건 개인의 금융생활 정보이고, 처리방침·보관기간·안전조치·파기
절차가 따라온다.

**이 결정으로 그 사슬 전체가 안 열린다.** `0037` 의 반증 조건(*"깃 수준을 넘어 서비스로
공개하면"*)도 발동하지 않는다.

### LLM 서빙은 사용자 수가 정하지 않는다 — 확인했다

```
extract_llm.py   입력이 `spcl_cnd`(공시 조건문 원문) + 가입기간 **뿐**이다
                 (파일 주석 13번째 줄 — "기본금리·최고금리를 주지 않는다")
                 **월 1회 배치**다. 사용자 요청 경로가 아니다
사용자 요청 경로    score_all 16ms → view.build. **LLM 이 한 번도 안 불린다**
```

사용자가 10명이든 10만이든 추출은 월 1회 배치다. **LLM 서빙이 필요해지는 것은 사용자
수가 아니라 어떤 부품을 켰는가다**(R2·R4·G) — `0042` 가 그 자리를 다룬다.

### 화면 계약은 사용자 수와 무관하다 — D4 가 중요한 이유

*"사용자가 한 명이니 A1~A13 은 과하다"* 로 읽힐 수 있어서 명시한다. **계약이 막는 것은
"여러 사용자" 가 아니라 "화면이 거짓말하는 것"** 이고, 그 대상은 만든 사람 자신이다.

```
0019   조건이 한 글자도 없는데 4.80% 가 확정처럼 보였다 — 사람이 표본을 읽어서 찾았다
0029   후보 4개 스코프에서 확정 카운터가 6개 질문 동안 0으로 고정 — 사람이 세션에서 찾았다
0035   `세후` 라벨이 한 화면에만 없었다 — 코드는 알고 사용자는 못 읽었다
0039   A1 이 렌더된 줄이 아니라 헬퍼 출력을 보고 있었다 — 음성 검사가 찾았다
```

**넷 다 사용자가 한 명일 때 일어난 일이다.** 그 한 명이 속았고, 계약과 검사가 그것을
잡았다. 이 프로젝트가 내놓을 것의 핵심이 그 규율이라 사용자 수와 독립이다.

## Alternative

- **A. 사용자 수를 열어 두고 "나중에 확장 가능하게" 설계한다** — 지금 정하지 않는다
- **B. 계정 없이 멀티유저만 지원한다** (무상태로 여러 사람이 쓴다) — 배포만 하면 된다
- **C. 지금 계정을 만든다** — 나중에 붙이는 비용을 미리 없앤다

## Why rejected

- **A** — *"확장 가능하게"* 가 실제로 뜻하는 것은 **쓰지 않는 구조를 미리 만드는 것**이고,
  `CLAUDE.md` 1번이 막는 모양이다(선행 저장소가 실패한 순서 — 구조 먼저, 쓸 곳은 나중).
  그리고 **전제를 안 적으면 다른 결정들이 무엇에 기대고 있는지 알 수 없다** —
  `0037`(깃 단위 공개)·`0040`(무상태·DB 없음)이 전부 이 전제 위에 선다
- **B** — 기술적으로 되는데(무상태라 그렇다) **`0037` 의 반증 조건이 발동한다** —
  서비스로 공개하는 순간 광고·자문 규제 판단을 다시 열어야 한다. 얻는 것(남이 써 본다)이
  그 비용을 넘지 않는다. 시연은 화면 녹화·스크린샷으로 된다
- **C** — 개인정보보호법이 들어온다. **얻는 사용자가 0명인데 지켜야 할 것이 늘어난다**

## 반증 조건

- **남에게 실제로 써 보게 해야 하면** — 예를 들어 면접에서 시연을 요구받는 경우.
  **먼저 화면 녹화·스크린샷으로 되는지 본다.** 그것으로 안 되는 요구(직접 입력해 보게
  해야 한다)가 실재하면 이 결정을 다시 읽는다 — 그때도 **계정 없는 공개**가 먼저다
- **포트폴리오 공개 형태가 바뀌면** — `0037` 이 *"깃 단위에서 끝날 가능성이 높다"* 를
  전제로 서 있다. **가능성이 높다는 말은 확정이 아니다**
- **"사용자 한 명" 을 근거로 계약·검사를 줄이려는 판단이 나오면** — D4 가 그것을 막는다.
  줄여도 되는 것은 **인프라**(배포·인증·관측)이고 **정직성 장치가 아니다**
- **혼자 쓰는데도 이어하기·저장이 필요해지면** — 세션이 길어지면(질문 39개) 실제로
  생길 수 있다. 그때는 **클라이언트 보관**이 먼저다(`0040`) — 서버 저장으로 가면
  `0026` 이 열린다
