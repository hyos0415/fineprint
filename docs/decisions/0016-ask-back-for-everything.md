# 0016 · 애매하면 전부 되묻고, 못 채우면 사유를 보여준다

2026-08-26 · 이슈 [#2](https://github.com/hyos0415/fineprint/issues/2) (D3) ·
사전등록 [`../spec/prereg-06-matching-and-judgment.md`](../spec/prereg-06-matching-and-judgment.md) §1.5 · §1.7

## Decision

조건을 판정할 수 없으면 **유형을 가리지 않고 되묻는다.** 물을 때는 **공시 문구를 그대로
인용**하고, 답 선택지에 **"모르겠다"**를 둔다. 되물어도 못 채우면 조용히 빼지 않고
**"이 사유 때문에 실제 금리가 다를 수 있습니다"**를 사용자에게 보여준다.

사람 결정이다 — *"애매하거나 확인이 필요하면 모두 반문해서 정보를 확정할 수 있게 하자.
정보가 모자라면 어떠한 사유 때문에 예상 금리와는 조금 다를 수 있다는 메시지를 출력하자."*

```
못 채운 사유 여섯 가지 — 앞 넷은 되물어서 없앨 수 있다

미응답     답하지 않은 조건이 있습니다. 답하면 금리가 확정됩니다
수치필요   금액·횟수를 답하면 금리가 확정됩니다
모름       사용자가 모른다고 답한 조건이 있어 금리를 확정할 수 없습니다
이행필요   가입 후 계속 실천해야 받는 우대금리가 포함돼 있습니다. 중단하면 그만큼 낮아집니다
추첨       추첨·랜덤으로 주는 우대금리가 포함돼 있어 실제 금리는 더 낮을 수 있습니다
단계불명   충족 정도에 따라 금리가 달라지는 조건이 있는데 공시에 단계가 다 나와 있지
           않습니다. 실제 금리는 표시된 최대보다 낮을 수 있습니다
```

## Evidence

**유형별로 "물을 수 있나"를 따지던 접근이 필요 없어졌다.** 실천·미션 66건을 문구 20개로
훑어 넷으로 나눴는데, 그중 11건(16.7%)이 **공시가 무엇을 하라는지 말하지 않는 것**이었다.

```
"ESG 실천 우대금리 1.00%"      x5     무엇이 ESG 실천인가
"봉사활동 또는 상품홍보"         x5     몇 시간? 어디에 홍보?
"스마트폰뱅킹의 상품알리기"       x1
```

우리가 요약해서 물으면 사용자가 판단할 근거를 빼앗는다. **문구를 그대로 보여주고
"충족하십니까 / 모르겠습니다"를 받는 것**이, 우리가 대신 분류하는 것보다 정확하다.
그래서 4군을 따로 뺄 필요가 없다.

12개월 상품에서 전부 되물었을 때다.

```
                 확정   범위   설명부족  추출불확실  계산불가
은행권 79개
  아무것도 안 물음     4     60       5        8        2
  전부 되물음        64      0       5        8        2      범위가 사라진다

저축은행 297개 (공시미반영 176 별도)
  아무것도 안 물음    52     57       6        5        1
  전부 되물음       105      4       6        5        1      단계불명 4개만 남는다
```

**되물은 뒤 남는 것은 사유 두 개뿐이다.**

```
이행필요   은행권 46개 · 저축은행 15개    약속을 지켜야 받는 금리가 포함돼 있다
단계불명   저축은행 4개                  계단식 우대 (prereg-06 §1.6)
```

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| A | 유형별로 "물을 수 있는 것"만 골라 묻는다 | **우리가 대신 분류한다.** "ESG 실천"을 못 묻는다고 정하면 그 상품은 영원히 범위에 남는다. 사용자는 자기가 ESG 우대를 받는지 알 수도 있다 |
| B | 애매한 조건은 충족으로 가정한다 | **과대 진술.** `0015`에서 배제한 것과 같은 방향이다 |
| C | 애매한 조건이 있는 상품을 목록에서 뺀다 | 닫는 것만 남기면 개선을 측정할 수 없다. `0011`에서 이미 기각한 방향이다 |

## Why rejected

A는 겉보기에 친절하지만 **판단을 시스템이 가져간다.** `problem.md` §1이 "시스템은 선호를
추측하지 않고 계산만 책임진다"고 했는데, "이 조건은 물을 가치가 없다"는 판단도 추측이다.

## 반증 조건

- **질문이 너무 많아 사용자가 포기하면** — 지금 은행권에서 유형 13개, 저축은행에서 더
  적다. 이게 25개를 넘으면 "많이 걸리는 것부터 N개만" 으로 줄이고 나머지는 범위로 둔다
- **"모르겠다" 답이 절반을 넘으면** — 문구를 그대로 보여주는 방식이 실패했다는 뜻이다.
  그때는 유형별로 사람이 쓴 질문 문구를 넣는다
- **사유 문장을 보고도 사용자가 금리를 오해하면** — 사람 검수에서 확인할 항목이다

## 부수 관측 — `판정불가_불특정` 이 0건이다

열거값에 자리를 만들어 뒀는데 **1,051개 항목 중 0건**이다. 이 자리를 만든 근거는
케이뱅크 "입금할 때마다 랜덤" 사례였는데, 그 상품은 이 스냅샷(은행·저축은행 예적금)에
없다. `추첨` 사유는 코드에 있지만 **지금 데이터에서는 한 번도 쓰이지 않는다** —
지웠다가 다른 상품군에서 다시 만나는 것보다 남겨 두는 쪽을 골랐다.
