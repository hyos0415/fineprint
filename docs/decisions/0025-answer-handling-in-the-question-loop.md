# 0025 · 질문 루프가 답을 읽는 방식 — "아니오"는 조건을 지우고, "모르겠다"는 다시 묻지 않는다

2026-08-28 · 설계 [`../spec/design.md`](../spec/design.md) §되묻기 흐름 ·
앞선 결정 `0016`(전부 되묻는다) · `0024`(되묻기 흐름) ·
구현 `src/analysis/ask_loop.py` · `src/analysis/calculate.py` ·
이슈 [#11](https://github.com/hyos0415/fineprint/issues/11)

## Decision

`0024`가 정의한 흐름을 실제 루프로 만들면서, **답을 받아 상태에 넣는 규칙 둘**을
정했다. 둘 다 `--state`에 답을 미리 적어 넣던 시절에는 드러나지 않던 자리다.

```
Q1  수치 질문("평잔이 얼마입니까")에 "아니오" 를 답하면
    → 수치를 0 으로 넣지 않고, **그 유형 자체를 `False`** 로 되돌린다

Q2  수치 질문에 "모르겠다" 를 답하면
    → 다시 묻지 않는다. `모름` 사유를 붙이고 범위로 낸다
```

## Evidence

### Q1 — 0을 넣으면 반대 방향으로 거짓이 된다

수치 질문은 두 방향이 다 있다. 임계가 **최소**면(`"1천만원 이상"`) 0은 미충족이라
말이 되지만, **최대**면(`"1천만원 이하"`) 0은 **충족**이 된다.

```
"6~12개월제(만기일시지급식) 5천만원 이상 가입"       0 → 미충족   맞다
"가입금액 1천만원 이하"                          0 → 충족    사용자는 "안 한다" 고 답했다
```

사용자가 "아니오"라고 말한 조건이 **충족으로 세어져 금리가 올라간다.** `0019`가
금액 임계 미탐 36건에서 막은 것과 같은 방향의 실패다(모르면 과대 진술 쪽으로 기운다).

**유형 쪽을 `False`로 되돌리면 두 방향 모두 안전하다.** `condition_met()`이 유형
답에서 먼저 갈라지므로 임계 비교까지 가지 않는다. 그리고 `questions_left()`가 그
유형의 수치 후속까지 같이 지워, `0024` P4의 "남은 수는 줄어들기만 한다"도 지켜진다.

### Q2 — 같은 질문을 무한히 되물었다

`question_for()`는 유형 답이 `모름`이면 되묻지 않는데(`0016`), **수치 키에는 같은
검사가 없었다.** 유형에 "예", 수치에 "모르겠다"를 답하면 `condition_met()`이 다시
`None`을 내고 → 같은 질문이 다시 상위로 올라온다.

```
[11] 잔액_평잔_가입금액 — 이 조건을 충족하십니까?     예
[12] 잔액_평잔_가입금액 — 얼마나 하십니까?           모르겠다
[13] 잔액_평잔_가입금액 — 얼마나 하십니까?           ← 같은 질문. 끝나지 않는다
```

**시뮬레이션에서는 절대 안 나타나는 버그다.** `ask_budget.py`의 페르소나는 수치에
항상 숫자로 답한다. 사람이 답하는 루프를 만들자마자 첫 시험에서 나왔다 — `0024`가
*"사람이 직접 22개를 답해봐야 안다"*고 적은 것의 첫 사례다.

사유 코드도 같이 고쳤다. 이 경우는 `수치필요`("답하면 확정됩니다")가 아니라
**`모름`**이다 — 사용자가 이미 답했고, 그 답이 "모른다"이므로 되물어도 안 없어진다.

### 기준선은 안 움직였다

두 수정 뒤 재측정 — 은행권 확정 39/67 · 폭 0.176%p · 커버리지 84.8%,
저축은행 88/106 · 0.277%p · 35.7%. **`0022`·`0023` 값 그대로다.** 평가 경로가 수치에
"모르겠다"를 쓰지 않으므로 예상된 결과지만, 재보고 적는다.

**루프가 `0024`의 실측표도 그대로 재현한다.** 시뮬레이션과 사람용 루프가 같은 답을
낸다는 확인이다.

| `--auto` | 질문 수 | 확정 | 1위 |
|---|---|---|---|
| 예 | 22 | 64/67 | 5.92% |
| 아니오 | 15 | 65/67 | 4.06% |
| 모름 | 15 | 4/67 | 5.92% |

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| A | 수치 "아니오"를 0으로 넣는다 | 최대 방향 임계(`"1천만원 이하"`)를 충족시킨다. 과대 진술 |
| B | 수치 질문에 "아니오" 선택지를 안 준다 | 유형에 "예"라고 답한 뒤 마음이 바뀌는 경로가 막힌다. 실제로 있는 상황이다 |
| C | 수치 "모르겠다"를 유형 "모르겠다"로 올린다 | 같은 유형의 **다른 상품** 임계까지 한꺼번에 지운다. 사용자는 한 상품 기준을 모른다고 답한 것뿐이다 |
| D | 되묻기 횟수 상한으로 무한 루프를 막는다 | 증상만 막는다. 사용자는 같은 질문을 두 번 본다 |

## 반증 조건

- **수치 질문에서 "아니오"를 고르는 비율이 0에 가까우면** — Q1이 실제로는 안 쓰이는
  경로다. 그러면 B(선택지 제거)가 더 단순하다
- **수치 "모르겠다" 뒤에 사용자가 "그 유형 자체를 안 한다"고 정정하려 하면** —
  C가 맞았던 것이다. 세션 로그의 중단 사유에서 관측된다
- **기준선이 움직이면** — 평가 경로가 이 두 수정에 걸린 것이다. 위 재측정으로
  안 움직인 것을 확인했고, 움직이면 그 자체가 신호다
