# 0061 · 0단계 폼에 표시용 스크립트 하나를 허용한다 — 금액 칸 쉼표

2026-09-09 · 이슈 [#73](https://github.com/hyos0415/fineprint/issues/73) · `prereg-29` 사람 세션 비고 · 관련 `0038`(JS 없이 도는 화면) · `0043`(렌더 함수 하나)

## Decision

**사람이 정했다** (2026-09-09 · *"추천대로 가보자"*). 0단계 폼의 금액 칸 둘(예금 예치 · 적금 월 납입)에 **치는 동안 쉼표를 넣는 스크립트**를
둔다. `50000000` → `50,000,000`. 이 저장소 화면의 첫 번째이자 유일한 스크립트다.

```
하는 것       입력 중인 숫자에 쉼표를 넣는다 · 문장에서 채워 온 값도 처음부터 쉼표로 보인다
안 하는 것    계산 · 판정 · 표시 결정 · 서버 호출. 한글 읽기("오천만 원")도 스크립트가 아니라 **서버**가 붙인다 — 같은 읽기 코드를 두 벌 두지 않는다
꺼져 있으면   폼은 그대로 동작한다. 서버 `parse_amount()` 는 쉼표 있는 값과 없는 값을 다 받는다
```

## Evidence

사람 세션 4런(`prereg-29` §7). 사용자가 미리 채워진 `5000000` 을 읽지 못해 500만원인지 5천만원인지 확인할 수 없었다 —
*"이거 알아보기 힘드네 4,000 처럼 보여줄 수 있으면"*. **읽을 수 없는 값은 확인된 값이 아니다**(A19 의 취지). 서버가 한글 읽기를
붙이는 것으로 절반은 풀렸지만, 치는 동안 읽히게 하는 것은 브라우저에서만 할 수 있다.

## Alternative

- **서버만 (JS 없음)** — 제출 뒤에만 한글 읽기가 붙는다. 치는 동안은 못 읽는다. 사람이 이 안을 보고 스크립트를 골랐다
- **`<input type="number">`** — 쉼표를 보이지 않고, `5천만원` 같은 단위 입력을 막는다
- **JS 로 한글 읽기까지** — 읽기 코드가 파이썬과 JS 두 벌이 된다. `0035` 가 찾은 실패("문구가 두 곳에 있었다")와 같은 모양 — 기각

## Why rejected

위에 같이 적었다.

## 반증 조건

- 이 스크립트가 **표시 이외의 일**(값 검증 · 단위 변환 · 서버 호출)을 하게 되면 — `0038` 의 예외가 아니라 위반이다. 되돌린다
- 화면 계약 검사가 보는 HTML 과 브라우저가 보이는 값이 **달라서 계약을 놓친 사례**가 나오면 — 스크립트를 뺀다
- 스크립트가 둘 이상으로 늘면 — "표시용 하나" 라는 이 결정의 전제가 깨진 것이다. 그때 다시 정한다
