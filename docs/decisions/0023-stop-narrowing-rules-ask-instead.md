# 0023 · 규칙을 그만 좁힌다. 대신 되묻는다

2026-08-27 · 사전등록 [`../spec/prereg-08-ask-the-step.md`](../spec/prereg-08-ask-the-step.md) ·
진단 [`../spec/prereg-07-type-assignment.md`](../spec/prereg-07-type-assignment.md) §7 ·
이슈 [#2](https://github.com/hyos0415/fineprint/issues/2)

## Decision

**저축은행 커버리지 1.0%p 를 규칙으로 쫓는 것을 그만둔다.** 원인 세 개를 다 특정하고
후보 규칙까지 쟀지만 만들지 않는다. 대신 **되물을 수 있는 것을 되묻는 데로 옮긴다.**

```
안 만든다   `적용해제` 규칙 (저축 +4행) · `cap` 규칙 (저축 +1 · 은행 -1)
안 한다     배타 그룹 재추출 (저축 +1행)
한다        임계를 읽는 짝 정규식을 맞춘다 — 계단식으로 오분류된 8문구가 질문으로 나간다
남긴다      진짜 계단 3문구는 `단계불명` 으로 (`prereg-06` §1.6 후보 A 확정)
```

**저축은행 커버리지는 35.7% 로 남는다.** `0018` 게이트 36.7% 는 계속 불통과다.
그 처리는 이 결정에서 하지 않는다 (아래 "남은 결정").

## Evidence

### 원인을 셋까지 좁혔고, 그중 둘은 예고에 없던 것이었다

`prereg-07` §7 이 하락 1.0%p 를 **3행 · 상품 3개**까지 나열했다.
`START-HERE` 4번이 예고한 원인은 둘인데 **3행 중 2행이 셋째 원인**이었다.

| 원인 | 상품 | 무엇 |
|---|---|---|
| 배타 그룹 누락 | 웰뱅 워킹 적금 | 걸음수 4단계를 쪼개고 묶지 않았다 (합 13.0 · 폭 7.0) |
| cap 오분류 | 웰뱅 든든적금 | 신용평점 항목의 상한 3.0 을 상품 전체 cap 으로 올렸다 |
| **중복 계상** | KB일반정기적금 2행 | `"미등록시 우대금리 적용해제"` 를 별개 항목 +0.1 로 만들었다 |

셋째 원인의 문장은 **`0019` 가 이미 읽은 문장**이다. 방향(`must_not_have`)만 고치고
**항목은 남겼다.** 그래서 합계가 계속 부풀어 있었고, v2 가 같은 문장에서 7번째 항목을
만들 때 대가를 냈다.

### 규칙을 좁혀서 얻는 것과 잃는 것을 다 쟀다

| 후보 규칙 | 걸리는 범위 | 저축은행 | 은행권 |
|---|---|---|---|
| `cap` 이 어떤 항목 금리와 같으면 상품 cap 이 아니다 | cap 붙은 쌍 175 중 **57** | +1행 | **-1행** |
| 근거 문구에 `"적용해제"` 가 있으면 중복 항목 | 항목 7개 (저축은행만) | +4행 | ±0행 |
| 배타 그룹 재추출 | 프롬프트 전체 | +1행 | 미측정 |

세 규칙을 다 넣으면 37.7% 까지 간다 — **기준선 36.7% 보다 위**다. 그래도 안 만든다.

### 묶는 신호는 라벨도 구조도 못 믿는다 — 규칙을 좁혀도 안 된다

`0022` 는 `exclusive_group` **라벨**이 반반 틀린다는 것을 보였다. 그러면 라벨 대신
**구조**(같은 조건문·같은 조건 유형에 항목이 여러 개)로 계단을 알아볼 수 있는지 재봤다.

```
계단 후보 군집   저축은행 8개 · 은행권 10개
그런데 진짜 계단이 아닌 것이 섞여 있다
  KB맑은하늘적금   실천_미션_인증 4항목이 한 그룹인데 합 0.8 = 공시 폭 0.8
                → 배타가 아니다. 별개 조건 4개다
  NH내가Green    같은 유형 4항목 · 그룹 없음 · 합 0.8 < 공시 폭 1.0
```

**구조 신호도 반반이다.** 라벨도 구조도 못 믿는 것을 규칙으로 가르려 하면 어느 쪽으로
좁혀도 절반은 틀린다. **사람 판단이 이 지점을 짚었다.**

> 규칙 그만 좁혀도 될 것 같다. 저축은행 상품이기도 하고, 솔직히 저런 건 추출하기보다
> 질문을 해야 하는 게 맞는 부분이라고 본다.

### 되묻기로 옮기자마자 진짜 문제가 나왔다 — 계단식의 8/11 은 계단이 아니었다

`0016` 은 "유형을 가리지 않고 되묻는다" 로 정했는데 **계단식만 예외**로 질문이 안
나가고 있었다. 그 예외의 정의를 실제 문구에 대 보니 **정의가 틀렸다.**

```
THRESHOLD_MONEY   "500만원이상" 의 `이상` 을 흡수한다 → has_threshold() 는 "임계 있다"
MONEY_VALUE       흡수부가 없다. `이` 가 한글이라 막힌다 → parse_threshold() 는 "못 읽겠다"
결과              "임계가 있는데 못 읽겠다" = 계단식  ← 오분류
```

| | 계단식 분류 문구 | 실은 단일 임계 | 진짜 계단·애매 |
|---|---|---|---|
| 은행권 | 7종 | **5종** | 2종 |
| 저축은행 | 4종 | **1종** | 3종 |

`prereg-06` §1.6 이 "11건 · 1.0%" 라 적은 열린 결정의 실체는 **3문구**다.
`"해지원금 기준 500만원이상 : 최고0.2%p"` 에는 단계가 없다.

**같은 종류의 세 번째 구멍이다** — `천만원` 단위 누락(`prereg-06` §1.1) ·
붙여쓰기 미탐 36건(`0019`) · 짝 불일치(여기). 앞의 둘을 고칠 때 짝을 안 봤다.

### 실측 — 가드는 전부 통과, 예측 둘은 틀렸다

| | 전 | 후 | |
|---|---|---|---|
| 커버리지 | 84.8% · 35.7% | **84.8% · 35.7%** | 한 행도 안 움직였다 |
| 은행권 확정 (예산 12) | 39/67 | **39/67** | **변화 0 — 예측 ≥60% 는 틀렸다** |
| 은행권 폭 평균 (예산 12) | 0.185%p | **0.176%p** | 내려갔다 |
| 은행권 확정 (예산 40) | 56/67 | **64/67** | +8행 |
| 은행권 폭 평균 (예산 40) | 0.123%p | **0.105%p** | 내려갔다 |
| `단계불명` 문구 | 7 · 4종 | **3 · 3종** | |
| 저축은행 | — | **전부 변화 0** | 옮겨간 문구의 상품이 `공시미반영` 층이다 |

**효과는 크지만 13번째 질문 뒤에 있다.** 옮겨간 문구의 수치 후속 질문이 예산 12개
밖으로 밀린다. 예측이 틀린 이유는 "효과가 없다" 가 아니라 **"보는 창이 다르다"** 다.
`0018` 의 예산 지표는 제 일을 하고 있고, 이 개선을 그 창이 못 본다.

**사전등록의 기준값도 틀렸다** — `START-HERE` 의 `0019` 시점(v1) 값을 옮겨 적었다.
같은 코드 경로에서 정규식만 바꿔 다시 쟀고 그 값을 위에 적었다. `prereg-08` §6 에
경위를 남겼다.

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| A | 후보 규칙 셋을 다 넣는다 (37.7%) | 문구를 박는 규칙이 늘어난다. `cap` 규칙은 효과가 권역마다 반대인데 cap 붙은 쌍의 3분의 1을 건드린다 |
| B | `적용해제` 규칙만 넣는다 (+4행, 부작용 0) | **가장 아까운 대안이다.** 그래도 규칙 하나를 문구로 좁히는 것이고, 지금 필요한 것은 그 방향의 중단이다. 사람 판단이 그것이다 |
| C | 배타 그룹을 재추출로 고친다 | `0013` 과 부딪친다. 그리고 라벨도 구조도 못 믿는 것이 확인됐다 |
| D | 계단식 스키마에 `tiers` 를 넣고 재추출 (`prereg-06` §1.6 후보 B) | 규모가 **3문구**다. 재추출 값어치가 없다 |

## Why rejected

B 를 버린 것이 이 결정에서 가장 값을 치른 부분이다. 저축은행 +4행 · 은행권 부작용 0 ·
발자국 7항목이라 **숫자만 보면 넣는 게 맞다.**

넣지 않은 이유는 하나다 — **이 프로젝트에서 규칙을 좁히는 일이 이미 세 번 같은 모양으로
돌아왔다.** `천만원` 누락 · 붙여쓰기 미탐 · 짝 불일치. 그때마다 규칙을 하나 더 좁혀서
막았고, 그다음 구멍이 같은 종류로 다시 나왔다. `0007`(규칙 파서 깎기 종료)이 재서 남긴
결론과 같다 — 세 라운드 깎아 개발 집합은 +9.1%p 였고 **처음 보는 기관은 +0.5%p** 였다.
규칙은 특정 은행의 표기 습관을 배운다.

**그래서 이번에는 규칙을 늘리지 않고, 되물을 수 있는 것을 되묻는 쪽으로 옮겼다.**
그리고 그렇게 옮기자마자 규칙 셋보다 큰 것을 찾았다 — 계단식의 8/11 이 계단이 아니었다.

## 반증 조건

- **9월 공시에서 `단계불명` 문구가 다시 늘어나면** — 짝 정규식 수정이 이번 표본에만
  맞은 것이다. 지금 은행권 3종 · 저축은행 3종이다
- **옮겨간 6문구 중 하나라도 실제로는 계단이었으면** — 사용자에게 **과대 진술**이 된다
  (단일 임계로 보고 최고 금리를 확정으로 낸다). 사람이 6종을 다 읽었고 하나도 계단이
  아니었지만, 9월에 새 문구가 들어오면 다시 읽는다
- **`적용해제` 를 안 고친 대가가 커지면** — 지금 저축은행 4행이다. 월 갱신에서 같은
  문장이 늘어 10행을 넘으면 B 를 다시 본다
- **예산 12개 창이 개선을 계속 못 보면** — 이번뿐이 아니라 다음 개선도 13번째 질문
  뒤에 나타나면, 예산 12개가 지표로서 무엇을 재는지 다시 봐야 한다. `0018` 을
  뒤집는다는 뜻이 아니라 **부 지표를 하나 더 놓는다**는 뜻이다
- **저축은행 커버리지가 35.7% 아래로 더 내려가면** — 규칙을 안 만들기로 한 판단이
  틀린 것이다. 그때는 B 부터 다시 꺼낸다

## 남은 결정 — 사람이 정할 것

1. **`0018` 저축은행 게이트 36.7% 를 어떻게 하는가.** 35.7% 로 남기로 정했으므로
   `0022` 대안 D(기준선 재등록)를 유지할 근거가 사라졌다 — 그때 유지한 이유가
   *"바를 낮추지 않고 넘을 방법을 아는 상태로 둔다"* 였는데 **이제 넘지 않기로 정했다**
2. **저축은행 홀드아웃 자격.** `prereg-07` §7 의 숫자를 이미 봤다. 이 결정은 저축은행을
   보고 규칙을 고른 것이 아니라 **규칙을 안 만들기로** 한 것이고, 실제 수정은 짝 정규식
   불일치라 저축은행에서 효과가 0 이다. 홀드아웃을 태우지 않았다고 보지만 사람이 확인할 것
