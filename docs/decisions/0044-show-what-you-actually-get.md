# 0044 · 지금 확실히 받는 금리 순을 화면에 낸다

2026-09-02 · 이슈 [#42](https://github.com/hyos0415/fineprint/issues/42) ·
`../spec/prereg-14-human-walkthrough.md` §8 · `0017` 의 미완성 부분

## Decision

**정렬을 사용자에게 고르게 한다.** 시작 폼에 선택지를 두고, 화면 안에서도 버튼 하나로
바꾼다. 답한 것은 그대로 유지된다.

```
조건을 다 채웠을 때 받을 수 있는 금리 순    ← 기본값 (`0017`)
지금 확실히 받는 금리 순                 ← 새로 낸다. 조건을 채우기 어렵다면 이쪽
```

**성과 줄의 낱말도 같이 바꾼다.** 확정순 화면에서 `최고` 라고 쓰면 거짓이다 —
`확실히 받는 것 중 최고` 라고 쓴다. 화면 계약 **A8 에 이 낱말을 검사하는 줄을 더했다**
(원래 있던 `최고` 검사는 그대로 둔다).

**정렬 규칙을 `prefs.sorter()` 한 곳에 모았다.** 흩어져 있으면 노출하는 순간 갈라진다.

## Evidence

`--sort lo` 는 **처음부터 있었다**(`0017`). CLI 에만 있었고 웹에는 없었다.

사람 완주 2런에서 이 말이 나왔다.

> 사실상 내 기준에서 답하는 게 별 의미가 없는 게 **카드 안 쓰고 소득 없는 상황**이니깐

재 봤다 (은행권 12개월 · 메인 67개 · 카드·급여·잔액은 아니오, 돈 안 드는 조건은 예).

```
확정 금리 최고    3.64% → 3.64%   답을 9개 해도 **안 움직인다** — 말이 맞다
확정 상품 수      4개 → 23개      얻는 것은 높은 금리가 아니라 **확신**이다
화면 맨 위       카카오뱅크 우리아이적금 2.54~5.92%
실제로 받는 것     Only One 주거래 우대적금 3.64~4.06%   ← **다른 상품이다**
```

무작위 200명(전부 답한 끝 상태)에서 얼마나 흔한지 쟀다.

```
최대순 1위 ≠ 확정순 1위      39명 / 200 (19.5%)
갈릴 때 확정 금리 차이        중앙값 +0.38%p · 최대 +1.44%p
0.5%p 이상 놓치는 사람        19명 (9.5%)
```

**5명 중 1명이 화면 맨 위 상품보다 확실히 더 주는 상품을 옆에 두고 있었다.**

`0017` 이 이미 이렇게 예측해 뒀다.

> **조건을 못 채우는 사용자에게만 크게 움직인다.** 그 사람이 정확히 알아야 할
> 사람이므로 방향이 맞다.

**예측은 맞았고 구현이 반만 따라갔다.** 그 사람이 봐야 할 정렬이 화면에 없었다.

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| B | 조건을 못 채우는 것이 보이면 **화면이 알아서** 확정순을 같이 보여준다 | *"못 채운다"* 를 **시스템이 판정**하는 것이다. 이 프로젝트는 선호를 추측하지 않는다 — 계산만 책임진다(`CLAUDE.md` 한 줄 요약 · `0024` P2). 넘지 말아야 할 선에 닿는다 |
| C | 기본 정렬을 확정순으로 되돌린다 | `0017` 이 실측으로 기각했다 — 확정순 첫 화면은 사실상 기본금리 순이고 **조건이 좋은 상품이 묻힌다**(상위 3위가 0/3 겹친다) |
| D | 두 목록을 한 화면에 나란히 놓는다 | 상품 하나가 두 번 나온다. 목록 1위가 둘이면 A8(성과 줄 = 목록 1위)이 성립하지 않는다 |

## Why rejected

B 가 가장 편했다 — 사용자가 아무것도 안 골라도 되니까. 그런데 그러려면 시스템이
*"이 사람은 조건을 못 채운다"* 를 판정해야 하고, 그건 **답을 대신 정하는 쪽으로 가는
첫 걸음**이다. 이 저장소는 되묻기를 넣을 때 같은 자리에서 같은 선택을 했다 —
모르면 추측하지 않고 **묻는다**(`0016`·`0024` P5).

A 의 대가는 하나다. **선택지가 하나 늘어난다.** 사용자가 무엇을 고를지 모를 수 있다.
그래서 두 가지를 같이 했다 — 선택지 이름을 *"조건을 다 채웠을 때 받을 수 있는 금리 순"* ·
*"지금 확실히 받는 금리 순"* 으로 **풀어 쓰고**, 화면에 **지금 무슨 순서인지 항상 적는다.**
고르지 않아도 기본값이 `0017` 그대로라 아무것도 안 바뀐다.

## 반증 조건

- **아무도 안 바꾸면** — 선택지가 늘기만 하고 쓰이지 않는다는 뜻이다. 그때는 B 를
  다시 본다(판정을 시스템이 하되 **사용자에게 이유를 보여주는** 형태로)
- **바꿔도 목록이 거의 같으면** — 19.5%는 무작위 답 사용자다. **실제 사용자 분포에서**
  갈리는 비율이 5% 아래면 화면을 복잡하게 만든 값을 못 한 것이다
- **확정순 화면을 보고 "그럼 5.92% 는 어디 갔나" 가 나오면** — 확정순 상위 10개에는
  최대 금리가 높은 상품이 안 들어온다. 지금은 전환 버튼 문구가 그걸 안내하는데,
  그것으로 부족하면 **확정순 화면에도 "다 채우면 최대 얼마" 를 한 줄 적어야 한다**
- **A8 이 새 낱말을 안 잡으면** — 일부러 깨뜨려 확인했다(정렬만 최대순으로 되돌리고
  라벨은 확정순으로 두면 세션 하나에서 30건 잡힌다). 이게 0건이 되면 검사가 죽은 것이다
