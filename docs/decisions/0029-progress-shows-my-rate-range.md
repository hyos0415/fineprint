# 0029 · 상태바 둘째 숫자를 "내 금리 범위" 로 바꾼다

2026-08-31 · 사전등록 [`../spec/prereg-11-candidate-scope.md`](../spec/prereg-11-candidate-scope.md) §7 ·
앞선 결정 `0017`(최고부터 보여주고 깎는다) · `0024` P4(상태바 숫자 둘) · `0026`(완주율은 지표가 아니다) ·
`0028`(후보 집합) · 이슈 [#15](https://github.com/hyos0415/fineprint/issues/15)

## Decision

**`0024` P4 의 둘째 숫자를 바꾼다.** 확정 상품 수를 주 지표에서 부 지표로 내리고,
그 자리에 **사용자 자신의 금리 범위**를 올린다.

```
전   진행  답한 질문 7/7개 · 남은 0개
     성과  금리가 정해진 상품 2/4개

후   진행  답한 질문 7/7개 · 남은 0개
     성과  최고 2.75~3.26%  우리SUPER주거래적금  (폭 1.18 → 0.51%p)   ← 주
           금리가 정해진 상품 2/4개                                   ← 부
```

**데이터는 둘 다 유지한다.** 상태 dict 에 범위·폭·확정 수·1위 상품을 전부 담고,
화면이 무엇을 앞에 놓을지만 정한다 — UI 를 붙일 때 같은 dict 로 시각 요소만 바꾼다.

**새 화면 계약 A8** — 성과 줄의 범위는 실제 1위 상품의 `net_lo~net_hi` 와 같아야 한다.

## Evidence

### `0024` 의 반증 조건 4가 발동했다

`0024` 는 이 상황을 **미리 적어 뒀다.**

> **확정 상품 수가 사용자에게 성과로 읽히지 않으면** — P4 의 둘째 숫자가 제 일을 못
> 하는 것이다. 폭 평균이나 1위 금리 변화로 바꿔 본다

2026-08-31 사람 세션(우리은행·적금 스코프 · 질문 7개 완주)에서 자기보고로 나왔다.

> 진행상황에 대해서 볼 때 그냥 진행 바밖에 안 보이던데 시각적으로??

### 원인은 데이터에 있다 — 안 움직이는 숫자였다

```
단계    0    1    2    3    4    5    6    7
확정    0    0    0    0    0    0    0    2      ← 마지막 답에서야 처음 움직였다
폭    1.18 0.59 0.51 0.51 0.51 0.51 0.51 0.51   ← 초반 두 답에서 크게 움직였다
```

**후보가 4개뿐이면 확정 카운터는 거의 안 변한다.** 전체 카탈로그(67상품) 세션에서는
4 → 50 까지 움직였다 — 즉 확정 수는 **후보 집합 크기에 종속**이고, `0028` 로 스코프를
넣은 뒤 그 약점이 드러났다. 반면 **범위 폭은 후보 크기와 무관하게 매 답마다 움직인다.**

### 그런데 확정 수를 버리지는 않는다

`0024` P4 가 확정 수를 넣은 이유가 여전히 유효하다 — **"모르겠다" 와 "아니오" 를
가르는 유일한 숫자**다(끝까지 갔을 때 예 64 · 아니오 65 · 모름 4). 폭만 보여주면
"모르겠다" 의 대가가 다시 안 보인다. 그래서 **주/부로 나란히 둔다.**

### 1위 상품이 바뀌는 것을 숨기지 않는다

`0017` 이 *"답할수록 순위가 바뀐다"* 를 의도한 설계다. 그래서 범위 옆에 **상품명을
같이 적는다** — 안 적으면 `2.07~3.26 → 2.75~3.26` 이 서로 다른 상품의 비교인데
같은 상품이 좁아진 것처럼 읽힌다.

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| A | 확정 수를 유지하고 시각 강조(막대·색)만 준다 | **안 움직이는 숫자는 강조해도 안 읽힌다.** 위 실측 |
| B | 범위만 보여주고 확정 수를 뺀다 | "모르겠다" 의 대가가 안 보인다 (`0024` P4 · 대안 D 와 같은 자리) |
| C | 폭 **평균**(메인 층 전체)을 쓴다 | 지표로는 맞지만(`ask_budget.py`) 사용자에게 추상적이다. **내가 받을 금리**가 아니다 |
| D | 1위 금리(hi)만 보여준다 | 최댓값 단독 표시는 `0017` 이 금지했다 |

## 반증 조건

- **범위도 안 읽히면** — 상태바 자체가 과한 것이다. 그때는 상품 목록만 남기고
  상태바를 줄이는 쪽을 본다(질문 진행은 "남은 N개" 한 줄로 충분할 수 있다)
- **1위 상품이 매 답마다 바뀌어 범위가 널뛰면** — 비교가 무의미해진다. 그러면 C(폭 평균)
  또는 "내가 고른 상품 하나를 고정해 추적" 으로 바꾼다
- **A8 위반이 나오면** — 성과 줄과 상품 목록이 다른 값을 말하는 것이다. A1~A7 과 같은
  종류의 실패이므로 즉시 고친다
- **확정 수가 부 지표로 내려간 뒤 "모르겠다" 비율이 올라가면** — 대가가 안 보여서
  사용자가 쉽게 "모르겠다" 를 고르는 것이다. `0024` P4 의 원래 우려가 맞았던 것이므로
  주/부를 되돌린다

## 남은 것

- **A7 줄에 가입 채널을 붙이는 것** — 같은 세션에서 나온 별개 발견이다. 사용자가
  스코프 밖 상품(경남은행)을 고려하지 않은 이유가 *"주거래도 아니고 연고도 없고 실물을
  본 적도 없다"* 였는데, **`join_way`(비대면 가능 여부)가 그 판단에 필요한 정보**이고
  데이터는 이미 100% 채워져 있다. 로드맵 E5(편의 속성 결합)와 붙는다 — 별도 작업
