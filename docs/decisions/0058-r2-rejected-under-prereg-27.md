# 0058 · R2 조건 답 제안은 `prereg-27` 아래에서 기각 — 값은 거래 은행 목록에 있었다

2026-09-07 · 이슈 [#73](https://github.com/hyos0415/fineprint/issues/73) · `prereg-27` §6 · `0057`(방향 · "기각이 되면 그거 나름대로도 결론")

## Decision

```
D1  자연어에서 **조건 답 후보**를 뽑아 화면에 올리는 것은 이 사전등록의 관문(잘못 채운 답 0 · 프롬프트 두 판)을 넘지 못했다.
    **기각을 결론으로 기록한다.** 확인 화면(A19)은 만들지 않는다. 최고 판은 Qwen3.5-4B v1 — 화면 오답 1(보수적 "모름") · 원출력 4
D2  **값이 어디 있었는지를 남긴다** — 질문 감소의 대부분이 **거래 은행 목록**(F6 의 `_거래은행`)에서 왔다. 우리·국민 거래가 있다는 한
    문장이 86 → 27, 거래 없다는 문장이 42 → 11. 조건 답 하나는 1~2개다. 거래 은행 목록과 스코프(권역·은행·상품군·기간·금액)는
    **스키마 enum 으로 닫히는 값**이라 오답의 모양이 다르다(없는 은행이 나올 수 없다)
D3  그래서 다음 후보는 **좁힌 R2** 다 — 자연어 → 스코프 + 거래 은행 목록만(조건 답 없음). 이것은 `0042` 원안(D3 화이트리스트 넷)에
    거래 은행 목록 하나를 더한 모양이고, `0057` 이 넓힌 조건 답은 빼는 것이다. **만들지는 않았다** — 새 사전등록(`prereg-28`)과
    **새 표본 문장**이 먼저다(같은 20문장으로 다시 재면 조정이다). 할지는 사람이 정한다
D4  로컬 서빙은 세워졌다 — llama.cpp b10830 · CUDA 13.3 · 8GB 에 4B/7.8B/9B 전부 적재 · 문장 하나 6~9초. 이 자산은 남는다
D5  관측 넷을 원칙으로 적어 둔다 — ① 작은 모델에 규칙을 더하면 채우는 쪽으로 기운다 ② 큰 모델이 더 정확하지 않았다(9B·7.8B 가 4B 보다
    화면 오답이 많거나 같다) ③ 화이트리스트 필터가 원출력 오답의 절반 이상을 걸렀다 — 안전은 필터가 만들고 있다
    ④ 가장 위험한 오답은 뜻이 뒤집히는 것("처음이야" → 첫거래 아니오)이고, 그것은 필터가 우연히 걸렀다
```

## Evidence

`prereg-27` §6 표. 여섯 판 중 화면 오답 0 이 없다. 예측은 일곱 중 다섯이 맞았고 틀린 둘이 결론을 정했다 — P5(지연 > 5초)와
**P6(가치 중앙값 2.5 < 3)**. 즉 안전 축은 아슬아슬하고 가치 축은 조건 답 쪽이 작다. 둘을 합치면 "조건 답 제안" 은 위험 대비 얻는 것이 작다.

**이 결론은 오늘 하루의 결론과 이어진다** — LLM 이 사용자와 만나는 유일한 자리를 재 봤고, 모델이 **사용자의 말을 조건 답으로 옮기는 일**은
확인 화면을 붙여도 20문장에서 1~2개가 어긋났다. 그 어긋남이 과대 진술 방향이면 이 프로젝트가 가장 막는 실패라서 0 을 요구했다.

## Alternative

- **A. 관문을 고쳐 다시 잰다**(예: 과대 진술만 0 · "모름" 은 안 채운 것으로) — 측정 뒤에 기준을 고치는 것이다(`CLAUDE.md` 3번). 하려면
  **새 사전등록 · 새 표본**으로 한다(D3). 기각
- **B. 프롬프트를 세 번째로 고친다** — `0057` 이 두 판으로 못 박았다. 두 판의 결과가 반대 방향(4B 악화 · 9B 개선)이라 세 번째가
  수렴할 근거도 없다. 기각
- **C. 더 큰 모델(27B 이상)** — 8GB 에 안 올라간다. 클라우드로 보내면 `0042` D1(개인정보) 위반. 기각
- **D. 확인 화면을 붙이면 오답도 사용자가 고르니 괜찮다** — 확인이 형식이 되는 것을 `0057` 반증 조건 2 가 이미 경고했다. 제안이 틀리면
  사용자는 그것을 기본값으로 읽는다. 기각
- **E. 조건 답은 빼고 스코프 + 거래 은행 목록만** — D3. **후보로 남긴다** (사람 결정)

## Why rejected

위에 같이 적었다.

## 반증 조건

- **새 표본 · 새 사전등록(`prereg-28`)에서 좁힌 R2(스코프 + 거래 은행)가 은행 enum 오답 0 · 목록 일치 ≥ 90% 를 넘으면** — D3 의 후보가
  살아난다. 그때 화면(확인 단계 포함)을 만든다
- **8GB 에 올라가는 한국어 모델이 크게 좋아지면** — D1 을 다시 잰다. 단 같은 20문장은 쓰지 않는다
- **사람 세션에서 "폼이 귀찮다 · 말로 하고 싶다" 가 반복 관측되면** — 가치 축의 가정이 바뀐 것이다. R2 전체를 다시 본다
- **필터가 걸러 낸 뒤집힘 오답이 필터 안에서도 나오면**(후보 집합 안의 키를 뒤집어 채우면) — 지금 결과보다 나쁜 것이다. 조건 답 제안은
  더 멀어진다
