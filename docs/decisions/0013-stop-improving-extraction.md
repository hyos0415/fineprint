# 0013 — 추출 개선을 여기서 멈춘다. 남은 실패의 71%는 공시 문제다

> 날짜: 2026-08-26 · 상태: 유효 · `E10`·`E11` 진단 결과 · 사전등록 `../spec/prereg-04-fallback.md`

## Decision

**폴백 83.9%(은행권)를 받아들이고 추출기를 더 손보지 않는다.**

- `E11`(`threshold` 재추출)을 **하지 않는다**
- 상위 모델 재시도, 규칙 버전 앙상블도 **하지 않는다**
- 남은 실패는 `설명부족` · `계산불가` 층으로 **사용자에게 표시**한다(`problem.md` §5)

## Evidence

**폴백 이후 남은 실패를 원인별로 셌다.**

| | 은행권 26행 | 저축은행 25행 | 합계 51행 |
|---|---:|---:|---:|
| **고칠 수 있다** | 8 (31%) | 2 (8%) | **10 (20%)** |
| **못 고친다 — 공시 문제** | 17 (65%) | 19 (76%) | **36 (71%)** |
| 미분류 | 1 | 4 | 5 |

**못 고치는 것 두 종류**

```
A-1  공시 상한 < 실제 폭      14행    "최고 0.5%p" 라는데 실제 폭이 2.0
A-2  조건문에 금리가 없다      22행    "입금실적에 따라 우대금리 적용" — 숫자가 없다
```

**어떤 추출기도 없는 숫자를 만들 수 없다.** A-1은 어제 상품설명서 실물로 확인한
현상이다(`0011`) — 법정 공시 서류에서도 "이벤트시 별도 고시"로 끝난다.

**고칠 수 있는 것 두 종류 — 규칙 하나당 4~6행**

```
B-1  상한만 있고 항목 0개     6행    "개인형 우대이율: 최대0.5%"  → 상한을 답으로
B-2  N가지 중 M가지 선택      4행    "9가지 중 6가지, 항목당 0.1%"  → 6×0.1
```

**은행권 +3.4%p · 저축은행 +1.1%p.** 그리고 B-1은 이미 편중이 확인됐다 —
`0011`에서 재봤을 때 은행권 11행 적중 / 저축은행 2행 적중이었다.

**넘침 쪽도 대상이 작다.** 폴백 이후 넘침은 은행권 12행 · 저축은행 13행이다.
`threshold`는 그중 일부만 겨냥한다.

**규칙 버전 앙상블은 막혔다.**

```
앙상블 상한 (v2 or v3 or B)
  은행권      83.9%  →  +0.0%p    v2 가 잡는 것을 v3·B 가 다 잡는다
  저축은행     79.1%  →  +1.1%p
```

## 현실적 천장

```
은행권 236행
  폴백이 맞힌 것            198   83.9%
  고칠 수 있는 모자람          8    3.4%   → 손보면 87.3%
  공시 문제 (못 고침)         17    7.2%
  넘침                     12    5.1%
  미분류                     1
                          ─────
  천장                     약 88~92%
```

**83.9%가 천장에서 4~8%p 아래다.** 그 간격을 메우려면 규칙을 또 깎아야 하는데,
오늘 두 번 확인한 것이 있다.

```
0007        규칙 세 라운드 → 개발 +9.1%p · 홀드아웃 +0.5%p
0012 부수    v3 → 은행권 폴백 +6.8%p · 저축은행 폴백 −1.1%p
```

**규칙 깎기는 개발 집합에서만 듣는다.** B-1이 이미 은행권에 편중돼 있으므로
같은 패턴을 반복할 것으로 본다.

## Alternative

- **(가) B-1·B-2 규칙을 사전등록하고 넣는다** — 비용 0, +2~3%p
- **(나) `threshold` 재추출** — $1, 넘침 12~13행 겨냥
- **(다) 상위 모델(Sonnet/Opus)로 실패한 것만 재시도**
- **(라) 공시 최고금리를 추출기에 준다** — 목표를 알려주고 맞추게 한다

## Why rejected

- **(가) B-1·B-2**: 얻는 게 8행인데 규칙 복잡도가 늘고, 은행권에 편중된 패턴이다.
  **미래에 다시 열 수 있다** — 다른 권역 데이터가 늘어 편중이 아님이 확인되면
- **(나) `threshold`**: 대상이 넘침 12~13행이고, 그중 `threshold`가 원인인 것은
  일부다(`0011` 확인: 고시금리 포함 표기·복합 조건이 섞여 있다). 재추출 비용보다
  얻는 게 작다. **사용자별 계산에는 여전히 필요하므로 `E11`은 폐기가 아니라 보류다**
- **(다) 상위 모델**: 남은 실패의 71%가 "없는 숫자"다. 모델을 키워도 없는 숫자를
  못 만든다. 돈만 든다
- **(라) 최고금리를 알려주기**: **금지된 방향이다.** `prereg-03` §1이 "추출기가 목표값을
  보면 거기에 맞춰 값을 만들어낸다"고 명시했다. 닫힘률이 채점 지표인데 그 답을 입력에
  주면 지표가 무의미해진다

## 그래서 남은 실패를 어떻게 다루나

**추출로 못 고치는 것은 사용자에게 알린다.** 이미 층 구조가 있다(`calculate.py`).

```
설명부족    "광고 최고금리의 일부는 공시된 조건으로 설명되지 않습니다"     A-1 · 14행
계산불가    "조건을 읽어내지 못해 금리를 계산할 수 없습니다"            A-2 · 22행
공시미반영   "조건문에 우대가 있으나 공시에 반영되지 않았습니다"          폭 0 행
```

**이게 추천기에서는 기능이다.** 검증기였다면 "지표가 낮다"로 끝났을 것을,
추천기에서는 "이 상품은 광고대로 못 받을 수 있다"는 경고로 쓴다.

## 반증 조건

- **다른 권역에서 "고칠 수 있는" 비율이 50%를 넘으면** → 20%는 이 두 권역에 국한된
  것이다. 그때 B-1·B-2를 다시 검토한다
- **`threshold`를 넣었을 때 사용자별 계산 정확도가 크게 오르면** → `E11`을 닫힘률
  관점으로만 판단한 것이 좁았다. 사용자별 계산은 별도 지표로 재야 한다
- **A-2(금리 없는 조건문)가 상품설명서에는 숫자로 있으면** → `0011`의 판단이 상품
  유형에 국한된 것이다. 케이뱅크 "입금실적에 따라" 유형을 아직 확인하지 않았다
- **폴백 83.9%가 다른 권역에서 70% 미만으로 떨어지면** → 천장 추정이 이 두 권역에
  과적합한 것이다
