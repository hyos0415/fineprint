# 0015 · 금액·횟수 임계는 되묻는다

2026-08-26 · 이슈 [#2](https://github.com/hyos0415/fineprint/issues/2) (D3) ·
사전등록 [`../spec/prereg-06-matching-and-judgment.md`](../spec/prereg-06-matching-and-judgment.md) §1.3

## Decision

우대조건에 금액·횟수 임계가 붙어 있으면 **사용자에게 수치를 되묻고 비교한다.**
안 물어봤으면 판정 불가로 두어 범위에 넣는다 — 추측하지 않는다.

```
"급여이체 실적(월 50만원 이상)"  +  사용자 "급여이체 O"        →  판정 불가 (범위)
                              +  사용자 "월 80만원"          →  충족   (확정)
                              +  사용자 "월 30만원"          →  미충족 (확정)
```

질문은 **유형 하나에 하나**다. 상품마다 임계가 달라도 "월 몇 회 하십니까"는 한 번
물으면 되고 비교는 상품별로 한다. 계산기는 **답 하나가 상품 몇 개를 확정으로 옮기는지**
순으로 질문을 보여준다.

## Evidence

**재추출이 필요 없었다.** $1이 든다고 예상했는데 **근거 문구에 숫자가 이미 있었다.**
임계 항목 143개 중 **132개(92.3%)**를 정규식으로 읽는다.

12개월 상품에서 확정이 이만큼 늘었다.

```
              A 확정  A 범위      B 확정  B 범위
은행권 79개       51     13    →     64      0      범위가 사라진다
저축은행 297개     86     23    →    105      4      계단식 4개만 남는다
```

**폴백 83.9%는 그대로다.** 임계 처리는 추출이 아니라 판정 단계라 닫힘률과 무관하다.

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| A | 임계가 붙은 조건은 판정 불가로 둔다 | 정직하지만 13.6%를 통째로 범위에 버린다. **B가 공짜로 되니 A를 유지할 이유가 없다** |
| C | 사용자가 "O"라고 하면 임계도 충족으로 본다 | **과대 진술.** 이 프로젝트가 잡으려던 실패가 정확히 그것이다 |
| D | 이미 묻는 가입금액과 비교한다 | "펀드 보유액"처럼 안 묻는 항목은 여전히 모른다. B의 부분집합이다 |

## Why rejected

C는 `problem.md` §1이 금지한 방향이다. A는 B의 비용이 0으로 드러난 순간 근거를 잃었다.

## 반증 조건

- **설문 항목이 사용자가 포기할 만큼 늘어나면** — 지금 되물을 질문은 유형당 하나이고
  은행권에서 5개다. 이게 15개를 넘으면 다시 A로 후퇴하거나 "모르면 넘기기"를 넣는다
- **파싱이 임계를 잘못 읽어 확정이 틀리면** — 사람 표본 검토에서 오독이 5%를 넘으면
  파싱 결과를 확정 근거로 쓰지 않는다. 특히 단위 오독은 1,000배 오차를 낸다
- **되물어도 확정이 안 늘면** — 지금 +25%다. 다른 스냅샷에서 +5% 미만이면 이 결정의
  근거가 사라진다

## 부수 발견 둘

**1. 단위 목록 누락은 방향이 나쁘다.** 처음 정규식에 `천만원`이 없어서 `"5천만원 이상"`을
임계로 세지 못했다(11.5% → 실제 13.6%). **임계인 줄 모르면 사용자 답을 그대로 충족으로
세어 과대 진술이 된다.** 값을 읽을 때 `천만원`을 `만원`으로 읽으면 **1,000배 오차**다.
그래서 검사 정규식과 파싱 정규식이 같은 단위 목록을 쓰게 묶었다.

**2. 계단식 우대는 추출기가 정보를 버렸다** (11건 · 1.0%).

```
"자동이체 입금횟수 우대금리 : 최고 0.5%p - 5회이상 : 0.2%p, 10회이상 : 0.3%p, 15회이상 0.5%p"
```

스키마에 단계를 담을 자리가 없어 **가장 높은 금리만 남았다.** 사용자가 "10회"면
실제로는 0.3%p인데 우리가 아는 값은 0.5%p다. 지금은 판정 불가로 남긴다.
스키마에 `tiers`를 넣을지는 열린 결정이다(`../spec/prereg-06-matching-and-judgment.md` §1.6).
