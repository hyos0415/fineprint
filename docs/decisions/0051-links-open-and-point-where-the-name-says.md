# 0051 · 링크는 눌러서 열리고, 이름이 가리키는 곳으로 간다 — 스킴만 보정하고 코드로 짝짓는다

2026-09-04 · 이슈 [#60](https://github.com/hyos0415/fineprint/issues/60) · `prereg-21` ·
앞선 결정 `0037`(링크만 주고 가입은 받지 않는다) · `prereg-20` §5(스킴 없는 URL 10곳)

## Decision

**사람이 스킴을 정했다** — *"붙이든 안 붙이든 눌러서 열리게"*. 그것을 다섯으로 옮긴다.

```
D1  홈페이지 URL 은 API 값 그대로다. **스킴이 없을 때만 화면에 낼 때 `https://` 를 붙인다.**
    저장 데이터는 안 고친다. 파라미터가 붙은 2곳(우리은행 · 푸른저축은행)도 그대로다 (`0037` D2)
D2  대표전화는 API 값 그대로다(숫자만 · 8~10자리). 하이픈을 우리가 넣지 않는다. 대신 `tel:` 링크로
    눌러서 걸리게 한다 — 스킴 결정과 같은 태도다(표기를 지어내지 않고 동작만 보장)
D3  **기관 코드(`co_no`)로 짝짓는다.** 이름으로 짝짓지 않는다 — `prereg-20` P4 가 코드 짝을 확인했다
D4  고지에 *"여기서 가입 신청을 받지 않습니다"* 를 더한다 (`0037` D4). 상수는 `calculate.NOTICE` 하나다
D5  화면 계약 **A17** — (가) 목록의 모든 상품에 홈페이지·전화가 화면에 있다 (나) 화면 URL 은 API 값
    그대로거나 `https://` + API 값이다 (다) **링크가 가는 기관(코드)과 화면 이름(company)이 같은
    기관이다.** (다)는 측정 중에 더했다 — 아래
```

링크는 **목록**에만 붙인다. 스코프 밖 줄(A7)과 비교 리포트(F1)에는 안 붙인다 — 그 자리는 "밖에
무엇이 있나"·"왜 이 금리인가" 이고 갈 곳은 목록에 있다.

## Evidence

`prereg-21` §5. 여섯 예측 중 넷이 맞았다 — 뷰 모델의 숫자는 한 칸(고지)만 달라졌고, 은행권은
A1~A17 전부 통과다.

**D5 (다)를 더하게 만든 관측.** 링크를 코드로 붙이고 보니 저축은행 12개월 화면 상품 71개 중 12개가
**코드의 기관과 이름의 기관이 다르다** — 코드 0010378(바로저축은행)의 금리 행에 하나저축은행
`1Q 비대면정기예금` 의 이름·조건이 붙어 있다. 원인은 추출의 행 짝짓기(상품코드만 키)이고 저축은행
행 297 중 160 이 그렇다. 이슈 [#61](https://github.com/hyos0415/fineprint/issues/61) 로 뺐다.
**링크가 있어서 드러났다** — 링크가 없을 때는 이름과 금리가 다른 기관 것이어도 화면에서 보이지
않았다. `0031`(A11 이 상품 수 오류를 찾음)과 같은 모양이다.

**P1 은 스크립트로 97곳 중 95곳, 브라우저로 97곳 전부.** 페퍼저축은행은 파이썬 인증서 저장소의
실패(curl 200)였고, JT저축은행(403)은 **사람이 같은 날 브라우저로 열어 확인했다 — 열린다.** 그래서
"열린다" 의 정의를 사용자 브라우저 기준으로 고쳐 적었다(`prereg-21` §5 · 아래 반증 조건 2 발동).

## Alternative

- **A. 스킴 없는 URL 을 그대로 낸다** — 링크가 안 된다. 사람이 *"눌러서 열리게"* 로 기각했다
- **B. 저장 데이터(`company_*.json`)의 URL 을 고친다** — 원본이 API 값과 달라진다. 다음 달 받으면
  다시 없어지고, 우리가 고친 것과 API 가 준 것을 가를 수 없게 된다
- **C. 전화에 하이픈을 넣는다** — 8자리(1588-xxxx)·9자리(02-xxx-xxxx)·10자리(0xx-xxx-xxxx)의 규칙을
  우리가 정하는 것이다. 틀리면 없는 번호를 화면에 낸다. `tel:` 이 같은 일을 표기 없이 한다
- **D. 이름으로 짝짓는다** — 저축은행 화면의 A17 (다) 위반이 사라진다. **기각** — 그러면 금리와 링크가
  다른 기관이 된다. 행이 틀린 것을 링크가 덮어 주는 셈이다
- **E. 코드-이름이 다른 행은 링크를 비운다** — 화면은 조용해지고 결함은 남는다. 검사가 잡아야 할
  것을 렌더러가 숨긴다(`0039` 가 막은 자리)
- **F. JT저축은행 링크를 §4 대로 빈 칸으로 낸다** — 403 은 스크립트 기준이고 기관 제외 목록(사람이
  관리하는 사전)을 새로 만들어야 한다. 사람이 브라우저로 한 번 열어 보는 것이 더 싸고 정확하다

## Why rejected

위에 같이 적었다.

## 반증 조건

- **`https://` 를 붙인 10곳 중 https 로 안 열리는 곳이 생기면** — D1 의 전제(실측 10곳 전부 https 200)가
  깨진 것이다. `--open` 을 다시 돌리고 그 기관은 빈 칸으로 낸다(추측으로 http 를 붙이지 않는다)
- **사람이 JT저축은행을 브라우저로 열어도 안 열리면** — `prereg-21` §4 대로 빈 칸 처리하고 기관 제외
  목록을 만든다. 열리면 §3 의 "열린다" 정의를 브라우저 기준으로 고쳐 적는다.
  **열렸다 (2026-09-04 · 사람 확인) — 정의를 고쳐 적었고 빈 칸 처리는 없다**
- **API 가 URL 에 추적 파라미터를 붙여 주기 시작하면** — 우리가 붙인 것이 아니어도 실적이 누군가에게
  돌아가는 구조다. `0037` 반증 조건 2 를 같이 다시 읽는다
- **사용자 세션에서 "여기서 가입하면 되나요" 가 나오면** — D4 의 문장이 일을 안 하는 것이다(`0037`
  반증 조건 4). 문구·위치를 고친다
- **#61 이 닫힌 뒤에도 저축은행 A17 (다)가 걸리면** — 짝짓기 말고 다른 원인이 있다. 그 행을 먼저 본다
