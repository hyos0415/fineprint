# 0062 · 카드 데이터는 지금 모으지 않는다 — 기계가 읽는 공적 원천에 연회비·전월 실적 칸이 없다

2026-09-09 · `prereg-32` §6 · 사람 제안(교차판매 · 그래프) · 관련 `0056`(코퍼스도 같은 이유로 지금 안 모음) · `0037`(권유하지 않는다) · 결정 README D5·D7

## Decision

카드 상품 데이터(연회비 · 전월 실적 기준 · 발급 기관)를 **지금은 수집하지 않는다.** 따라서 "카드를 만들면 남는 게 있나" 를 계산해 주는 교차판매 화면도 열지 않는다.
카드실적 조건은 지금처럼 질문 루프가 묻고, 카드의 조건은 F3 기관 링크에서 사용자가 확인한다.

## Evidence

`prereg-32` §6 — 공적 원천 여섯을 봤다. 기계가 읽는 것은 둘(여신금융협회 카드다모아 비공개 JSON · 공공데이터포털 산업은행 카드상품 API)이고 둘 다 **전월 실적 기준 칸이 없다**.
카드다모아는 8개 카드사 대표 상품 46개뿐이라 은행권 17개 기관 중 농협·기업·경남·부산·전북·iM·수협 계열 카드가 없다. 실적 기준은 카드사별 HTML 에만, 자유 문장으로 있다.
같은 날 §5 실측으로 **그래프도 필요 없음**(두 홉 고유 4 · AND 7)이 먼저 나왔으므로, 카드 데이터가 있었어도 쓸 자리는 "손익 한 줄" 이었다.

## Alternative

- **카드사별 HTML 수집** — 기관마다 모양이 다르고 카드마다 페이지를 읽어야 한다. `0056` 이 상품설명서에서 본 것과 같은 모양. 지금 사람 세션에 그 수요가 관측되지 않았다
- **민간 비교 사이트(카드고릴라 등) 재사용** — 출처가 공시가 아니고 약관·재배포 문제가 있다. 이 저장소는 공시만 원천으로 쓴다
- **연회비만(산업은행 API 모양) 모아서 반쪽 화면** — 실적 기준 없이 "연회비 vs 우대 이자" 만 보이면 조건을 숨긴 화면이 된다. 하지 않는다

## Why rejected

위에 같이 적었다.

## 반증 조건

- 여신금융협회나 공공데이터포털에 **카드사 전체 · 연회비 · 전월 실적 기준**이 칸으로 있는 API/CSV 가 생기면 — 다시 잰다(새 사전등록 · 첫 화면은 "이미 쓰는 카드가 있으면" 질문의 정밀화)
- 사람 세션에서 "이 은행 카드 조건이 뭔지 여기서 보고 싶다" 가 반복되면 — 카드사 HTML 을 **17개 상품에 붙은 카드만** 손으로 확인하는 작은 조사를 연다(`0056` 의 G 착수 조건과 같은 논리)
- 그래프 실측(`prereg-32` §5)의 반증 — 외부 상품 데이터가 결합돼 두 홉 고유 10건 이상이 생기면 D5 를 연다
