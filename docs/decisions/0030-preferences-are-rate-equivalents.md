# 0030 · 선호 가중치는 "금리 몇 %p 와 맞바꾸겠는가" 다

> 날짜: 2026-08-31 · 상태: 유효

사전등록 [`../spec/prereg-12-preference-weights.md`](../spec/prereg-12-preference-weights.md) ·
이슈 [#24](https://github.com/hyos0415/fineprint/issues/24) ·
앞선 결정 `0017`(최고부터 보여주고 깎는다) · `0024` P2(추측 금지) ·
`0028`(후보 집합 · A7) · `0029`(성과 = 내 금리 범위)

## Decision

**선호 가중치의 단위를 금리 %p 로 둔다.** 추상 0~1 가중치를 쓰지 않는다.
그리고 **선호로 상품을 목록에서 빼지 않는다** — 맨 아래로 내리고 이유를 그 줄에 적는다.

```
설문 5문항 → 고정 표 → 조정 %p → 점수 = net_hi + 조정 → 정렬
```

정한 것 넷.

1. **단위는 %p 환산이다.** `"영업점에 갈 수 있습니까?" 되도록 안 간다 → 영업점만
   상품에 −0.50%p`. 화면에 그 문장이 그대로 나간다
2. **금리 축은 따로 묻지 않는다.** 금리가 기준 단위(계수 1.0 고정)이고, 다른 축의
   %p 환산값이 곧 금리 대비 상대 중요도다
3. **기본값이 없다.** `--prefs` 를 안 주면 조정은 0개이고 정렬은 지금과 소수점까지
   같다 (`0017` 의 `net_hi` 순)
4. **점수는 정렬에만 쓴다.** 화면의 금리 칸은 계속 `net_lo~net_hi` 이고 조정은
   별도 칸이다. 화면 계약 **A10**(가중치가 보이고 고칠 수 있다) · **A11**(가중치는
   정렬만 바꾼다)이 이것을 전수로 검사한다

## Evidence

### 시작 근거 — 기관 접근성이 금리 2.67%p 를 이겼다

2026-08-31 사람 세션에서 사용자가 스코프 밖 **+2.67%p** 를 보고도 후보에 넣지 않았다
(`prereg-11` §M4 · `0028` 반증 조건 1).

> 굳이 경남은행 상품에 대해서 가입을 해보고 싶다는 생각이 안 들었어. 금리 우대가 있긴
> 하지만, 주거래 은행도 아니고, 경남에 연고도 없고, 경남은행 실물을 본적도 없어서

**추측이 아니라 관측이다.** 그리고 이 관측이 그대로 숫자가 된다 — 그 사용자에게
"처음 보는 기관" 페널티는 **2.67%p 보다 크다.** 표의 `처음기관=많이` 를 −3.00%p 로
잡은 근거가 이 하한 하나다. **표본 1이라고 표에 적었다.**

### 0~1 가중치를 안 쓰는 이유 둘

```
설명할 수 없다      0~1 로 정렬하면 화면에 "왜 이 순서인지" 를 못 적는다.
                  problem.md §3 은 "왜 이 순서인지가 같이 나온다" 를 약속했다
후보에 종속된다     0~1 정규화는 축마다 min·max 가 필요하고 그 기준은 후보 집합에
                  따라 변한다. 후보 4개 스코프에서 확정 카운터가 죽은 것(`0029`)과
                  **같은 실패 모양**이다
```

### 확실성 축은 눈금이 임의가 아니다 — 그리고 검산했다

계수 0 이면 `net_hi` 정렬(= `0017` 이 채택한 기본), 1.0 이면 `net_lo` 정렬
(= `0017` 이 남겨 둔 `--sort lo`) 과 **항등식으로 같다.**

```
점수 = net_hi − 1.0 × (net_hi − net_lo) = net_lo
```

`prereg-12` 예측 4로 **재기 전에** 적었고 **적중했다** — 페르소나 셋 × 권역 둘,
여섯 조건 전부에서 `확실성=많이` 정렬이 `--sort lo` 정렬과 **순서가 완전히 같았다.**
다섯 문항 중 숫자에 근거가 붙는 것은 이 축과 위의 `처음기관` **둘뿐이고**, 나머지
셋은 표에 **"근거 없음 — 판단"** 이라고 그대로 적었다.

### 가중치가 판정에 안 샜다 (주 판정 M9)

`ask_budget.py`(기준선·게이트·예산 12개)는 `prefs` 를 **한 번도 안 쓴다**(구조 가드).
숫자도 소수점까지 같다.

| | 기준선 (`prereg-11` §7) | 재측정 |
|---|---|---|
| 은행권 확정 (예산 12) | 37/67 (55.2%) · 폭 0.185%p · 커버리지 84.8% | **같다** |
| 저축은행 확정 (예산 12) | 85/106 (80.2%) · 폭 0.386%p · 커버리지 35.7% | **같다** |

### 가중치가 실제로 순위를 바꾼다 (M10)

**안 바꿨으면 이 기능은 없어도 되는 것이었다.** `prereg-12` §7 이 재기 전에 못 박은
조합 여섯 × 페르소나 셋에서, **1위가 바뀌는 조합이 두 권역 모두에 있었다.**

```
은행권      거래기관+처음기관=많이   1위 교체 · 상위10 중 8~9개 교체 (페르소나 셋 전부)
           확실성=많이           1위 교체(2/3) · 자리 바꾼 쌍 4~14
저축은행    영업점=못간다          맨 아래로 45개 · 1위 교체 · 자리 바꾼 쌍 20
           확실성=많이           1위 교체 · 자리 바꾼 쌍 최대 26
```

**은행권에서 `영업점` 조합이 아무것도 안 한 것도 결과다** — 은행권은 영업점 전용이
**0건**이고 저축은행이 263건(39%)이기 때문이다(`problem.md` §6 · 이슈 #22).
즉 이 축은 저축은행에서만 일한다.

### 검사기 버그를 쫓아가니 더 큰 것이 나왔다 — 고치지 않고 이슈로 냈다

A11 이 처음 2,388건 불통과였는데 **선호가 샌 것이 아니라 대조를 상품 코드로 짝지은
것**이었다. 코드가 유일하지 않다 — 저축은행 12개월은 **행 297개에 code 92개**다.
쫓아가 보니 `rank_questions()` 는 상품을 **code 로** 세고 `ask_budget` 은 **행으로**
세며, 행 기준으로 다시 세면 **질문 우선순위가 1위부터 달라진다.**

**`0018` 이 고정한 우선순위와 게이트 분모를 동시에 건드리므로 여기서 고치지 않았다.**
고치면 기준선이 움직이고 그건 별도 사전등록이 먼저다(`CLAUDE.md` 3번).
이슈 [#25](https://github.com/hyos0415/fineprint/issues/25) 로 냈고, `0030` 에서
손댄 것은 **검사기 두 곳뿐**이다.

### 화면이 거짓말하는 자리를 하나 찾았다

`0029` 가 넣은 성과 줄이 `최고 2.79~2.88% WON적금` 이라고 썼는데, **같은 화면 3위에
3.26% 가 있었다.** 선호가 걸리면 1위가 최고 금리가 아니다. `"최고"` 라는 말 한 단어가
`0019` 의 부산은행(사용자 입력 0개에서 4.80% 가 확정처럼 보였다)과 같은 모양을 만든다.
**선호가 걸리면 `1위` 로 쓴다.** 그리고 **A8 을 강화했다** — `성과 최고 …` 라고
쓰는데 목록에 더 높은 `net_hi` 가 있으면 위반이다. 낱말만 옛날로 되돌리면 한 세션에서
**8건**을 잡는다(공허한 assert 가 아니라는 확인이다).

## Alternative

- **A. 추상 0~1 가중치 (`problem.md` §3 의 원래 서술)** — 축마다 min·max 정규화 후
  가중 합산
- **B. 선호로 상품을 제외한다 (`problem.md` §3 의 원래 서술)** — "비대면 필수" 면
  영업점 전용 상품을 목록에서 뺀다
- **C. 기본 가중치 프로필을 우리가 정해 둔다** — "대부분 이 정도" 로 채워 놓고
  사용자가 고치게 한다
- **D. 금리 중요도를 따로 묻는다** — `problem.md` §3 의 첫 예시 그대로
- **E. 조정을 `net_hi` 에 더해 그 값을 금리로 보여준다** — 화면이 단순해진다

## Why rejected

- **A** — 화면에 "왜 이 순서인지" 를 못 적는다(`problem.md` §3 이 약속한 것이다).
  그리고 정규화 기준이 후보 집합에 종속돼 `0029` 와 같은 실패 모양이 된다
- **B** — 제외하면 "선호로 뺀 상품 중 최고 금리" 를 보여주는 장치를 A7 과 똑같이 하나
  더 만들어야 한다. 안 만들면 `0017`(좋은 상품이 묻힌다) · `0028` A7(좁히는 대가를
  보여준다)이 막은 실패를 선호에서 되살린다. **그 문장은 `0017`·`0028` 보다 먼저
  쓰였다** — `problem.md` §3 을 같이 고쳤다
- **C** — `0024` P2 위반이다. 사용자가 말하지 않은 것을 시스템이 채운다. 화면에
  그 사실이 안 보이면 `0019` 의 부산은행과 같은 모양이다(입력 0개인데 단정하는 화면)
- **D** — 같은 것을 두 번 묻는 것이다. %p 환산 단위에서는 다른 축의 값이 이미
  "금리 대비 상대 중요도" 다
- **E** — **공시에 없는 숫자를 사용자에게 금리라고 보여주는 것**이다. 이 프로젝트가
  잡으려던 실패를 우리가 만드는 셈이다(`problem.md` §5). A11 이 이 실수를 잡으려고
  있는 assert 다

## 반증 조건

- **사용자가 옮긴 가중치를 자주 고치면** — 고정 표의 숫자가 그 사용자에게 안 맞는
  것이다. 지금 근거가 있는 값은 둘뿐이고 셋은 판단이므로 **그럴 개연성이 높다.**
  고친 값이 쌓이면 표를 다시 본다 (`prereg-12` §8-1)
- **사용자가 %p 라는 단위를 못 읽으면** — 화면에 `-3.00%p` 를 보여주는 것 자체가
  안 통하는 것이다. 그때는 표시를 말로 바꾸되(`금리보다 훨씬 중요`) **내부 단위는
  유지한다** — 설명 가능성이 %p 를 고른 이유였다
- **선호를 넣어도 1위가 거의 안 바뀌면** — 이 기능은 없어도 된다. 지금 실측은 그
  반대다(조합 여섯 중 둘 이상에서 1위 교체). **다만 은행권 `영업점` 축은 실제로 0이다**
- **맨 아래로 내린 상품을 사용자가 그래도 고르면** — 순위로 다루는 것이 약해서
  아무 일도 안 일어나는 것이다. 그때는 제외(대안 B)를 A7 과 같은 장치와 **함께** 다시 본다
- **A11 이 언제든 불통과하면** — 가중치가 판정에 샌 것이고, 그 순간 `problem.md` §4 의
  *"틀릴 수 없는 것 / 틀릴 수 있는 것"* 구분이 무너진다. 구현을 되돌린다
