# 0045 · 조건은 기관별로 갈린다 — 목록 하나로 묻고 나머지는 유도한다

2026-09-02 · 이슈 [#44](https://github.com/hyos0415/fineprint/issues/44) ·
사전등록 `../spec/prereg-15-conditions-are-per-institution.md` (구현 전 커밋 `4b8349e`)

## Decision

**사용자의 답을 기관별로 갖는다.** 조건 유형 17종 중 **6종을 기관 상대**로 분류하고,
그 답을 `자동이체@국민은행` 처럼 기관이 붙은 키로 받는다. 나머지 11종은 전역이다.

```
기관 상대 6종   첫거래_신규고객 · 주거래_장기거래_재예치 · 급여_연금이체 ·
              카드실적 · 자동이체 · 타상품_보유동시가입
기관 무관       나이·지역 같은 사용자 속성 · 마음먹으면 어디서든 하는 것 ·
              이 상품 자체에 대한 것(목표달성_납입실적) · 잔액_평잔_가입금액
```

**질문은 안 늘린다 — 목록 하나로 묻고 나머지를 유도한다.**

```
① 한 번 묻는다   "거래해 본 기관을 골라 주세요" (여러 곳 가능 · 답 셋의 유일한 예외)
② 안 고른 기관    첫거래 = 예 · 그 기관의 실적 조건 전부 아니오
               **거래가 없으면 그 기관에 실적이 있을 수 없다**
③ 고른 기관      6종을 되묻는다. 단 한 기관 안에서 첫거래와 주거래는 **배타**다
④ 기관 무관      전역으로 한 번만 묻는다
```

**유도된 답은 상태에 저장하지 않는다.** 읽을 때 `answer_of()` 가 계산한다 — 그래야
화면의 *"답한 질문 N개"* 가 **사용자가 실제로 답한 수**로 남는다(화면 계약 A6).

**문구 단위 키에도 기관을 넣는다.** `카드실적@국민은행#a3f1c2d9`.

## Evidence

**지금 동작이 불가능한 것을 참이라고 말하고 있었다.** 은행권 12개월 실측이다.

```
자동이체            답 하나 → 상품 22개 · 기관 10곳
첫거래_신규고객       답 하나 → 상품 21개 · 기관 10곳
주거래_장기거래_재예치  답 하나 → 상품 12개 · 기관 8곳
```

한 사람이 8개 은행에서 동시에 주거래일 수 없다. 그리고 **한 기관 안에서도** 불가능한
조합을 허용했다 — 은행권 5개 · 저축은행 2개 상품이 `첫거래`와 `주거래`를 동시에 받았다.

```
애큐온저축은행 처음만난적금    첫거래 +3.50%p · 주거래 +2.00%p → +5.50%p 를 다 줬다
부산은행 더(The) 특판 정기예금  첫거래 +0.75%p · 주거래 +0.75%p → +1.50%p
```

`problem.md` 가 인용한 피해 사례가 *"최고금리 10%를 보고 가입했는데 우대금리를 못
받았다"* 다. **우리가 그것을 작은 규모로 재생산하고 있었다.**

고친 결과 — 예측 7개 중 6개가 맞았다(`prereg-15` §6). 은행권 · 거래 1곳 중앙값이다.

```
확정률          58.2% → 76.1%     P1 맞았다 (예측 70% 이상)
평균 확정 금리    2.975% → 2.727%   P2 맞았다 (예측 2.80% 아래) — 과대 진술이 사라졌다
과대였던 상품     30개 · 평균 0.554%p · 최대 3.384%p    P3 맞았다
첫거래·주거래 동시  5개 → 0개 · 저축은행 2개 → 0개        P4 맞았다
질문 수          0곳 10 · 1곳 15 · 2곳 16 · 3곳 20 · 전부 60   P5 방향 맞고 수치는 적다
예산 12개 폭 평균  0.185 → 0.105     **P6 이 반대로 틀렸다** (나빠진다고 예측했다)
상위 3위 교체     1단계에서 2개, 그 뒤 전 구간 0        P7 맞았다
```

**정확성이 올라가면서 확정률도 올랐다.** 보통은 하나를 얻으면 하나를 잃는데, 여기서는
사용자가 답할 수 없던 것을 묻지 않게 되며 **"아니오" 가 유도로 채워지고, "아니오" 는
결정적**이기 때문이다.

**`잔액_평잔_가입금액` 은 사람의 추측과 반대로 갔다.** 문구를 전부 꺼내 읽으니 *그 은행
예치금*(아이엠뱅크 전월 총수신 평잔 30만원)과 *이 상품 가입금액*(SC e-그린세이브 5천만원
이상 가입)이 섞여 있었다. 기관 상대로 두면 **거래 없는 은행의 가입금액 문구까지 막힌다** —
거래해 본 적 없는 은행에도 1천만원은 넣을 수 있다. 기관 무관으로 둬도 과대 진술이 없다:
이 유형의 유형 답 하나로 올라가는 상품이 **0개**다(`has_threshold()` 가 항상 문구 단위
후속 질문을 요구해서 실질 판정이 이미 문구 단위이고, 문구는 상품 하나에 붙는다).

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| B | 기관 상대 조건을 **기관마다 예/아니오**로 묻는다 | 은행권에서 (유형, 기관) 쌍이 **56개**다. `0018` 이 질문 수 상한을 기각했으니 못 물을 이유는 없지만, 목록 하나로 같은 정보를 받을 수 있는데 56번 묻는 것은 **사용자에게 우리 구현을 떠넘기는 것**이다 |
| C | 지금처럼 전역으로 두고 화면에 *"기관마다 다를 수 있습니다"* 를 적는다 | 계산은 그대로 틀린 채로 두고 **경고문으로 면피**하는 것이다. `0019` 가 막은 자리와 같다 — 코드는 있는데 사용자가 못 읽는 상태 |
| D | 0단계 폼에서 거래 은행을 받는다 | 0단계는 **후보 집합(검색 축)** 을 받는 자리다(`0028`). 거래 은행은 후보를 좁히는 것이 아니라 후보 안에서 조건을 판정하는 것이라 축이 다르다. 섞으면 *"거래 은행만 보여줄까요"* 로 오해된다 |
| E | 유도된 답을 상태에 써 넣는다 | 구현은 더 쉽다. 그런데 화면의 *"답한 질문 N개"* 가 사용자가 답하지 않은 것까지 세게 된다 — `prereg-09` §8 에서 사람이 지적해 고친 바로 그 거짓말이다 |

## Why rejected

**B 를 안 고른 이유가 이 결정의 핵심이다.** 목록 질문은 `0027`(답은 예/아니오/모름
셋뿐)의 **유일한 예외**이고, 예외를 만드는 데는 대가가 있다 — 화면 · CLI · 검사기 ·
API 검증 네 곳에 다른 모양의 답을 넣어야 했다. 그 대가를 낸 이유는 **정보량이 같은데
질문이 56개에서 1개로 줄기 때문**이다. 사용자에게 물을 것은 *"어느 기관과 거래하나"*
하나이고, 나머지 55개는 그 답에서 논리적으로 따라 나온다.

**유도는 추측이 아니다.** 우리가 모르는 것을 채우는 게 아니라, 사용자가 이미 말한 것의
필연적 귀결을 두 번 묻지 않는 것이다(`0016` 이 막은 것은 앞쪽이다). 그래서 유도는 둘로
제한했다 — ①거래 없는 기관에 실적이 있을 수 없다 ②신규이면서 동시에 주거래일 수 없다.
*"첫거래 = 예이면 그 은행 카드실적도 아니오"* 같은 것은 **넣지 않았다** — 공시 문구가
*"당행 예금 최초 가입"* 처럼 상품군까지 좁히는 경우가 있어 참이 아닐 수 있다.

**같은 이유로 "거래해 본" 을 우리가 정의하지 않는다.** 계좌만 만들고 안 쓴 것을 거래로
볼지는 사람마다 다르다. 문구를 그대로 보여주고 답을 받는다.

## 반증 조건

- **사람이 목록에서 자기 은행을 못 찾으면** — 은행권 17곳 · 저축은행 30곳을 이름으로
  줄 세운다. 이름이 `주식회사 케이뱅크`·`농협은행주식회사` 처럼 공시 원문 그대로라
  사용자가 아는 이름과 다를 수 있다. 그러면 **F5(낱말 대응표 · 이슈 #45)의 대상**이고,
  여기서 이름을 손대면 `0031`(상품 신원)과 같은 사고가 난다
- **목록에 "모름" 으로 답하는 사람이 많으면** — 그 경로는 유도가 안 걸려 예산 12개
  시점의 폭 평균이 **0.432**(기준선 0.185)로 나쁘다. 편의 기능이 아니라 정확성 문제이므로,
  많으면 질문 순서를 다시 본다(`prereg-15` §5 의 P6 조항)
- **유도된 "아니오" 가 틀렸다는 관측이 나오면** — 예컨대 거래 이력이 없는데도 받을 수
  있는 실적 조건이 있으면(가족 명의 실적 등) ①이 깨진다. 그 문구를 찾으면 유도에서 뺀다
- **첫거래·주거래를 동시에 받는 상품이 다시 0개가 아니게 되면** — 유도 ②가 새는 것이다.
  `measure_per_institution.py` 의 P4 칸이 그걸 본다
- **기관 상대 6종 분류가 틀렸으면** — 사람이 확정한 것이다(`prereg-15` §1). 특히
  `마케팅_정보동의`·`실천_미션_인증`을 기관 무관에 둔 것은 *"어려운 미션이 아니고
  이득이 되면 하겠다"* 는 사람의 판단이다. 사람이 실제로 답하다가 *"그건 그 은행
  앱이어야 하는데"* 가 나오면 기관 상대로 옮긴다
