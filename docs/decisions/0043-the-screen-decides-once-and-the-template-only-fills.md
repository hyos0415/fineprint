# 0043 · 표시 결정을 한 곳에 모으고, 템플릿은 꽂기만 한다

> 날짜: 2026-09-02 · 상태: 유효

로드맵 F4-2 · 이슈 [#40](https://github.com/hyos0415/fineprint/issues/40) ·
앞선 결정 `0038`(FastAPI + Jinja2 · 템플릿에 판정 금지) · `0039`(계약 두 겹) ·
`0040`(무상태) · `0035`(문구는 한 곳에) · `0027`(문구를 그대로 묻는다)

**사전등록이 없다.** 구현이고, 완료 조건은 회귀다 — CLI 출력 무변동 + A1~A13 통과 +
서버·CLI 뷰 모델 대조.

## Decision

```
D1  상품 한 줄의 **표시 결정**을 `view.display()` 로 모은다 — 범위 문자열 · 남은 조건
    라벨 · 선호 조정 문구 · 주의 코드 · 채널. **CLI 의 `product_line` 도 그것을 읽는다**

D2  **HTML 을 만드는 자리는 함수 하나다** — `render.render_screen(vm, form, reports)`.
    라우트는 그것을 부르기만 하고, F4-3 의 렌더 겹 검사도 같은 함수를 부른다

D3  `/api/screen`(JSON)과 `POST /screen`(HTML)이 **같은 함수**로 뷰 모델을 만든다
    (`_screen_payload`). 둘이 갈라질 자리를 없앤다

D4  **폼을 표준 라이브러리로 파싱한다.** `python-multipart` 를 넣지 않는다 —
    `requirements.txt` 예외를 다섯 번째로 늘릴 사유가 안 된다

D5  **PRG(POST-redirect-GET)를 쓰지 않는다.** 쓰기가 없어서 막을 것이 없고, 표준 PRG 는
    상태를 URL 에 올리게 되어 POST 를 고른 이유와 어긋난다

D6  **템플릿의 슬라이싱은 배치로 본다.** 질문 카드의 공시 문구를 앞 셋만 펼치고 나머지는
    접는다 — **자르거나 빼지 않는다**(`0027` · `prereg-10` §6)
```

## Evidence

### D1 이 없으면 템플릿이 판정한다

`0038` 반증 조건이 *"`{% if %}` 가 화면 계약을 판정하기 시작하면 계약이 뷰 모델 밖으로
샌다"* 고 적어 뒀다. 그런데 표시 결정이 `ask_loop.product_line` 안에 있었다.

```
범위 문자열        폭이 0이면 숫자 하나, 아니면 `lo~hi`          ← A1 이 검사하는 것
남은 조건 라벨      "남은 3개" / "남은 3개 (금리 영향 없음)" / "확정"
선호 조정 문구      "선호밖" / "조정 -0.50%p"                    ← A11 이 검사하는 것
```

**HTML 에서 이걸 다시 판정하면 두 렌더러가 서로 다른 말을 하게 된다.** `0035` 가 찾은
실패가 정확히 그 모양이었다(세후 라벨이 한 화면에만 있었다). 그래서 `view.display()` 로
옮기고 **CLI 가 그것을 읽게** 했다 — 한쪽만 쓰는 칸을 만들지 않는다(`0039` 반증 조건 1).

**CLI 출력 회귀 0줄** (권역 2 × 상태 5 + 스코프 1에서 화면·상태·리포트 전수 대조).

### D4 — 의존성을 안 늘렸다

```
FastAPI 의 Form(...)          python-multipart 를 요구한다
Starlette 의 request.form()   urlencoded 에도 요구한다 (실측 — 500 이 났다)
우리 폼                        파일 업로드가 없는 application/x-www-form-urlencoded
                              → urllib.parse.parse_qs 다섯 줄로 끝난다
```

`0038` 이 *"예외는 사유를 함께 적는다"* 로 정했다. **표준 라이브러리로 되는 일에 예외를
만들 사유가 없다.** 그래서 본문을 직접 읽는다 — content-type 을 확인하고, 아니면 415 다.

### D5 — PRG 는 여기서 막을 것이 없다

```
PRG 가 막는 것   새로고침 때 같은 **쓰기**가 두 번 일어나는 것 (주문·결제·글쓰기)
우리 서버        쓰기가 없다 (`0040` 무상태). 재제출되면 같은 화면이 다시 그려진다
표준 PRG 의 대가  리다이렉트 대상이 GET → **상태가 URL 에 올라간다**
                급여이체·카드실적 같은 답이 URL 과 서버 로그에 남는다
```

쿠키로 우회할 수는 있지만 **화면 편의 하나 때문에 상태를 브라우저에 저장**하는 것이라
폼 hidden 을 고른 이유와 어긋난다(이슈 #40). 새로고침 시 브라우저의 재제출 확인 창은
**UX 흠집이지 결함이 아니다.**

### 웹 흐름을 끝까지 돌렸다 — 폼 hidden 으로 상태가 이어진다

브라우저가 하는 일을 그대로 흉내내 응답 HTML 에서 hidden 을 긁어 다음 POST 에 실었다.
**JS 를 안 쓰므로 이것이 실제 사용자 흐름과 같다.**

```
질문 15개를 답해 남은 0 까지 · 남은 질문 수가 한 번도 늘지 않았다 (A4)
분모가 39 → 38 → 35 → 29 → 26 → 18 → 15 로 줄었다 (`0026` — 줄어드는 것은 전체다)
마지막 화면에 세후 라벨(A12) · 고지(A13) · 범위(A1) · 리포트(F1) 전부 있다
```

```
CLI 계약 검사    은행권 시드 200 · 저축은행 시드 200 → **A1~A13 전부 통과** (50초 · 128초)
서버·CLI 대조    케이스 6개 · 에러 계약 6개 → **전부 통과** (`_screen_payload` 공유 뒤)
```

### D6 — 문구가 21개 붙는 유형이 있었다

`자동이체` 질문 카드에 공시 문구가 **21개** 나왔다(CLI 는 셋만 보여준다). 자르지 않고
앞 셋만 펼치고 나머지는 `<details>` 로 접었다. **몇 개를 먼저 보여줄지는 배치 결정**이고,
내용을 빼거나 자르는 것이 아니다.

## Alternative

- **A. HTML 에서 표시를 다시 판정한다** — `view.display()` 를 만들지 않는다
- **B. `python-multipart` 를 넣는다** — 프레임워크가 요구하는 대로 쓴다
- **C. PRG 를 쿠키로 구현한다** — 새로고침 확인 창을 없앤다
- **D. 라우트 핸들러에서 바로 HTML 을 만든다** — 함수를 따로 두지 않는다
- **E. 질문 카드에 문구를 전부 펼친다** — 아무것도 접지 않는다

## Why rejected

- **A** — 두 렌더러가 갈라진다. `0035`(문구가 두 곳에 있었다)와 `0039`(검사가 렌더 대신
  헬퍼를 봤다)가 같은 뿌리의 실패였다. **세 번째를 만들지 않는다**
- **B** — 표준 라이브러리로 되는 일이다. 예외를 늘리는 사유가 "프레임워크가 그렇게
  하니까" 로는 부족하다(`0038`)
- **C** — 상태를 브라우저에 저장하는 것이고, 폼 hidden 을 고른 이유(기기에 안 남는다)를
  깬다. 얻는 것이 확인 창 하나다
- **D** — **F4-3 이 부를 자리가 없어진다.** `0039` D3 가 *"렌더러가 늘 때마다 렌더 겹을
  하나 더 건다"* 로 정했는데, 함수가 없으면 그 검사를 못 붙인다
- **E** — 21개를 한 번에 보여주면 사용자가 질문을 못 읽는다. 접는 것은 **감추는 것이
  아니다** — 개수를 적고 펼칠 수 있게 둔다

## 반증 조건

- **F4-3 에서 웹 렌더 겹을 걸었더니 `render_screen` 만으로 부족하면** — D2 의 함수 하나가
  화면 전부를 만들지 못하는 것이다(예: 0단계 폼도 검사해야 한다면). 그때는
  `render_start` 도 같은 대접을 한다
- **템플릿에 `{% if %}` 가 쌓이면** — 배치 조건(있으면 보여준다)과 판정 조건(폭이 있으면
  범위로)을 사람이 구분하지 못하게 된다. **판정이 하나라도 들어오면 `view.display()` 로
  올린다**
- **사용자가 새로고침 재제출 창 때문에 혼란스러워하면** — D5 가 틀린 것이다. 그러면
  쿠키가 아니라 **"이 화면을 다시 그립니다" 버튼**을 두는 쪽을 먼저 본다
- **`parse_qs` 로 못 읽는 폼이 생기면** — 파일 업로드가 필요해지는 경우다(예: state 를
  파일로 올려 이어하기 · D9). 그때는 `python-multipart` 예외를 **사유와 함께** 적는다
- **CLI 와 웹의 표시가 갈라지면** — `view.display()` 를 한쪽만 고친 것이다. CLI 회귀 대조가
  그것을 잡는다(권역 2 × 상태 5 + 스코프 1)
