# 0018 · 도피 방지 제약식 — 커버리지 게이트 + 질문 예산 12개

2026-08-27 · 이슈 [#3](https://github.com/hyos0415/fineprint/issues/3) ·
사전등록 [`../spec/prereg-06-matching-and-judgment.md`](../spec/prereg-06-matching-and-judgment.md) §2.3(1)

## Decision

**개선을 주장하려면 두 관문을 통과해야 한다.**

```
게이트   메인 층(확정+범위) 비율이 기준선 아래로 떨어지면 개선으로 인정하지 않는다
         기준선 — 은행권 12개월 81.0% (64/79) · 저축은행 12개월 36.7% (109/297)

예산     상위 12개 질문까지만 답한 상태에서 확정률과 범위 폭을 잰다
         13번째부터는 화면에 띄우든 말든 자유지만 **평가 지표에 안 들어간다**
```

**커버리지는 점수에 더하지 않는다. 통과·불통과만 가른다**(사람 결정). 더하면
"커버리지를 조금 깎고 다른 지표를 크게 올리는" 거래가 가능해지고, 그게 막으려던 도피다.

**질문 우선순위와 동점 처리도 여기서 같이 못 박는다.** 안 그러면 상위 12개를 사후에
고르는 우회가 생긴다 — 결과를 보고 유리한 질문을 상위로 올리면 예산이 무력해진다.

```
1순위   상품 커버리지 내림차순 — 그 질문 하나가 판정을 여는 상품 수
2순위   질문 키 사전순 — 내용에 무관한 기준을 일부러 골랐다
```

2순위를 **금리 크기처럼 의미 있는 값으로 두지 않은 이유**가 있다. 그런 값은 시스템이
만들어내는 값이라, 추출 금리를 키우면 순위를 밀어올릴 수 있다. **사전순은 시스템이
조작할 수 없다.**

질문 하나의 단위는 **조건 유형 하나**다(`0016`). 유형 여러 개를 한 질문으로 합쳐
예산을 아끼는 우회를 막는다. 수치 후속 질문(`_금액`·`_횟수`)은 별도로 센다 —
비싸게 세는 쪽이다.

구현은 `src/analysis/calculate.py`의 `ASK_BUDGET`·`rank_questions()`,
측정은 `src/analysis/ask_budget.py`.

## Evidence

**막아야 할 구멍이 둘인데 사전등록의 후보 셋은 한쪽만 보고 있었다.**

```
구멍 A   전부 "근거 없음"으로 표시하면 틀린 금리를 절대 안 보여준다   ← 상수 스텁과 같은 모양
구멍 B   답할 리 없는 질문을 잔뜩 만들면 "되물으면 확정된다"로 확정률이 오른다
```

구멍 A는 선행 저장소에서 실제로 관측됐다 — `"UNSUPPORTED"`만 반환하는 상수 스텁이
1·2·3순위 지표를 전부 이겼다(`../reference/finance-verifier-findings.md` §0.4).

질문을 하나씩 늘려가며 층과 범위 폭을 실측했다(다 충족 페르소나).
재현: `python src/analysis/ask_budget.py 20260826 --group bank --tolerance`.

| 답한 질문 | 은행권 메인 | 확정 | 폭 평균 | 저축은행 메인 | 확정 | 폭 평균 |
|---:|---:|---:|---:|---:|---:|---:|
| 0 | **64** | 4 | 0.696 | **109** | 52 | 0.624 |
| 6 | **64** | 21 | 0.306 | **109** | 75 | 0.383 |
| **12** | **64** | **47** | **0.096** | **109** | **91** | **0.239** |
| 전부(23·26) | **64** | 64 | 0.000 | **109** | 105 | 0.058 |

**메인 층 수는 되묻기와 무관하다.** 은행권 64 · 저축은행 109가 질문 0개에서 전부
답할 때까지 한 번도 안 움직인다. 되묻기는 `범위`를 `확정`으로 옮길 뿐이고, 메인
안팎은 닫힘률(=추출)이 정하기 때문이다. **커버리지 게이트는 구멍 A를 막지만
구멍 B에는 소수점 한 자리도 반응하지 않는다.**

**범위 폭 평균은 질문 수의 단조 감소 함수다.** 질문을 늘리면 무조건 좋아진다.
**폭 평균을 지표로 쓰면 구멍 B를 막기는커녕 정확히 보상한다.** 그래서 폭은
예산을 고정한 시점에서만 읽는다.

### K를 12로 잡은 근거 — 수확 체감이 거기서 꺾인다

```
은행권      질문 12개  확정 47/64 (73.4%) · 폭 0.696 → 0.096 (-86%)  |  남은 11개가 확정 +17
저축은행    질문 12개  확정 91/109 (83.5%) · 폭 0.624 → 0.239 (-62%)  |  남은 14개가 확정 +14
```

### 동점은 실제로 예산 경계에 걸린다

은행권 11·12위가 둘 다 7상품(`고객군_자격`·`기타`), 13·14위가 둘 다 6상품이다.
저축은행도 11·12위가 둘 다 4상품이다. **2순위 기준이 누가 예산 안에 드는지를 정한다** —
그래서 사후에 정하면 안 된다.

사전순 규칙을 넣기 전후로 예산 시점 값은 **바뀌지 않았다**(은행권 47/64·0.096,
저축은행 91/109·0.239). 저축은행은 예산 안에 드는 질문 구성이 경계에서 한 개
바뀌었는데도 값이 같았다.

### 부수 확인 — 허용 오차로는 커버리지를 부풀릴 수 없다

메인 층 판정이 `TOLERANCE`(0.06%p)에 걸려 있어 우회로를 확인했다. **없다.**

```
허용 오차 %p    0.06    0.10    0.20    0.50    1.00    5.00
은행권 메인     81.0%   77.2%   68.4%   51.9%   31.6%    7.6%
저축은행 메인    36.7%   31.3%   29.3%   26.6%   24.2%   20.2%
```

넓힐수록 **줄어든다** — `공시 최고금리 = 기본금리`인 행이 `공시미반영` 층으로 빠지기
때문이다. 이 방향은 막을 필요가 없다.

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| A | 커버리지 하한만 (사전등록 후보 1) | **구멍 B에 무감각하다.** 질문을 25개 더 만들어도 값이 안 움직인다 |
| B | 범위 폭 평균 상한만 (후보 2) | **구멍 B를 보상한다.** 폭은 질문 수의 단조 감소 함수다 |
| C | A + B (후보 3) | 둘을 더해도 구멍 B는 그대로 열려 있다 |
| D | 질문 **개수 자체에 상한**을 두고 넘으면 불인정 | 사용자에게 정말 유용한 질문을 추가하는 길까지 막는다. 예산 방식은 **지표가 그것으로 오르지 않게** 할 뿐 질문 추가를 금지하지 않는다 |
| E | 커버리지를 점수에 가중 합산 | **거래가 가능해진다** — 커버리지를 조금 내주고 확정률을 크게 올리는 수가 생긴다 |

## Why rejected

A·B·C가 공유하는 문제는 하나다 — **후보를 고를 때 구멍 B를 몰랐다.** 되묻기를 넣고
은행권 범위가 0이 된 것을 보고 "개선"이라 적었는데, 그게 진짜 개선인지 질문을 늘려서
얻은 값인지 가릴 장치가 없었다. 실측해 보니 두 후보 지표 중 **하나는 질문에 무감각하고
하나는 질문에 보상적**이어서, 어느 쪽도 구멍 B를 못 막았다.

E를 뺀 이유는 이 프로젝트가 선행 저장소에서 배운 것과 같다. **가중 합산은 도피를
"비싸게" 만들 뿐 막지 못한다.** 게이트는 거래를 허용하지 않는다.

## 반증 조건

- **예산 12개 안에서 확정률이 오르는데 실제 사용자가 12개를 다 못 채우면** — 예산이
  현실보다 후한 것이다. 사용자가 실제로 답하는 개수를 관측하면 K를 그 값으로 내린다
- **커버리지 기준선을 통과하면서 확정률이 오르는 변경이 하나도 안 나오면** — 게이트가
  너무 빡빡해 개선 자체를 막고 있는 것이다. 그때는 기준선이 아니라 **층 정의**를 의심한다
- **질문 우선순위 1순위(커버리지)가 상품 수를 부풀리는 방향으로 악용되면** — 한 질문이
  판정을 여는 상품 수를 늘리려고 조건 유형을 과하게 넓게 매핑하는 경우다. `기타` 유형
  비율이 늘어나는지로 관측한다
- **은행권과 저축은행에서 최적 K가 크게 갈리면** — 지금은 둘 다 12에서 꺾인다.
  권역별로 K가 달라야 하면 단일 예산이 성립하지 않는다
