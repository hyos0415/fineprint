# 0055 · 가입 금액은 표시만 바꾼다 — 예상 이자는 원으로, 3층은 선을 넘은 상품에만 말한다

2026-09-04 · 이슈 [#69](https://github.com/hyos0415/fineprint/issues/69) · `prereg-25` ·
앞선 결정 `0028`(스코프 축에 납입액) · `0030`(선호는 정렬만 · A11) · `0032`(세율은 조문 핀) · `0035`(세후 라벨 A12) ·
`design.md` §세금 계산(3층 · "선을 넘을 때만 묻는다" · "최종 세액은 내지 않는다")

## Decision

```
D1  0단계에 **가입 금액 둘**을 선택으로 받는다 — 예금은 예치 금액, 적금은 월 납입액. CLI(`--deposit`·`--monthly`) ·
    웹 폼 · `_carry` · 이어하기 코드에 실린다. **`state` 에 넣지 않는다** — 조건 답이 아니라 검색 축이다
D2  **금액은 표시만 바꾼다.** 금리·순서·층·사유는 금액과 무관하다(P1 · A11 이 선호에 대해 지키는 것과 같은 선).
    금액이 없으면 화면은 지금과 글자 하나 다르지 않다(P6)
D3  **예상 이자는 리포트에 원으로, 세전·세후 둘 다 범위로** 낸다. 산수는 `calculate.interest()` 한 곳이고 CLI 텍스트와
    웹이 같은 칸을 읽는다. 가정 셋(만기 일시 지급 · 복리는 월복리 · 자유적립식은 매달 같은 금액)을 **화면에 한 줄로** 적는다
D4  **3층(금융소득종합과세)은 그 상품의 세전 이자 최대가 기준(연 2,000만원 · `config/tax-2026.json`)을 넘을 때만**
    그 상품에 말한다. 기준의 절반 이상이면 "경계에 가깝다" 로 단정하지 않는다. **절반은 근거 없음 — 판단.**
    최종 세액은 내지 않는다
D5  **기존 금융소득을 묻는 질문(HITL)은 만들지 않는다 — 지금은.** 현실적 금액(예금 5천만 · 적금 월 100만)에서 두 권역
    모두 넘음 0 · 경계 근처 0 이다(P2). 뜨지 않을 질문을 만들지 않는다. 걸리는 사용자가 관측되면 그때 설계한다
D6  화면 계약 **A18** — 금액이 있으면 리포트(텍스트·웹)에 예상 이자가 세전·세후 원 숫자와 가정 한 줄로 있어야 하고,
    없으면 `예상 이자` 가 없어야 한다. 검사는 예금 5천만원 · 적금 월 100만원을 넣고 본다
D7  `잔액_평잔_가입금액` 문구를 금액으로 **자동 판정하지 않는다.** 15문구 중 "이 상품 가입금액" 과 "다른 계좌 잔액" 이
    섞여 있고 그 분류는 추측이다(`0016`). 사람이 문구를 보고 답한다(`0027`)
```

## Evidence

`prereg-25` §5 — 여섯 예측 적중. 뷰 모델은 금액과 무관(P1), 금액 없는 출력은 기준과 동일(P6), 두 렌더러가 같은
원 숫자(P5 · A18). 5억을 넣어야 저축은행 예금 12행이 선을 넘고 은행권은 0 이다 — 은행권 예금 최대가 실효 4% 아래다.

**로드맵 D1 이 틀려 있었다.** *"0단계 축 — 기간·납입액·기관·상품군 ✅ CLI"* 라고 적었는데 납입액을 받는 자리는
없었다(`0028` S1 이 축으로 **적었을 뿐**). 문서의 ✅ 를 코드 grep 으로 확인하지 않은 채 남아 있었다.

## Alternative

- **A. 금액을 `state` 에 넣는다** — 조건 답과 섞이면 `is_state_key()` 검증과 세션 로그의 뜻이 흐려진다. 축은 축이다
- **B. 목록 화면(한 줄)에도 이자를 쓴다** — 줄이 이미 금리·채널·남은 조건·조정·주의로 꽉 차 있고, 이자는 금액이 있을
  때만 있는 칸이다. 리포트가 "이 숫자가 어디서 왔나" 를 말하는 자리라 거기가 맞다. 목록에 쓸 이유가 관측되면 그때
- **C. 기존 금융소득을 0단계에서 묻는다** — 모든 사용자에게 뜨는 질문이 하나 늘고, 그 답으로 바뀌는 사용자가 지금
  데이터에는 없다(P2). `0026` 이 막은 "묻지 않을 수 있는 것을 묻는" 방향이다
- **D. 종합과세 구간의 세후 금리 범위를 계산해 보인다** — 종합소득·공제 없이는 범위도 못 좁힌다. `design.md` 가
  "할 수 없는 것" 에 적어 둔 자리다. 걸리는 사용자가 없는 지금 만들 이유가 없다
- **E. 복리 주기를 상품 설명서에서 읽는다** — 코퍼스가 없다(G). 월복리 가정을 화면에 적는 것으로 대신한다
- **F. 절반 대신 다른 문턱(70% · 90%)** — 어느 값도 근거가 없다. 절반으로 두고 판단이라 적었다

## Why rejected

위에 같이 적었다.

## 반증 조건

- **사람 세션에서 이자 숫자를 "받을 금액" 으로 단정해 읽으면** — 가정 한 줄이 일을 안 하는 것이다. 위치·문구를 고친다
- **현실적 금액에서 "경계 근처" 이상이 뜨는 사용자가 관측되면** — D5 의 전제가 깨진다. HITL 질문의 설계(`prereg`)를 연다
- **공시에 복리 주기가 들어오거나 상품 설명서(G)로 읽게 되면** — 월복리 가정을 그 값으로 바꾸고 가정 문장을 고친다
- **금액이 금리·순서를 바꾸는 코드가 생기면** — D2 위반. A11 과 같은 모양의 검사(금액 유무로 vm 대조)를 계약에 더한다
- **세율표의 기준금액이 바뀌면** — `fetch_law.py --check` 가 본다(`0032`). 문장의 숫자는 config 에서 오므로 따라 바뀐다
