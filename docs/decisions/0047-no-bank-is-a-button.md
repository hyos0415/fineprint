# 0047 · "거래해 본 은행이 없다" 는 버튼이다 — 빈 제출은 답이 아니다

2026-09-03 · 이슈 [#48](https://github.com/hyos0415/fineprint/issues/48) ·
`prereg-16` §6 (나)·(나-2) · `0045` 반증 조건 2 가 발동한 자리

## Decision

목록 질문(*"거래해 본 은행을 골라 주세요"*)의 답을 **버튼 셋**으로 받는다.

```
고른 대로 계속            체크한 은행 목록. 하나도 안 골랐으면 넘어가지 않는다 —
                        같은 화면을 안내 한 줄과 함께 다시 낸다
거래해 본 은행이 없습니다   빈 목록. 명시적 답이다
모르겠습니다              유도를 안 쓰고 은행마다 따로 묻는다. 그대로 둔다
```

버튼 라벨과 안내 문장은 뷰 모델(`view.question_card`)이 들고 CLI 와 웹이 같은 것을
읽는다. 빈 제출을 막는 판정은 서버(`app.py`)가 하고 템플릿은 받은 문장을 꽂기만 한다
(`0038`·`0043`). 화면 계약 `A3` 가 버튼 셋과 안내 문장이 있는지 검사한다.

**"모름" 경로는 지우지 않는다** (사람 결정). 정말 모르는 사람의 답이고, 그 사람이 걷는
경로의 비용(질문 48개 · 5분)은 로드맵 F7 의 일이다. F7 은 ⏸ 그대로다 — 이 결정이 **실수로**
그 경로에 들어가는 사람을 막아 주므로 압력이 줄었을 뿐, 경로 자체는 남아 있다.

## Evidence

`prereg-16` 3런. 같은 사람이 저축은행을 두 번 돌았고 목록 답만 달랐다.

```
(나)   "모름"       질문 48개 · 5분 이상 · 확정 97/106
(나-2) 빈 제출      질문 15개 · 3분 언저리 · 확정 96/106
```

사람은 거래가 없다는 것을 **알면서** "모르겠습니다" 를 눌렀다. 이유를 이렇게 말했다.

> 이지선다라 모르겠습니다 · 없습니다 같은 선택지처럼 느껴졌어

옛 화면은 버튼이 둘(고른 대로 계속 · 모르겠습니다)이고 *"하나도 고르지 않고 눌러도
됩니다 — 거래해 본 은행이 없다는 답입니다"* 가 **안내문**이었다. 안내문은 읽히지 않았다.
`prereg-16` §3 P2 가 이 위험을 재기 전에 적었고 그대로 일어났다.

답도 흔들렸다 — "모름" 경로에서 계좌가 없는 민국저축은행 주거래에 **예**, 애큐온 첫거래에
**아니오**. 거래가 없으면 첫거래는 예 · 주거래는 아니오가 사실이다. 목록 답 하나가 질문
33개와 틀린 답을 낳았다.

## Alternative

- **안내문을 더 크게 쓴다.** 기각 — 안내문이 있었고 읽히지 않았다. 같은 수단을 키우는 것이다
- **빈 제출을 "없음" 으로 계속 받는다** (옛 동작). 기각 — 실수로 넘어간 빈 제출과 의도한
  "없음" 을 가를 수 없다. 사람이 *"안 골랐을 때 안 넘어가게"* 를 직접 요구했다
- **"모름" 버튼을 없앤다.** 기각 — 정말 모르는 사람의 답을 빼앗는 것이고, 선호를
  추측하지 않는다는 원칙과 어긋난다. 사람이 *"모름 경로는 유지해야 한다"* 고 정했다
- **체크박스에 `required` 를 건다.** 기각 — 체크박스 묶음에는 브라우저가 지원하지 않고
  JS 가 필요하다. 이 화면은 JS 없이 돈다(`0038` 점진적 향상)

## Why rejected

위에 같이 적었다.

## 반증 조건

- **"거래해 본 은행이 없습니다" 를 누른 사람이 실제로는 거래가 있었다고 나중에 말하면** —
  버튼 라벨이 "거래해 본" 의 뜻을 좁게 읽히게 한 것이다. `0045` §4 가 그 정의를 우리가
  하지 않는다고 적었으니 라벨을 다시 본다
- **빈 제출 안내가 나온 뒤에도 사람이 "모르겠습니다" 를 누르면** — 안내 문장이 아니라
  버튼 배치 문제다. 순서를 바꾼다(없음 버튼을 앞에)
- **모름 경로를 걷는 사람이 여전히 나오면** — 그건 이 결정의 실패가 아니라 F7 의 착수
  조건이 채워진 것이다. 이 결정은 실수로 들어가는 사람만 막는다
