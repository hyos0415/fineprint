# 0007 — 규칙 H·I·J를 채택하고 이슈 #6을 닫는다. 규칙으로 깎는 방향은 한계다

> 날짜: 2026-08-25 · 상태: 유효 · 이슈 #6 · 사전등록 `../spec/prereg-05-rules-refinement.md`

## Decision

세 가지를 정한다.

1. **채점 정의를 사전등록 §3의 글자대로 고친다** — 항목 0개도 산수 판정을 받는다.
   공시가 "우대분 없음"이라 말하는 행에서 파서가 아무것도 뽑지 않은 것은 옳은 행동이다.
   A의 개발 닫힘률 기준선이 **62.8% → 68.4%** 로 바뀐다 (규칙이 아니라 정의가 바꾼 값)
2. **규칙 H·I·J를 채택한다** — `parse_bonus_items_v3`. v2는 파일럿·gold 재현을 위해
   **그대로 둔다**. 개발 집합 68.4% → **77.5%**
3. **이슈 #6을 닫는다** — 홀드아웃 상승분이 **+0.5%p**뿐이다. 규칙을 더 깎는 것은
   개발 집합 점수만 올린다

## Evidence

**사전등록한 예측을 두 라운드 모두 달성했다** (`prereg-05` §4는 구현 전에 커밋했다).

| | 기준선 | 라운드 1 (H·I) | 라운드 2 (+J) |
|---|---:|---:|---:|
| 개발 닫힘률 | 68.4% (173/253) | **74.3%** (목표 74%) | **77.5%** (목표 +3%p → +3.2) |
| 항목 0개 | 13.4% | 11.5% | 12.6% (임계 13.4% 통과) |
| 못 고치는 13행 중 닫힌 수 | 0 | **0** | **0** |

**그런데 홀드아웃은 거의 오르지 않았다.**

```
개발 집합    68.4% → 77.5%   +9.1%p
홀드아웃     62.6% → 63.2%   +0.5%p
```

**원인을 세어 확인했다.** 규칙이 겨냥하는 표기가 홀드아웃에 거의 없다.

| | 개발(은행권) 79종 | 홀드아웃(저축은행 폭>0) 46종 |
|---|---:|---:|
| 규칙 H 대상 (항목별 상한) | 26.6% | **4.3%** |
| 규칙 I 대상 (대안 축) | 2.5% | **0.0%** |
| 규칙 J 대상 (기간 라벨) | 6.3% | **2.2%** |

**규칙이 고친 것은 은행권 기관들의 표기 습관이다.** 이는 `0004`가 근거 없이 판단으로
적은 문장("표기 변형에 규칙으로 대응하는 건 끝이 없다")에 **처음으로 숫자를 붙인 것**이다.

**같은 182행에서 제한 스키마 LLM은 71.4%다** (`prereg-03` §7.2). 규칙을 세 라운드 깎아도
격차 8.2%p가 줄지 않았다. B는 홀드아웃에 손댄 적이 없다. 다만 **B의 우위도 유의하지
않다**(p = 0.0987) — 표본이 작다.

**이슈 #6이 추정한 원인은 틀렸다.** 가장 큰 덩어리의 원인을 "배타 그룹(중복 적용 불가)
미처리"로 봤지만, 닫히지 않은 행 중 그 문구가 있는 것은 **3건**이었다. 실제 원인은
항목별 상한 오인(29행)·대안 묶음 합산(7행)·기간 표기(14행)였다.

## Alternative

- **(가) 규칙을 계속 깎는다** — 남은 57행에 규칙을 더 붙인다
- **(나) 홀드아웃을 보고 규칙을 고친다** — 저축은행에서 안 오르니 그쪽 표기를 흡수한다
- **(다) v2를 v3로 덮어쓴다** — 버전 둘을 유지하지 않는다
- **(라) 정의 수정(§1)을 하지 않고 62.8%를 유지한다**

## Why rejected

- **(가) 계속 깎기**: 홀드아웃 +0.5%p가 답이다. 개발 집합 점수만 오른다. 세 라운드에서
  이미 관측된 패턴이고, 네 번째 라운드가 다를 이유가 없다
- **(나) 홀드아웃 보고 고치기**: `prereg-04`가 쓸 홀드아웃이 사라진다. `prereg-05` §1에
  구현 전에 금지로 박아 두었고, 결과가 나빠졌다고 그 약속을 깨면 사전등록이 무의미하다
- **(다) v2 덮어쓰기**: 파일럿 30문항과 `gold_draft`가 v2로 만들어졌다. 덮어쓰면 그
  결과를 재현할 수 없다. 선행 프로젝트가 두 번 겪은 재현성 실패와 같은 모양이다
- **(라) 정의 유지**: 뽑을 게 없어서 안 뽑은 행을 실패로 세는 것은 지표가 틀린 것이다.
  사전등록 문서의 정의도 이미 그쪽이었고, 코드에만 없던 조건이 붙어 있었다

## 이 결정이 남기는 숫자

**A 규칙 파서의 성능은 두 숫자로 기록한다.** 하나만 쓰면 오해가 생긴다.

```
개발 집합(은행권 253행)         77.5%   ← 규칙이 이 데이터를 보며 만들어졌다
홀드아웃(저축은행 폭>0 182행)    63.2%   ← 처음 보는 기관에서의 성능. 이쪽이 진짜다
```

## 반증 조건

- **다음 홀드아웃(다른 권역)에서 v3가 v2보다 3%p 이상 높으면** → "규칙이 은행권 표기만
  고쳤다"가 틀린 것이다. 규칙 H·I·J가 실제로 일반적인 표기를 다룬 것이 된다
- **표본을 넓힌 뒤에도 B가 A를 유의하게 넘지 못하면** → 이 결정의 "격차 8.2%p"는
  182행의 우연이었다는 뜻이고, `0004`의 첫 번째 반증 조건이 발동한다
- **v3가 파일럿 gold를 재현하면** → v2·v3 두 버전을 유지할 이유가 없다. 하나로 합친다
- **`prereg-05` §5의 임계 표현이 다시 문제를 일으키면** → "홀드아웃에서 떨어지면"이라는
  방향 조건은 느슨했다. 다음부터 "개발 상승분의 절반 이상이 홀드아웃에 나타나야 한다"처럼
  **일반화 비율**로 적는다. 이건 이미 관측된 결함이므로 반증 조건이 아니라 **교정 사항**이다
