# 0021 · 유형 배정 재추출을 채택한다 — 게이트를 사람이 넘겼다

2026-08-27 · 사전등록 [`../spec/prereg-07-type-assignment.md`](../spec/prereg-07-type-assignment.md) ·
이슈 [#2](https://github.com/hyos0415/fineprint/issues/2)

## Decision

**v2 추출 결과를 정식으로 채택한다.** 그리고 **그것이 사전등록한 회귀 가드 하나를
통과하지 못했다는 사실을 여기 남긴다.**

```
주 지표(은행권)      문구 종 5/5 (100%) · 항목 14/14      예측 >= 9/11    통과
홀드아웃(저축은행)    문구 종 6/7 (86%) · 항목 24/27       예측 >= 3/9     크게 통과

회귀 가드
  닫힘률            은행권 76.5 -> 77.8 · 저축은행 74.7 -> 73.6           통과
  `기타` 비율        은행권 3.4 -> 0.7% · 저축은행 4.7 -> 0.8%             통과
  항목 0개 비율       은행권 4.7 -> 3.8% · 저축은행 18.9 -> 14.9%           통과
  커버리지          은행권 79.7 -> 82.3%                                통과
                  저축은행 36.7 -> 35.4%                    **불통과**
```

**사전등록대로면 채택하지 않는 것이 맞다.** 사람이 그것을 알고 채택했다.
파일은 `extract_llm_*.json`이 v2이고, 옛것은 `extract_llm_v1_*.json`으로 남겼다.

## Evidence

### 원리가 옮겨붙었다 — 이게 이 실험의 값어치다

프롬프트에 **예시가 아니라 판정 원리**를 넣었고, 근거는 **은행권 A군 11건만** 봤다
(저축은행은 홀드아웃이라 읽지 않았다). 홀드아웃 예측을 **33%로 낮게** 잡은 이유는
저축은행 A군이 대부분 `고객군_자격`(출산·한부모·신용평점·착한운전)이라 은행권
사례(전자명함·개인사업자·기부금)와 겹치지 않기 때문이다.

**86%가 나왔다.** 겹치지 않는 유형이 맞았다는 것은 **예시를 외운 게 아니라 원리가
작동했다**는 뜻이다. 낮게 잡은 예측이 이 해석을 가능하게 했다.

틀린 하나는 `"올해의 띠"`다 (`기타` 2 : `고객군_자격` 1).

### 부수 소득 — 계단식이 처음으로 표현됐다

`prereg-06` §1.6의 열린 결정(계단식 우대 11건 · 1.0%)이 부분적으로 풀렸다.

```
WELCOME 아이사랑 정기적금   "만 16세이하 가구원수 3명/2명/1명" -> 항목 3개 + exclusive_group
웰뱅 든든적금             "신용평점 850/650/350점" -> 항목 3개 + exclusive_group
```

v1은 이걸 **항목 하나로 접어 가장 높은 금리만** 남겼다. 재추출 여부를 `0013` 기준으로
고민하던 항목인데, **유형 배정을 고치는 김에 따라왔다.**

### 커버리지가 떨어진 이유 — 쪼개기가 반반 성공했다

```
잘 됨   WELCOME 아이사랑   가구원수 3명/2명/1명 -> excl=g1 -> 그룹 최댓값 6.0. 정확
안 됨   웰뱅 워킹 적금     걸음수 1/2/3/4백만보 -> excl 누락 -> 1+2+3+6 = 12%p (공시폭 7.0)
안 됨   웰뱅 든든적금      "최대 연 3.0%p"(신용평점 항목의 상한)를 상품 전체 cap 으로 올림
```

**쪼개는 것 자체는 맞는 방향이고, 쪼갠 뒤 묶는 신호(`exclusive_group`·`cap`)가
불안정하다.** 그건 별개의 문제로 열려 있다 (아래).

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| A | 사전등록대로 채택하지 않는다 | 주 지표 100% · 홀드아웃 86% · `기타` 4.5배 감소 · 계단식 해결을 **커버리지 1.3%p 때문에 전부 버린다** |
| B | 저축은행만 v1을 쓴다 | 프롬프트는 하나다. 권역마다 다른 추출기를 쓰면 권역 비교가 성립하지 않는다 |
| C | 커버리지가 회복될 때까지 프롬프트를 고쳐 재실행 | **결과를 보고 고치는 것**이다. 사전등록에 재시도 규정이 없고, 넣으려면 새 사전등록이 필요하다 |

## Why rejected

A가 원칙이고, 그것을 넘긴 것이 이 결정이다. **넘긴 이유를 적는 것이 이 문서의 목적이다.**

커버리지 1.3%p 하락의 원인이 **v2가 나빠서가 아니라 층 판정 코드의 내부 모순과
얽혀 있다**는 것이 진단으로 드러났다(아래 "열린 문제"). 게이트가 잡은 것이 v2의
품질 저하인지 우리 채점의 결함인지 **게이트만으로는 가릴 수 없다.**

**그래도 게이트를 없애지 않는다.** 게이트는 제 일을 했다 — 커버리지가 떨어진다는
신호를 냈고, 그 신호를 쫓아가서 내부 모순을 찾았다. 신호를 낸 장치를 결과가
마음에 안 든다고 끄지 않는다.

## 열린 문제 — `exclusive_group` 신호를 못 믿는다

층 판정(`declared_all`)은 배타 그룹을 **무시하고 다 더하는데**, 같은 파일의
`bonus_range()`와 공식 닫힘률(`compare_extractors.declared_llm`)은 **그룹 최댓값**을 쓴다.
어느 쪽이 맞는지 재봤더니 **어느 쪽도 아니었다.**

```
배타 그룹이 붙은 행에서 공시 폭에 맞는 쪽
  은행권 93행    최댓값 35 · 합산 32 · 둘 다 틀림 26
  저축은행 46행   최댓값 18 · 합산 16 · 둘 다 틀림 12
```

**반반이다.** 추출기가 `exclusive_group`을 절반쯤 잘못 붙인다는 뜻이다 —
`iM함께예금`은 `g1`에 `[0.1 × 5]`가 들어 있는데 공시 폭이 0.45라 **다섯 개가 다 더해져야**
맞는다. 중복 적용 불가가 아니라 별개 조건 다섯 개를 한 그룹으로 묶은 것이다.

**이건 이 결정에서 정하지 않는다.** 기준선이 크게 움직이는 변경이라
(`prereg-06` §2.3(1)처럼) **고치기 전에 사유를 등록**해야 한다.

## 반증 조건

- **다음 달 공시에서 홀드아웃 성적이 크게 떨어지면** — 86%가 원리의 힘이 아니라
  이번 표본의 운이었다는 뜻이다. 9월 공시로 확인한다
- **`기타`가 0.7%까지 줄었는데 사람이 표본을 읽어 오분류가 늘었으면** — `기타`를 줄이라는
  지시가 **아무 유형에나 밀어넣는 것**으로 작동한 것이다. `기타` 비율만 보면 안 된다
- **저축은행 커버리지가 다음 측정에서도 안 돌아오면** — 내부 모순과 무관하게 v2가
  나쁜 것이다. 그때는 이 결정을 뒤집는다
- **쪼갠 항목의 `exclusive_group`·`cap` 오류가 지금(반반)보다 늘면** — 쪼개기가
  순손실이 된다. 항목 수가 늘수록 묶는 신호가 더 필요해지기 때문이다
