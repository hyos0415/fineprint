# 0035 · 화면이 자기가 무엇인지 말하고, 판매업자 기준을 그대로 지킨다 (A안 + B안 병기)

> 날짜: 2026-08-31 · 상태: 유효

이슈 [#31](https://github.com/hyos0415/fineprint/issues/31) · 로드맵 I5 ·
앞선 결정 `0034`(광고 규제는 실재하나 판매업자를 묶는다) · `0017`(범위로 쓴다) ·
`0026` D4(편의와 정직 사이에서 타협하지 않는다) · `design.md` 화면 계약 A12·A13

**사람이 정했다.** `0034` D5 가 열어 둔 결정을 사람이 **A·B 병기**로 닫았다 —
*"A랑 B랑 모두 같이 병기 가능한 거 아님???? 둘 다 해주면 좋을 거 같은데"*.
이슈 #31 이 *"A·B 는 배타적이 아니다"* 라고 적어 둔 그 자리다.

## Decision

**A안(화면이 자기가 무엇인지 밝힌다)과 B안(판매업자 기준을 자발적으로 지킨다)을
둘 다 한다. 그리고 둘 다 assert 로 박는다.**

```
A안 → 화면 계약 A13   화면에 이 한 줄이 항상 있다
                     "이 화면은 금융감독원 공시를 계산한 결과입니다 —
                      상품을 판매·중개하지 않고, 특정 상품을 권하지 않습니다"

B안 → 화면 계약 A12   금리를 보여주는 화면에는 `세후` 라벨이 항상 있다
                     "금리는 모두 세후입니다 — 이자소득세 등 15.4% 를 뗀 값입니다"
                     (세율은 config 에서 읽는다. 문자열에 안 박는다)
```

정한 것 넷.

```
D1  **"광고가 아니다" 라고 선언하지 않는다.** 그건 법적 판정이고 우리가 내릴 것이
    아니다. 대신 **우리가 하는 일과 안 하는 일**을 적는다 — 그건 사실이고,
    판정은 사실 위에서 남이 한다

D2  **규제 적용 대상인지와 무관하게 판매업자 기준을 지킨다.** 문서에서는 근거를
    *"법이 우리에게 명령한다"* 가 아니라 *"규제가 요구하는 수준과 우리 방향이
    같다"* 로 쓴다 (`0026` 반증 조건에 붙여 둔 문장과 같다)

D3  **말로 지키지 않고 검사로 지킨다.** A12·A13 을 `check_screen_contract.py` 에
    넣어 **모든 중간 상태**에서 본다. `0034` D3 가 "A12 후보" 로 남겨 둔 것을
    같은 PR 안에서 만들었다

D4  **이슈 #31 을 닫지 않는다.** A·B 로 답한 것은 *"그래서 화면을 어떻게 하나"* 이고,
    *"F3(가입 링크)이 중개인가"* 와 *"유권해석(D안)을 언제 받나"* 는 그대로 남는다.
    #31 의 범위를 그쪽으로 좁힌다
```

## Evidence

### `0034` D3 가 틀렸다 — 질문 루프 화면은 세후 라벨을 안 지키고 있었다

`0034` 는 *"우리는 이미 지키고 있다 — `calculate.py` 의 목록 헤더가 `세후 확정~최대` ·
`세전` 이다"* 라고 적었다. **그 화면만 봤다.**

```
calculate.py 목록 헤더        "세후 확정~최대" · "세전"        <- 있다
ask_loop 최종 화면            `세후` 라는 말이 **한 번도 없다**   <- 없었다
                             (grep 결과 0건. 상품 줄은 `3.26~5.12%` 뿐이다)
```

**사용자가 실제로 보는 것은 뒤쪽이다.** 화면 계약 검사가 대상으로 삼는 화면도
`ask_loop.render_final_screen()` 이다 — *"사용자가 12번째 질문에서 그만두면 보는
화면"* 이라는 이유로 그 함수를 읽게 해 뒀는데, 정작 세후 라벨은 **다른 화면**을 보고
"지키고 있다" 고 적었다.

`0019`(부산은행 · 조건이 한 글자도 없는데 4.80% 로 보였다)와 같은 종류다 —
**코드는 알고 있는데 사용자가 못 읽는 자리**다. 세율은 `tax_rate` 로 모든 행에 들어
있었고 화면에만 없었다.

### 그래서 B안은 문구 추가가 아니라 누락 수정이었다

```
python src/analysis/check_screen_contract.py 20260826 --group bank --term 12 --seeds 20
  A1~A11  통과 · **A12·A13 통과**
저축은행 (20260825 · seeds 10)                A1~A13 통과
--prefs 확실성=많이 (seeds 5)                  A10·A11 포함 A1~A13 통과

음성 검사 — `screen_header()` 를 일부러 빼고 돌렸다
  A12  **불통과 156건**  "금리가 있는 화면에 `세후` 라벨이 없다"
  A13  **불통과 156건**  "성격 고지가 화면에 없다"
```

**빼면 잡힌다는 것을 확인했다.** 통과만 보고 넘기면 검사가 아무것도 안 보는 경우와
구분되지 않는다.

### 문구를 한 곳에만 둔다

```
calculate.NOTICE          A13 문구. `ask_loop.NOTICE = C.NOTICE` 로 참조한다
ask_loop.tax_label()      A12 문구. 세율은 `scored[].tax_rate` 에서 읽는다
check_screen_contract     `L.NOTICE` 를 읽는다 — 사본을 만들지 않는다
```

**검사기가 자기 사본을 갖고 있으면 렌더 쪽만 고쳐도 통과한다.** 그리고 세율을
문자열에 `15.4%` 로 박으면 `config/tax-2026.json` 이 바뀔 때 어긋나는 자리가 생긴다 —
`0032` 가 세율을 조문 좌표에 핀으로 박은 것과 같은 이유로, 화면도 config 를 읽는다.
**상품별로 세율이 갈리면**(`0033` 이 지금은 아니라고 확인했다) 뭉뚱그리지 않고
*"세율이 상품마다 다릅니다"* 로 떨어진다.

### A안을 "광고가 아니다" 로 쓰지 않은 이유

법 §22① 이 판매업자등이 아닌 자의 광고를 금지한다. 그 문장에 대고 *"우리는 광고가
아니다"* 라고 화면에 쓰는 것은 **우리가 우리 사건을 판정하는 것**이다. 게다가 그
판정은 이슈 #31 에서 아직 열려 있다 — 우리가 화면에 결론을 써 놓고 이슈를 열어 두면
문서와 화면이 서로 다른 말을 한다.

**대신 검증 가능한 사실만 적는다** — 공시를 계산한 결과이고, 판매·중개하지 않고,
특정 상품을 권하지 않는다. 셋 다 지금 코드가 하는 일 그대로다(추천 목록은 계산 순서이고
`0030` 이 가중치를 사용자에게서만 받는다).

## Alternative

- **A안만** — 성격 고지만 달고 규제 준수는 적용 대상이 갈린 뒤에 정한다
- **B안만** — 자발적 준수만 하고 화면에는 아무 말도 안 넣는다
- **A+B 를 문서에만 적는다** — assert 는 만들지 않는다 (`0034` D3 상태 그대로)
- **화면에 "광고가 아닙니다" 라고 명시한다** — A안의 직역
- **유권해석(D안)을 먼저 받고 그 결과대로 한다**

## Why rejected

- **A안만** — 고지는 붙지만 **세후 라벨 누락이 그대로 남는다.** 오늘 찾은 실제 결함이
  그것이고, 고지 한 줄이 그것을 대신하지 않는다
- **B안만** — 준수는 하지만 **우리가 무엇인지 화면에서 말하지 않는다.** 사용자가
  "이게 광고인가 비교인가" 를 판단할 근거가 화면에 없다. 그리고 그 판단은
  `problem.md` §2-(가)가 시작점으로 삼은 문제와 같은 종류다
- **문서에만 적는다** — `0026` 이 화면 계약을 assert 로 박은 이유와 정면으로 어긋난다.
  F4(UI)로 옮길 때 조용히 사라지는 종류이고, **오늘 사라져 있던 것을 방금 찾았다**
- **"광고가 아닙니다"** — 위 Evidence 마지막 항목. 우리가 내릴 판정이 아니고, 열린
  이슈와 화면이 다른 말을 하게 된다
- **유권해석 먼저** — F1·F4 가 멈춘다. 그리고 A+B 는 어느 쪽으로 판정되든 **손해가
  없는 방향**이다(광고에 해당해도 지켜야 하는 것을 지키고 있고, 아니어도 사용자에게
  더 정직하다). 유권해석은 F3(가입 링크)를 만들 때가 진짜 시점이라 #31 에 남긴다

## 반증 조건

- **F4(UI)에서 A12·A13 이 통과하는데 사용자가 세후 여부를 못 읽으면** — 문자열이
  화면에 있는지만 보는 검사의 한계다. 그러면 검사를 "금리 칸 옆" 위치까지 보게 고친다
  (지금은 화면 문자열 어디에 있어도 통과한다)
- **고지 문구가 길어서 사용자가 안 읽으면** — 화면 맨 위 두 줄을 차지하는데, 사용자
  세션에서 *"이게 뭐냐"* 는 질문이 나오면 문구가 일을 안 하는 것이다. 그때는 문구를
  줄이거나 위치를 바꾼다. **없애지는 않는다**
- **이슈 #31 이 "우리는 광고에 해당한다" 로 닫히면** — A안 문구를 다시 봐야 한다.
  *"판매·중개하지 않는다"* 는 그대로 사실이지만, 그 경우 문제는 문구가 아니라
  **서비스 형태**다(`0034` 반증 조건과 같다)
- **상품별로 세율이 갈리는데 `tax_label()` 이 뭉뚱그리면** — 지금은 `tax_rate` 집합의
  크기가 1이 아니면 *"세율이 상품마다 다릅니다"* 로 떨어지게 해 뒀다. 그 분기가 실제로
  타질 때(A2 코퍼스 뒤 · `0033`) 문구가 충분한지 다시 본다
- **`calculate.py` 와 `ask_loop` 의 고지가 갈라지면** — 상수를 한 곳에 두고 참조하게
  했는데, 세 번째 화면(F1 리포트 · F4 UI)이 자기 사본을 만들면 같은 실패가 반복된다.
  그때는 검사기가 **모든 렌더 경로**를 읽는지부터 본다
