# 0046 · 우리가 지은 낱말을 화면에서 없앤다 — 표 하나와 검사 하나로

2026-09-02 · 이슈 [#45](https://github.com/hyos0415/fineprint/issues/45) · 로드맵 F5 ·
`prereg-14` §1 관찰 2

## Decision

**화면 낱말 표를 `calculate.py` 한 곳에 두고, 렌더러 셋이 전부 그 표를 읽는다.**
그리고 낱말을 **두 종류로 다르게** 다룬다.

```
없앤다     내부 이름·코드처럼 **만든 사람만 아는 것**
          `급여_연금이체` → `국민은행으로 급여·연금 받기` · `추출불확실` → `우리 해석이 불확실`
          `미응답` → `안 답한 조건 있음` · `스코프` → `찾는 범위` · `메인` → `계산할 수 있는 상품`
설명한다   `%p`·`공시`·`세후`·`우대조건` 처럼 **정확해서 필요한 낱말**
          첫 등장에서 풀어 준다 — 쉽게 만드는 것과 흐리게 만드는 것은 다르다
```

**키는 바꾸지 않는다.** `CONDITION_TYPES` 는 추출 스키마의 enum 이고(재추출 없이는 못
바꾼다), 층·사유 코드는 상태 dict·세션 로그·옛 측정의 키다. 이름을 바꾸면 데이터와 지난
기록이 다 어긋난다 — `0031`(상품 신원)이 겪은 자리다. **표를 옆에 두고 화면만 라벨을 읽는다.**

**`A14` 를 화면 계약에 더한다.** 내부 이름이 화면에 남아 있으면 위반이다. 목록은
`calculate.internal_words()` 한 곳에서 오고, **결정 번호**(`0017`·`decisions/0018`)가
새는 것도 같이 잡는다.

**기관 상대 라벨은 `이 은행` 자리에 실제 이름을 넣는다.** 꼬리로 붙이면
*"이 은행의 다른 상품 가입·보유 · 국민은행"* 이 되어 두 번 읽어야 한다. 자리에 넣으면
*"국민은행의 다른 상품 가입·보유"* 다. **조사도 맞춘다** — `카카오뱅크과` 가 아니라
`카카오뱅크와`, `농협은행으로` 와 `카카오뱅크로`를 가른다.

**은행 이름은 화면에서 법인 형태만 뗀다.**

```
농협은행주식회사 → 농협은행     주식회사 케이뱅크 → 케이뱅크
주식회사 하나은행 → 하나은행     주식회사 카카오뱅크 → 카카오뱅크    토스뱅크 주식회사 → 토스뱅크
```

은행권 17곳 중 **5곳**이 그렇고 저축은행 30곳은 하나도 없다. **브랜드 이름으로 바꾸지
않는다** — `농협은행 → NH농협은행` · `중소기업은행 → IBK기업은행` 같은 개칭은 공시에 없는
이름을 우리 기억으로 채우는 것이다. 사람이 확정하면 `ORG_ALIAS` 에 근거와 함께 적는
자리를 만들어 뒀고 **지금은 비어 있다.**

**신원은 공시 이름이 진다** (`0031` 과 같은 규칙). 상태(`_거래은행`)·후보 대조·스코프는
전부 공시 이름을 쓰고 **화면만** `org_label()` 을 지난다. 웹 체크박스도 갈라 뒀다 —
`value` 는 `농협은행주식회사`, 보이는 글자는 `농협은행` 이다. 안 갈랐으면 사용자가 고른
이름과 계산에 들어간 이름이 달라진다. **목록 순서도 표기 이름 순이다** — 공시 이름으로
세우면 `주식회사 카카오뱅크` 가 ㅈ 자리에 있는데 화면에는 ㅋ 으로 보인다.

## Evidence

**근거는 측정이 아니라 관측이다.** 화면 152장(권역 2 × 상태 5 × 찾는 범위 2 × 선호 2 ×
화면 4 + 0단계 폼)을 훑어 무엇이 실제로 나가는지 셌다.

```
내부 이름 13종     급여_연금이체 · 잔액_평잔_가입금액 · 조건불명_공시미기재 …  리포트·웹·질문
층 이름 4종       공시미반영 · 설명부족 · 추출불확실 · 계산불가              CLI·웹
사유 코드 7종      미응답 · 단계불명 · 이행필요 · 중복우대불명 …              CLI·리포트·웹
우리 말 3종       스코프 · 메인 · "판정을 엽니다"                        CLI·웹
```

**밑줄 이름 16종 중 3종은 은행이 지은 상품명이었다** — `해피라이프_여행스케치적금` ·
`여행스케치_남도투어적금` · `해피라이프_여행스케치외화적금`. **그건 공시 원문이므로
손대지 않는다**(`0031`·`0019`). 그래서 `A14` 목록은 상품명을 담지 않는다.

사람이 완주하며 말한 것이 이 관측과 같다.

> "⚠ 스코프 밖에 …" 이런 문구들도 **스코프는 사용자는 전혀 몰라.** 쉽게 풀어서 쓰는
> 부분이 필요할 거 같다고 느껴진다

**`M2`(뜻 모르는 낱말 수)는 근거가 못 된다.** 사람 완주에서 **2개**가 나왔고 위 표의
낱말을 **하나도 안 셌다** — 만든 사람이 표본이라 자기가 지은 낱말의 뜻을 안다.
`prereg-14` §4 가 그 편향을 미리 적었고 그대로 실현됐다. 그래서 이 작업은
**자기보고가 아니라 "화면에 그렇게 쓰여 있다" 는 사실** 위에 선다.

**`A14` 가 살아 있다는 증거 둘.**

1. 음성 검사 — 라벨을 안 쓰는 렌더러로 되돌리면 잡는다.
   ```
   유형 라벨을 안 쓴다   질문 1 · 리포트 13 · 웹 14
   층 라벨을 안 쓴다     화면 3 · 웹 3
   사유 라벨을 안 쓴다    화면 3 · 리포트 3 · 웹 3 · 모델 3
   ```
2. **만들자마자 내가 못 본 누락을 잡았다** — 비교 리포트가 중복 우대 설명 끝에
   `(0022)` 를 쓰고 있었다. 손으로 훑어서는 못 찾은 자리다.

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| B | `CONDITION_TYPES`·층·사유 코드의 **이름 자체를 바꾼다** | 데이터와 지난 기록이 어긋난다. 조건 유형은 추출 스키마의 enum 이라 **재추출 없이는 못 바꾸고**($ 든다), 세션 로그 38개와 사전등록 여덟 편의 숫자가 그 이름으로 적혀 있다. `0031` 이 상품 신원에서 겪은 사고와 같은 모양 |
| C | 대응표를 **새 모듈**로 뺀다 | 표가 데이터에서 멀어진다. `CAVEAT`(사유 문장)·`TIERS`(층 정의)가 이미 `calculate.py` 에 있는데 라벨만 다른 파일에 두면 한쪽만 고쳐진다(`0035` 가 찾은 실패) |
| D | 낱말을 **전부** 없앤다 (`%p`·`공시`·`세후`까지) | 흐려진다. `%p` 를 "포인트" 로 뭉개면 금리와 금리 차이를 구분할 수 없고, `세후` 는 공정위 예규가 요구하는 표기다(`0034` · A12). **쉽게 만드는 것과 흐리게 만드는 것은 다르다** |
| E | 라벨 꼬리에 기관을 붙인다 (`… · 국민은행`) | *"이 은행의 다른 상품 가입·보유 · 국민은행"* 은 "이 은행" 이 무엇인지 한 번 더 생각하게 만든다. 자리에 넣는 쪽이 한 번에 읽힌다 |
| F | 은행 이름을 **브랜드 이름**으로 바꾼다 (`NH농협은행`·`IBK기업은행`·`SC제일은행`) | 공시에 없는 이름을 **우리 기억으로** 채우는 것이다. 은행 이름을 틀리게 쓰는 것은 금리를 틀리게 쓰는 것과 같은 급의 실패이고, 확인할 원천이 손에 없다(공시 API 의 `kor_co_nm` 이 우리가 가진 유일한 이름이다). `CLAUDE.md` 5번이 별칭 사전 경로를 막아 둔 것과 같은 결이다. **사람이 "별로 중요하지 않다" 고 판단해 안 넣었다**(2026-09-02) |

## Why rejected

**B 가 옳은 방향처럼 보이는 것이 이 결정의 함정이다.** 이름이 나쁘면 이름을 고치는 게
맞는데, 여기서 그 이름은 **데이터의 키**다. `자동이체` 를 `이 은행 계좌에서 자동이체` 로
바꾸면 추출 결과 1,072개 항목과 세션 로그 38개와 `prereg-03`·`05`·`09`·`10`·`13`·`15` 의
숫자가 전부 옛 이름을 가리키게 된다. **화면을 고치는 일이 측정 기록을 깨뜨리면 안 된다.**

그래서 표를 옆에 뒀고, 그 대가는 하나다 — **표와 코드가 어긋날 수 있다.** `A14` 가 정확히
그 대가를 갚는다. 표에서 빠진 유형은 `type_label()` 이 내부 이름을 그대로 내고, 그것이
화면에 나가면 `A14` 가 잡는다. **없는 이름을 지어내는 쪽으로는 가지 않는다**(`0019`).

**D 를 안 고른 이유도 같은 결의 문제다.** 이 저장소가 지키는 것은 *"사용자가 볼 숫자와
받을 숫자가 같다"* 이고, 낱말을 뭉개면 숫자가 무엇을 뜻하는지가 흐려진다. 그래서 남기고
**첫 등장에서 풀어 준다** — `%p 는 퍼센트포인트 — 금리의 차이입니다 (3.0% → 3.5% 가
+0.5%p)` 를 목록과 리포트 머리에 놓고, 고지가 `공시` 를 *"은행이 금융감독원에 신고한
정보"* 로 푼다.

**`기관` 이 아니라 `은행` 이라고 쓴다** (사람 결정 · 2026-09-02). `기관` 은 우리가 데이터
축을 부르는 말이고, 사람들은 저축은행과 은행을 굳이 가려 부르지 않는다. 실제 화면에는
거의 안 나온다 — 기관 상대 질문에는 **은행 이름이 그 자리에 들어가기** 때문이다.

## 반증 조건

- **사람이 완주하며 여전히 낱말을 물으면** — 그 낱말이 표에 없다는 뜻이다. `A14` 는
  **우리가 아는 낱말만** 잡으므로 표 밖의 것은 못 잡는다. 그때는 표를 늘린다
- **`A14` 가 0건인 채로 화면에 어려운 말이 남으면** — 검사가 죽은 것이다. 음성 검사
  (라벨을 안 쓰게 되돌리기)로 확인한다. 지금은 질문 1 · 리포트 13 · 웹 14 · 모델 3 이 잡힌다
- **라벨이 조건의 뜻을 바꾸면** — 번역이 아니라 해석이 된다. 가장 위험한 칸이
  `기타`(→ *"그 밖의 조건"*)와 `판정불가_불특정`(→ *"누가 받는지 미리 알 수 없는 우대"*)이다.
  공시 문구가 그 아래 그대로 붙으니 사용자가 대조할 수 있지만, **문구 없는 조건에서
  라벨만 보고 답하는 일이 생기면** 라벨을 빼고 문구만 보여주는 쪽으로 돌린다
- **`A14` 가 정상적인 문장을 잡기 시작하면** — 지금은 라벨이 자기 내부 이름을 품는 칸
  (`추첨` → *"추첨으로 주는 우대"* · `자동이체` → *"이 은행 계좌에서 자동이체"*)과
  `모름`·`기타`를 검사에서 뺐다. 그 규칙이 무너지면 검사가 소음이 된다
- **조사 보정이 틀린 이름이 나오면** — 지금은 한글로 끝나는 은행 이름만 맞춘다. 영문·숫자로
  끝나는 이름(`SC제일은행 1호` 같은 것)이 들어오면 받침 없는 쪽으로 떨어진다
- **법인 형태를 떼서 두 은행이 같은 이름이 되면** — `org_label()` 이 서로 다른 은행을 한
  이름으로 보여주게 되고, 그건 `0031` 이 상품 신원에서 막은 실패와 같은 모양이다.
  **이 조건은 희망이 아니라 검사다** — `A14` 가 표기 충돌을 잡는다(지금 은행 17곳·저축은행
  30곳 다 충돌 0). 일부러 겹치게 넣어 잡히는 것을 확인했다
- **사용자가 화면의 이름으로 검색·입력했는데 안 걸리면** — CLI 목록 답은 부분 일치라
  표기 이름(`농협은행`)이 공시 이름(`농협은행주식회사`)에 걸린다. 그런데 **0단계의
  `--company` 스코프는 공시 이름을 그대로 부분 일치**시킨다 — `NH농협` 처럼 공시 이름에
  없는 조각을 넣으면 안 걸린다. 그 경로는 아직 표기 이름을 안 본다
