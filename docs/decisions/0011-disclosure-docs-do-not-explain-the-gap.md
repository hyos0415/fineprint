# 0011 — 상품설명서에도 설명 안 되는 금리가 없다. 수집 1순위를 내린다

> 날짜: 2026-08-26 · 상태: 유효 · 근거: 제주은행 J정기예금 상품설명서 실물 확인

## Decision

세 가지를 정한다.

1. **상품설명서 수집을 1순위에서 내린다.** "설명 안 되는 금리가 설명서에는 있을 것"이라는
   가정이 **틀렸다.** 법정 공시 서류에서도 "이벤트시 별도 고시"로 끝난다
2. **"근거 없음" 표시를 정식 기능으로 확정한다** (`../spec/problem.md` §5).
   임시 대응이 아니라, 공시 체계가 실제로 설명하지 않으므로 정당하다
3. **설명서 수집은 다른 이유로 계속한다.** 세제 혜택·가입 제한·중도해지 이자율은
   API에 없고 설명서에만 있다. **다만 우선순위는 3순위로 내린다**

## Evidence

**제주은행 J정기예금 상품설명서(준법감시인 심의필 2025-01-697호)를 직접 확인했다.**

설명서 2페이지 우대이자율 항목이 공시(`spcl_cnd`)와 **글자 그대로 같다.**

```
"아래의 요건 충족여부에 따라 최고 0.5%p 제공합니다.
   ① 이 예금 상품을 비대면 채널로 가입 시 0.3%p 우대 (가입시 제공)
      단, 이벤트시 비대면 채널에 고시한 우대금리를 추가 적용 할 수 있습니다.
   ② 계약 기간의 1/2 이상 매월 jBANK 로그인 시 0.2%p 우대 (만기시 제공)"
```

**기본금리는 설명서와 공시가 여섯 구간 전부 일치한다.**

| 기간 | 설명서 (2025.12.29) | 공시 기본 (2026-08) | 공시 최고 | 설명 안 되는 폭 |
|---|---:|---:|---:|---:|
| 1개월 | 1.40 | 1.40 | 2.40 | 0.50%p |
| 3개월 | 1.70 | 1.70 | 2.90 | 0.70%p |
| 6개월 | 1.90 | 1.90 | 3.30 | 0.90%p |
| 12개월 | 2.00 | 2.00 | 3.80 | 1.30%p |
| 24개월 | 1.85 | 1.85 | 3.80 | 1.45%p |
| 36개월 | 1.85 | 1.85 | 3.85 | 1.50%p |

**기간이 길수록 설명 안 되는 폭이 커진다.** 그런데 설명서에 적힌 우대조건은 기간과
무관하다(비대면 가입 0.3 + 로그인 0.2). **이벤트 금리가 기간별로 다르게 붙는다는
뜻이고, 그 값은 어느 문서에도 없다.**

## 정정 — "두 공시가 어긋난다"는 표현은 틀렸다

작업 중에 "설명서와 공시가 서로 다른 값을 말한다"고 적었다. **아니다.**

```
설명서   "나열된 조건으로 최고 0.5%p · 단 이벤트 우대금리를 추가 적용할 수 있다"
공시     최고금리 3.85%  ( = 기본 1.85 + 0.5 + 이벤트 1.5 )

둘은 모순되지 않는다. 둘 다 "이벤트 금리가 따로 있다"고 말하고,
둘 다 그 값을 적지 않는다. 같은 곳을 가리키는데 그곳이 문서가 아니다.
```

그리고 **공시 수치가 현재값이다.** 설명서가 자기 금리표를 스스로 부인한다 —
"신규 시 적용 이자율이 변동될 수 있습니다 / 기본이자율은 신규일 당시 고시된 이자율 적용".
설명서의 표는 작성 시점 스냅샷이다.

## Alternative

- **(가) 다른 상품도 더 받아보고 판정한다** — 케이뱅크 +6%p 등
- **(나) 약관까지 받아본다** — 설명서 말고 예금거래 약관
- **(다) 수집을 통째로 접는다**

## Why rejected

- **(가) 더 받아보기**: 여전히 열려 있는 선택지다. 다만 **가장 확실한 케이스에서 답이
  나왔다** — 이 상품은 설명 안 되는 폭이 6개 기간에 걸쳐 일관되게 나타나고, 설명서가
  그 구조를 명시적으로 "별도 고시"로 넘긴다. 표본을 늘리기 전에 우선순위를 조정하는
  것이 순서다. **다른 유형(케이뱅크 "랜덤 지급")은 성격이 달라 따로 확인할 값어치가 있다**
- **(나) 약관**: 약관은 계약 조항이고 금리 수치를 담지 않는다. 설명서가 금리를 다루는
  문서인데 거기 없으면 약관에도 없다
- **(다) 통째로 접기**: 설명서에만 있는 정보가 실재한다(아래). 목적을 바꿔서 계속한다

## 설명서에만 있는 것 — 수집을 접지 않는 이유

API에는 하나도 없고 설명서에는 있다.

```
세제 혜택      "비과세종합저축 : 가능(전 금융기관 통합한도 범위내)"   ← 세금 2층 재료
가입 제한      미성년자·외국인·비거주자·공동명의 불가
최저 가입금액   30만원 이상
중도해지 이자율  경과월수별 20~80% 산식
만기후 이자율   1개월 이내 50% · 3개월 이내 25% · 이후 0.1%
재예치         가능 (일반 → 비과세종합저축 전환은 불가)
예금자보호      1억원까지
```

**세제 혜택이 특히 중요하다.** API 765개 상품 중 비과세 언급이 20건뿐인데
(`../spec/design.md` §2), 설명서에는 상품마다 있다. 오늘 설계한 세금 2층
(비과세 자격 판정)의 재료가 여기다.

## 바뀐 수집 우선순위

| | 전 | 후 |
|---|---|---|
| 1 | 상품설명서 — 세 가지를 동시에 푼다 | **정책·정부 상품** — API에 0건 |
| 2 | 정책·정부 상품 | **지점 위치** |
| 3 | 지점 위치 | **상품설명서** — 세제·가입제한·중도해지 목적으로만 |

## 반증 조건

- **다른 상품(특히 케이뱅크 "입금할 때마다 랜덤" 유형)의 설명서에 금리표가 있으면** →
  이 결정이 한 상품에 과적합한 것이다. 유형별로 다시 판정해야 한다
- **이벤트 금리를 고시하는 페이지를 찾으면** → 수집 대상이 설명서가 아니라 그 페이지다.
  1순위가 다시 올라간다
- **설명서의 기본금리표가 공시와 어긋나는 상품이 나오면** → "공시가 현재값"이라는 판단이
  틀린 것이다. 어느 쪽을 정답으로 쓸지 다시 정해야 한다
- **비과세 정보가 설명서에도 없는 상품이 절반을 넘으면** → 3순위 목적마저 성립하지
  않는다. 수집을 접는다

## 부수 결정 — PDF 도구

직접 만든 파서(`src/ingest/pdf_text.py`)를 **버리고 `pdfplumber`로 갈아탔다.**

```
직접 만든 파서   "기 간기본이자율만기지급식1개월이상 3개월미만1.403개월이상..."   표가 뭉개진다
pdfplumber      ["1개월이상 3개월미만", "1.40"]                            셀이 살아난다
```

**우리가 설명서에서 원하는 것이 정확히 표다.** 그래서 이 저장소의 무의존 관행
(`fetch_finlife.py` 주석)을 PDF에서만 깬다. 이유는 `requirements.txt`에 적었다.

PyMuPDF 를 쓰지 않은 이유는 **AGPL** 이다 — 이 저장소는 공개이고 라이선스 파일이 없어
결합저작물 문제가 생긴다. `pdfplumber` 는 MIT 다.

> **열린 항목**: 저장소 라이선스가 없다. 공개 저장소인데 라이선스가 없으면 남이 읽을 수는
> 있어도 쓸 수는 없다. 사람이 정할 일이다.
