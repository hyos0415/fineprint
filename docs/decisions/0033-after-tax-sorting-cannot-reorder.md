# 0033 · 세후 정렬은 세전 정렬과 순서가 같다 — 뒤집으려면 상품별 과세 유형이 필요하다

> 날짜: 2026-08-31 · 상태: 유효

로드맵 E7(옛 이름 E9) · 앞선 결정 `0032`(세율은 조문에 핀) · `0030`(선호 가중치는 세후 %p) ·
`problem.md` §4(세금이 순위를 뒤집는다) · §9(없는 데이터) · 이슈 없음(직접 커밋)

**사전등록이 없다.** 측정하려던 것이 **구조적으로 0** 이라 잴 것이 남지 않았다.
아래 Evidence 가 왜 0 인지를 코드와 실측으로 적는다.

## Decision

**"세후 정렬이 세전 정렬과 순위를 얼마나 바꾸나" 를 측정하지 않고 닫는다.**
지금 데이터로는 **한 번의 실행에서 모든 상품이 같은 세율을 받으므로 순서가 보존된다.**

따라서 셋을 확정한다.

```
D1  E7 을 "측정할 것이 없음" 으로 닫는다. 세후 정렬은 그대로 유지한다
    — 순위는 안 바뀌지만 **화면에 나가는 숫자**는 세후여야 한다
D2  problem.md §4 의 "세금이 순위를 뒤집는다" 예시(A 3.85 일반과세 vs B 3.50 비과세)에
    **"지금 데이터로는 재현 불가능하다"** 를 명시한다. 지우지 않는다 — 틀린 예시가
    아니라 **아직 데이터가 없는 예시**다
D3  E7 의 선행 조건을 **E3(세율표 검증) → A2(상품설명서 코퍼스)** 로 고친다.
    E3 는 닫혔는데도 E7 이 못 열린 이유가 그것이다
```

## Evidence

### 세율이 상품 속성이 아니라 사용자 상태다 — 코드 한 줄

```python
# src/analysis/calculate.py:818
exempt = bool(state.get("_비과세종합저축_대상"))
# :771  def after_tax(rate, tax, exempt=False):
# :773      r = 0.0 if exempt else tax["일반과세"]["합계"]
```

`state` 는 **사용자가 답한 것**이다. 상품 행(`row`)에서 오는 값이 아니므로 한 번의
실행에서 모든 상품이 같은 `r` 을 받는다. 그러면

```
net = gross × (1 − r),  r 이 전 상품 공통 상수
→ gross 의 순서와 net 의 순서가 같다 (r < 1 이므로 단조 증가 변환)
```

**세후 정렬이 세전 정렬을 재배열할 수 있는 자유도가 애초에 없다.**

### 실측 — 은행권·저축은행 × 비과세 켜고 끄고, 넷 다 순서가 같다

```
python src/analysis/calculate.py 20260826 (bank) · 20260825 (savingsbank) · 12개월
정렬 키: 세전 (-gross_hi, -gross_lo, name)  vs  세후 (-net_hi, -net_lo, name)
행 신원: (상품코드, 기관코드, 단리/복리, 적립방식, 상품명)   ← `0031`

  은행권      비과세=끔   79행    세율 집합 {0.154}   세전순 == 세후순
  은행권      비과세=켬   79행    세율 집합 {0.0}     세전순 == 세후순
  저축은행    비과세=끔  297행    세율 집합 {0.154}   세전순 == 세후순
  저축은행    비과세=켬  297행    세율 집합 {0.0}     세전순 == 세후순
```

**세율 집합의 크기가 1인 것이 핵심**이다 — 실행마다 원소가 하나다. 상품별로 다른
세율을 받는 행이 **0개**다.

### 그런데 `problem.md` §4 의 예시는 세율이 상품별로 다르다고 전제한다

```
A상품   세전 3.85%  →  세후 3.26%    일반과세
B상품   세전 3.50%  →  세후 3.50%    비과세 대상자
```

같은 사용자에게 A 는 과세, B 는 비과세로 나오는 상황이다. 그러려면 **"이 상품이
비과세종합저축으로 가입 가능한가"** 가 상품 속성으로 있어야 한다. 그 값이 없다.

```
금융감독원 '금융상품한눈에' API 가 주는 필드   상품명 · 기관 · 채널 · 우대조건 문구
                                          · 기간별 기본/최고금리 · 단리복리 · 적립방식
과세 유형                                   **없다**
```

`collection-list.md` 가 적어 둔 그대로다 — *"설명서에만 있는 것은 따로 있다 —
**세제 혜택(비과세종합저축 가능 여부)**·가입 제한 (…)"* (`collection-list.md:23`).
그래서 이 예시를 재현하는 데 필요한 선행은 E3 가 아니라 **A2(상품설명서 코퍼스)** 다.

### 세율이 상품별로 갈릴 수 있는 자리는 실재한다 — 다만 우리 데이터에 없다

```
조특법 §89의3   조합등예탁금 (신협·농협·수협·새마을금고)
                2026년 가입분 100분의 5 · 2027년 이후 100분의 9
config/tax-2026.json   "이 저장소 데이터에는 해당 상품이 없어 화면에 쓰이지 않는다"
```

취급 기관이 상호금융이라 `finlife` 의 은행·저축은행 목록에 안 들어온다. **세율 차이가
상품군 사이에 실재하는데 우리가 그 상품군을 안 가지고 있다** — 이것도 데이터 문제이고
계산 문제가 아니다.

### 그러면 세후 계산은 왜 남기나

순위에 영향이 없어도 **사용자가 보는 숫자**는 세후여야 한다. `3.85%` 와 `3.26%` 는
59bp 차이이고, 선호 가중치가 `영업점만 -0.50%p` 처럼 **세후 %p 단위**로 정의돼 있다
(`0030`). 세전으로 바꾸면 가중치의 단위가 깨진다. **정렬 효과가 0인 것과 표시가
필요한 것은 별개다.**

## Alternative

- **A. 상품별 과세 유형을 우리가 추정해 넣고 측정한다** — 상품명·기관으로 비과세
  취급 여부를 유추
- **B. 사용자 상태를 여러 개 돌려 "상태별 순위 차이" 로 재정의한다** — 비과세 켠
  사용자와 끈 사용자의 순위를 비교
- **C. 열어 두고 A2 를 기다린다** — 상태를 ⏸ 로 두고 닫지 않는다
- **D. E7 을 그냥 지운다** — 측정할 것이 없으니 로드맵에서 삭제
- **E. 세후 정렬을 세전 정렬로 되돌린다** — 어차피 순위가 같으니 단순하게

## Why rejected

- **A** — 이 저장소가 가장 강하게 막는 방향이다. 과세 유형은 가입 자격·한도·기관
  취급 여부가 걸린 값이고, 추정해서 넣으면 **`0032` 가 세율 자동 파싱을 금지한 것과
  같은 모양의 조용한 오류**가 된다. 게다가 그 추정치로 측정하면 재는 대상이 우리
  추정의 편향이 된다
- **B** — 같은 사용자가 두 상태를 동시에 가질 수 없다. **한 화면 안에서 순위를 뒤집는
  것**이 §4 의 주장이었고, 상태를 바꿔 두 화면을 비교하는 것은 다른 질문이다.
  질문을 답할 수 있는 모양으로 바꿔치기하는 것이라 `0018` 이 막는 도피에 가깝다
- **C** — ⏸ 로 두면 "언젠가 잴 것" 으로 남아 **왜 못 재는지가 기록에 없다.** 오늘
  확인한 것(세율 집합 크기 1 · 필요한 선행이 A2)은 A2 가 들어오든 안 들어오든 사실이다.
  닫고 적어 두는 쪽이 정보가 많다
- **D** — 지우면 **problem.md §4 의 예시가 근거 없이 남는다.** 그 예시를 읽는 사람이
  "이게 지금 되는 일" 이라고 믿게 된다. 닫는 것과 지우는 것은 다르다
- **E** — 위 Evidence 마지막 항목. 표시 숫자와 가중치 단위가 세후에 묶여 있다
  (`0030`). 순위 효과 0을 근거로 세전으로 돌리면 화면이 사용자가 못 받는 금리를
  말하게 된다 — `0017` 이 막은 자리와 방향이 같다

## 반증 조건

- **A2 코퍼스에서 상품별 과세 유형이 나오고, 그것을 넣었는데도 순위가 안 바뀌면** —
  §4 의 예시가 데이터 문제가 아니라 **주장 자체가 틀린 것**이다. 그러면 예시를 지우고
  "세금은 숫자만 바꾸고 순서는 안 바꾼다" 로 §4 를 고친다
- **한 실행에서 세율 집합의 크기가 2 이상이 되는데 이 결정이 그대로 남아 있으면** —
  구조가 바뀐 것을 문서가 못 따라간 것이다. 위 실측 스크립트(세율 집합 크기)를
  **회귀 검사로 승격**한다
- **3층(금융소득종합과세 · E4)을 만들었더니 상품별로 다른 세율이 붙으면** — 3층은
  사용자의 연 금융소득 총액이 기준이라 지금은 전 상품 공통이라고 본다. 상품별로
  갈리는 설계가 나오면 E7 을 **다시 연다**
- **세금우대 취급 상품군(상호금융)이 수집 범위에 들어오면** — 그 순간 세율이 상품별로
  갈린다. 지금 `fetch_finlife.py` 의 `GROUPS` 는 은행·저축은행 둘뿐이고
  (`topFinGrpNo` `020000`·`030300`) 조합등예탁금 취급 기관이 거기 없다.
  권역이 늘어나면 E7 을 다시 연다
