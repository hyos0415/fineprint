# 0022 · 배타 그룹을 못 믿으므로 범위로 낸다

2026-08-27 · 사전등록 [`../spec/prereg-06-matching-and-judgment.md`](../spec/prereg-06-matching-and-judgment.md) §2.3(1) ·
이슈 [#2](https://github.com/hyos0415/fineprint/issues/2)

## Decision

**`exclusive_group`을 믿을지 말지 고르지 않는다. 두 해석을 다 열어 범위로 낸다.**

```
lo = 그룹 최댓값   중복 적용 불가가 맞다면 (보수)
hi = 합산         중복 적용 가능하다면 (낙관). 공시 최고금리 상한에 걸린다
층 판정 = 공시 폭이 [lo, hi] 안에 들어오면 설명된 것으로 본다
사유    = `중복우대불명`
```

> 여러 우대조건이 함께 적용되는지 하나만 적용되는지 공시가 분명하지 않습니다.
> 함께 적용되지 않으면 실제 금리는 표시된 최대보다 낮습니다

**기준선은 바꾸지 않는다** — 은행권 79.7% · 저축은행 36.7% 그대로다(사람 결정).

## Evidence

### 공식이 틀린 게 아니라 라벨을 못 믿는다

층 판정은 배타 그룹을 무시하고 다 더했는데, 같은 파일의 `bonus_range()`와 공식
닫힘률(`compare_extractors.declared_llm`)은 그룹 최댓값을 썼다. **같은 항목이 두 값을
냈다.** 어느 쪽이 맞는지 재봤더니 **어느 쪽도 아니었다.**

```
배타 그룹이 붙은 행에서 공시 폭에 맞는 쪽
  은행권 93행    최댓값 35 · 합산 32 · 둘 다 틀림 26
  저축은행 46행   최댓값 18 · 합산 16 · 둘 다 틀림 12
```

`iM함께예금`은 `g1`에 `[0.1 × 5]`가 들어 있는데 공시 폭이 0.45라 **다섯 개가 다
더해져야** 맞는다. 중복 적용 불가가 아니라 **별개 조건 다섯을 한 그룹으로 묶은 것**이다.

논리로는 답이 정해져 있다 — 공시 최고금리는 조건을 다 채운 사람이 받는 값이고,
중복 적용 불가면 하나만 받으니 그룹 최댓값이 맞다. **논리가 맞는데 데이터가 반반이면
틀린 것은 공식이 아니라 라벨이다.**

### 실측 — 예측보다 효과가 작았다

| | 예측 (재기 전) | 실측 |
|---|---|---|
| 은행권 커버리지 | ≥ 85% | 82.3 → **84.8%** (미달) |
| 저축은행 커버리지 | ≥ 40% | 35.4 → **35.7%** (크게 미달) |
| **밴드 전용 행** | 메인의 20% 미만 | 은행권 **1.5%** · 저축은행 **0%** |

**예측을 유리하게 적었고 현실은 덜 유리했다.** 그대로 남긴다.

**밴드 전용 행이 거의 0인 것이 이 결정의 안전 근거다.** 완화 조치 1로 걸어 둔 지표다 —
두 점 규칙 어느 쪽으로도 설명 안 되는데 밴드로만 들어온 행이 많으면 판정이 느슨해진
것인데, 은행권 1건·저축은행 0건이다. **범위로 바꿔서 공짜로 얻은 커버리지가 없다.**

### 앞선 진단이 절반 틀렸다 — 정정한다

`0021`에서 v2 게이트를 넘길 때 *"저축은행 커버리지 하락이 내부 모순과 얽혀 있다"*를
근거의 하나로 댔다. **밴드로 고쳐도 35.7%로 옛 기준선 36.7% 아래다.** 넷 중 하나만
고쳐졌다.

```
WELCOME 아이사랑    excl=g1 이 제대로 붙어 있었다      → 밴드로 복구됨
웰뱅 워킹 적금       excl 이 아예 없다 (1+2+3+6=12%p) → 밴드 무관. v2 의 진짜 회귀
웰뱅 든든적금       하위 항목 상한을 상품 cap 으로 올림   → 밴드 무관. v2 의 진짜 회귀
KB일반정기적금       -0.10%p                        → 밴드 무관
```

**저축은행 하락의 대부분은 v2의 실제 회귀다.** `0021`의 그 근거는 절반만 맞았다.

## Alternative

| | 방법 | 왜 안 골랐나 |
|---|---|---|
| A | 층 판정도 합산으로 (지금까지) | 층 라벨과 표시 금리가 **다른 근거**를 쓴다. 내부 모순이 남는다 |
| B | 층 판정을 그룹 최댓값으로 | 커버리지가 은행권 69.6% · 저축은행 **18.5%**로 급락한다. 계산해줄 수 있는 저축은행 상품이 절반으로 준다 — `0018`이 막으려던 **도피 방향**이다 |
| D | 기준선을 실측값(84.8% · 35.7%)으로 다시 등록 | 저축은행은 **못 넘은 바를 낮추는 모양**이 된다. 사람 결정으로 유지했다 |

## Why rejected

B의 대가가 결정적이다. 라벨이 절반쯤 틀린 신호를 **믿는 쪽으로 강하게 해석**하면,
그룹이 가짜인 상품에 "근거 없음"을 잘못 붙인다. 저축은행에서 그게 상품 절반이다.

**A와 B 사이에서 고르는 것 자체가 함정이었다.** 라벨을 못 믿는데 둘 중 하나를 고르면
어느 쪽으로 고르든 절반은 틀린다. 이 프로젝트는 그럴 때 범위를 낸다 —
`0015`(임계) · `0016`(애매한 유형) · `0017`(최댓값 단독 표시 금지) · `0019`(조건불명)이
전부 같은 답을 했다. **이번이 넷째다.**

D를 뺀 이유는 사람 결정이다 — 바를 낮추는 대신 **넘을 방법을 아는 상태로 둔다.**
원인이 이미 특정돼 있다(`excl` 누락 · `cap` 오분류).

## 반증 조건

- **밴드 전용 행이 메인의 20%를 넘으면** — 판정이 느슨해진 것이다. 지금 1.5% · 0%다.
  월 갱신 뒤 이 값이 커지면 이 결정을 다시 본다
- **`중복우대불명`이 붙은 상품에서 사용자가 실제로 받은 금리가 lo 쪽에 몰리면** —
  배타 그룹 라벨이 사실은 맞다는 뜻이고, 그러면 B(그룹 최댓값)로 가야 한다.
  다만 이걸 관측하려면 사용자 실제 수령 금리가 필요하다 — **지금은 잴 수 없다**
- **`중복우대불명`이 너무 많은 상품에 붙으면** — 지금 은행권 메인 67개 중 16개(24%)다.
  절반을 넘으면 사유가 경고가 아니라 배경 소음이 된다
- **추출기가 `exclusive_group`을 아예 안 붙이기 시작하면** — 밴드가 사라져 A와 같아진다.
  월 갱신 때 그룹이 붙은 행 수를 같이 본다

## 뒤에 드러난 것 — 층 라벨이 이 결정을 안 따르고 있었다 (2026-08-28)

`prereg-09`의 화면 계약 전수 검사(A2)가 찾았다. **밴드를 만들었는데 층 라벨은 폭을
안 봤다** — 조건을 전부 답해 `unknown`이 0이 되면 밴드 폭이 1.69%p 남아 있어도
`확정`이 붙었다(`아이행복적금` 4.02~5.71%).

```
tier = "범위" if rng["unknown"] else "확정"          ← 고치기 전
tier = "범위" if (unknown 또는 폭 > 0) else "확정"     ← 고친 뒤
```

**이 결정의 내부 모순이 한 칸 더 남아 있었던 것이다.** 위 §Alternative가 지적한
*"층 라벨과 표시 금리가 다른 근거를 쓴다"* 가 정확히 그 자리다. 기준선은 예산 12개
확정이 은행권 58.2 → **55.2%** · 저축은행 83.0 → **80.2%** 로 내려갔고(폭 평균·커버리지
무변동), 재등록 사유는 `prereg-09` §7.1에 **고치기 전에** 적었다.
