# 0012 — 폴백 구조를 채택한다. 규칙 먼저, 못 닫은 것만 AI

> 날짜: 2026-08-26 · 상태: 유효 · 사전등록 `../spec/prereg-04-fallback.md`

## Decision

**추출은 폴백 구조로 한다.** 규칙 파서(v3)를 먼저 돌리고, 산수가 안 맞는 행만
제한 스키마 LLM에 보낸다.

```
1. A(규칙 v3) 실행
2. |A 합계 − 폭| <= 0.06  →  A 채택하고 끝
3. 아니면 B(제한 스키마 LLM) 실행
4. |B 합계 − 폭| <= 0.06  →  B 채택
5. 둘 다 실패 →  B 채택 + "계산불가" 라벨   (B 는 condition_type 을 갖고 있다)
```

**분모도 함께 고친다** — "우대조건 있는 행" + **"공시 최고금리 > 기본금리"**.
폭 0 행은 버리지 않고 `공시미반영` 층으로 별도 보고한다.

## Evidence

**사전등록을 실행 전에 커밋했다**(`b915431`). 은행권은 B를 안 돌린 상태였다.

| | 은행권 236행 (판정) | 저축은행 182행 (참고) |
|---|---:|---:|
| A 규칙 v3 | 75.8% | 63.2% |
| B 제한 스키마 | 71.2% | 71.4% |
| **폴백** | **83.9%** | **79.1%** |
| 폴백 − A | **+8.1%p** | +15.9%p |
| LLM 호출 비율 | **24.2%** | 36.8% |

**예측 83.8% 이상 → 실측 83.9%.** 0.1%p 차로 통과했다.

**부 지표가 전부 같은 방향이다.** 폴백이 주 지표만 올린 게 아니다.

| | A | B | 폴백 |
|---|---:|---:|---:|
| 진짜 과다 추출 (은행권) | 16 | 19 | **12** |
| 항목 0개 (은행권) | 6.4% | 4.2% | **1.7%** |
| 진짜 과다 추출 (저축은행) | 38 | 23 | **13** |

**넘침도 줄고 항목 0개도 줄고 호출 비용도 24%다.** §6이 "폴백이 넘침을 늘리면 실패"로
걸어둔 조건과 반대 방향이다.

## Alternative

- **(가) B 단독** — LLM 하나만 쓴다
- **(나) A 단독** — 규칙만 쓴다. 비용 0
- **(다) 폴백 5단계를 A 채택으로** — 둘 다 실패 시 규칙 결과를 남긴다

## Why rejected

- **(가) B 단독**: 두 권역 모두 폴백보다 낮다(71.2% / 71.4% vs 83.9% / 79.1%).
  그리고 **은행권에서는 A보다도 4.6%p 낮다** — 규칙이 강한 곳에서 LLM 하나로 가면 손해다
- **(나) A 단독**: 폴백보다 은행권 8.1%p · 저축은행 15.9%p 낮다. 비용 차이는
  호출 24%에 $1 수준이라 이 격차를 정당화하지 못한다
- **(다) 실패 시 A 채택**: 닫힘률은 같지만 **A는 `condition_type`이 없다.**
  사용자별 금리 계산이 불가능해진다. 실패한 행도 추천 화면에는 올라가므로
  구조가 있는 쪽을 남긴다

## 예상과 달랐던 것 — 방향 차이는 권역이 아니라 추출기 특성이다

사전등록 §3에 "권역마다 실패 방향이 반대다"라고 적었다. **절반만 맞았다.**

```
넘침 / 모자람      A 규칙        B 제한스키마
은행권              16 / 41       19 / 49
저축은행             38 / 29       23 / 29
```

**A만 권역에 따라 방향이 바뀐다.** B는 두 권역 모두 모자람이 주다.

**B가 일관되게 모자라는 것은 설계 의도와 맞다** — 제한 스키마는 열거값에 없는 것을
버리므로 과다보다 과소로 기울고, 사용자 화면에서는 그게 안전한 방향이다.
`prereg-04` §3의 서술은 A에만 해당하는 것으로 정정한다.

## 규칙 버전 — 개발 집합과 홀드아웃에서 반대다

```
              은행권 (개발)              저축은행 (홀드아웃)
          A          폴백            A          폴백
v2      67.4%      77.1%          62.6%      80.2%
v3      75.8%      83.9%          63.2%      79.1%
차이     +8.4%p     +6.8%p         +0.6%p     −1.1%p
```

**v3는 개발 집합에서 폴백까지 올리고, 홀드아웃에서는 폴백을 내린다.**
규칙을 깎으면 v2가 실패해 B에게 넘겨 맞혔던 행을 v3가 "성공"으로 가로챈 뒤 틀리는
경우가 생긴다. 홀드아웃에서는 그 손실이 이득보다 크다.

**`0007`이 이슈 #6을 닫은 판단이 별개 근거로 뒷받침됐다** — 그때는 "홀드아웃에서
안 오른다"였고, 이번엔 "폴백에서는 오히려 내려간다"다.

## 반증 조건

- **다른 권역에서 폴백이 A와 5%p 이내면** → 폴백의 이득이 이 두 권역에 국한된 것이다.
  조건부 구조("규칙이 약한 곳에서만 폴백")를 검토해야 하고, 그러면 "어디가 약한가"를
  판별하는 문제가 새로 생긴다
- **B의 모자람이 넘침보다 적어지는 권역이 나오면** → "제한 스키마는 과소로 기운다"가
  틀린 것이다. 열거값 설계를 다시 봐야 한다
- **LLM 호출 비율이 40%를 넘는 권역이 나오면** → 규칙이 그 권역에서 너무 약하다는
  뜻이고, 비용 계산을 다시 해야 한다
- **폴백의 진짜 과다 추출이 A보다 많아지는 권역이 나오면** → 5단계(둘 다 실패 시 B 채택)가
  넘침을 만드는 것이다. A 채택으로 바꿔야 한다
- **McNemar 가 두 권역에서 반대 방향으로 유의하면** → 은행권 p=0.1524(A 우세 방향),
  저축은행 p=0.0315(B 우세). 지금은 은행권이 유의하지 않아 모순이 아니다.
  표본을 늘렸을 때 둘 다 유의해지면 "권역에 따라 우열이 뒤집힌다"는 뜻이고,
  단일 파이프라인으로는 안 된다
