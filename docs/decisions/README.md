# 결정 기록 (Decision Log)

> **문제 정의는 `../spec/problem.md`가 현재 유효하다** (2026-08-24 갱신).
> 아래 열린 결정 D1·D3·D4는 그 이전(조건 누락 중심) 기준으로 작성됐고, 각 이슈 본문
> 맨 위에 무엇이 바뀌었는지 적어두었다. D1·D4는 파일럿 결과 뒤에 정한다(`after-pilot`),
> D3은 파일럿 진행에 필요해 지금 열려 있다(`blocking`).

## 형식

모든 결정은 `0000-template.md`의 5항목으로 남긴다.

```
Decision · Evidence · Alternative · Why rejected · 반증 조건
```

파일명은 `NNNN-<주제-슬러그>.md` (`0001-`부터 순번). **결정 직후 커밋한다** —
결정이 언제 근거로 승격됐는지 추적할 수 없으면, 선행 프로젝트가 두 번 겪은
재현성 실패와 같은 모양이 된다.

### D1 / D4 참고 자료 (결정 시 근거)

**코퍼스 상한 — 실측**

```
은행 정기예금 전수                        38개  (total_count=38)
  우대조건(spcl_cnd) 있음                 32개
  조건 항목 2개 이상                      22개
  조건 항목 3개 이상                      18개
  "모두 충족"·"및"·"함께" 명시적 AND        6개   ← D1의 병목, D3가 필요한 이유
negative(오류 없는 claim) 재사용 가능       71건  (finance_verifier Pilot 46 + Test 25)
```

**D1 검정력 참고**: 구조 검사가 잡고 Verifier가 놓치는 건수가 **6건이면 유의**(p≈0.03,
쌍체 이항검정). 놓치는 비율을 감안하면 정답 20~25건에서 그 6건이 안정적으로 확보된다.
12건이면 효과가 거의 완벽할 때만 유의해진다.

**D4는 두 숫자를 쌍으로 정한다** — 재현율만 정하면 "정상 claim 과차단"을 놓친다.
3구간 판정 예시:

| 구간 | 조건 | 결정 |
|---|---|---|
| 충분 | 누락 잡음 ≥80% · 정상 오차단 ≤5% | 구조 불필요. 리포트 쓰고 종료 |
| 애매 | 잡음 50~80% 또는 오차단 5~15% | 놓친 **유형**을 분석해 결정 |
| 불충분 | 잡음 <50% 또는 오차단 >15% | 구조 필요. 다음 단계로 |

**세 번째 필수 조건**: 재현율과 함께 **조건 추출 성공률**을 반드시 같이 보고한다.
추출이 40% 실패하면 재현율 숫자 자체가 무의미하고, 그 실패가 오히려 "형식을 제한한
스키마가 필요하다"는 근거가 된다.

| 원 항목 | 처리 |
|---|---|
| Q1 `verify_metrics.py`/serialization 이관 여부 | **조정안 채택** — 코드가 아니라 "산출물과 계산 코드를 함께 커밋하고 지표 재현을 검증하는 패턴"을 자산으로 승격. 코드는 새 도메인에 맞게 새로 씀. Codex의 수용 기준("전 지표가 baseline과 완전 일치")을 이 프로젝트 eval harness의 완료 조건으로 사용 |
| Q2 handoff §2.1(정규화) 정정 여부 | v2 §2에 반영 — 아래 §초기 결정 참고 |
| Q3 KAG `docs/CONTEXT.md` 발견 1 정정 여부 | **원 저장소를 수정하지 않는다.** 그 문서는 선행 저장소의 진실 원본이므로 보존하고, 코드 사실과 충돌한다는 점만 인용 시 명시 |
