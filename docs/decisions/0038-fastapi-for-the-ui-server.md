# 0038 · UI 는 FastAPI + Jinja2 서버 렌더로 간다 — 의존성 정책의 예외 셋

> 날짜: 2026-08-31 · 상태: 유효

로드맵 F4-1 · 계획 [`ui-plan.md`](../spec/ui-plan.md) ·
앞선 결정 `0036`(리포트 객체와 렌더를 갈랐다) · `problem.md` §7(숫자 칸은 코드가 채운다) ·
`requirements.txt`(표준 라이브러리 기본 · 예외는 사유를 함께 적는다)

**사전등록이 없다.** 측정이 아니라 도구 선택이다.

## Decision

**UI 서버를 FastAPI + Uvicorn 으로 세운다.** `requirements.txt` 의
*"표준 라이브러리만 쓰는 것을 기본으로 한다"* 에 대한 **두 번째 예외**이고, 첫 번째
(`pdfplumber`)와 같은 형식으로 **사유를 파일에 함께 적는다.**

```
D1  FastAPI + Uvicorn 을 requirements.txt 에 예외로 적는다 — 사유 세 줄과 함께
D2  **계산은 파이썬 그대로 재사용한다.** 서버는 evaluate()·report.build() 를 부르는
    얇은 껍데기다. JS 로 계산을 다시 쓰지 않는다 (`problem.md` §7)
D3  **Pydantic 모델을 뷰 모델 계약의 일부로 쓴다** — 화면 계약 assert 앞에 스키마
    검증을 한 겹 둔다. 다만 **assert 를 대체하지 않는다**(아래 반증 조건)

D4  **화면은 서버 렌더다 — Jinja2.** TypeScript·React 를 쓰지 않는다. 부분 갱신이
    필요한 자리는 `fetch` 20줄로 조각을 바꿔 끼운다 (2026-09-01 추가)

D5  따라서 `requirements.txt` 의 예외는 **셋**이다 — `fastapi` · `uvicorn` ·
    `jinja2`. 셋 다 사유를 함께 적는다
```

## Evidence

### 사람이 써 보고 싶다고 했다 — 그것을 그대로 적는다

> FAST API 를 해보고 싶었음

**이 저장소는 "근거 없음 — 판단" 을 그대로 적는 곳이다**(`0030` 의 가중치 표 다섯 중
셋이 그렇게 적혀 있다). 학습 목적은 정당한 사유이고, 숨기면 나중에 *"왜 FastAPI 를
썼나"* 에 없는 근거를 만들게 된다.

### 그리고 이 프로젝트에 실제로 붙는 이유가 하나 있다

F4-0 이 **뷰 모델을 정의하는 일**이다. Pydantic 모델이 그 계약의 일부를 타입에 박는다.

```
지금 (F1 까지)   화면 계약 A1~A13 이 **렌더된 문자열**을 본다
                 "세후" in screen · C.CAVEAT[code] in screen
F4-1 뒤          뷰 모델 → Pydantic 검증 → 렌더 → 문자열 검사
                 net_lo/net_hi 가 둘 다 있어야 한다거나 사유 코드에 문장이 딸려
                 있어야 한다는 것이 **API 경계에서** 잡힌다
```

**OpenAPI 문서가 자동으로 나오는 것도 이 저장소가 좋아하는 방향이다** — 계약이 코드
주석이 아니라 문서에 남는다.

### 라이선스를 확인했다 — `pdfplumber` 를 고를 때 걸렀던 문제가 없다

```
FastAPI    MIT
Pydantic   MIT
Starlette  BSD-3-Clause
Uvicorn    BSD-3-Clause
```

`requirements.txt` 가 *"PyMuPDF 는 AGPL 이라 공개 저장소에 올리면 결합저작물 문제가
생긴다"* 로 기각한 그 검사를 통과한다. 넷 다 permissive 다.

### 프런트를 서버 렌더로 두는 이유 — 계약이 파이썬에 남는다 (2026-09-01)

```
서버 렌더    HTML 이 서버에서 나온다 → check_render(vm, html) 이 CLI·리포트에
            붙은 것과 **같은 모양**으로 붙는다 (`0039` 의 렌더 겹)
클라이언트 렌더  렌더가 브라우저에 있다 → 계약 검사를 파이썬에서 못 돌린다.
            헤드리스 브라우저나 JS 테스트 러너가 들어와 **결국 스택이 는다**
```

**TS·React 를 뺀 이유는 사람이 말했다** — *"기술 스택 하나 더 늘리는 게 될 것
같아서 꺼려졌다"*. 그리고 계산기를 TS 로 옮기는 안은 더 무겁다 — `calculate.py`
1,231줄 + `prefs.py` 269줄을 옮기는 것으로 끝나지 않고, **그 계산기를 검사하는
것들이 전부 파이썬이다**(화면 계약 439줄 · 리포트 241줄 · 뷰 모델 150줄 · 질문
예산 189줄 · `prereg` 측정 스크립트). 계산기만 옮기면 **검사기가 검사하는 계산기와
사용자가 쓰는 계산기가 달라진다** — `problem.md` §7 이 막는 "두 답" 이다.

### Jinja2 는 학습이 아니라 실체로 정당화된다

**FastAPI 와 근거가 다르다.** FastAPI 는 학습 동기가 있었고 그것을 그대로 적었다.
Jinja2 는 사람이 *"이미 써 본 것 같다"* 고 했으므로 학습 동기가 약하다. 그래서
**실체로만 정당화한다.**

```
① HTML 분량이 **예측된다** — 화면 셋이 전부 반복 구조이고, 같은 내용의 텍스트
   렌더러가 이미 report.render 241줄 · render_final_screen 50줄이다.
   태그가 붙으면 몇 배가 된다. f-string 안의 HTML 은 그 규모에서 못 읽는다
② 자동 이스케이프 — 데이터에 `&` 와 `"` 가 **실제로 있다**(상품명·기관명·공시
   문구 1,831개 중 3개). 손으로 거는 이스케이프는 **빠뜨리는 게 기본값**이다
③ 표준 경로 — FastAPI 공식 문서가 쓰는 방식이라 막혔을 때 답이 나온다
④ 라이선스 BSD-3-Clause — `pdfplumber` 때 PyMuPDF 를 AGPL 로 기각한 검사를 통과한다
```

**한 번 틀린 판단을 적어 둔다.** 처음에는 *"표준 라이브러리로 시작하고 HTML 조립이
300줄을 넘으면 그때 Jinja2 로 간다"* 는 전환 조건을 제안했다. 사람이 기각했다 —
*"안 되는 걸 관찰하고 진자로 확장하는 것보다, 현재 HTML 분량이 어떻게 될지 아는데
안 쓰는 것도 이상하다"*. **맞는 지적이다.** "관찰한 뒤에 바꾼다" 는 이 저장소가
**모르는 것**에 쓰는 규율이다(지표·실험·부품의 필요성). 아는 것에 쓰면 규율이
아니라 낭비다 — **예측 가능한 고통을 일부러 겪는 것**이 된다.

## Alternative

- **A. `http.server`(표준 라이브러리)** — 의존성 0개. 엔드포인트가 둘뿐이라 충분하다
- **B. Flask** — FastAPI 보다 얇고 의존성이 적다
- **C. 서버를 안 세우고 정적 HTML + JSON 으로 굴린다** — 배포도 실행도 없다
- **D. Django** — 관리 화면·ORM 이 딸려 온다

프런트 쪽 (2026-09-01)

- **E. React + TypeScript 프런트** — 뷰 모델이 이미 JSON 계약이라 붙이기는 쉽다
- **F. 계산기까지 TS 로 이식하고 서버를 없앤다** — 정적 호스팅으로 끝난다
- **G. 표준 라이브러리만 — f-string + `html.escape()` · `string.Template`** — 의존성 0
- **H. 클라이언트 렌더 (정적 HTML + `fetch` 로 JSON 받아 JS 가 그린다)**
- **I. 파이썬 HTML DSL (htpy·dominate)** — 자동 이스케이프 · 의존성 1

## Why rejected

- **A** — **기각 사유가 "부족해서" 가 아니다.** 실제로 충분하다(로컬 단일 사용자 ·
  엔드포인트 둘). 스키마 검증과 자동 문서가 없어서 위 Evidence 두 번째 항목을 못 얻고,
  **사람이 FastAPI 를 써 보고 싶다고 했다.** 의존성 4개(전이 포함)를 그 대가로 받는다.
  **의존성을 늘리는 쪽을 골랐다는 것을 여기 명시해 둔다**
- **B** — 스키마 검증·자동 문서가 없어 A 와 같은 자리다. "얇다" 는 이점이 A 보다 작다
  (A 는 의존성이 0이다)
- **C** — **계산기를 JS 로 다시 써야 한다.** 질문에 답할 때마다 범위·순위가 갱신되는데
  (`0017`·`0025`) 그것을 브라우저에서 하려면 `evaluate()` 를 옮겨야 한다. 계산이 두
  군데 있으면 **두 답이 나온다** — `problem.md` §7 이 막는 자리이고, 이 저장소가
  `0035` 에서 *"문구는 한 곳에만 둔다"* 로 같은 실패를 이미 겪었다
- **D** — 쓰지 않을 것이 대부분 딸려 온다. ORM 이 필요 없다 — 데이터는 스냅샷 파일이고
  답은 저장하지 않을 수 있다(`ui-plan.md` §정할 것)
- **E** — 스택이 하나 는다. 사람이 그것을 이유로 기각했고, 서버 렌더로도 필요한
  것(부분 갱신)이 `fetch` 20줄로 된다
- **F** — **경량화가 아니라 이중 유지비다.** 위 Evidence — 계산기를 검사하는 것들이
  전부 파이썬이라 계산기만 옮기면 두 답이 나온다. 정당한 형태는 파이썬을 원천으로
  두고 **골든 테스트로 동치를 강제**하는 것인데, 그건 구현 하나를 영원히 더 유지하는
  일이다. 그리고 **A2·G(검색·리랭커)가 오면 파이썬 서버가 다시 필요하다**
- **G** — 의존성 0 은 매력적이고 지금 렌더러와 방식이 같다. 그런데 위 ①·② 때문에
  **예측 가능한 고통을 사서 지는 것**이 된다
- **H** — 렌더가 브라우저로 가면 계약 검사를 파이썬에서 못 돌린다. `0039` 가 만든
  렌더 겹이 무력해지고, 대신 JS 테스트 도구가 들어온다
- **I** — 잘 동작하지만 덜 알려져 있다. 막혔을 때 답을 찾기 어렵고 다른 데 쓸 일이
  적다. 같은 의존성 하나면 표준 경로(Jinja2)를 쓴다

## 반증 조건

- **Pydantic 검증이 통과하는데 화면 계약이 깨지면** — 스키마는 "칸이 있나" 까지만 본다.
  *"폭이 남았는데 단일 숫자로 렌더했나"* 는 스키마가 못 잡는다. **그래서 A1~A13 을
  없애지 않는다.** 스키마가 assert 를 대체할 수 있다고 판단하는 순간 이 결정이 틀린 것이다
- **의존성 때문에 실행이 번거로워지면** — 지금은 `python src/...` 하나로 다 돌아간다.
  `uvicorn` 실행·포트·재시작이 끼면서 **CLI 경로가 방치되기 시작하면** 그것이 신호다.
  CLI 는 계약 검사의 대상이라 죽으면 안 된다
- **배포를 하게 되는데 FastAPI 때문에 형태가 제약되면** — `0037` 이 *"공개는 깃 단위에서
  끝날 가능성이 높다"* 를 전제로 선다. 정적 호스팅으로 가야 하는 상황이 오면 C 안이
  다시 살아나고, 그때는 **계산을 어디서 하나**가 다시 쟁점이다
- **`requirements.txt` 에 사유를 안 적으면** — 예외를 만든 것이 아니라 정책을 깬 것이다.
  F4-1 의 완료 조건에 넣는다. **예외는 셋이고 셋 다 사유가 필요하다**
- **Jinja2 템플릿에 로직이 쌓이면** — 템플릿은 그리는 곳이고 판정하는 곳이 아니다.
  `{% if %}` 가 화면 계약을 판정하기 시작하면(예: 폭이 있으면 범위로, 아니면 단일
  숫자로) **계약이 뷰 모델 밖으로 새는 것**이다. 그때는 그 판정을 `view.build()` 로
  올린다 — 템플릿은 이미 정해진 문자열을 꽂기만 해야 한다
