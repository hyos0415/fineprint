# 0059 · R2 2차 결과 — 조건 답은 관문을 넘고 거래 은행 목록이 걸렸다 · 다음은 사람 결정

**이 문서는 결정이 아니라 결정의 재료다.** `prereg-28` §4 가 이 결과 조합을 예상하지 못해 조항이 서로 부딪히므로, 여기서 정하지 않고
후보를 적어 사람에게 넘긴다.

## 무엇이 나왔나 (`prereg-28` §6)

```
조건 답 (급여이체 예 · 카드실적 아니오 …)   TEST 30문장 화면 오답 0 · 빠뜨림 11% → 관문 통과. 단 원출력 오답 6 을 전부 후보 집합 필터가 걸렀다
좁힌 R2 (스코프 + 거래 은행 목록)          스코프 96% · 거래 은행 28/30 → 통과. **틀린 은행 2건** → 불통과 —
                                        "우리은행 거래 없고 신한만 써" 에서 우리를 거래로 · "웰컴저축은행 적금" 에서 웰컴을 거래로
```

**1차와 뒤집혔다.** 1차는 "값은 거래 은행에 있고 조건 답은 위험하다" 였는데, 2차에서 조건 답은 0 이 나오고 거래 은행이 틀렸다.
표본이 작아(30) 둘 다 확정이 아니다 — 0 과 1 을 가르지 못하는 크기다.

## 왜 거래 은행이 더 위험한가

거래 은행 목록은 F6 이 그것으로 **다른 답을 유도**한다(안 고른 은행은 첫거래 예 · 주거래 아니오). 목록에 은행 하나가 잘못 들어가면 그 은행에
대한 조건 여럿이 한 번에 틀린다. 조건 답 하나가 틀리는 것보다 파급이 크다. 그래서 (다)를 0 으로 둔 것이 맞았고, 2건이 난 것은 무겁다.

## 후보

```
A  **전부 제안 · 전부 확인** — 스코프 · 거래 은행 · 조건 답 셋을 다 "제안" 으로 확인 화면(A19)에 올린다. 어떤 값도 확인 없이 들어가지 않는다
   (`0057` D2 그대로). 거래 은행 제안은 목록 질문의 체크박스를 **미리 체크한 상태**로 보이고 사용자가 고친다.
   → (다)의 2건은 사용자가 체크를 풀어야 하는 자리가 된다. 확인이 형식이 되면 위험(`0057` 반증 조건 2)
B  **조건 답만 제안 · 스코프와 거래 은행은 폼** — 관문을 넘은 것만 넣는다. 그러나 값의 대부분이 거래 은행에 있어(1차 P6 · 2차 합 280 의 대부분)
   얻는 것이 작다
C  **거래 은행만 빼고 A** — 스코프(96%)와 조건 답(0)은 제안하고, 거래 은행은 지금처럼 사용자가 목록에서 직접 고른다.
   틀렸을 때 파급이 큰 하나를 빼는 것이라 안전 쪽으로 기운다. 값은 조건 답 쪽만 남는다
D  **R2 닫기** — `0058` 그대로. 표본 30 으로는 어느 쪽도 확정이 아니라는 이유
```

**Claude 의 추천은 A 다.** 이유 둘 — ① 확인 단계가 있으면 제안의 오답은 "사용자가 고칠 자리" 가 되고 그것이 `0057` 이 처음부터 그린 모양이다
② 어느 값도 자동으로 들어가지 않으므로 (다)의 2건은 화면에서 눌러서 빠진다. 다만 반증 조건을 하나 먼저 적어야 한다 — **사람 세션에서
제안을 그대로 다 통과시키는 일이 반복되면**(고친 것 0) 확인이 형식이 된 것이고, 그때는 거래 은행 제안을 빈 상태로 되돌린다(C 로).

## 표본에 대해 정직하게

30문장에서 화면 오답 0 은 "오답률이 0" 이 아니라 "3% 아래일 가능성이 높다" 정도다. DEV 40문장에서는 3 이었다. 화면에 붙인 뒤 **사람 세션**이
진짜 표본이고, 그때 확인 화면에서 사용자가 무엇을 고쳤는지가 다음 측정값이다(고친 항목 = 모델의 오답).
