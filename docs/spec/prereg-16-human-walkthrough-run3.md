# prereg-16 · 사람이 바뀐 화면을 완주한다 (3런) — 목록 질문과 바뀐 낱말을 본다

> 작성 2026-09-03 (**재기 전**) · 선행 `prereg-14`(1런·2런) · 화면을 바꾼 결정 `0045`(F6 ·
> 조건은 기관별로 갈린다) · `0046`(F5 · 화면 낱말을 사람 말로) · 로드맵 F7 의 선행

**이 문서는 재기 전에 쓴다.** `prereg-14` 의 예측 P1~P8 은 **옛 화면**에 대한 것이다.
그 사이에 화면이 두 번 크게 바뀌었다 — 질문이 기관별로 갈리고 맨 앞에 **목록 질문**이
생겼고(F6), 내부 이름·층·사유 코드가 전부 **사람 말**로 바뀌었다(F5). 옛 예측을 그대로
쓰거나, 돌리고 나서 기준을 고르면 이 저장소의 규율이 깨진다(`CLAUDE.md` 3번).

## 왜 재나 — 두 결정이 남긴 물음이 셋이다

```
1. 목록 질문이 답할 수 있는 형태인가        `0045` 가 맨 앞에 "거래해 본 은행을 골라 주세요"
                                        를 두었다. 은행권 17곳 · 저축은행 30곳을 이름으로
                                        줄 세운다. 사람이 자기 은행을 찾는가
2. 목록에 "모름" 을 고르는가               `0045` 반증 조건 2. 그 경로는 유도가 안 걸려
                                        예산 12개 시점 폭 평균 0.432(기준선 0.185) ·
                                        확정률 20.9% 다. **얼마나 흔한지를 모른다** —
                                        이 답이 로드맵 F7 의 착수 조건이다
3. 바뀐 낱말이 조건의 뜻을 바꿨나           `0046` 반증 조건 3. 가장 위험한 칸은
                                        `기타`(→ "그 밖의 조건") 와
                                        `판정불가_불특정`(→ "누가 받는지 미리 알 수 없는 우대")
```

2런에서 남은 것도 같이 본다 — 공시에 뜻이 없는 낱말(탑스 · 소중한 날)이 기관별 판정
뒤에도 질문으로 나오는가.

## §1 무엇을 세나 — 정의 (재기 전 확정)

`prereg-14` §6 의 정의를 그대로 잇는다. 새로 더한 것은 **L(목록)** 과 **W(낱말)** 다.

```
M1a  맥락이 없어서 고를 수 없었다 — 어느 은행/상품의 문구인지 몰라서
M1b  용어를 몰라서 고를 수 없었다 — 은행은 알지만 그 은행 고유 용어를 모른다
M1c  짐작으로 눌렀다 — 고를 수는 있었지만 근거가 없었다
     안 센다 — 의도적으로 "모름" 을 고른 것. 시스템이 지원하는 답이다 (`0024` P5)

M3   같은 걸 두 번 묻는 것처럼 느낀 자리 수
M4   완주했나 (예/아니오) · 걸린 시간 (초). **완주율은 지표가 아니다**(`0026` D2)

M2   뜻을 모르는 낱말 수 — **부 지표. 근거로 쓰지 않는다.**
     `prereg-14` §7 이 확인했다: 만든 사람이 표본이라 자기가 지은 낱말을 안 센다.
     세더라도 기록만 한다

L1   목록 질문에서 자기 은행을 **이름으로 찾았나** (예/아니오 · 못 찾은 은행 이름)
L2   목록 질문의 답 — 고른 은행 수 / "거래 없음"(하나도 안 고르고 제출) / "모름"
     (웹의 **모르겠습니다** 버튼 · CLI 의 `[모름]`). 웹은 두 답이 다른 동작이라
     (`screen.html` 안내문) 사람이 그 차이를 읽었는지도 적는다
L3   목록 질문에 걸린 시간 (초) — 나머지 질문 평균과 따로 적는다

W1   라벨만 보고 답한 뒤 **문구를 읽고 답을 바꾼** 자리 수
     라벨이 뜻을 바꿨는지 보는 유일한 관측 방법이다. 답을 바꿨다 = 라벨과 문구가
     다른 말을 했다
W2   `기타` · `판정불가_불특정` 라벨이 화면에 나온 횟수 (W1 과 대조한다)
```

## §2 표본 — 어떻게 도나

```
사람      1명 (만든 사람). `prereg-14` §4 의 약점이 그대로다 — M1·M2 는 **하한**으로 읽는다
세션      2회. 둘 다 12개월 · 찾는 범위 없음 · 선호 없음 · 정렬 최대순
  (가) 은행권      ← prereg-14 의 (가)와 같은 경로. 2런(39개 · 완주)과 **앞뒤 비교**가 된다
  (나) 저축은행    ← 목록이 30곳이다. 이름으로 아는 곳이 적어 "모름" 이 나올 가능성이
                    가장 큰 경로. 3런에서 처음 도는 권역이다
기록      질문마다 (순서, 조건 유형 라벨, 은행, 고른 답, M1 해당 여부, W1 해당 여부)
         목록 질문은 L1~L3 을 따로
어디서    웹 — python -m uvicorn src.web.app:app --host 127.0.0.1 --port 8000
         세션 로그 data/pilot/ask_session_*.json
```

**(나)를 넣는 이유** — F7 의 착수 조건은 *"모름 경로가 얼마나 흔한가"* 다. 은행권만
돌면 사람이 자기 은행을 아니까 "모름" 이 나올 리가 없고, 그러면 F7 물음에 답이 안 된다.
저축은행은 그 반대 극단이다. 두 극단을 다 봐야 하한과 상한이 나온다.

**6개월 경로는 안 돈다** — `prereg-14` (나)가 계단식(M3)을 보려고 6개월을 골랐는데,
`0023` 뒤로 계단식은 3문구뿐이고 이번 물음(목록·낱말)과 무관하다.

## §3 예측 — 재기 전에 적는다

```
P1  (가) L1 = 예 · L2 = 은행 1곳 이상 · "모름" 아님
    근거 — 자기가 거래하는 은행은 이름으로 안다. 0045 반증 조건 1(공시 원문 이름)은
    F5 가 법인 형태를 떼서 닫았다 (농협은행주식회사 → 농협은행)

P2  (나) L2 = **"거래 없음"** 이다 — "모름" 이 아니다
    근거 — 저축은행 계좌가 없는 사람은 없다는 것을 안다. "모름" 은 거래 여부 자체를
    모를 때의 답이고, 그 상태는 드물다고 본다. **이게 틀리면 F7 이 바로 열린다**
    위험 — 웹에서 "거래 없음" 은 **아무것도 안 고르고 제출**하는 것이라, 사람이 그걸
    답으로 인식하지 못하고 **모르겠습니다** 를 누를 수 있다. 그러면 P2 는 틀리지만
    원인은 F7(질문 순서)이 아니라 **화면 형태**다. L2 기록에 "왜 그 버튼을 눌렀나"
    한 줄을 같이 받아 둘을 가른다

P3  (가) 질문 수가 **10~20개** 안이다 (목록 질문 포함)
    근거 — prereg-15 P5 실측. 거래 0·1·2·3곳이 10·15·16·20개였다. 어느 은행이냐에
    따라 ±2 흔들린다

P4  (가) M1a = 0 — 2런에서 0이 됐고 F6 이 질문 문장에 은행 이름을 넣었다

P5  (가) M1b ≤ 1 — 2런의 2건(탑스=제주은행 · 소중한 날=국민은행)은 이제 **그 은행을
    골랐을 때만** 질문으로 나온다. 안 고르면 유도로 "아니오" 가 되어 묻지 않는다.
    사람의 거래 은행에 제주은행이 없다고 보고 1 이하로 쓴다. 국민은행이 있으면 1 이다

P6  M3 = 0 — 12개월에는 계단식 문구가 없고, 첫거래·주거래가 배타라 한쪽만 묻는다(0045)

P7  W1 = 0 — 라벨 아래 공시 문구가 그대로 붙어 있어 대조가 된다.
    **1건이라도 나오면** 0046 반증 조건 3 이 발동한다 → 라벨을 빼고 문구만 보여주는
    쪽으로 돌린다

P8  M4 = 완주 · (가) 180초 이하
    근거 — 8/31 재측정이 7개에 44초였다. 20개면 130초 안쪽이고 목록 질문에 시간이
    더 든다 (L3 로 따로 잰다)

P9  (나) 질문 수가 (가)보다 **적다** — "거래 없음" 이면 은행 상대 조건이 전부 유도된다.
    prereg-15 §6 이 저축은행 9~15개라 했다
```
