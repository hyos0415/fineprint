# 1부 · 조건 매칭 (이슈 #2)

## 1.1 애매함의 규모 — 실측

추출된 조건 항목 **1,051개**(은행권 711 · 저축은행 340) 기준.

| | 건수 | 비율 | 무엇이 문제인가 |
|---|---:|---:|---|
| **금액·횟수 임계가 붙어 있다** | **143** | **13.6%** | 되물어서 판정한다 (§1.3) |
| 사용자가 답할 수 없는 층 2 유형 | 131 | 12.5% | 실천·미션 66 · 무조건·특판 46 · 쿠폰·코드 19 |
| `기타`로 분류됨 | 40 | 3.8% | 어느 상태 변수에도 대응하지 않는다 |
| 부정 조건 (`must_not_have`) | 6 | 0.6% | 예상보다 적다 (§1.4) |

> **[정정 2026-08-26]** 처음 적은 270건(25.7%)은 **부풀려진 값이었다.** 정규식이
> `12개월` 같은 **가입기간 표기까지 임계로 오인**했다. 기간은 `applies_to_term` 이 이미
> 처리하므로 임계가 아니다.
>
> ```
> 느슨한 정규식        270  25.7%   ← 기간 표기 149건이 섞였다
> 엄격한 정규식        121  11.5%   ← 실제 임계
>    금액 (3천만원 등)   58   5.5%
>    횟수·인원 (6회 이상) 64   6.1%
> ```
>
> **A안의 대가가 절반 이하로 줄었다.** 11.5%만 범위로 빠진다.
>
> **[재정정 2026-08-26]** 11.5%도 **낮게 잡힌 값이었다.** 단위 목록에 `천만원`이 없어서
> `"5천만원 이상 가입"`을 임계로 세지 못했다. 단위를 고친 뒤 **143건(13.6%)**이다.
>
> 이 버그는 방향이 나쁘다 — **임계인 줄 모르면 사용자 답을 그대로 충족으로 세어
> 과대 진술이 된다.** 그리고 값을 읽을 때 `천만원`을 `만원`으로 읽으면 5천만원이
> 5만원이 되어 **1,000배 오차**가 난다. 그래서 검사 정규식과 파싱 정규식이 **같은 단위
> 목록**을 쓰게 묶었다(`calculate.py` 의 `THRESHOLD_MONEY` · `MONEY_VALUE`).

**임계값이 가장 큰 문제다.** 예시:

```
"6~12개월제(만기일시지급식) 5천만원 이상 가입"
"만기일 기준 전전월 마지막 영업일에 수익증권(펀드)을 3천만원 이상 보유 시"
"급여이체 실적(월 50만원 이상) 6개월 이상"
```

## 1.2 지금 구현된 규칙 — 사람 승인이 필요하다

`src/analysis/calculate.py`의 `condition_met()`에 이미 들어간 규칙이다.
**사전등록 없이 내가 정한 것이므로 여기서 명시하고 승인을 받는다.**

```python
층 2 중 "무조건_특판_이벤트"   →  항상 충족  (가입고객 모두에게 적용된다)
층 2 중 "판정불가_불특정"      →  판정 불가 (None)
polarity == "must_not_have"  →  사용자 상태를 반대로 읽는다
사용자가 답하지 않은 유형       →  판정 불가 (None)
판정 불가가 있으면            →  하나의 값이 아니라 범위를 낸다
```

**범위를 내는 것이 이 설계의 핵심이다.** 모르는 것을 추측하지 않는다.

## 1.3 정해야 할 것 — 임계값 처리 (270건, 25.7%)

**후보 넷.** 각각 무엇을 얻고 잃는지 적는다.

| | 방법 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A** | **임계가 붙은 조건은 "판정 불가"로 둔다** | 정직하다. 틀린 숫자를 안 낸다 | 25.7%가 범위로 빠져 추천이 흐려진다 |
| **B** | **임계를 추출해 사용자에게 금액·횟수를 묻는다** | 정확해진다 | 재추출 $1 + 입력 항목이 늘어난다 |
| **C** | 사용자가 "O"라고 하면 임계도 충족으로 본다 | 추천이 선명하다 | **과대 추정.** 이 프로젝트가 잡으려던 실패다 |
| **D** | 금액은 이미 묻는다(가입금액). 그것과 비교한다 | 일부는 정확해진다 | "펀드 보유액"처럼 안 묻는 항목은 여전히 모른다 |

**C는 배제한다.** 사용자가 "카드 씀"이라고 답했는데 조건이 "월 100만원 이상"이면
충족이 아닐 수 있고, 그걸 충족으로 계산하면 실제보다 높은 금리를 보여준다.
`problem.md` §1이 금지한 방향이다.

### 결정 — B를 채택했다. 수치가 필요하면 **되묻는다** (2026-08-26)

A(판정 불가로 두기)를 먼저 구현했고, 같은 날 **B로 옮겼다.** 사람 결정이다 —
*"급여이체 실적에 대한 수치가 필요한 경우 그냥 다시금 물어보게 하자."*

**재추출은 필요 없었다.** $1이 든다고 적었는데 **근거 문구에 숫자가 이미 있었다.**
임계 항목 143개 중 **132개(92.3%)**를 정규식으로 읽어낸다.

```
"급여이체 실적(월 50만원 이상) 6개월 이상"   →  (금액, 500,000, 최소)
"펀드를 3천만원 이상 보유 시"                →  (금액, 30,000,000, 최소)
"자동이체 6회 이상"                         →  (횟수, 6, 최소)
```

사용자 답은 **단위를 붙인 키**로 받는다. 유형만 O/X로 받으면 금액인지 횟수인지 몰라
엉뚱한 비교를 하게 된다.

```
--state 자동이체                         "자동이체 하십니까"      → 예
--state 자동이체_횟수=6                   "월 몇 회 하십니까"      → 6회
--state 잔액_평잔_가입금액_금액=5000만원     "평잔이 얼마입니까"      → 5천만원
```

**질문은 유형 하나에 하나다.** 상품마다 임계가 달라도 "월 몇 회 하십니까"는 한 번
물으면 되고, 비교는 상품별로 각자 한다. 계산기가 물어야 할 질문을 **답 하나가 상품
몇 개를 확정으로 옮기는지** 순으로 보여준다.

```
잔액_평잔_가입금액_금액   상품 6개   임계 30만원 · 50만원 · 2,000만원 · 5,000만원
카드실적_금액            상품 4개   임계 10만원 · 100만원
급여_연금이체_금액         상품 3개   임계 10만원 · 50만원
자동이체_횟수             상품 2개   임계 3회 · 6회
```

### 얼마나 확정이 늘어났나 — 실측

12개월 상품 기준이다. "답할 수 있는 것만"은 실천·미션과 쿠폰을 안 묻는 경우다(§1.5).

| | | A 확정 | A 범위 | **B 확정** | **B 범위** |
|---|---|---:|---:|---:|---:|
| 은행권 79개 | 전부 답함 | 51 | 13 | **64** | **0** |
| | 답할 수 있는 것만 | 40 | 24 | **51** | 13 |
| 저축은행 297개 | 전부 답함 | 86 | 23 | **105** | **4** |
| | 답할 수 있는 것만 | 82 | 27 | **100** | 9 |

**확정이 25% 늘고, 은행권은 범위가 0이 된다.** 남는 범위의 원인은 임계가 아니라
**답할 수 없는 유형**(실천·미션 등 §1.5)과 **계단식 우대**(§1.6)다 — 둘 다 다음 결정이다.

**폴백 83.9%는 그대로다.** 임계 처리는 추출이 아니라 판정 단계라서 닫힘률과 무관하다.

### 남긴 것 — A 경로는 코드에 그대로 있다

수치를 아직 안 물어봤으면 **A와 똑같이 동작한다**(판정 불가 → 범위). 사용자가 설문을
끝까지 안 채워도 시스템이 멈추지 않고, 그때 보여주는 값이 과대 진술이 아니다.

```
금액   \d[\d,]*(천만원|백만원|십만원|억원|만원|천원|억|원)
횟수   \d+(회|건|명|개|일|주차|좌)\s*(이상|이내|초과|미만|까지)
기간   제외 — applies_to_term 이 처리한다
방향   이상·초과·부터 → 최소 / 이내·미만·이하·까지 → 최대
```

### 부수 수정 — 금리 상한을 넣었다

A를 구현하다 **AI가 금액을 금리 칸에 넣은 사례 2건**을 발견했다.

```
"6~12개월제(만기일시지급식) 5천만원 이상 가입"
  → rate = 5000 · rate = 5000000     (은행권 711개 항목 중 2건 · 0.3%)
```

스키마에 금리 상한이 없어 통과했다. **한 항목이 20%p 를 넘으면 금리가 아니라고
본다**(`MAX_ITEM_RATE`). 관측된 정상 최댓값은 9.0%p("31일 저금 성공 시 연 9.0%")다.

이 2건은 이미 실패로 세고 있었으므로 **폴백 83.9% 판정에는 영향이 없다.**
표시 문자열만 `-5000000.10%p` → `-0.10%p` 로 정상화됐다.

## 1.4 부수 관측 — 부정 조건이 6건뿐이다

`must_not_have`가 1,051개 중 **6건(0.6%)**이다. 전부 같은 문구다.

```
"신규가입일 포함 14일 이내 타기관 공인인증서 미등록시 우대금리 적용해제"
```

**금융위원회 소비자 경보가 지목한 유형인데 데이터에는 거의 없다.**

> "A씨는 최고금리 10%를 보고 적금에 가입했으나 **가입 이전 6개월간 카드 사용실적이
> 있어** 우대금리를 적용받지 못했다" (2023-04-05)

`problem-v1-verifier.md` §2-(나)가 이 유형을 두 번째 타깃으로 삼았는데,
**우리 데이터(은행·저축은행 예적금)에는 사실상 없다.** 두 가지 가능성이 있다.

1. 그 사례가 다른 상품군(카드 연계 적금 등)의 것이다
2. B가 부정 조건을 `required`로 잘못 읽고 있다

**2번을 확인해야 한다** — `기타` 40건과 함께 사람이 표본 검토할 항목이다.

## 1.6 새로 열린 결정 — 계단식 우대 (11건, 1.0%)

되물어도 판정할 수 없는 조건이 **11건** 남는다. 하나의 조건에 임계가 여러 개이고
**금리도 단계별로 다르다.**

```
"자동이체 입금횟수 우대금리 : 최고 0.5%p - 5회이상 : 0.2%p, 10회이상 : 0.3%p, 15회이상 0.5%p"
"목표달성 축하 우대이율: 최고 연 1.0%p, 50만원 이하: 연 0.5%p, 50만원 초과: 연 1.0%p"
```

**추출기가 이걸 항목 하나로 접었다** — 스키마에 단계를 담을 자리가 없어서 가장 높은
금리만 남았다. 사용자가 "10회"라고 답하면 실제로는 0.3%p인데 우리가 아는 값은 0.5%p다.
**추측하면 과대 진술이므로 판정 불가로 남긴다.**

| | 방법 | 얻는 것 | 잃는 것 |
|---|---|---|---|
| **A** | 지금처럼 판정 불가 (범위) | 공짜. 과대 진술 없음 | 상품 4개가 범위에 남는다 |
| **B** | 스키마에 `tiers: [{임계, 금리}]` 를 넣고 재추출 | 정확해진다 | 재추출 $1 + 스키마 복잡도. **1.0%를 위해** |
| **C** | 계단식은 가장 낮은 단계 금리로 본다 | 공짜. 과소로 기운다 | 근거 없는 값을 확정으로 보여준다 |

**미정.** 규모가 1.0%라 B의 값어치가 의심스럽다 — `0013`(추출 개선 중단)과 같은 판단이
적용될 자리로 보인다. 다만 **이건 추출기가 정보를 버린 사례**라서 성격이 다르다.

## 1.5 층 2 유형을 어떻게 물을 것인가 (131건, 12.5%)

| 유형 | 건수 | 사용자에게 물을 수 있나 |

| `실천_미션_인증` | 66 | **애매하다.** "대중교통 이용하겠습니까"는 물을 수 있지만 "ESG 서약"은? |

### 결정 — 유형을 가리지 않고 되묻는다 (2026-08-26 · `decisions/0016`)

**"물을 수 있나"를 따지는 것 자체를 그만뒀다.** 문구 20개를 훑어 넷으로 나눠 봤더니,
못 묻는다고 판정할 이유가 없었다.

| 군 | 성격 | 건수 | 예 |
|---|---|---:|---|
| 1 | 가입할 때 클릭 한 번 | 25 (37.9%) | `"온실가스 줄이기 실천서약서 동의"` · `"통장미발급"` |
| 2 | 가입 후 계속 해야 한다 | 19 (28.8%) | `"대중교통 미션: 1년제 연 0.4%p"` · `"계약기간의 1/2이상 매월 로그인"` |
| 3 | 이미 갖고 있는지 묻는 사실 | 11 (16.7%) | `"손하나로인증 서비스 등록"` · `"자원봉사자, 헌혈자"` |
| 4 | **공시가 무엇을 하라는지 안 말한다** | 11 (16.7%) | `"ESG 실천 우대금리 1.00%"` · `"봉사활동 또는 상품홍보"` |

4군도 **문구를 그대로 보여주고 되묻는다.** 우리가 요약하면 사용자가 판단할 근거를
빼앗는다 — 사용자는 자기가 그 은행에서 ESG 우대를 받는지 알 수도 있다.

2군은 물어서 받은 답이 **사실이 아니라 약속**이므로, 충족으로 계산하되
`이행필요` 사유를 붙여 보여준다(§1.7).

**쿠폰 19건은 문구 6개가 전부 같은 질문이다** — `"금리우대 쿠폰이나 코드가 있습니까"`
하나로 끝난다(쿠폰·코드 17건, 추천인 2건).

## 1.7 못 채웠을 때 무엇을 보여주는가 (`decisions/0016`)

**조용히 빼지 않는다.** 판정하지 못한 조건이 있으면 사유를 문장으로 보여준다.

| 사유 | 보여줄 문장 | 되물어서 없앨 수 있나 |
|---|---|---|
| `미응답` | 답하지 않은 조건이 있습니다. 답하면 금리가 확정됩니다 | 그렇다 |
| `수치필요` | 금액·횟수를 답하면 금리가 확정됩니다 | 그렇다 (§1.3) |
| `모름` | 사용자가 모른다고 답한 조건이 있어 금리를 확정할 수 없습니다 | 물었고 답이 "모름"이다 |
| `이행필요` | 가입 후 계속 실천해야 받는 우대금리가 포함돼 있습니다. 중단하면 그만큼 낮아집니다 | 아니다 — 미래의 일이다 |
| `단계불명` | 충족 정도에 따라 금리가 달라지는 조건이 있는데 공시에 단계가 다 나와 있지 않습니다 | 아니다 (§1.6) |
| `추첨` | 추첨·랜덤으로 주는 우대금리가 포함돼 있어 실제 금리는 더 낮을 수 있습니다 | 아니다 — **지금 데이터에 0건** |

### 전부 되물었을 때 — 실측

```
                 확정   범위          되물은 뒤 남는 사유
은행권 79개         64      0          이행필요 46
저축은행 297개      105      4          이행필요 15 · 단계불명 4
```

**은행권은 범위가 사라진다.** 남는 것은 "약속을 지켜야 받는다"는 주의뿐이다.

### (1) 추천기판 회피 방지 제약 ★ 가장 중요

**검증기에서 배운 것**: `"UNSUPPORTED"`만 반환하는 상수 스텁이 1·2·3순위 지표를
전부 이겼다(`reference/finance-verifier-findings.md` §0.4).

**추천기에도 같은 구멍이 있다.**

```
계산 불가 상품을 많이 만들수록 "틀린 금리를 안 보여준다" 는 점에서 안전해 보인다
  → 극단으로 가면 전부 "근거 없음" 으로 표시하는 시스템이 가장 안전하다
  → 그게 스텁과 같은 모양이다
```

**제약식 후보**

```
후보 1   메인 층(확정+범위) 비율이 기준선 아래로 떨어지면 개선으로 인정하지 않는다
         지금 은행권 ?% · 저축은행 12개월 36.7%(109/297)

후보 2   "범위 폭"의 평균이 늘면 인정하지 않는다
         모르는 조건이 늘어 범위가 넓어지는 것을 벌점으로 준다

후보 3   둘 다 본다
```

**미정.** 후보 3이 안전해 보이나 지표가 둘로 늘어난다.

### (2) 추천 자체를 무엇으로 재는가

가중합 정렬은 자동으로 맞으므로, 실제 측정 대상은 **입력**이다.

| 측정 대상 | 지표 | 정답을 어떻게 만드나 |
|---|---|---|
| 실수령 금리 계산 | 사람이 확정한 정답과 일치율 | **사람 검수 필요** — 몇 건? |
| 계산 불가 식별 | 층 라벨 정확도 | 사람 검수 |
| 편의 속성 | `join_way` 파싱 정확도 | 결정론적 — 단위 테스트 |

**미정 — 사람이 검수할 표본 크기.** `0008`이 "층별 20~25문항"으로 정했는데
그건 검증기 기준이었다. 추천기에서는 **상품 × 사용자 상태 조합**이 단위다.

### (3) 민감도 — 설문 답이 흔들리면 순위가 흔들리나

`problem.md`가 "시스템은 계산만 책임진다"고 했다. **설문 답이 조금 달라질 때
1위가 크게 바뀌면 그 말이 껍데기가 된다.**

```
재는 방법   가중치를 ±10% 흔들었을 때 상위 3위 구성이 얼마나 바뀌나
임계 후보   상위 3위 중 2개 이상이 유지되어야 한다
```

**미정.**
