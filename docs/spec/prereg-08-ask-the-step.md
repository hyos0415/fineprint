# 사전 등록 08 — 계단식은 추출하지 않고 되묻는다

2026-08-27 작성 · **재기 전에 커밋한다** · 이슈 [#2](https://github.com/hyos0415/fineprint/issues/2)

앞선 기록: `prereg-07` §7(하락 원인 진단) · `decisions/0021`·`0022`(열린 문제) ·
`prereg-06` §1.6(계단식 열린 결정)

## 0. 사람이 정한 방향

**규칙을 더 좁히지 않는다. 재추출도 하지 않는다.**

`prereg-07` §7이 저축은행 커버리지 1.0%p 하락의 원인을 세 개로 좁혔고, 각각에 대한
후보 규칙까지 쟀다. 사람이 그걸 보고 정했다.

> 규칙 그만 좁혀도 될 것 같다. 저축은행 상품이기도 하고, 솔직히 저런 건 추출하기보다
> 질문을 해야 하는 게 맞는 부분이라고 본다.

그래서 다음 셋을 **하지 않는다.**

| 안 하는 것 | 효과였던 것 | 왜 버리나 |
|---|---|---|
| `적용해제` 규칙 | 저축은행 +4행 | 문구를 박는 방향이다. 규칙을 하나 더 좁힌다 |
| `cap` 규칙 | 저축은행 +1 · 은행권 **-1** | 효과가 권역마다 반대인데 cap 붙은 쌍의 3분의 1을 건드린다 |
| 배타 그룹 재추출 | 저축은행 +1행 | `0013`(추출 개선 중단)과 부딪친다 |

**대가를 분명히 적는다** — 저축은행 커버리지는 **35.7%에 머문다.** `0018`의 게이트
36.7%는 계속 불통과 상태다. 그것을 어떻게 다룰지는 이 사전등록의 범위가 아니다
(§5에 남긴다).

## 1. 그래서 무엇을 하는가 — 계단식을 질문으로 낸다

`0016`은 **"유형을 가리지 않고 되묻는다"**로 정했다. 그런데 계단식만 예외로 남아 있다.

```
question_for()   계단식이면 None 을 낸다 — "수치를 받아도 금리를 모른다"
condition_met()  계단식이면 None 을 낸다 — 판정 불가
사용자 화면       `단계불명` 사유만 붙고 **질문은 안 나간다**
```

계단식은 `parse_threshold()`가 `None`을 낼 때로 정의돼 있다. 즉 **근거 문구에 숫자가
둘 이상이면 계단식**이다. 그 정의를 실제 문구에 대 봤더니 **대부분이 계단식이 아니었다.**

### 1.1 실체 — 계단식 11문구 중 8문구는 정규식 구멍이었다

같은 파일에 임계를 읽는 정규식이 **둘**인데 서로 안 맞는다.

```
THRESHOLD_MONEY   "…(천만원|만원|…)(?:\s*(?:이상|이하|미만|초과|까지))?(?![가-힣])"
                  → "500만원이상" 의 `이상` 을 흡수한다.        임계가 있다고 본다
MONEY_VALUE       "…(천만원|만원|…)(?![가-힣])"
                  → 흡수하는 부분이 없다. `이` 가 한글이라 막힌다.  못 읽는다
```

`has_threshold()`는 앞을 쓰고 `parse_threshold()`는 뒤를 쓴다. 그래서 **"임계가 있는데
못 읽겠다" = 계단식**으로 잘못 흘러간다.

| | 계단식으로 분류된 문구 | 실은 단일 임계 | 진짜 계단·애매 |
|---|---|---|---|
| 은행권 | 7종 (12행) | **5종 (10행)** | 2종 (2행) |
| 저축은행 | 4종 (6행) | **1종 (2행)** | 3종 (4행) |

잘못 분류된 예다. 단계가 없다 — 임계가 하나뿐이다.

```
"해지원금 기준 500만원이상 : 최고0.2%p"
"신용(체크)카드사용실적300만원이상:최고 0.3%p"
"1년이상, 1천만원이상 0.20%p"                 (숫자 둘이지만 하나는 기간이다)
"가입기간12개월이상 계약금액 10억이상 0.10%p"
```

진짜 계단은 이것뿐이다.

```
"요구불평잔 : 0.2% -300만원이상 0.1%, 500만원이상 0.2%"
"신용(체크)카드결제실적 : 0.1% -전월결제금 300만원이상 0.05%, 500만원이상 0.1%"
"당 저축은행 APP 월1회 이상 로그인 기록 횟수에 따라 차등적용+2.0% (12회이상:2.0%)"
```

**`prereg-06` §1.6이 "11건 · 1.0%"라 적은 열린 결정의 실체는 3문구다.**

**이건 같은 종류의 세 번째 구멍이다.** 첫째는 `천만원` 단위 누락(`prereg-06` §1.1),
둘째는 `"1천만원이상"` 붙여쓰기 미탐 36건(`0019`), 셋째가 이것이다. 코드 주석이 둘째를
"같은 종류의 두 번째 구멍"이라 적어 뒀는데 **같은 파일 안의 짝 정규식은 안 고쳤다.**

## 2. 무엇을 바꾸는가

**정규식 하나를 짝에 맞춘다. 규칙을 추가하지 않는다.**

```
MONEY_VALUE 에 THRESHOLD_MONEY 와 같은 후행 흡수부를 넣는다
    (?:\s*(?:이상|이하|미만|초과|까지))?(?![가-힣])
```

그러면 저 8문구가 `단계불명`(되물어도 못 없앤다)에서 `수치필요`(되물으면 없어진다)로
옮겨간다. **질문이 나가기 시작한다.** 진짜 계단 3문구는 숫자가 둘 이상이므로 그대로
`단계불명`에 남는다 — `prereg-06` §1.6의 후보 A를 그 3문구에 대해 유지하는 것이다.

**계단식 자체를 추출로 풀지 않는다.** 스키마에 `tiers`를 넣는 후보 B는 기각한다 —
규모가 3문구고, 사람이 정한 방향이 그쪽이 아니다.

## 3. 예측 — 재기 전에 적는다

**이 수정은 확정률을 올리는 방향이다. 유리한 방향이라 사전등록이 더 중요하다.**

| | 지금 | 예측 |
|---|---|---|
| 은행권 `단계불명` 문구 | 7종 | **2종** (5종이 옮겨간다) |
| 저축은행 `단계불명` 문구 | 4종 | **3종** (1종이 옮겨간다) |
| 은행권 확정 (예산 12개) | 58.7% | **올라간다 · ≥ 60%** |
| 저축은행 확정 (예산 12개) | 81.7% | **올라가거나 같다 · ≥ 81.7%** |
| 은행권 폭 평균 | 0.170%p | **내려가거나 같다 · ≤ 0.170** |
| 저축은행 폭 평균 | 0.241%p | **내려가거나 같다 · ≤ 0.241** |
| 커버리지 | 84.8% · 35.7% | **안 변한다 — 층 판정은 사용자 상태와 무관하다** |

**커버리지가 조금이라도 변하면 예상 밖이다.** 그러면 "층 판정은 상태 무관"이라는
`0018`의 관측과 이 사전등록의 전제가 틀린 것이고, 그 사실을 먼저 적는다.

## 4. 회피 방지 — 통과 못 하면 채택하지 않는다

| 가드 | 기준 |
|---|---|
| 커버리지 | 은행권 84.8% · 저축은행 35.7% 에서 **한 행도 안 움직여야 한다** |
| 질문 예산 | 12개 고정. 우선순위 규칙(커버리지 내림차순 → 사전순)도 안 건드린다 |
| 옮겨간 문구 검수 | 옮겨간 문구 **6종 전부**를 사람이 눈으로 보고 진짜 단일 임계인지 확인한다 |
| 진짜 계단 | 3문구는 `단계불명`에 남아야 한다. 하나라도 옮겨가면 정규식이 과하게 먹은 것이다 |
| 방향 | 임계를 읽으면 사용자가 못 넘을 때 **미충족으로 확정**된다. 과대 진술이 줄어드는 방향이어야 한다 — 늘어나면 불통과 |

## 5. 이 사전등록이 정하지 않는 것 — 사람에게 남긴다

1. **저축은행 커버리지 게이트 불통과를 어떻게 다루는가.** 35.7%로 남는다.
   `0022` 대안 D(기준선을 실측값으로 재등록)가 다시 열린다 — 지난번에 "바를 낮추지 않고
   넘을 방법을 아는 상태로 둔다"로 유지했는데, **이제 넘지 않기로 정했다.** 같은 이유가
   더는 성립하지 않는다
2. **`prereg-07` §7이 찾은 세 원인을 기록으로만 남기는가.** 규칙은 안 만들지만
   `KB일반정기적금`이 같은 우대금리를 두 번 세는 것은 **사실로 남아 있다**
3. **저축은행 홀드아웃 자격.** `prereg-07` §7의 숫자를 이미 봤다. 이 사전등록은
   저축은행 데이터를 보고 고르는 것이 아니라 **정규식 짝 불일치를 고치는 것**이라
   홀드아웃을 태우지 않는다고 본다 — 그 판단이 맞는지도 사람이 확인할 것
