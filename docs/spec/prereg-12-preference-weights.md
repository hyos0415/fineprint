## 0. 무엇을 만드나

```
설문 문항       고정 선택지로 묻는다 — 5문항
고정 가중치 표   답 → **금리 %p 환산** 값. 추상 0~1 가중치가 아니다
--prefs 입력    안 주면 가중치 0개 = 지금 동작 그대로
세후 가중합 정렬  점수 = net_hi + 조정. **점수는 정렬에만 쓰고 금리 칸에 안 들어간다**
화면 A10·A11    가중치가 보이고 고칠 수 있다 · 가중치는 정렬만 바꾼다
```

`problem.md` §3 이 받겠다고 적어 둔 **두 입력 중 하나(내 선호)** 가 지금 통째로
비어 있다. 정렬은 `net_hi` 단순 내림차순이고(`0017`), 그래서 지금 만든 것은
"추천기" 가 아니라 **계산기 + 되묻기**다.

## 1. 무엇을 주장하지 않는가 — 이게 이 사전등록의 첫 항목인 이유

**"정렬이 좋아졌다" 를 잴 정답이 없다.** `problem.md` §4 는 *"정답은 취향이 아니라
계산이다"* 라고 적었는데, 그 문장이 성립하는 것은 **가중치가 주어진 뒤**다. 가중치가
주어지면 순서는 하나뿐이고 그건 검산할 수 있다. 그러나 **가중치 자체가 맞는지는
검산할 수 없다.** 가중치를 넣으면 순위가 바뀌는데, 그게 나아진 건지 확인할 방법이 없다.

그래서 이 사전등록은 다음을 **성과로 주장하지 않는다.**

1. **정렬 품질** — "가중치를 넣으니 더 좋은 상품이 위로 왔다" 를 주장하지 않는다.
   그걸 재려면 "이 사용자에게 어느 상품이 맞았나" 라는 정답 라벨이 필요한데 없다
2. **사용자 만족·선택률·클릭** — 데이터가 없다. 사람 세션은 지금까지 두 번이고
   둘 다 표본 1이다
3. **가중치 표의 숫자가 옳다는 것** — 다섯 문항 중 숫자에 근거가 붙는 것은 **둘뿐**이다
   (§2 의 Q3 하한 · Q4 눈금). 나머지는 **근거 없음 — 판단**이라고 표에 그대로 적는다
4. **순위가 많이 바뀌는 것이 좋다는 것** — M10 은 방향이 없는 지표다. 크면 "가중치가
   실제로 작동한다", 작으면 "이 기능은 없어도 된다" 는 뜻일 뿐이고, **둘 다 결과다**

`CLAUDE.md` 의 *"잴 수 없는 것을 성과로 주장하지 않는다"* 와 `design.md` §6 이
R4(리포트 서술)에 대해 이미 한 것과 같은 처리다. R4 를 "편의 기능" 이라고 적어 둔
그 자리에, 정렬 품질도 같이 적는다.

**대신 잴 수 있는 것 셋이 §7 의 M9·M10·M11 이다.**

## 2. 설문 문항과 고정 가중치 표 — 숫자의 근거를 문항마다 적는다

### 단위를 "금리 %p 환산" 으로 두는 이유

`problem.md` §3 의 예시는 *`"금리가 얼마나 중요한가?" 매우 그렇다 → 금리 가중치 0.8`*
이라는 **추상 0~1 가중치**다. 그 형태를 쓰지 않는다. 이유가 둘이다.

```
설명할 수 없다   0~1 가중치로 정렬하면 화면에 "왜 이 순서인지" 를 쓸 수가 없다.
                problem.md §3 은 "왜 이 순서인지가 같이 나온다" 를 약속했다
정규화가 후보에 종속   축을 0~1 로 정규화하려면 min·max 가 필요한데 그건 후보 집합에
                따라 변한다. 후보 4개짜리 스코프에서 확정 카운터가 죽은 것(`0029`)과
                **같은 실패 모양**이다
```

대신 **각 축을 "금리 몇 %p 와 맞바꾸겠는가" 로 묻는다.** 그러면 화면에
`영업점만 −0.50%p` 라고 그대로 적을 수 있다.

**금리 축은 따로 묻지 않는다.** 금리가 기준 단위(계수 1.0 고정)이고, 다른 축의
%p 환산값이 곧 "금리 대비 상대 중요도" 다. 금리를 또 물으면 같은 것을 두 번 묻는다.

### 표 — 답 다섯 개, 조정값 다섯 개

| 문항 | 답 | 조정 (%p) | 숫자의 근거 |
|---|---|---|---|
| **Q1** 가입할 때 영업점에 갈 수 있습니까? | 못 간다 | `영업점만` 상품을 **맨 아래로** | 사용자의 사실 진술이라 숫자가 필요 없다 |
| | 되도록 안 간다 | `영업점만` **−0.50** | **근거 없음 — 판단** |
| | 상관없다 | 0 | — |
| **Q2** 거래해 본 기관이 어디입니까? | (기관 이름들 · 없으면 비움) | — | Q3 와 짝이다 |
| **Q3** 거래해 본 적 없는 기관에 가입하는 것이 부담됩니까? | 많이 | Q2 **밖** 기관 **−3.00** | **실측 하한 2.67%p** — 아래 |
| | 조금 | −0.50 | **근거 없음 — 판단** |
| | 상관없다 | 0 | — |
| **Q4** 조건에 따라 금리가 크게 달라지는 상품이 부담됩니까? | 많이 | 폭 1%p 당 **−1.00** | **`--sort lo` 와 같아지는 값** — 아래 |
| | 조금 | −0.50 | **근거 없음 — 판단** (두 끝의 중간) |
| | 상관없다 | 0 | **`--sort hi` 와 같아지는 값** = 지금 기본 |
| **Q5** 가입 후에 계속 해야 하는 조건이 부담됩니까? | 많이 | 이행 조건 1개당 **−0.30** | **근거 없음 — 판단** |
| | 조금 | 1개당 −0.10 | **근거 없음 — 판단** |
| | 상관없다 | 0 | — |

**Q3 의 3.00%p 에는 실측 하한이 있다.** 2026-08-31 사람 세션에서 사용자가 스코프 밖
**+2.67%p** 를 보고도 후보에 넣지 않았다(`prereg-11` §M4 자기보고 · `0028` 반증 조건 1).

> 굳이 경남은행 상품에 대해서 가입을 해보고 싶다는 생각이 안 들었어. 금리 우대가 있긴
> 하지만, 주거래 은행도 아니고, 경남에 연고도 없고, 경남은행 실물을 본적도 없어서

**그 사용자에게 "처음 보는 기관" 페널티는 2.67%p 보다 크다.** 3.00 은 그 하한 바로
위 값이다. **표본 1 이다** — 관측 한 건에서 나온 하한이라고 표에 그대로 적는다.

**Q4 는 이 표에서 유일하게 눈금이 임의가 아닌 축이다.** 계수가 0 이면 `net_hi` 정렬
(= `0017` 이 채택한 기본), 1.0 이면 `net_lo` 정렬(= `0017` 이 남겨 둔 `--sort lo`) 과
**항등식으로 같다.**

```
점수 = net_hi − 1.0 × (net_hi − net_lo) = net_lo
```

**두 끝이 이미 결정된 값이라 이 축은 검산할 수 있다** — §5 의 예측 4번이 그것이다.

**빈 값은 추측하지 않는다.** `채널미상` 2건에는 Q1 조정을 넣지 않는다
(`channel_label` 이 이미 정한 것 · 이슈 #22).

### 기본값을 우리가 정하지 않는다 — `0024` P2 를 지키는 자리

**`--prefs` 를 안 주면 가중치는 0개다.** 그러면 조정이 전부 0 이고 정렬은 지금과
소수점까지 같다. 우리가 "보통 이 정도" 라고 채워 넣는 순간 `0024` P2(사용자가 말하지
않은 것을 추측하지 않는다) 위반이고, 화면에 그 사실이 안 보이면 `0019` 의 부산은행
사례와 같은 모양이 된다 — **사용자 입력 0개인데 시스템이 단정한 화면.**

**옮긴 결과는 화면에 보이고 고칠 수 있어야 한다** (`problem.md` §3 · 화면 계약 A10).
설문 문구 대신 %p 를 직접 적을 수 있게 한다.

```
--prefs 영업점=되도록안간다,거래기관=우리·농협,처음기관=많이,확실성=조금,이행=상관없음
--prefs 영업점=-0.8                      ← 표를 덮어쓴다
```

## 3. 정렬 — 점수는 금리 칸에 안 들어간다

```
조정 = − (Q1 계수 if 채널 == 영업점만)
       − (Q3 계수 if 기관이 Q2 목록 밖)
       − Q4 계수 × (net_hi − net_lo)
       − Q5 계수 × (met + unknown 중 ONGOING 유형 개수)

점수 = net_hi + 조정
정렬 = (맨아래여부, −점수, −net_hi, −net_lo, 이름)
```

**기준을 `net_hi` 로 두는 것은 `0017` 을 그대로 따르는 것이다** — "조건을 다 채웠을 때
얼마인가" 로 줄을 세우고 답을 받을수록 깎인다. Q4 계수가 그 기준선을 `net_lo` 쪽으로
연속적으로 옮긴다.

**점수는 절대 금리 칸에 들어가지 않는다.** 화면의 금리는 계속 `net_lo~net_hi` 이고,
조정은 별도 칸(`조정 −0.80%p`)으로 나간다. 점수를 금리처럼 보여주면 **공시에 없는
숫자를 사용자에게 보여주는 것**이고, 그건 이 프로젝트가 잡으려던 실패다
(`problem.md` §5 · 화면 계약 A5).

### 선호로 상품을 목록에서 빼지 않는다 — `problem.md` §3 에서 갈라지는 자리

`problem.md` §3 은 *`"비대면 가입이 필요한가?" 필수다 → 영업점 필수 상품 제외`*
라고 적어 놨다. **제외하지 않는다. 맨 아래로 내리고 이유를 적는다.**

```
제외하면      "선호로 뺀 상품 중 최고 금리" 를 보여주는 장치를 A7 과 똑같이 하나 더
             만들어야 한다. 안 만들면 0017(좋은 상품이 묻힌다)·0028 A7(좁히는 대가를
             보여준다)이 막은 실패를 선호에서 되살린다
내리면        장치가 필요 없다. 상품은 화면에 남아 있고 왜 아래에 있는지가 그 줄에 적힌다
```

`problem.md` §3 의 그 문장은 `0017`·`0028`·A7 이 나오기 **전에** 쓰였다.
문서를 같이 고친다 (§8 아님 — 이건 이 작업의 산출물이다).

## 4. 새 화면 계약 A10 · A11

```
A10  --prefs 가 걸린 화면에는 **옮긴 가중치 전부**가 %p 로 보여야 하고,
     고치는 방법이 같이 적혀 있어야 한다
A11  --prefs 를 걸어도 각 상품의 net_lo · net_hi · tier · caveats 가
     안 걸었을 때와 **완전히 같아야 한다** — 가중치는 정렬만 바꾼다
```

**A11 이 이 작업의 핵심 방어선이다.** 가중치가 판정(층·범위·사유)에 새어 들어가면
사용자의 취향이 "이 상품의 금리가 얼마인가" 라는 사실을 바꾸는 것이고, 그 순간
`problem.md` §4 의 *"틀릴 수 없는 것 / 틀릴 수 있는 것"* 구분이 무너진다.

A1~A9 는 `prereg-09`(A1~A6) · `0028`(A7) · `0029`(A8) · 이슈 #22(A9) 에 있다.

## 8. 이 사전등록이 정하지 않는 것

1. **가중치 표의 숫자가 옳은지** — 잴 방법이 없다(§1-3). 다섯 중 셋은 판단이라고
