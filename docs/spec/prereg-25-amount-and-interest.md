# prereg-25 · 가입 금액 → 예상 이자 → 2,000만원 게이트(E4 첫 조각) — 금액은 표시만 바꾼다

> 작성 2026-09-04 (**고치기 전**) · 이슈 [#69](https://github.com/hyos0415/fineprint/issues/69) ·
> 근거 `design.md` §세금 계산(3층 · "선을 넘을 때만 묻는다" · "최종 세액은 내지 않는다") · `config/tax-2026.json`
> `금융소득종합과세.기준금액_원` · `problem.md` §7(숫자 칸은 코드가 채운다) · 로드맵 §E E4 · §D D1

## §1 없으면 어떻게 되나

흐름도(`design.md` §1)에 *"2,000만원 선을 넘나? → 사용자에게 묻는다"* 가 있는데 코드에 없다. 그리고 그 앞 단계인
**가입 금액 입력이 없다** — 로드맵 D1 이 ✅ 라고 적었지만 `0028` S1 이 축으로 적었을 뿐 CLI·웹 어디에도 받는 자리가
없다(코드 grep 0건). 금액이 없으면 사용자는 "몇 % 인지" 는 알아도 **"얼마 받는지"** 는 스스로 계산해야 하고,
종합과세 선에 걸리는지는 알 길이 없다.

## §2 무엇을 만드나

- **0단계 금액 둘(선택)** — 예금은 예치 금액, 적금은 월 납입액(원). CLI(`calculate.py --deposit · --monthly`) ·
  웹 폼 · `_carry` · 이어하기 코드에 실린다. **`state` 에 넣지 않는다** — 조건 답이 아니라 검색 축이다(`0028`)
- **예상 이자(원)** — 상품마다 세전·세후 이자를 기간·적립방식·단리/복리로 계산한다(`calculate.interest`).
  세전 = 금리 범위(`gross_lo`~`gross_hi`)로, 세후 = 그 세율로. 반올림은 원 단위. **금리는 다시 계산하지 않는다** —
  `evaluate()` 가 낸 값 위의 산수다
  ```
  단리   예금  P × r × n/12                 적금(정액)  m × r × n(n+1)/24
  복리   예금  P × ((1 + r/12)^n − 1)       적금(정액)  Σ_{k=1..n} m × ((1 + r/12)^k − 1)
  ```
  **가정 셋을 적는다** — ① 복리는 **월복리**로 본다(공시에 복리 주기가 없다) ② 자유적립식은 월 납입액을 매달 같이
  넣는 것으로 본다 ③ 이자는 만기에 한 번 받는 것으로 본다(만기일시지급 · 이자소득 귀속은 지급일이라 종합과세
  비교는 만기 해 한 해의 금액으로 한다). 세 가정을 화면에 한 줄로 적는다
- **3층 게이트** — 세전 이자 **최대**가 기준(2,000만원)을 넘으면 그 상품에 *"이 상품 이자만으로 종합과세 기준을
  넘습니다 — 세후는 다른 소득에 따라 더 낮아질 수 있습니다"*, 기준의 **절반** 이상이면 *"경계에 가깝습니다 — 다른
  이자·배당이 있으면 넘을 수 있습니다"*, 아니면 아무 말 없음. **절반은 근거 없음 — 판단**이다. 최종 세액은 내지
  않는다. **기존 금융소득을 묻는 질문(HITL)은 이 조각에 없다** — P2 가 그 질문이 실제로 필요한지를 먼저 본다
- **화면 계약 A18** — 원 단위 숫자가 화면(리포트 텍스트 · 웹)에 있으면 같은 블록에 **세전·세후 라벨**과 **가정 한 줄**이
  있어야 한다. 금액이 없으면 원 단위 숫자가 화면에 없어야 한다
- **하지 않는 것** — `잔액_평잔_가입금액` 문구를 금액으로 자동 판정하지 않는다. 15문구를 읽어 보니 "이 상품 가입금액"
  (SC 5천만원 · 광주 1천만원 · 경남 20백만원 · 푸른·안양 10억 · 웰컴 총불입금)과 "다른 계좌 잔액·평잔"(아이엠 총수신 평잔 ·
  제주 출금계좌 평잔 · 웰컴 입출금 평잔)이 섞여 있고 그 분류는 추측이다(`0016`). 사람이 문구를 보고 답한다(`0027`)

## §3 예측 — 고치기 전에 적는다

기준 출력을 받아 뒀다 — `calculate.py --report 3` 두 권역(금액 없음) · 빈 상태 뷰 모델 JSON(`prereg-21` 때 것 ·
`0052` 뒤 갱신).

```
P1  표시만       금액을 줘도 products 의 net_lo·net_hi·tier·caveats·순서가 같다 (뷰 모델 JSON 동일 · 리포트에 `이자` 만 늘어남)
P2  게이트       현실적 금액(예금 5천만 · 적금 월 100만 · 12개월)에서 두 권역 모두 **넘음 0 · 경계 근처 0** —
                즉 HITL 질문은 지금 데이터의 어떤 사용자에게도 뜨지 않는다. 5억이면 넘음 상품 = gross_hi ≥ 4.0% 인 예금 수
P3  계약         A1~A17 그대로 통과 · A18 통과 (금액 있을 때 원 숫자 옆에 세전·세후·가정 · 없을 때 원 숫자 0)
P4  이어하기      코드에 금액 둘이 실리고 붙여 넣으면 같은 화면 (HTML 동일) · 크기 증가 100B 미만
P5  한 벌        CLI 리포트(`calculate --report`)와 웹 리포트의 이자 숫자가 같다 (같은 `report.build`)
P6  무금액 회귀   금액 없이 돌린 `--report 3` 출력이 기준과 같다 (두 권역) · `--auto 예` CLI 화면 동일
```

## §4 판정 조항

```
P1 이 틀리면   금액이 계산에 샌 것이다. 되돌리고 어디서 새는지 찾는다 (A11 이 선호에 대해 지키는 것과 같은 선)
P2 가 틀리면   (걸리는 상품이 있으면) 어느 상품·얼마인지 적는다. HITL 질문의 설계가 다음 이슈로 열린다
P3 이 틀리면   A18 이 잡은 것은 렌더러 누락 — 고친다. 다른 코드면 이 변경과 무관한 회귀다
P4 가 틀리면   RESUME_KEYS 에 안 넣은 것이다. 넣는다
P5 가 틀리면   두 렌더러가 다른 산수를 한 것이다 — `report.build` 한 곳으로 모은다
P6 이 틀리면   기본값 경로를 건드렸다. 되돌린다
```

## §5 결과 (2026-09-04 · 고친 뒤)

**여섯 예측이 맞았고 P2 의 뒷문장 하나가 부정확했다.**

```
P1  맞음   금액을 줘도 뷰 모델 JSON 이 같다 (products·questions·notices 전부) · 리포트에 `이자` 칸만 늘어남
P2  맞음   예금 5천만 · 적금 월 100만 · 12개월 — 은행권·저축은행 모두 **넘음 0 · 경계 근처 0**.
           → HITL 질문(기존 금융소득)은 지금 데이터의 현실적 사용자에게 뜨지 않는다. 만들지 않은 것이 맞았다
    부정확  "5억이면 넘음 = gross_hi ≥ 4.0% 인 예금 수" 는 **단리 기준**으로 쓴 것이다. 저축은행 5억에서 넘음 12 인데
           단리 4% 이상 예금 행은 5 다 — 복리 상품이 3.93% 부터 실효 4% 를 넘는다. 실효 연 4% 이상으로 세면 12 = 12.
           예측을 적을 때 복리를 빠뜨렸다. 은행권 5억은 넘음 0 · 경계 근처 25
P3  맞음   A1~A17 그대로 · A18 두 권역·두 정렬 통과 (리포트 텍스트 · 웹 둘 다)
P4  맞음   이어하기 코드에 금액 둘이 실리고 붙여 넣으면 HTML 동일 · 우리 적금 빈 상태 코드 189 B
P5  맞음   1위(카카오뱅크 우리아이적금 · 월 100만) 세전 195,000~455,000원 · 세후 164,970~384,930원 — CLI 텍스트와 웹에 같은
           문자열. A18 자체가 두 렌더러에서 리포트 숫자를 대조하므로 이 예측은 계약으로 굳었다
P6  맞음   금액 없는 `--report 3` 두 권역 출력 동일 · `--auto 예` CLI 화면 동일
```

**A18 의 실제 검사 모양** — §2 는 "원 단위 숫자가 있으면" 이라고 적었는데 공시 문구 자체에 `1천만원이상` 같은
원이 있어 그대로 쓰면 오탐이다. 검사는 **`예상 이자` 블록**을 본다 — 금액이 있으면 리포트마다 세전·세후 원 숫자
(`calculate.won()` 표기)와 가정 문장이 화면 글자에 있어야 하고, 금액이 없으면 `예상 이자` 가 없어야 한다.

**잘못된 금액**(`오천만`)은 400 과 문장으로 떨어진다 — 읽는 규칙은 CLI 와 같은 `parse_amount()` 다.

결정은 [`0055`](../decisions/0055-amount-changes-only-the-display.md).
