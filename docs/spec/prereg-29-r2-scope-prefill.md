# prereg-29 · R2 스코프 미리 채움 — 자연어 한 문장으로 0단계 폼의 다섯 칸을 채우고, 사용자가 고쳐서 낸다

> 작성 2026-09-09 (**측정·구현 전**) · 이슈 [#73](https://github.com/hyos0415/fineprint/issues/73) · 결정 [`0060`](../decisions/0060-r2-scope-only.md) D2·D3·D6 ·
> 앞선 실험 `prereg-27`(1차) · `prereg-28`(2차·3차) · 원안 `0042`

## §1 무엇을 만드나 — 한 문단

0단계 폼에 **"내 상황" 상자(선택)** 를 둔다. 사용자가 *"우리은행 적금 1년, 매달 30만원"* 처럼 적고 "칸 채우기" 를 누르면
서버가 **로컬 모델**(llama.cpp · Qwen3.5-4B)에 그 문장을 한 번 보내고, 돌아온 값으로 **권역 · 은행 좁히기 · 예금/적금 · 기간 · 금액**
다섯 칸을 채운 채 같은 폼을 다시 그린다. 사용자는 채워진 칸을 보고 고친 뒤 "목록 보기" 를 누른다 — 그 제출은 지금과 같은 `/screen` 이다.

모델이 하는 일은 여기까지다. **조건 답은 채우지 않고**(`0060` D1) **거래 은행 목록도 채우지 않는다**(D3). 문장은 응답을 만든 뒤 버린다(`0042` D3).

## §2 정한 것 — 구현 전에 적는다

```
호출     v5(은행 역할 스키마) **한 번**. START-HERE 메모는 "v3 스코프 + v5 은행" 두 번(12초)이었으나, v5 한 번에 스코프 네 칸과
        "보고싶음" 은행이 다 나온다(4초). 단 v5 단독의 스코프 정확도는 TEST2 에서 재지 않았다 — §3 P0 으로 먼저 잰다.
        P0 이 틀리면 hybrid(두 번)로 간다. answers 는 스키마에 남기되 **읽지 않는다**(스키마를 바꾸면 측정한 판이 아니다)
채우는 칸  권역(group) · 은행 좁히기(company · 공시 이름 · 쉼표) · 예금/적금(kinds) · 기간(term) · 금액(예금 예치 · 적금 월 납입)
        은행은 v5 의 "보고싶음" 역할만. "거래함"·"거래없음" 은 어디에도 쓰지 않는다
빈 칸만   사용자가 이미 적어 둔 칸은 덮지 않는다. 모델은 **비어 있는 칸만** 채운다 — 사람이 적은 값이 모델 값보다 앞선다
표시     채운 칸마다 "문장에서 채움 · 확인하세요" 표시를 붙인다. hidden 이 아니라 **보이는 칸**에 들어간다(A19)
원문     응답 HTML 에 문장을 되돌려 넣지 않는다. 상자는 비운 채로 다시 그리고 "문장은 서버에 남지 않았습니다" 한 줄
빈 상자   상자가 비어 있으면 모델을 **부르지 않는다**(호출 0) — 폼을 그대로 다시 그린다
서빙 없음  모델 서버가 없거나 30초 안에 답이 없으면 "지금은 문장으로 채울 수 없습니다 — 직접 골라 주세요" 한 줄. 폼은 그대로 동작
기간     모델이 낸 기간이 메뉴(6·12·24·36)에 없으면 그 값을 메뉴에 더해 보인다 — 조용히 12 로 바꾸지 않는다
금액     모델이 낸 원 단위 정수를 그대로 칸에 넣는다. "5천" 같은 단위 없는 문장은 §5 반증 조건이다
```

## §3 예측 — 재기 전에 적는다

```
P0  v5 단독   TEST2(30문장 · `r2_sample3.py`)에서 v5 한 번 호출의 스코프 다섯 칸 합계 ≥ 88% — hybrid 가 90% 였고 스코프 필드는 같은
             프롬프트 문장에서 나온다. **틀리면 hybrid 로 간다(§4).** 한 번만 잰다 · 라벨·프롬프트는 안 고친다
P1  회귀 0    상자를 비우고 제출하면 화면(HTML)이 지금과 **바이트 동일**하다 — `/screen` 은 손대지 않는다. 화면 계약 A1~A18 은 그대로 통과
P2  A19      미리 채운 값은 전부 **보이는 칸**(input value · select selected)에 있고, hidden 에는 없다. 응답 HTML 에 문장이 없다.
             상자가 비었을 때 모델 호출은 0
P3  서빙 없음  llama-server 를 내린 채 "칸 채우기" 를 누르면 한 줄 안내와 함께 폼이 그대로 나온다(500 아님). 그 폼으로 "목록 보기" 가 된다
P4  지연     Qwen3.5-4B · 문장 하나 중앙값 ≤ 6초 (v5 DEV 4.2초 · 프롬프트가 폼 요청에 그대로 실린다)
P5  사람 세션  사람이 자기 문장으로 4런. 채워진 칸 중 사람이 **고친 칸 ≤ 20%**. 이 숫자가 `0060` 반증 조건 1 의 값이다
```

## §4 판정 조항

```
P0 이 틀리면   v5 단독은 쓰지 않고 hybrid(v3 스코프 + v5 은행 · 두 번 호출)로 구현한다. §2 의 "호출" 줄을 고치고 사유를 §6 에 적는다
P1 이 틀리면   `/screen` 을 건드린 것이다 — 되돌린다. 미리 채움은 `/prefill` 하나에만 산다
P2 가 틀리면   화면 계약 위반이다. 검사기가 잡아야 하고 잡지 못하면 검사기부터 고친다
P3 이 틀리면   서빙이 필수가 된 것이다 — 폼은 서빙 없이 동작해야 한다(`0060` D6 "상자를 비우면 지금과 같다")
P4 가 틀리면   대기 표시 한 줄로는 부족하다. 8초를 넘으면 상자를 폼 아래로 내리고 "느릴 수 있다" 를 적는다. 그래도 뺄 이유는 아니다
P5 가 틀리면   `0060` 반증 조건 1 발동 — 상자를 뺀다. 코드는 남긴다
금액 오독      "5천" 을 5,000원으로 채우는 것이 사람 세션에서 나오면 금액 두 칸은 미리 채우지 않는다(`0060` 반증 조건 4)
```

## §5 반증 조건 (`0060` 에서 옮겨 적음)

- 사람 세션에서 고친 칸 20% 초과 → 상자를 뺀다
- 단위 없는 금액 오독이 화면에 뜨면 → 금액 칸은 비운다
- "은행도 말로 넣고 싶다" 가 반복되면 → D3(거래 은행)을 **제안 + 확인**으로 붙이는 실험을 새 사전등록으로 연다

**구현하며 본 것 (합성 문장 · 사람 세션이 아니다)**
- *"우리은행 적금 1년, 매달 30만원"* → 권역·상품군·기간·월 납입은 채웠고 **은행 칸은 비었다**(모델이 우리은행에 "보고싶음" 을 안 붙였다).
  은행 칸이 가장 약하다는 TEST2 관측(22/30)과 같다. 틀려도 좁히기만 안 된 것이고 사용자가 적으면 된다
- *"예금 5천"* → 예금 금액 **5,000,000**(500만원). 사람은 5천만원으로 읽을 자리다. `0060` 반증 조건 4 의 모양이 합성 문장에서 나왔다 —
  조항대로 **사람 세션에서 나오면** 금액 칸을 비운다. 지금은 표시("문장에서 채움 — 확인하세요")가 붙은 보이는 칸이라 두고, 4런에서 본다
- *"저축은행 예금 18개월 3천만원"* → 권역 저축은행 · 기간 메뉴에 18개월이 더해져 선택됨 · 3천만원. 사용자가 이미 적은 은행 칸("농협")은 덮지 않았다
