## 0. 파일럿이 답하는 질문 하나

> **AI가 "이 조건이면 이 상품에서 얼마를 받는다"고 답할 때, 실제로 틀리는가?**

**개선을 재는 게 아니다.** 실패가 실재하는지만 본다. 실패가 없으면 이 태스크는 성립하지
않으므로 거기서 닫는다(§5).

주의할 구분 — 파일럿은 **답변을 생성하는 모델**의 실패를 관측한다. 검증기 성능을 재는
것은 본 실험이고, 파일럿이 통과한 뒤에 한다.

## 1. 시나리오 (problem.md §5의 A)

```
질문: "저는 [상태]입니다. [상품명]에 1천만원을 12개월 맡기면 연 몇 %를 받나요?"
      + 그 상품의 공시 원문 전문(우대조건 · 기본금리 · 기간별 금리)
답변: 모델이 생성
정답: 공시로 계산한 값 (§4 규칙)
```

두 상품 비교(시나리오 B)는 파일럿에 넣지 않는다. 단일 상품에서 실패가 없으면 비교에서도
볼 것이 없다.

## 2. 표본 — 30문항, 상품 30개 (결정론적 선정)

**층을 먼저 정한다.** 12개월 만기 상품 96건을 "공시된 최고금리가 명시된 우대조건 합계로
설명되는가"로 나눈다. 이 분류가 정답 유형을 결정하기 때문이다(§4).

| 층 | 뜻 | 전체 | 파일럿 |
|---|---|---:|---:|
| **닫힘** | 항목별 금리가 명시돼 있고, 그 합계(상한 적용)가 최고금리 − 기본금리와 오차 0.06%p 이내로 일치 | **40건** | **15문항** |
| **안닫힘** | 위 등식이 성립하지 않는다 — 항목 금리가 아예 없거나(예: 마이키즈 적금 3%→7%, "입금실적에 따라 우대"), 합계가 폭과 맞지 않는다(J정기예금 2.00%→3.80%인데 명시 우대는 0.5%p) | **36건** | **10문항** |
| **조건없음** | 우대조건이 없다 (금리 항목 0개이고 기본금리 = 최고금리) | **20건** | **5문항** |

세는 규칙은 §2.1, 구현은 `src/analysis/finlife_rules.py`.

### 2.1 층 분류 규칙 (v1) — 보정 사유 포함

층 분류의 목적은 하나다. **사용자 상태로부터 정확한 금리를 계산할 수 있는가.**
초판 규칙은 그것을 재지 못했다(항목별 금리가 없어도 "최고우대금리" 헤더 하나만 있으면
닫힘으로 판정했다). 구현은 `src/analysis/finlife_rules.py` 한 곳에 둔다.

| | 규칙 | 고치는 문제 |
|---|---|---|
| **A** | 우대금리 항목이 **0개**일 때 — 폭(최고−기본)이 0이면 `조건없음`, 폭이 있으면 `안닫힘`. 리터럴 목록은 **데이터에서 확인된 5개만** 쓴다 | `마이키즈 적금`(3%→7%인데 "입금실적에 따라 우대"만 적힘)이 닫힘으로 잘못 분류됐다 |
| **B** | "최대/최고 우대금리" 줄은 항목이 아니라 **상한**으로만 쓴다 | 헤더 값이 폭과 같아서 **우연히** 산수가 맞아 보이는 상품이 많았다 |
| **C** | `각 연0.10%p` 형태는 **앞에 나열된 금리 없는 항목 수 × 그 금리** | `iM함께예금`은 4×0.10+0.05=0.45=폭으로 정확히 닫히는데 안닫힘으로 오분류됐다 |
| **D** | 한 줄에 금리가 여럿이면 **최댓값 하나만** | 구간별 금리("300만원이상 0.05%, 500만원이상 0.1%")를 두 번 더했다 |

**리터럴 목록은 실측으로 정했다** — 97개 상품 전수에서 확인된 것만 넣는다.

```
없음 5건 · 해당없음 3건 · 해당사항없음 3건 · 우대조건없음 3건 · 해당무 1건
비교 전 정규화: 공백 제거 + 앞머리 기호(▶ ※ * · - 등) 제거   ← "▶ 해당사항없음" 때문
```

초판에 있던 `-`·`.`는 데이터에 없어서 뺐다. 추측으로 목록을 늘리지 않는다.

**편향 방향과 완화 조치 (중요).** 보정으로 층 분포가 이렇게 움직인다.

| 층 | 초판 규칙 | 보정 후 |
|---|---:|---:|
| 닫힘 | 61 | **40** (41.7%) |
| 안닫힘 | 20 | **36** (37.5%) |
| 조건없음 | 15 | **20** (20.8%) |

`안닫힘`이 늘면 정답이 "알 수 없다"인 문항이 늘고, 모델이 단정할 때 실패로 잡히기
쉬워진다 — **실패 관측이 쉬워지는 방향이라 우리에게 유리하다.** 그래서 두 가지를 박는다.

- **표본 배분은 15/10/5를 유지한다.** 층 비율에 비례시키지 않는다(유리해진 층을 늘리지 않는다)
- **30문항의 층 판정을 사람이 확인한다.** 자동 규칙은 초안이다. 파싱이 우대금리가 아닌
  숫자를 항목으로 읽는 경우가 남아 있다(예: `· 만기 해지 시 : 연 2.50% 제공`)

**선정 규칙(난수를 쓰지 않는다): 각 층에서 상품명 오름차순 정렬 → `len//n` 간격으로
균등 추출 → 앞에서 n개. 같은 스냅샷이면 누가 돌려도 같은 30개가 나온다.
재현: `python src/analysis/build_pilot_sample.py 20260824`

## 3. 사용자 상태 — 6개 변수, 3개 패턴

변수는 우리 데이터에서 가장 흔한 조건 유형 6개로 고정한다(각 25·20·17·15·13·10건).

```
급여이체 · 자동이체 · 카드실적 · 첫거래(해당 은행 첫 거래) · 비대면가입 · 청약보유
```

각 문항에 아래 세 패턴 중 하나를 **순환 배정**한다(층 안에서 순서대로).

| 패턴 | 상태 |
|---|---|
| **P-많음** | 급여 O · 자동이체 O · 카드 O · 첫거래 O · 비대면 O · 청약 O |
| **P-일부** | 급여 O · 자동이체 O · 카드 X · 첫거래 X · 비대면 O · 청약 X |
| **P-없음** | 전부 X |

금액(1천만원)과 기간(12개월)은 **고정**한다. 파일럿에서 변수를 늘리지 않는다.

**질문에 다음 문장을 반드시 포함한다** — 이게 없으면 정답이 결정되지 않는다.

> "위에 적은 상태만 해당하고, 그 밖의 조건(봉사활동, 서약, 이벤트, 다른 상품 보유 등)은
> 해당하지 않는다고 가정하세요."

## 4. 정답 규칙 (측정 전에 고정)

| 층 | 정답 |
|---|---|
| **조건없음** | 기본금리 (단일 값) |
| **닫힘** | 기본금리 + 충족된 조건의 우대금리 합 (상한이 있으면 상한 적용) |
| **안닫힘** | **"공시 정보로는 정확한 금리를 알 수 없다"** — 명시 우대조건으로 최고금리가 설명되지 않으므로 단정할 수 없다. 단, 답변이 **"최소 X% 이상"처럼 하한을 말하면 정답으로 인정**한다(X = 기본 + 충족 우대) |

**정답을 만드는 경로와 검증 경로를 분리한다.** 정답은 사람이 원문을 보고 확정한 조건표에서
계산하고, 계산은 코드가 한다. 자동 추출 결과를 정답 계산에 쓰지 않는다 — 추출 오류가
정답과 측정에 같이 들어가면 오류가 보이지 않는다.

**손계산 대조**: 30건 중 10건은 사람이 손으로 계산해 코드 결과와 맞춘다(불일치가 있으면
코드를 고치고 전건 재계산).

## 5. 실패 분류와 닫는 기준 ★

### 실패 유형

| 코드 | 실패 | 예 |
|---|---|---|
| **F1** | 조건 누락 · 미충족 조건을 충족으로 가정 | 카드 X인데 카드 우대를 더했다 |
| **F2** | 부정 조건 오독 | "보유이력이 없어야" 하는데 있어야 하는 것으로 읽었다 |
| **F3** | 확인 불가인데 단정 | 안닫힘 층에서 "3.80%를 받는다"고 단정 |
| **F4** | 기본금리 무시 · 최고금리로 답 | 조건을 하나도 안 채웠는데 최고금리를 말했다 |
| **F5** | 상한 무시 | 항목 합계가 상한을 넘는데 그대로 더했다 |
| **F6** | 기간·금액 조건 무시 | 6개월 금리로 12개월을 답했다 |

### 닫는 기준 — 미리 정한다

모델 두 개(Qwen3.5-4B · Claude Haiku 4.5)로 30문항씩, 총 60응답.

| 관측 | 판정 |
|---|---|
| **두 모델 모두 오답이 5건 미만**(30건 중) | **이 태스크는 성립하지 않는다. 파일럿에서 닫는다.** 리포트에 "실패가 관측되지 않았다"를 결과로 쓴다 |
| 오답이 **F4·F5·F6(수치·산수형)에만** 몰리고, **F1·F2·F3(조건 해석형)이 두 모델 합쳐 3건 미만** | **결정론적 계산기로 충분하다. 구조화·그래프 불필요.** 계산기와 리포트로 프로젝트를 마감한다 |
| **F1·F2·F3가 두 모델 합쳐 3건 이상** | 구조화 방향이 유효하다. 본 실험(게이트 §3)으로 넘어간다 |
| **안닫힘 층 10건 중 F3가 6건 이상** | `INSUFFICIENT`(확인 불가) 판정을 **주 타깃으로 확정**한다 |

두 번째 줄이 이 문서의 핵심이다. **산수만 틀리는 거라면 그래프도 구조도 필요 없다** —
그 결론이 나올 수 있게 기준을 미리 적어둔다.

## 8. 이 파일럿이 주장하지 않는 것

- **개선 효과를 주장하지 않는다.** 구조화가 얼마나 낫다는 얘기는 본 실험의 몫이다
- **실제 사용자 분포를 대표하지 않는다.** 사용자 상태 3패턴은 우리가 정한 것이다.
  본 실험에서는 분포를 바꿔가며 결론이 뒤집히는지 보는 민감도 분석을 넣는다
  (`problem.md` §7)
- **모델 순위를 매기지 않는다.** 두 모델을 쓰는 이유는 체급으로 해소되는 문제인지
  보려는 것뿐이다
