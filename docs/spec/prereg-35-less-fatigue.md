# prereg-35 · 화면 피로 줄이기 — 접되, 계약은 접지 않는다 (F7 · 이슈 #85)

> 작성 2026-09-10 (**고치기 전**) · 사람 요청 — *"설문 받는 사람이 피로하지 않게 설계"* · *"4개 다 하고 내가 한 번 검수"* · 교육장 파일럿(#83 · `prereg-34`)의 전제 ·
> 관련 `0038`(템플릿은 판정하지 않는다) · `0043`(렌더 함수 하나) · `0061`(스크립트는 표시용 하나) · 화면 계약 A1~A19 · 로드맵 F "모바일 UI(표 → 카드)"

## §1 무엇이 피로한가 — 기준선 (고치기 전 · `visible()` 로 잰 값)

```
                 보이는 글자(펼친 것만)   보이는 입력 칸   버튼   표 행    비고
시작 화면            2,298               15            3      0     권역·기간·스냅샷·정렬·은행·상품군·금액 2·선호 5·목록축·이어하기·내 상황이 한 번에
질문 화면(0답)       4,414               17            4     23     질문 카드는 글자 375 에서 시작(위쪽) — 그 아래 목록 표 23행 + 사유 표 + 리포트가 매 질문마다 다시 그려진다
```

피로의 자리 셋 — ① 첫 화면의 칸 15개 ② 질문마다 목록 전체가 다시 그려져 스크롤이 튄다 ③ 폰에서 표가 안 읽힌다. 그리고 ④ 끝이 없다 — "더 물을 것이 없습니다" 뒤에 설문으로 가는 문이 없다.

## §2 무엇을 만드나 — 화면 넷 · CSS 만 · 계산·뷰 모델 무변동

```
원칙   접되, 계약은 접지 않는다. 화면 계약 문장(성과 줄 범위 · 세후 라벨 · 고지 · 진행 카운터 · 사유 문장 · 스코프 밖 경고)은 기본으로 **보이는 자리**에 남는다.
      접는 것은 보조 정보(전체 목록 · 리포트 · 선호 표 · 부가 입력)만. `<details>` 안에 넣은 계약 문장은 검사기(A20)가 위반으로 잡는다
①  시작   보이는 것 — 참가자 안내 한 줄 · "내 상황" 상자 + 칸 채우기 · 권역 · 예금/적금(select · 전체/예금/적금) · 기간 · **목록 보기**. 나머지(은행 좁히기 · 금액 2 ·
      정렬 · 스냅샷 · 선호 5 · 목록축 · 이어하기)는 "더 정하기" `<details>`. **그 안의 칸에 값이 있으면(사용자가 적었든 문장에서 채웠든) 서버가 펼쳐서 낸다** —
      A19(채운 값은 보이는 칸)를 접기가 깨면 안 된다. 펼침 여부는 render_start 가 값 유무로 정한다(템플릿은 받은 플래그만 쓴다)
②  질문   위에서부터 — 세후 라벨·고지(작게) · 진행 바 + "답한 N/M" · 성과 줄(1위 범위 · 이름 · 정해진 상품 수) · **질문 카드**(버튼 44px) · "여기서 멈추고 결과 보기" 버튼 ·
      스코프 밖 경고 · 사유 문장(펼침) → 그 아래 `<details>` "상품 N개 전부 보기"(정렬 전환 포함) · `<details>` 리포트(1위만 open · 지금과 같음) · 이어하기
③  카드   640px 아래에서 목록 표를 CSS 로 카드로 그린다(`td` 에 `data-th` · 표 → 블록). 리포트 안은 소제목 셋(금리가 어떻게 쌓였나 · 조건 · 세금)으로 갈라 눈이 쉴 자리
④  마지막  "여기서 멈추고 결과 보기"(질문 화면) 또는 질문이 끝났을 때 — 질문 카드 자리에 **요약 카드**: 성과 줄 · 정해진 상품 수 · 답한 질문 수 · 사유 개수 · 설문 링크.
      요약 문장은 뷰 모델에 이미 있는 문자열을 배치하는 것이지 새 판정이 아니다. 설문 링크는 `SURVEY_URL` 환경변수 — 없으면 "설문은 진행자가 안내합니다".
      서버는 설문을 받지 않는다(`0040`) · 멈춤은 `stop=1` 폼 값 하나 · 답은 그대로 hidden 으로 나른다(이어하기 코드도 그대로)
검사   A20 — 계약 문장이 닫힌 `<details>` 안에 있지 않다 (성과 줄 범위 · 세후 라벨 · 고지 · "답한 질문" · 사유 문장 · 스코프 밖 %) · 채운 칸이 든 details 는 open ·
      멈춤 화면에도 A12·A13·A14·성과 줄이 있다 · 스크립트는 시작 화면의 하나(`0061`)뿐
```

## §2-2 검수 중 더한 것 (2026-09-10 · 사람 검수 P7 도중 · *"무슨 은행들이 있는지 모를 거 같다 · 뭔 검색을 해야할지 모른다"*)

- **첫 화면이 "몰라도 된다" 를 말한다** — "어디서 찾을까요 — 몰라도 됩니다. 권역과 기간만 고르면 전부 보여드립니다" · 그 아래 **지금 있는 것** 한 줄
  (은행 18곳 · 예금 38 · 적금 59 | 저축은행 79곳 · 예금 391 · 적금 277 · 공시 기준). 숫자는 서버(`app._catalog`)가 최신 스냅샷 원천에서 센다(조건없음 포함 · #87)
- **은행 좁히기 = 체크박스 목록** — 이름을 치는 칸이 아니라 있는 것을 고른다. 표기 이름을 보이고 공시 이름을 보낸다(F5). 권역별 접기 · 고른(문장에서 채운) 은행이 든 권역은 펼친다.
  체크(`company_pick` 여럿)는 서버가 `company` 쉼표 문자열로 합친다 — 안쪽은 그대로
- **"내 상황" 예시 문장을 은행 없는 것으로** — "1년짜리 적금 아무 은행이나 · 매달 20만원 정도"
- **검사기 결함 하나를 고쳤다** — `unfolded()` 가 비탐욕 정규식이라 중첩 접기(닫힌 것 안의 접기)에서 바깥 나머지를 "보이는 글자" 로 새게 했다. A20 이 느슨해지는 방향이라
  스택으로 다시 썼다(단위 시험 · 중첩 4단). 아래 §5 숫자는 고친 뒤 값이다 — 첫 계측(792 · 1,312)과 큰 차이는 없었다(그 화면엔 중첩이 없었다)

- **기간은 공시에 있는 것만** (사람 검수 *"18개월 적금 아무 은행이나 → 18개월 상품이 없다고 나온다"*). 공시의 가입 기간 단위는 1·3·6·12·24·36개월뿐이라 "없다" 는 맞는 말이었지만,
  화면이 두 군데서 헛걸음시켰다 — 문장에서 채운 18 을 메뉴에 더해 고르게 했고, "없다" 안내가 어떤 기간이 있는지 말하지 않았다. 고친 것: 기간 메뉴는 서버가 카탈로그에서 실측한 기간만 ·
  prefill 은 없는 기간을 채우지 않고 "18개월은 공시에 없는 기간 — 1·3·6·12·24·36" 안내 · "없다" 오류에도 있는 기간을 적는다. A19 에 "없는 기간은 채우지 않는다" 검사 추가.
  `prereg-29` 의 "메뉴 밖 기간은 메뉴에 더해 보인다" 규칙은 이것으로 **철회** — 공시에 없는 기간을 고를 수 있게 하는 것이 정직이 아니었다
