# prereg-30 · 예상 이자의 월 환산 — 예금만 · "월 이자" 가 아니라 "월로 환산하면"

> 작성 2026-09-09 (**고치기 전**) · 이슈 [#78](https://github.com/hyos0415/fineprint/issues/78) · 앞선 `prereg-25`(E4 첫 조각 · `0055` · A18) ·
> 사람 요청 — *"보통 월 이자 얼마를 받는지 약간 알 수 있으면 도움이 되려나"* · 사람 결정 — *"안전한 형태로 작성"*

## §1 무엇이 문제인가

리포트의 예상 이자는 **만기에 한 번 받는 총액**이다(`prereg-25` 가정 ③). 사용자는 "그래서 한 달에 얼마인가" 를 알고 싶은데,
그 숫자를 그대로 "월 이자" 라고 쓰면 두 가지가 틀릴 수 있다.

```
①  지급 방식   정기예금의 기본은 만기 일시 지급이고 월 이자 지급식은 따로 고르는 옵션이다(보통 금리가 조금 낮다).
              공시(`finlife`)에는 지급 방식 칸이 없다 — 어느 상품이 월 지급을 지원하는지 우리 데이터로는 모른다
②  적금        매달 넣는 돈이 달라 "월 이자" 라는 말이 성립하지 않는다 (k 번째 납입은 n−k+1 개월치 이자)
```

## §2 무엇을 만드나 — 안전한 형태

- **예금에만** `월환산` 을 낸다 — 세전·세후 각각 `이자 ÷ 개월` (원 · 반올림). 적금은 내지 않는다
- 문구는 **"월로 환산하면 약 ○○원"** 이고 바로 옆에 가정 한 줄 — *"만기 이자를 개월 수로 나눈 값입니다. 실제 지급 시기와 방식(만기
  일시 · 월 지급)은 상품마다 다릅니다"*. 문장은 `calculate.MONTHLY_NOTE` 한 곳에서 오고 텍스트·웹이 같은 것을 읽는다(`0035`)
- **금리 · 순서 · 확정 여부 · 종합과세 판정은 바뀌지 않는다** — `interest()` 가 이미 낸 값 위의 나눗셈 하나다
- 화면 계약 **A18 확장** — 예금 리포트에 월 환산 숫자가 있으면 그 옆에 `MONTHLY_NOTE` 가 텍스트·웹 둘 다에 있어야 하고, **적금 리포트에는 월 환산이
  없어야** 한다

## §3 예측 — 고치기 전에 적는다

```
P1  무변동    은행권 12개월 · 금액 예금 5천만원 · 적금 월 100만원에서 상품별 `net_lo`·`net_hi`·`tier`·`caveats`·순서·`종합과세` 가 고치기 전과 같다
P2  예금만    예금 리포트에는 월환산이 있고 적금 리포트에는 없다 (두 권역 · 전부)
P3  산수      월환산 × 개월 = 세전/세후 총액 (반올림 ±개월 원 안)
P4  A18      텍스트·웹 리포트에 월환산 숫자와 MONTHLY_NOTE 가 같이 있다 · 계약 A1~A19 통과
P5  값의 크기  5천만원 · 12개월 · 세후 2.7%(은행권 평균 확정) 근처면 월 환산은 **약 11만원** — 사람이 "이 정도" 로 감을 잡을 수 있는 크기
```

## §4 판정 조항

```
P1 이 틀리면   계산기를 건드린 것이다. 되돌린다 — 월환산은 `interest()` 반환 dict 에 칸을 더하는 것뿐이어야 한다
P2 가 틀리면   적금에 월환산이 나간 것 — 거짓말 자리다. 검사기가 잡아야 한다
P4 가 틀리면   숫자만 있고 가정이 없는 화면 — A12·A18 과 같은 위반. 렌더러를 고친다
```

P2  예금만   은행권 예금 25/25 있음 · 적금 54/54 없음 · 저축은행 예금 87/87 · 적금 109/109 → 맞음

            자리수는 맞고 값은 20% 높게 나왔다. 사람이 감을 잡는 크기라는 점은 그대로

**적은 것** — 문구는 "월로 환산하면 약" 이고 "월 이자" 라는 말은 화면 어디에도 없다. 지급 방식은 공시에 없으므로 이 화면은 그것을 말하지 않는다 —
사용자가 월 지급을 원하면 기관 링크(F3)로 확인하는 자리다.
