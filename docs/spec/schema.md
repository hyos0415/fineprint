# FINeprint — Schema

> 상태: **의도적으로 비어 있음.** 반증 게이트(`../handoff/v2.md` §3) 통과 전에는 착수하지 않는다.

## 왜 지금 쓰지 않는가

게이트 결과가 스키마의 필요 형태를 결정한다.

- 결정론적 체크리스트로 충분하면 → 스키마는 **평면 조건 리스트**면 된다. 노드·간선 불필요
- 조건 그룹 논리(AND/OR/예외)가 필요하면 → 논리식 표현이 필요
- 다중 상품·다중 홉 비교가 필요하면 → 그때 그래프

게이트 전에 스키마를 확정하면, 선행 저장소가 실패한 순서(그래프 먼저, 계약 나중)를 방향만
바꿔서 반복하는 셈이다.

## 착수 시 최우선 산출물 — 구분표 (D2)

두 독립 감사가 **1급 수렴**으로 동일하게 요구한 단 하나의 문서다
(`../audit/00-comparison.md` M1). 선행 저장소 실측:

```
리터럴 형태 엔티티 노드      152 / 925 = 16.4%
목적어가 리터럴인 트리플      183 / 773 = 23.7%   ← 트리플 1/4이 속성을 간선으로 표현
교차문서 브릿지 중 리터럴      6 / 42  = 14.3%
```

handoff v1 §6의 노드 후보 10종 중 `Rate`·`Term`·수치성 `Condition`을 노드로 두면,
**선행 저장소가 트리플의 23.7%에서 겪은 실패를 스키마에 명시적으로 설계해 넣는 것**이 된다.

따라서 착수 시 가장 먼저 다음 표를 채운다. Finlife 필드별로 미리 결정한다.

## 선행 저장소에서 이관 금지 (감사 확정)

- 자유도 높은 Entity/Relation 생성 — 허용 타입 0, 출력 언어 미제약(영문 83종),
  리터럴/개체 미구분, **파싱 실패가 조용히 버려지고 계측되지 않음**
- `SimpleLLMPathExtractor` 사용 패턴 — allowlist를 받지 못하므로 schema-first에서는
  패턴 재사용이 아니라 **추출기 교체**다
- LLM 생성 Cypher 무검증 실행
- 정규화(별칭 사전) 접근 — 선행 저장소가 시도해 **기각**했다.
  재등장 엔티티가 925개 중 42개(4.5%)뿐이라 완벽한 별칭 사전의 상한이 이미 낮다.
  **"이번엔 정규화를 제대로 하자"는 이미 기각된 경로다** — 해법은 추출 시점에 형식을
  제한하는 것이다

## 불변식 (착수 시 스키마에 선언)

- **원문 필드와 LLM 파생 필드를 강제 분리한다.** 선행 저장소에서 LLM 생성 메타데이터가
  추출 입력으로 재투입되어 가짜 연결을 만든 실증 사례가 있다
  (`../audit/00-comparison.md` C4·U2). 이건 "개선 항목"이 아니라 **차단 조건**이다
- 파싱/추출 실패 항목은 **버리지 않고 계측한다** (M3)
