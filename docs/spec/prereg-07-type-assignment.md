# 사전 등록 07 — 유형 배정을 고치는 재추출

> 등록일 2026-08-27 · 상태: **실행·채점 완료** · 이슈 [#2](https://github.com/hyos0415/fineprint/issues/2)
>
> **이 문서를 커밋한 뒤에 실행한다.** 예측·판정 기준·회피 방지 제약을 재기 전에 못 박는다.

## 0. 무엇을 하려는가

`기타`로 분류된 40건을 사람이 읽었더니(`prereg-06` §1.8) **20건은 17종 중 하나로
갔어야 하는 것**이었다. 조건이 이상해서가 아니라 **우리가 못 읽은 것**이다.

```
"아파트관리비 이체"            → 자동이체
"개인사업자 계좌 실적 :1.0%p"   → 급여_연금이체   (원문이 "급여실적 ①급여이체 ②개인사업자" 로 묶었다)
"전자명함을 통한 신규 시 0.2%"   → 쿠폰_코드_추천인
"고향사랑기부금 납부고객 우대"    → 실천_미션_인증
"출산예정인자-배우자 포함"       → 고객군_자격
```

**`기타`로 두면 사용자가 무엇을 답해야 할지 모르는 질문을 받는다.** 문구는 그대로
보여주지만(`0016`), 같은 성격의 조건이 상품마다 다른 질문으로 흩어진다.

## 1. 왜 별칭 사전이 아니라 재추출인가

`CLAUDE.md` 5번이 금지한 것은 **손으로 쓴 매핑표**다. 그리고 같은 줄이 해법도 적어 뒀다 —
*"해법은 추출 시점에 형식을 제한하는 것이다."* 그게 이 실험이다.

재보고 확인했다(`prereg-06` §1.8 부속 측정).

| 방법 | 결과 | 판정 |
|---|---|---|
| 중복 제거(ER의 전형적 용도) | 뭉친 48곳 중 중복 **0곳** | 벌 게 없다 |
| 문자열 유사도로 유형 맞히기 | **5/12 (42%)** | 못 쓴다 |
| 자기일관성(같은 문구 = 같은 유형) | 9종 47항목(4.5%) · 저축은행 확정 +3 | **채택**(`0020`) — 사전이 아니다 |
| **추출 시점 개선** | 이 문서 | 남은 길 |

**`0013`(추출 개선 중단)의 범위를 명시한다.** `0013`이 멈춘 것은 **닫힘률**이다 —
*"남은 실패의 71%는 공시 문제"*라서 멈췄다. 이 실험이 고치는 것은 **유형 배정**이고,
A군 20건은 공시가 안 적은 게 아니라 **적혀 있는데 우리가 못 읽은 것**이다. 다른 지표다.

## 2. 무엇을 바꾸는가 — 예시가 아니라 **원리**를 넣는다

**예시를 나열하면 그게 별칭 사전이다.** 프롬프트에 `"아파트관리비 이체 → 자동이체"`를
적는 것과 코드에 적는 것은 같은 일이다. 그래서 **판정 원리**를 넣는다.

```
고객군_자격       사용자가 **누구인가**로 갈린다 — 나이·가족 구성·직업·자격·신분·보유 차량
실천_미션_인증     사용자가 **무엇을 했는가**로 갈린다 — 참여·기부·서약·인증·홍보
쿠폰_코드_추천인    **가입 경로에 제3자나 코드가 끼어 있으면** 여기다
기타             위 16종의 원리를 **전부 대 봤는데도** 안 맞을 때만 쓴다
```

그리고 **`아파트관리비 이체`는 이미 프롬프트에 있다** — `자동이체` 설명에
*"공과금·지로·아파트관리비·통신비 자동이체"*라고 적혀 있는데도 `기타`로 갔다.
**예시를 더 넣는 것만으로는 안 된다는 증거**이고, 원리를 넣는 이유다.

### 홀드아웃을 지킨다 — 이게 설계의 핵심이다

A군 20건은 **은행권 11 · 저축은행 9**로 갈린다. 저축은행은 홀드아웃이다
(`CLAUDE.md` — *"홀드아웃을 보고 규칙을 고치지 않는다. 고치면 홀드아웃 자격을 잃는다"*).

```
프롬프트에 넣는 근거   은행권 A군 11건만 본다
                    저축은행 A군 9건은 **읽지 않은 셈 치고** 일반화 측정에 쓴다
```

저축은행 A군은 대부분 `고객군_자격`(출산·한부모·띠·착한운전)이라 은행권 사례와 겹치지
않는다. **원리가 진짜 원리면 옮겨붙고, 예시를 외운 것이면 안 옮겨붙는다.** 그 차이를
재는 것이 이 실험의 값어치다.

## 3. 예측 — 실행 전에 적는다

| | 무엇 | 예측 | 왜 |
|---|---|---:|---|
| **주 지표** | 은행권 A군 11건이 사람이 읽은 유형과 일치 | **≥ 9/11 (82%)** | 원리를 직접 겨냥했다. 다만 아파트관리비는 이미 적혀 있는데도 틀렸으므로 11/11 은 예측하지 않는다 |
| **부 지표(홀드아웃)** | 저축은행 A군 9건 일치 | **≥ 3/9 (33%)** | 은행권 사례와 겹치지 않는다. 낮게 잡는다 — **높게 나오면 원리가 옮겨붙었다는 증거**다 |
| 부 지표 | `기타` 비율 | 3.8% → **2.5% 이하** | 20건이 빠지면 20/1051 = 1.9%p 준다 |

## 4. 회피 방지 제약 — 통과 못 하면 채택하지 않는다

프롬프트를 건드리므로 **다른 것이 깨질 수 있다.** `0018`의 게이트에 회귀 가드를 더한다.

```
게이트    커버리지가 기준선 아래로 떨어지면 불인정   은행권 79.7% · 저축은행 36.7%
회귀 1   닫힘률(폴백)이 2%p 이상 떨어지면 불인정    은행권 83.9% · 저축은행 79.1% (0012)
회귀 2   `기타` 비율이 3.8%에서 늘면 불인정
회귀 3   항목 0개 비율이 1.7%에서 늘면 불인정      (0012 부지표. 뽑기를 포기해 얻는 점수를 막는다)
```

**회귀 1이 가장 중요하다.** 유형 배정을 고치려다 금리 추출이 나빠지면 순손실이다.
닫힘률은 이 시스템이 계산을 해줄 수 있는지를 정하는 값이다.

**확정률은 판정에 쓰지 않는다.** 유형이 바뀌면 질문 순위가 바뀌고, 예산 12개 경계에서
밀리고 들어오는 것만으로 값이 흔들린다(`prereg-06` §1.8에서 실측했다 — 재분류 시뮬레이션에서
은행권 확정이 -2 였는데 원인이 오픈뱅킹 질문이 예산 밖으로 밀린 것이었다).
**같이 보고는 하되 채택 기준에는 넣지 않는다.**

## 7. 채택 뒤 측정 — 하락 1.0%p 를 상품 세 개까지 좁혔다 (2026-08-27)

**이 절은 사전등록이 아니라 사후 측정이다.** 판정 기준을 하나도 고치지 않았다.
`0021`이 남긴 열린 문제와 `START-HERE` "다음에 할 일" 4·5번을 **고치기 전에 규모부터
세어 본** 기록이다. 여기서 정하는 것은 없다.

### 7.1 무엇을 어떻게 셌나 — 재기 전에 고정한 정의

같은 스냅샷·같은 코드에 **추출 결과만 v1/v2로 바꿔** 넣고 행마다 층을 비교했다.
커버리지 판정(`tier`)은 사용자 상태와 무관하므로(`unexplained`는 공시 폭과 추출 항목만
쓴다) 아무 질문도 안 한 상태로 잰다. `0018`이 실측한 것과 같다 — 메인 층 수는 질문에
안 변한다.

```
쪼개짐           같은 조건문에서 v2 항목 수 > v1 항목 수
넘침             밴드 하한까지 공시 폭보다 크다        → 층 `추출불확실`
모자람           밴드 상한이 공시 폭보다 작다          → 층 `설명부족`
excl 누락 후보    넘침 + exclusive_group 이 한 항목도 없음 + 항목 2개 이상
cap 오분류 후보   모자람 + cap 이 합산을 자르고 + 공시 폭 > cap
부분집합 일치      항목 몇 개만 더하면 공시 폭과 맞는 조합이 있다
                = 배타 그룹이 있어야 맞는다는 직접 증거
```

**정의를 한 번 고쳤다.** 처음에는 공시 폭이 0인 행도 넘침으로 셌더니 후보가 42건으로
부풀었다. 폭 0 행은 코드가 이미 `공시미반영` 층으로 따로 빼는 곳이다 — 그 행에서는
**어떤 추출이든 넘침이 된다.** 결과 방향과 무관한 정정이라 고치고 다시 셌다(7건).

### 7.2 하락분은 3행이다. 상품 세 개로 다 나열된다

저축은행 12개월 297행에서 메인 층이 **109 → 106**이다. 빠진 행 4개, 들어온 행 1개다.

| 상품 | 공시 폭 | v1 층 | v2 층 | 항목 수 | v2 밴드 | cap |
|---|---|---|---|---|---|---|
| KB일반정기적금 (2행) | 0.20 | 범위 | 추출불확실 | 2 → 3 | 0.30~0.30 | 없음 |
| 웰뱅 든든적금 | 4.00 | 범위 | 설명부족 | 2 → 4 | 3.00~3.00 | 3.0 |
| 웰뱅 워킹 적금 | 7.00 | 범위 | 추출불확실 | 2 → 5 | 13.00~13.00 | 없음 |

**은행권은 같은 기간에 64 → 67로 올랐고 빠진 행이 0이다.** 항목이 늘어난 행도
2개뿐이다(저축은행은 27개). 쪼개기가 저축은행에서만 크게 일어났다.

### 7.3 원인이 셋이다 — 예고한 것은 둘이었다

`START-HERE` 4번은 원인을 `exclusive_group` 누락과 `cap` 오분류 둘로 적었다.
**셋 중 둘만 맞았다.** 3행 중 2행이 셋째 원인이다.

**원인 1 · 배타 그룹 누락 (웰뱅 워킹 적금 · 1행)** — 예고한 그대로다.

```
공시   연간 걸음수 -1백만보 이상 1.0%p -2백만보 이상 2.0%p -3백만보 이상 3.0%p
      -4백만보 이상 6.0%p  /  6회 이상 자동이체 1.0%p        (공시 폭 7.0)
v1    걸음수 항목 1개(6.0) + 자동이체 1.0                    합 7.0  맞다
v2    걸음수 항목 4개(1·2·3·6) + 자동이체 1.0, 그룹 없음        합 13.0  넘침
```

걸음수 네 단계는 하나만 받는 것이 분명한데 묶는 신호가 안 붙었다.

**원인 2 · 하위 항목의 상한을 상품 상한으로 올렸다 (웰뱅 든든적금 · 1행)**

```
공시   신용평점에 따라 우대 : 최대 연 3.0%p   ← "최대 3.0"은 이 항목 안의 상한이다
      850~650점 1.0 / 650~350점 2.0 / 350~1점 3.0  + 첫거래 1.0   (공시 폭 4.0)
v2    신용평점 3항목 + 그룹 g1 (여기까지 정확) · 그런데 cap=3.0 을 상품 전체에 걸었다
      → 1.0 + 3.0 = 4.0 이 3.0 으로 잘려 모자람
```

**쪼개기와 그룹은 맞았고 cap 하나가 틀렸다.**

**원인 3 · 같은 우대금리를 두 번 셌다 (KB일반정기적금 · 2행) — 예고에 없던 것**

```
공시   인터넷뱅킹 신규가입하여 출금계좌를 등록한 후 당일 창구 신규시 연 0.1%p 적용.
      단, 신규가입일 포함 14일 이내 타기관 공인인증서 미등록시 우대금리 적용해제
      KB스타클럽 고객 연 0.1%p                                (공시 폭 0.20)
v1    비대면_채널가입 0.1 + 고객군_자격 0.1                     합 0.20  맞다
v2    거기에 "미등록시 적용해제" 를 별개 항목 0.1 로 하나 더      합 0.30  넘침
```

**뒤 문장은 앞 우대금리의 단서다.** 0.1%p 는 하나인데 항목이 둘이 됐다.

**이 문장은 `0019`가 이미 읽은 문장이다.** `must_not_have` 6건을 표본으로 읽고
"AI가 방향을 뒤집었다"고 정정했는데, **항목 자체를 없애지는 않았다.** 방향만 고치고
금리를 남겼기 때문에 합계는 계속 부풀어 있었다. v2가 같은 문장에서 7번째 항목을
만들면서 그 판단이 대가를 냈다.

### 7.4 천장은 기준선 위다 — 3행이 아니라 6행이 걸려 있다

각 원인을 하나씩 고쳤다고 가정하고 다시 센 값이다. **채택한 것이 아니라 천장을 재려고
붙인 임시 패치다.**

| 무엇을 고치면 | 저축은행 메인 | 회복 |
|---|---|---|
| 손대지 않은 v2 | 106/297 = 35.7% | — |
| 원인 1만 (배타 그룹) | 107/297 = 36.0% | +1행 |
| 원인 2만 (cap) | 107/297 = 36.0% | +1행 |
| 원인 3만 (중복 계상) | 110/297 = 37.0% | **+4행** |
| 셋 다 | 112/297 = **37.7%** | +6행 |
| (기준선) | 109/297 = 36.7% | |

**원인 3이 v1에도 있던 행 2개를 같이 살린다.** 그래서 천장이 기준선과 같지 않고
1.0%p 위다. 세 상품만 되돌리는 문제로 보고 들어갔는데 그보다 컸다.

### 7.5 후보 규칙 둘의 발자국 — 하나는 깔끔하고 하나는 아니다

원인 2·3은 재추출 없이 규칙으로 잡힐 수 있는 모양이다(`0019`가 한 것과 같은 방식).
원인 1의 임시 패치는 `"걸음수"` 라는 **문구를 직접 박은 것**이라 채택 후보가 아니다 —
`CLAUDE.md` 5번이 막은 별칭 사전 방향이다. 나머지 둘만 발자국을 쟀다.

| 후보 규칙 | 걸리는 범위 | 저축은행 | 은행권 |
|---|---|---|---|
| `cap` 이 어떤 항목의 금리와 정확히 같으면 상품 cap 이 아니다 | cap 붙은 쌍 175 중 **57** | +1행 | **-1행** |
| 근거 문구에 `"적용해제"` 가 있으면 중복 항목이다 | 항목 7개 (저축은행만) | **+4행** | ±0행 |

**`적용해제` 규칙은 깔끔하다** — 은행권에서 한 행도 안 움직이고 저축은행에서 4행을
살린다. 발자국이 7항목이라 부작용 범위가 좁다.

**`cap` 규칙은 아니다.** cap 이 붙은 쌍의 3분의 1을 건드리는데 효과가 **권역마다 방향이
반대**다(저축 +1 · 은행 -1). 1행을 얻으려고 57쌍의 판정을 바꾼다.

### 7.6 계단식(`prereg-06` §1.6)은 하나도 안 풀렸다

`0021`이 부수 소득으로 적은 것과 `START-HERE` 5번이 "남은 일은 11건 전부가 이렇게
풀렸는지 세는 것"이라 적은 항목이다. **세어 보니 0건이다.**

| | v1 | v2 |
|---|---|---|
| 은행권 · 되물어도 판정 못 하는 행 | 9/79 · 상품 6 | **9/79 · 상품 6 (같음)** |
| 저축은행 · 같은 것 | 6/297 · 상품 4 | **6/297 · 상품 4 (같음)** |

상품 목록까지 완전히 같다. 예를 들어 이 항목은 v2에서도 그대로 접혀 있다.

```
미즈월복리정기예금   "요구불평잔 : 0.2% -300만원이상 0.1%, 500만원이상 0.2%"  → 항목 1개
```

**`0021`이 인용한 두 사례는 §1.6이 센 집합에 애초에 없었다.** 가구원수 "3명"·신용평점
"850점"은 임계 정규식(`회|건|명|개|일|주차|좌` · 금액 단위)에 안 걸려서 계단식으로
집계되지 않는다. 즉 `0021`의 "계단식이 처음으로 표현됐다"는 **맞는 말이지만 다른
집합에 대한 말**이고, §1.6의 열린 결정은 손대지 않은 채로 남아 있다.

그리고 v2가 실제로 쪼갠 계단식 둘(신용평점·걸음수)이 **그대로 7.3의 원인 1·2**다.
쪼개는 것 자체는 맞는 방향인데, 쪼갠 뒤 묶는 신호가 틀리면 순손실이 된다 —
`0021`의 반증 조건 넷째가 예고한 그대로다.

### 7.7 남은 결정 — 사람이 정한다

1. **`적용해제` 규칙을 채택하는가** (+4행 · 은행권 부작용 0). 기준선이 움직이므로
   `prereg-06` §2.3(1)처럼 **고치기 전에** 사유·편향 방향·완화 조치를 등록해야 한다
2. **`cap` 규칙은 어떻게 하는가** — 효과가 권역마다 반대다. 규칙을 좁힐지, cap 자체를
   `0022`처럼 밴드로 낼지, 그냥 두는지
3. **원인 1(배타 그룹 누락)은 규칙으로 잡을 수 없다** — 문구를 박지 않고 잡으려면
   추출 프롬프트를 고쳐 재추출해야 한다. `0013`(추출 개선 중단)과 부딪친다
4. **홀드아웃 자격** — 위 숫자는 전부 저축은행에서 나왔다. 저축은행은 `prereg-07`의
   홀드아웃이다. 이 숫자를 보고 규칙을 고르면 **저축은행은 다음 회차의 홀드아웃이
   아니다.** 9월 공시가 새 홀드아웃이 될 수 있다(`0010` — 월 1회 갱신)
