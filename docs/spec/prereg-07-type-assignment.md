# 사전 등록 07 — 유형 배정을 고치는 재추출

> 등록일 2026-08-27 · 상태: **실행 전** · 이슈 [#2](https://github.com/hyos0415/fineprint/issues/2)
>
> **이 문서를 커밋한 뒤에 실행한다.** 예측·판정 기준·회피 방지 제약을 재기 전에 못 박는다.

## 0. 무엇을 하려는가

`기타`로 분류된 40건을 사람이 읽었더니(`prereg-06` §1.8) **20건은 17종 중 하나로
갔어야 하는 것**이었다. 조건이 이상해서가 아니라 **우리가 못 읽은 것**이다.

```
"아파트관리비 이체"            → 자동이체
"개인사업자 계좌 실적 :1.0%p"   → 급여_연금이체   (원문이 "급여실적 ①급여이체 ②개인사업자" 로 묶었다)
"전자명함을 통한 신규 시 0.2%"   → 쿠폰_코드_추천인
"고향사랑기부금 납부고객 우대"    → 실천_미션_인증
"출산예정인자-배우자 포함"       → 고객군_자격
```

**`기타`로 두면 사용자가 무엇을 답해야 할지 모르는 질문을 받는다.** 문구는 그대로
보여주지만(`0016`), 같은 성격의 조건이 상품마다 다른 질문으로 흩어진다.

## 1. 왜 별칭 사전이 아니라 재추출인가

`CLAUDE.md` 5번이 금지한 것은 **손으로 쓴 매핑표**다. 그리고 같은 줄이 해법도 적어 뒀다 —
*"해법은 추출 시점에 형식을 제한하는 것이다."* 그게 이 실험이다.

재보고 확인했다(`prereg-06` §1.8 부속 측정).

| 방법 | 결과 | 판정 |
|---|---|---|
| 중복 제거(ER의 전형적 용도) | 뭉친 48곳 중 중복 **0곳** | 벌 게 없다 |
| 문자열 유사도로 유형 맞히기 | **5/12 (42%)** | 못 쓴다 |
| 자기일관성(같은 문구 = 같은 유형) | 9종 47항목(4.5%) · 저축은행 확정 +3 | **채택**(`0020`) — 사전이 아니다 |
| **추출 시점 개선** | 이 문서 | 남은 길 |

**`0013`(추출 개선 중단)의 범위를 명시한다.** `0013`이 멈춘 것은 **닫힘률**이다 —
*"남은 실패의 71%는 공시 문제"*라서 멈췄다. 이 실험이 고치는 것은 **유형 배정**이고,
A군 20건은 공시가 안 적은 게 아니라 **적혀 있는데 우리가 못 읽은 것**이다. 다른 지표다.

## 2. 무엇을 바꾸는가 — 예시가 아니라 **원리**를 넣는다

**예시를 나열하면 그게 별칭 사전이다.** 프롬프트에 `"아파트관리비 이체 → 자동이체"`를
적는 것과 코드에 적는 것은 같은 일이다. 그래서 **판정 원리**를 넣는다.

```
고객군_자격       사용자가 **누구인가**로 갈린다 — 나이·가족 구성·직업·자격·신분·보유 차량
실천_미션_인증     사용자가 **무엇을 했는가**로 갈린다 — 참여·기부·서약·인증·홍보
쿠폰_코드_추천인    **가입 경로에 제3자나 코드가 끼어 있으면** 여기다
기타             위 16종의 원리를 **전부 대 봤는데도** 안 맞을 때만 쓴다
```

그리고 **`아파트관리비 이체`는 이미 프롬프트에 있다** — `자동이체` 설명에
*"공과금·지로·아파트관리비·통신비 자동이체"*라고 적혀 있는데도 `기타`로 갔다.
**예시를 더 넣는 것만으로는 안 된다는 증거**이고, 원리를 넣는 이유다.

### 홀드아웃을 지킨다 — 이게 설계의 핵심이다

A군 20건은 **은행권 11 · 저축은행 9**로 갈린다. 저축은행은 홀드아웃이다
(`CLAUDE.md` — *"홀드아웃을 보고 규칙을 고치지 않는다. 고치면 홀드아웃 자격을 잃는다"*).

```
프롬프트에 넣는 근거   은행권 A군 11건만 본다
                    저축은행 A군 9건은 **읽지 않은 셈 치고** 일반화 측정에 쓴다
```

저축은행 A군은 대부분 `고객군_자격`(출산·한부모·띠·착한운전)이라 은행권 사례와 겹치지
않는다. **원리가 진짜 원리면 옮겨붙고, 예시를 외운 것이면 안 옮겨붙는다.** 그 차이를
재는 것이 이 실험의 값어치다.

## 3. 예측 — 실행 전에 적는다

| | 무엇 | 예측 | 왜 |
|---|---|---:|---|
| **주 지표** | 은행권 A군 11건이 사람이 읽은 유형과 일치 | **≥ 9/11 (82%)** | 원리를 직접 겨냥했다. 다만 아파트관리비는 이미 적혀 있는데도 틀렸으므로 11/11 은 예측하지 않는다 |
| **부 지표(홀드아웃)** | 저축은행 A군 9건 일치 | **≥ 3/9 (33%)** | 은행권 사례와 겹치지 않는다. 낮게 잡는다 — **높게 나오면 원리가 옮겨붙었다는 증거**다 |
| 부 지표 | `기타` 비율 | 3.8% → **2.5% 이하** | 20건이 빠지면 20/1051 = 1.9%p 준다 |

## 4. 회피 방지 제약 — 통과 못 하면 채택하지 않는다

프롬프트를 건드리므로 **다른 것이 깨질 수 있다.** `0018`의 게이트에 회귀 가드를 더한다.

```
게이트    커버리지가 기준선 아래로 떨어지면 불인정   은행권 79.7% · 저축은행 36.7%
회귀 1   닫힘률(폴백)이 2%p 이상 떨어지면 불인정    은행권 83.9% · 저축은행 79.1% (0012)
회귀 2   `기타` 비율이 3.8%에서 늘면 불인정
회귀 3   항목 0개 비율이 1.7%에서 늘면 불인정      (0012 부지표. 뽑기를 포기해 얻는 점수를 막는다)
```

**회귀 1이 가장 중요하다.** 유형 배정을 고치려다 금리 추출이 나빠지면 순손실이다.
닫힘률은 이 시스템이 계산을 해줄 수 있는지를 정하는 값이다.

**확정률은 판정에 쓰지 않는다.** 유형이 바뀌면 질문 순위가 바뀌고, 예산 12개 경계에서
밀리고 들어오는 것만으로 값이 흔들린다(`prereg-06` §1.8에서 실측했다 — 재분류 시뮬레이션에서
은행권 확정이 -2 였는데 원인이 오픈뱅킹 질문이 예산 밖으로 밀린 것이었다).
**같이 보고는 하되 채택 기준에는 넣지 않는다.**
