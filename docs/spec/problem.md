# 이 프로젝트가 푸는 문제

> 작성 2026-08-24 · 근거: 외부 출처(§3) + 우리 데이터 실측(§4)
>
> 앞선 문서들은 "구조가 필요한가"를 다뤘다. 이 문서는 그보다 앞선 질문에 답한다 —
> **무엇을 풀려는 것이고, 그 문제가 실제로 존재하는가.**

## 1. 한 문장

**AI가 예금·적금의 우대금리를 설명할 때, 사용자가 실제로 받을 금리를 과대하게
말하는 것을 잡아낸다.**

우리가 만드는 것은 상품을 추천하는 AI가 아니다. **AI의 답변이 공시 원문으로
뒷받침되는지 검사하는 검증기**다.

## 2. 무엇이 잘못되는가 — 네 가지

실제로 일어나는 실패를 네 가지로 나눈다. 각각 **실제 사례**와 **우리 데이터의 재료 수**를
같이 적는다. 재료가 없는 실패는 다루지 않는다.

### (가) 조건을 빠뜨린다

```
공시: 아래 조건을 모두 충족해야 보너스이율 0.1%
      - 5천만원 이상 가입
      - 만기 전전월 말에 펀드 3천만원 이상 보유
답변: "5천만원 이상 가입하면 0.1%를 받는다"          ← 펀드 조건 누락
```

재료: 조건 항목이 2개 이상인 상품 **63건**(예금 22 + 적금 43).
단, "모두 충족"이 원문에 명시된 상품은 예금 38개 중 6개뿐이라 정답 판정 규칙이 필요하다.

### (나) 없어야 하는 조건을 무시한다 ★ 규제기관이 지목한 유형

금융위원회가 2023년 4월 소비자 경보에서 든 실제 사례다.

> "A씨는 최고금리 10%를 보고 적금에 가입했으나 **가입 이전 6개월간 카드 사용실적이
> 있어** 우대금리를 적용받지 못했다."

조건이 "있어야 함"이 아니라 **"없어야 함"**이었다. 방향이 반대인 조건이다.
우리 데이터에도 정확히 같은 형태가 있다.

```
[전북은행 JB 123]      가입일직전 6개월 동안 당행 원화 정기예금 보유이력이 "없는" 경우 0.50%
[수협은행 Sh첫만남우대]  최근 1년간 수협은행 예적금 활동계좌 "미보유" 고객
```

재료: **2건**(예금). 적금까지 세면 더 늘어날 수 있으나 아직 전수 확인하지 않았다.

### (다) 판정할 수 없는데 단정한다

두 종류가 있고, 둘 다 근거가 있다.

**① 사용자 상태를 모른다.** "주택청약종합저축 보유 시 0.1%"라는 조건에서, 그 사용자가
청약을 갖고 있는지는 공시에 없다. 그런데 답변은 "가입하면 0.1%를 받는다"고 단정한다.

재료: 조건이 다른 상품 보유·가입을 요구하는 상품 **41건**(적금 29 + 예금 12).

**② 공시 문구에 세부 요건이 없다.** 실제 사용자 질문에서 드러난다 — "예적금 급여이체
우대 조건은 무엇으로 급여를 인식하나요?" 답을 보면 공시에 없는 요건이 줄줄이 나온다.

> "만기 전전월까지 총 6회 이상, 매월 50만원 이상 입금하되, 입금 적요에 '급여',
> '월급', 'SALARY' 등이 포함되어야 한다"

공시에는 `①급여이체`라고만 적혀 있다. **공시만으로는 충족 여부를 판정할 수 없다** —
정답은 "받는다"도 "못 받는다"도 아니라 **"이 정보로는 알 수 없다"**여야 한다.

재료: 급여이체 조건 **10건**, 자동이체 **25건**, 카드 실적 **20건**.

### (라) 기본금리를 무시하고 최고금리로 말한다

같은 금융위 경보의 경고다.

> "최고금리가 높더라도 기본금리가 현저히 낮은 경우 우대금리 조건을 충족하지 못하면
> 결과적으로 시중금리보다 오히려 낮은 금리를 적용받을 수 있다."

여기에 **합산 상한**까지 겹친다. 실제 상품을 보면 항목을 다 더해도 상한을 못 넘는다.

```
[수협은행 Sh해양플라스틱Zero!예금]  * 최대우대금리 0.35%
  1. 해양플라스틱감축서약  0.1%
  2. 봉사활동 또는 상품홍보 0.15%
  3. 입출금통장 최초신규    0.1%
  4. 자동이체 출금실적      0.1%
                          ─────
  단순 합계                0.45%   ← 상한 0.35%를 넘는다
```

재료: 합산 상한이 명시된 상품 **46건**, 기간별 기본금리 **181건**.

그리고 더 센 재료가 있다 — **12개월 상품 96건 중 36건(37.5%)은 공시된 최고금리를
명시된 우대조건으로 계산할 수 없다.** 조건을 다 채워도 최고금리에 도달하는 경로가
공시에 없다는 뜻이고, 이 경우 정답은 "알 수 없다"가 된다. 세는 규칙은
`prereg-02-pilot.md` §2.1, 구현은 `src/analysis/finlife_rules.py`.

## 3. 이 문제가 실재한다는 근거

**빈도가 아니라 존재를 보인다.** 아래는 우리가 만든 사례가 아니라 외부 자료다.

| 근거 | 무엇을 말하는가 | 우리 데이터의 대응 |
|---|---|---|
| **금융위원회 소비자 경보** (2023-04-05) — "최고금리 10%를 보고 가입했으나 가입 이전 6개월 카드 사용실적이 있어 우대금리를 못 받았다" | 부정 조건 때문에 실제 피해가 발생한다 | (나) 부정 조건 2건 |
| **같은 경보** — "최고금리가 높아도 기본금리가 낮으면 시중금리보다 낮아질 수 있다. 최종 예상금리를 비교해 결정하라" | 규제기관이 **최종 예상금리 계산·비교**를 소비자에게 요구한다 | (라) 상한 46건 · 기본금리 181건 |
| **금감원 '금융상품 한눈에' 소비자 만족도 조사** — "첫 거래, 타 상품 가입, 비대면 가입 등 우대금리를 적용하는 상품의 **일괄 검색이 어렵다**"는 의견에 따라 검색조건 신설 | 사용자가 **조건 유형별로** 상품을 찾고 싶어한다 | 첫거래 17건 · 타상품가입 41건 · 비대면 13건 |
| **실제 사용자 질문** — "급여이체 우대 조건은 무엇으로 급여를 인식하나요?" (답: 6회 이상·월 50만원·적요 문구) | 공시 문구만으로는 조건 충족을 판정할 수 없다 | (다)② 급여이체 10건 |

**마지막 줄이 특히 중요하다.** 조건 유형별 검색 수요는 우리가 세운 "조건 유형 노드"가
사용자에게 실제로 필요한 축이라는 뜻이다 — 우리 편의를 위한 설계가 아니다.

출처는 §7에 링크로 정리했다.

## 4. 우리가 가진 재료

한 줄 요약: **표본이 병목이던 상태를 벗어났다.**

```
상품            예금 38 + 적금 59 = 97건   (금융감독원 API, 2026-08-24 스냅샷)
조건 있는 상품   86건
기간별 금리      181건 (기본금리·최고금리)
조건 유형        16종 — 자동이체 25 · 카드 20 · 첫거래 17 · 마케팅동의 15 · 비대면 13 · 급여이체 10 …
혜택 갈래 2개+   59건 (3개+ 48 · 4개+ 27)
합산 상한 명시   46건
외부 상품 요구   41건
두 상품 조합     4,656가지
```

이전에 막혀 있던 숫자와 비교하면 차이가 분명하다 — 조건 누락 사례 3건,
레코드를 건너가는 사슬 4건(`decisions/0002`에서 폐기).

## 5. 고정하는 시나리오

**두 단계로 고정한다. 순서가 중요하다.**

**시나리오 A — 단일 상품 · 사용자 상태 주어짐** (파일럿은 여기서)

```
입력: 사용자 상태 { 급여이체 O, 자동이체 O, 카드실적 X, 청약 X, 12개월, 1천만원 }
      + 상품 하나의 공시 원문
답변: "이 상품에서 연 3.35%를 받을 수 있다"
정답: 원문으로 계산한 값 (기본금리 + 충족 조건의 우대금리, 상한 적용)
판정: SUPPORTED / UNSUPPORTED / INSUFFICIENT
```

**시나리오 B — 두 상품 비교** (그래프가 필요해지는 지점)

```
답변: "A가 유리하다. A 3.35% vs B 3.10%"
```

B가 A보다 어려운 이유는 하나다 — **사용자 상태 하나를 두 상품의 서로 다른 문구에
동시에 매칭**해야 한다. "자동이체"를 요구하는 상품 25개에 서로 다른 문구가 24종이다
(`자동이체실적` / `②공과금자동이체` / `자동이체우대금리연` …). 문구로는 매칭이 안 되고
**조건 유형으로만** 된다.

## 6. 그래프가 하는 일 — 그리고 하지 않는 일

**하는 일 두 가지.**

- **비교 쌍 선정**: 4,656개 조합에서 무작위로 뽑으면 대부분 한쪽이 압도적인 시시한 쌍이
  나온다. 조건 구조가 비슷한 쌍이 어려운 문제다. 상품↔조건유형 이분 그래프를 투영해
  유사도로 뽑는다. **측정 가능한 주장**: 그래프로 뽑은 쌍이 무작위 쌍보다 검증기
  오답률이 높다
- **반박 근거 경로**: "왜 3.35%가 아닌가"를 경로로 제시한다
  (`카드실적 X → ③갈래 미충족 → 0.1% 제외 → 3.25%`)

**하지 않는 일.** 조건 유형 매칭 자체는 조인(join)이고, 상한·기간 검사는 제약 검사다.
둘 다 그래프가 아니어도 된다. 그래서 ablation으로 가른다 — A(정규화+조인만) /
B(+그래프 유사도 쌍 선정).

**선행 연구는 이 방향을 지지한다.** 규칙 그래프로 LLM 출력을 결정론적으로 검증하고
"Rule 5.4에 따라 거주 12개월 미만이므로 자격 없음"처럼 반박하는 패턴이 이미 쓰인다
(§7). 즉 **신규성이 높은 접근은 아니지만 정당성이 확인된 접근**이다. 우리 기여는
한국 금융 공시 도메인에 적용한 것과, 측정 전에 예측·임계를 등록하는 방법론이다.

## 7. 아직 없는 근거 — 정직하게

- **빈도 통계가 없다.** "우대금리 관련 민원이 연간 몇 건인가"는 검색으로 찾지 못했다.
  금감원 통계자료실에서 직접 받아야 한다. 지금은 **존재 증명까지만** 확보한 상태이고,
  이걸 효과 크기 주장에 쓰지 않는다
- **실사용 질문 분포가 없다.** 우리가 정하는 사용자 상태 분포는 실제 분포가 아니다.
  방어는 세 겹으로 한다 — 존재 증명(위 §3) + 발견 비율 공개 + **상태 분포를 바꿔가며
  결론이 뒤집히는지 보는 민감도 분석**
- **이 태스크의 실패는 아직 관측되지 않았다.** 선행 프로젝트가 관측한 실패는 단일 상품
  검증에서 나왔다. 그래서 첫 작업은 **파일럿**이다 — 시나리오 A로 20~30건을 만들어
  기존 모델에 물어보고 오답이 실재하는지 본다. 오답이 기준 미달이면 이 태스크는 닫는다
