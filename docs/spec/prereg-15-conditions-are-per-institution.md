# prereg-15 · 조건을 기관별로 가른다 — 고치기 전에 예측을 적는다

> 작성 2026-09-02 (**구현 전**) · 로드맵 F6 · 이슈
> [#44](https://github.com/hyos0415/fineprint/issues/44)

**이 문서는 구현 전에 쓴다.** 지표·임계·표본을 측정 **전에** 못 박는 것이 이 저장소의
규율이고(`CLAUDE.md` 3번), 이번엔 **기준선이 움직이는 변경**이라 특히 필요하다.

## 왜 고치나 — 지금 불가능한 것을 참이라고 말한다

사용자의 답이 **기관과 무관한 전역 값**이다(`state = {조건유형: 예/아니오/모름}`).
그래서 답 하나가 여러 기관 상품을 한꺼번에 올린다. 은행권 12개월 실측이다.

```
자동이체            답 하나 → 상품 22개 · 기관 10곳
첫거래_신규고객       답 하나 → 상품 21개 · 기관 10곳
타상품_보유동시가입    답 하나 → 상품 19개 · 기관 9곳
주거래_장기거래_재예치  답 하나 → 상품 12개 · 기관 8곳
```

**더 나쁜 것은 논리적으로 불가능한 조합을 허용한다는 것이다.** "첫거래" 는 그 은행과
거래가 **없어야** 받고 "주거래" 는 거래가 **있어야** 받는데, 지금은 둘 다 받는다.

```
애큐온저축은행 처음만난적금    첫거래 +3.50%p · 주거래 +2.00%p  → 지금 +5.50%p 를 다 준다
부산은행 더(The) 특판 정기예금  첫거래 +0.75%p · 주거래 +0.75%p  → 지금 +1.50%p
전북은행 JB 123 정기예금      첫거래 +0.50%p · 주거래 +0.30%p  → 지금 +0.80%p
경남은행 주거래 프리미엄 적금    첫거래 +0.20%p · 주거래 +0.50%p  → 지금 +0.70%p
국민은행 KB내맘대로적금       첫거래 +0.10%p · 주거래 +0.10%p  → 지금 +0.20%p
세람저축은행 내가디자인하는적금   첫거래 +0.10%p · 주거래 +0.40%p  → 지금 +0.50%p
중소기업은행 IBK평생한가족통장   첫거래 +0.05%p · 주거래 +0.25%p  → 지금 +0.30%p
```

**은행권 5개 · 저축은행 2개.** `problem.md` 가 인용한 피해 사례가 *"최고금리 10%를
보고 가입했는데 우대금리를 못 받았다"* 다. **우리가 그것을 작은 규모로 재생산한다.**

## §1 무엇을 바꾸나

**기관 상대 조건의 답을 기관별로 갖는다.** 그리고 목록 질문 하나로 대부분을 유도한다.

```
① 한 번 묻는다      "거래해 본 은행을 골라주세요" (여러 개 가능)
② 안 고른 은행은     전부 유도된다 — 첫거래 = 예 · 그 은행 실적 조건 전부 아니오
                  **거래가 없으면 그 은행에 실적이 있을 수 없다**
③ 고른 은행에만      실적 조건을 되묻는다
④ 기관 무관 조건은    전역으로 한 번만 묻는다
```

### 유형 분류 (사람이 확정 · 2026-09-02)

**기관 상대 — 그 은행과의 관계·실적**
```
첫거래_신규고객         그 은행 거래 이력이 **없어야** 한다   ← ①의 목록으로 전부 정해진다
주거래_장기거래_재예치    그 은행과 거래가 **있어야** 한다
급여_연금이체          그 은행 계좌로 급여
카드실적              그 은행 카드 실적
자동이체              그 은행 계좌에서 자동이체
타상품_보유동시가입      그 은행의 다른 상품
```

**기관 무관 — 사용자 자신의 사실이거나, 마음먹으면 어디서든 할 수 있는 것**
```
고객군_자격            나이·지역·다자녀 — 사용자 속성이다
마케팅_정보동의         사람 확정 — "어려운 미션이 아니고, 이득이 되면 하겠다"
실천_미션_인증          사람 확정 — 위와 같은 층위로 본다
비대면_채널가입 · 오픈뱅킹_타행계좌등록 · 쿠폰_코드_추천인
목표달성_납입실적        **이 상품 자체**에 대한 것이다 (기관이 아니라 상품 상대)
무조건_특판_이벤트 · 기타 · 판정불가_불특정
잔액_평잔_가입금액       **실측 근거로 기관 무관에 둔다 — 아래 §1.1**
```

### §1.1 `잔액_평잔_가입금액` 은 왜 기관 무관인가 (사람 추측과 다른 결론)

사람이 *"아마 해당 은행에 예치금이 있는 케이스겠지? 그러면 같은 은행 얘기가 맞지
않을까"* 라고 물었다. **문구를 전부 꺼내 읽어 보니 두 가지가 섞여 있었다.**

```
그 은행 예치금 (기관 상대)          이 상품 가입금액 (사용자가 정한다)
  아이엠뱅크 전월 총수신 평잔 30만원      SC e-그린세이브 5천만원 이상 가입
  광주은행 요구불평잔                  광주은행 1천만원이상 0.20%p
  제주은행 자투리 출금계좌 평잔 50만원     경남은행 가입(재예치)금액 20백만원
  애큐온 입출금통장 월 평잔 50만원        경남은행 월부금 50만원
  웰컴 입출금통장 평잔 50만원 (3건)      푸른·안양 계약금액 10억
                                   웰컴 총 불입금 1백만원
```

**기관 상대로 두면 새 오류가 생긴다.** 거래 없는 은행의 게이트가 "아니오" 로 유도되면
평잔 문구는 맞게 걸리지만 **가입금액 문구까지 막힌다** — 거래해 본 적 없는 은행에도
1천만원은 넣을 수 있다.

**기관 무관으로 두어도 과대 진술이 없다** — 이 유형의 유형 답 하나로 올라가는 상품이
**0개**다(실측). `has_threshold()` 가 문구의 금액을 보고 **항상 문구 단위 후속 질문을
요구**하기 때문이다. 그래서 실질 판정은 이미 문구 단위이고, 문구는 상품 하나에 붙는다.

**남는 일은 따로 적는다** — 0단계에서 **가입 금액을 받으면** 이 유형의 문구 3개(권역별)가
질문 없이 풀리고, `E4`(세금 3층 · 2천만원 선)의 선행도 채워진다. 이 사전등록의 범위 밖이다.

### §1.2 문구 단위 키에 기관을 넣는다

문구 단위 키(`유형#해시`)가 기관을 안 담는다. 실측으로 **은행권 209개 중 1개**(0.5%)가
기관 2곳이 같이 쓰는 키였다(`급여_연금이체#deb3d786` — 국민은행·케이뱅크). 저축은행은
133개 중 0개다. **작지만 같은 결함이므로 키에 기관을 넣어 없앤다.**

## §2 기준선 — 측정 전에 못 박는다

`0018` 의 **예산 12개 시점**과 **전부 답한 시점** 둘 다 적는다.

```
                         예산 12개 시점                전부 답한 시점
은행권 12개월    메인 67 · 확정 37 (55.2%)      메인 67 · 확정 39 (58.2%)
              폭평균 0.185 · 폭최대 1.861      폭평균 0.172 · 평균 확정금리 2.98%
              질문 15개
저축은행 12개월  메인 106 · 확정 75 (70.8%)     메인 106 · 확정 82 (77.4%)
              폭평균 0.449 · 폭최대 7.614      폭평균 0.405 · 평균 확정금리 3.16%
              질문 13개
```

**`0018` 과 충돌하지 않는다.** `0018` 은 후보 D(*"질문 개수 자체에 상한을 두고 넘으면
불인정"*)를 **명시적으로 기각**했다 — 예산 12개는 *지표를 상위 12개 질문 시점에서
잰다* 는 뜻이다. 다만 **그 12개의 구성이 바뀌므로 예산 시점 값이 움직인다.**

## §3 예측 — 구현 전에 적는다

시뮬레이션(상품마다 그 기관에 맞는 상태를 주는 것)으로 미리 재 봤고, 그것이 지금
동작을 정확히 재현하는 것을 확인했다(거래 은행 전부 → 확정 39·82 로 기준선과 일치).
**아래는 그 시뮬레이션이 아니라 구현 결과에 대한 예측이다.**

```
P1  **확정률이 오른다.** 은행권 58.2% → 70% 이상 (거래 은행 1곳 페르소나)
    근거 — "아니오" 는 결정적이다. 거래 없는 은행 16곳의 실적 조건이 유도로 확정되므로
    범위가 확정으로 옮겨간다. 시뮬레이션에서 확정 39 → 47 이었다

P2  **평균 확정 금리는 내려간다.** 은행권 2.98% → 2.80% 아래
    근거 — 과대 진술이 사라진다. 시뮬레이션 2.73%

P3  **과대였던 상품이 은행권에서 30개 이상**이다 (메인 67개 중)
    평균 과대폭 0.4%p 이상 · 최대 3%p 이상
    근거 — 시뮬레이션에서 30개 · 0.55%p · 3.38%p

P4  **첫거래·주거래를 동시에 받는 상품이 0개가 된다** — 은행권 5개 · 저축은행 2개가
    지금 그렇다. 유도 규칙이 들어가면 논리적으로 불가능해진다

P5  **질문 수는 거래 은행 수에 따라 이렇게 된다** (은행권 · 지금 15개)
    ```
    0곳 10개(-5) · 1곳 16개(+1) · 2곳 21개(+6) · 3곳 26개(+11) · 17곳 61개(+46)
    ```
    저축은행권은 1곳이면 **지금과 같은 13개**다

P6  **예산 12개 시점의 폭 평균은 나빠진다** (은행권 0.185 → 0.25 이상)
    근거 — 질문 하나가 이제 기관 하나만 연다. 예산 안에 드는 질문이 여는 상품 수가
    줄어든다. **이것을 개선으로 위장하지 않는다** — 정확성의 대가로 기록한다

P7  **상위 3위 교체는 계속 0에 가깝다** — 지금 전 구간 0이다(`0017`).
    유도로 금리가 내려가는 상품이 30개면 순위가 흔들릴 수 있다. 3회 이상 나오면
    `0017` 의 반증 조건("상위 3위 교체가 답마다 2개 이상 계속 일어나면")을 다시 본다
```

## §4 이 측정이 못 하는 것 — 미리 적는다

```
페르소나가 인공이다
  → "거래 은행 N곳 + 나머지 전부 예" 는 실제 사용자가 아니다. 실제 분포를 모른다
급여이체를 배타로 두지 않는다
  → 한 사람이 급여를 한 은행으로만 받는 것이 보통이지만 분할 입금이 가능하다.
    **추측하지 않는다**(`0016`) — 사용자가 여러 은행에 예라고 답하면 그대로 둔다
"거래해 본" 의 정의를 사용자가 정한다
  → 계좌만 만들고 안 쓴 것을 거래로 볼지는 사람마다 다르다. 우리가 정의하지 않고
    문구를 그대로 보여주고 답을 받는다
잔액 유형은 이번 범위 밖이다
  → §1.1 대로 기관 무관에 두고, 0단계 금액 입력은 별도 과업이다
```

## §5 이 결과로 무엇을 하나

```
P1·P2·P3 이 맞으면   결정으로 기록한다. **정확성이 올라가고 확정률도 올랐다**는
                  드문 경우다 — 보통은 하나를 얻으면 하나를 잃는다
P4 가 틀리면        유도 규칙이 안 들어간 것이다. 구현 결함이므로 고친다
P6 이 예상보다 나쁘면  (폭 평균 0.35 이상) 질문 순서를 다시 본다 — `0018` 의 커버리지
                  순 정렬이 기관별 질문에 맞지 않을 수 있다
P7 이 틀리면        `0017` 의 반증 조건이 발동한다. 정렬을 다시 논의한다
```

**무엇을 고칠지는 위에 있고, 얼마나 움직였는지는 구현하고 나서 잰다.**
