## 왜 고치나 — 지금 불가능한 것을 참이라고 말한다

사용자의 답이 **기관과 무관한 전역 값**이다(`state = {조건유형: 예/아니오/모름}`).
그래서 답 하나가 여러 기관 상품을 한꺼번에 올린다. 은행권 12개월 실측이다.

```
자동이체            답 하나 → 상품 22개 · 기관 10곳
첫거래_신규고객       답 하나 → 상품 21개 · 기관 10곳
타상품_보유동시가입    답 하나 → 상품 19개 · 기관 9곳
주거래_장기거래_재예치  답 하나 → 상품 12개 · 기관 8곳
```

**더 나쁜 것은 논리적으로 불가능한 조합을 허용한다는 것이다.** "첫거래" 는 그 은행과
거래가 **없어야** 받고 "주거래" 는 거래가 **있어야** 받는데, 지금은 둘 다 받는다.

```

부산은행 더(The) 특판 정기예금  첫거래 +0.75%p · 주거래 +0.75%p  → 지금 +1.50%p

국민은행 KB내맘대로적금       첫거래 +0.10%p · 주거래 +0.10%p  → 지금 +0.20%p
세람저축은행 내가디자인하는적금   첫거래 +0.10%p · 주거래 +0.40%p  → 지금 +0.50%p

**은행권 5개 · 저축은행 2개.** `problem.md` 가 인용한 피해 사례가 *"최고금리 10%를
보고 가입했는데 우대금리를 못 받았다"* 다. **우리가 그것을 작은 규모로 재생산한다.**

## §1 무엇을 바꾸나

**기관 상대 조건의 답을 기관별로 갖는다.** 그리고 목록 질문 하나로 대부분을 유도한다.

```
① 한 번 묻는다      "거래해 본 은행을 골라주세요" (여러 개 가능)
② 안 고른 은행은     전부 유도된다 — 첫거래 = 예 · 그 은행 실적 조건 전부 아니오
                  **거래가 없으면 그 은행에 실적이 있을 수 없다**
③ 고른 은행에만      실적 조건을 되묻는다
④ 기관 무관 조건은    전역으로 한 번만 묻는다
```

### §1.1 `잔액_평잔_가입금액` 은 왜 기관 무관인가 (사람 추측과 다른 결론)

사람이 *"아마 해당 은행에 예치금이 있는 케이스겠지? 그러면 같은 은행 얘기가 맞지
않을까"* 라고 물었다. **문구를 전부 꺼내 읽어 보니 두 가지가 섞여 있었다.**

```
그 은행 예치금 (기관 상대)          이 상품 가입금액 (사용자가 정한다)
  아이엠뱅크 전월 총수신 평잔 30만원      SC e-그린세이브 5천만원 이상 가입
  광주은행 요구불평잔                  광주은행 1천만원이상 0.20%p
  제주은행 자투리 출금계좌 평잔 50만원     경남은행 가입(재예치)금액 20백만원
  애큐온 입출금통장 월 평잔 50만원        경남은행 월부금 50만원
  웰컴 입출금통장 평잔 50만원 (3건)      푸른·안양 계약금액 10억
                                   웰컴 총 불입금 1백만원
```

**기관 상대로 두면 새 오류가 생긴다.** 거래 없는 은행의 게이트가 "아니오" 로 유도되면
평잔 문구는 맞게 걸리지만 **가입금액 문구까지 막힌다** — 거래해 본 적 없는 은행에도
1천만원은 넣을 수 있다.

**기관 무관으로 두어도 과대 진술이 없다** — 이 유형의 유형 답 하나로 올라가는 상품이
**0개**다(실측). `has_threshold()` 가 문구의 금액을 보고 **항상 문구 단위 후속 질문을
요구**하기 때문이다. 그래서 실질 판정은 이미 문구 단위이고, 문구는 상품 하나에 붙는다.

**남는 일은 따로 적는다** — 0단계에서 **가입 금액을 받으면** 이 유형의 문구 3개(권역별)가
질문 없이 풀리고, `E4`(세금 3층 · 2천만원 선)의 선행도 채워진다. 이 사전등록의 범위 밖이다.

### §1.2 문구 단위 키에 기관을 넣는다

문구 단위 키(`유형#해시`)가 기관을 안 담는다. 실측으로 **은행권 209개 중 1개**(0.5%)가
기관 2곳이 같이 쓰는 키였다(`급여_연금이체#deb3d786` — 국민은행·케이뱅크). 저축은행은
133개 중 0개다. **작지만 같은 결함이므로 키에 기관을 넣어 없앤다.**

## §3.1 측정 페르소나를 못 박는다 (**측정 전** 추가 · 2026-09-02)

**왜 추가하나.** §3 이 *"거래 은행 1곳 페르소나"* 라고만 적었고 **어느 은행인지는 안
적었다.** 그런데 어느 곳을 고르는지가 숫자를 바꾼다 — 상품을 많이 가진 은행을 고르면
되물을 조건이 많아 확정률이 낮게 나오고, 적게 가진 은행을 고르면 높게 나온다.
**결과를 보고 고르면 유리한 값을 고르는 것**이라 측정 전에 규칙을 적는다.

```
지금(기준선)     유형 질문을 전역으로 전부 "예" — §2 의 "전부 답한 시점" 과 같은 상태
새 동작 · N곳    거래 은행 = 상품 커버리지 상위 N곳 · 나머지 질문은 전부 "예"
                N = 0 · 1 · 2 · 3 · 전부
```

**P1·P2·P3 은 "1곳" 으로 판정하되, 어느 한 곳을 고르지 않는다** — 은행권 17곳 각각을
"그 한 곳" 으로 둔 **17개 페르소나 전부**를 재고 **중앙값**으로 판정한다. 최소·최대도
같이 적는다. 저축은행도 같은 방식이다(기관 17곳).

**§2 기준선의 숫자 하나를 정정한다.** §2 의 *"전부 답한 시점"* 열은 **유형 질문만
답한 상태**이고(문구 단위 후속 질문은 안 답한 상태), 그 정의로 재현된다 —
은행권 확정 39/67 · 폭평균 0.172 · 폭최대 1.861, 저축은행 82/106 · 폭평균 0.405.
`평균 확정 금리` 는 **메인 상품의 `net_lo` 평균**이다(은행권 2.975 · 저축은행 3.160).
확정 층만 평균하면 3.176·3.236 이라 §2 의 값과 다르다 — **§2 가 쓴 정의가 앞의
것**이므로 그것을 쓴다. 문구 질문까지 전부 답하면 확정 50/67 · 폭평균 0.105 다.

**"질문 수" 의 정의도 §2 와 맞춘다** — 유형 질문 수다(문구 단위 후속 제외). 은행권
15 · 저축은행 13 이 그 값이다. 전체(문구 포함)는 39 · 45 다.

## §4 이 측정이 못 하는 것 — 미리 적는다

```
페르소나가 인공이다
  → "거래 은행 N곳 + 나머지 전부 예" 는 실제 사용자가 아니다. 실제 분포를 모른다
급여이체를 배타로 두지 않는다
  → 한 사람이 급여를 한 은행으로만 받는 것이 보통이지만 분할 입금이 가능하다.
    **추측하지 않는다**(`0016`) — 사용자가 여러 은행에 예라고 답하면 그대로 둔다
"거래해 본" 의 정의를 사용자가 정한다
  → 계좌만 만들고 안 쓴 것을 거래로 볼지는 사람마다 다르다. 우리가 정의하지 않고
    문구를 그대로 보여주고 답을 받는다
잔액 유형은 이번 범위 밖이다
  → §1.1 대로 기관 무관에 두고, 0단계 금액 입력은 별도 과업이다
```

P6 이 예상보다 나쁘면  (폭 평균 0.35 이상) 질문 순서를 다시 본다 — `0018` 의 커버리지
                  순 정렬이 기관별 질문에 맞지 않을 수 있다
P7 이 틀리면        `0017` 의 반증 조건이 발동한다. 정렬을 다시 논의한다
```

**무엇을 고칠지는 위에 있고, 얼마나 움직였는지는 구현하고 나서 잰다.**

### P5 — 예측보다 질문이 적었던 이유는 P4 를 고친 것이다

거래 1곳이면 예측이 16개였는데 **15개**였다. 한 기관 안에서 `첫거래` 와 `주거래` 가
**배타**라서, 커버리지 순으로 먼저 오는 쪽만 묻고 다른 쪽은 유도로 "아니오" 가 된다.
예측을 쓸 때는 그 유도를 셈에 넣지 않았다. **P4 를 고친 것이 질문 수도 하나 줄였다.**

2곳(예측 21 → 실측 16) · 3곳(26 → 20)의 차이는 **어느 기관을 고르느냐**다. §3.1 이
"상품 커버리지 상위 N곳" 으로 못 박았고, 커버리지 상위 기관이 반드시 기관 상대 조건을
많이 가진 기관은 아니다 — 부산은행은 상품 수는 2위인데 기관 상대 조건은 둘뿐이다.

### P6 — 왜 반대로 틀렸나. 예측의 논리는 **한 경로에서만** 맞았다

예측의 근거는 *"질문 하나가 이제 기관 하나만 연다"* 였다. 그 말은 맞지만 **목록 질문을
셈에서 빼놓았다** — 목록 질문 하나가 기관 16곳의 조건을 한꺼번에 "아니오" 로 정하므로,
예산 12개 안에서 옛 동작보다 훨씬 멀리 간다.

```
예산 12개 · 은행권 폭 평균     기준선 0.185
  거래 0곳    0.089     거래 1곳  0.105     거래 2곳  0.126     거래 3곳  0.135
  목록에 "모름"            0.432   <- 예측의 논리가 맞는 유일한 경로
```

**"모름" 경로에서는 예측이 맞았다.** 유도가 걸리지 않으니 질문 하나가 기관 하나만 열고,
예산 12개 시점의 폭 평균이 0.432 로 기준선보다 크게 나쁘다(확정률도 20.9%).
§5 의 판정 조항("폭 평균 0.35 이상이면 질문 순서를 다시 본다")은 §3.1 이 못 박은
N곳 페르소나를 두고 쓴 것이라 발동하지 않지만, **이 경로는 남은 일로 적는다** —
목록에 모른다고 답한 사용자는 예산 안에서 옛 동작보다 못한 화면을 본다.

### P7 — 교체가 일어난 자리는 목록 질문 하나였다

단계별 교체 수가 은행권에서 `[2, 1, 0, 0, ...]` 이다. **1단계(목록 질문)에서 2개,
2단계에서 1개, 그 뒤로 전 구간 0**이다. 목록 답 하나가 기관 16곳의 조건을 정하니
그 순간 순위가 움직이는 것이 당연하고, `0017` 의 반증 조건은 *"답마다 2개 이상 계속"*
이라 발동하지 않는다. 거래 은행을 전부 고른 페르소나와 "모름" 페르소나는 교체 0이다.

### 얻은 것과 잃은 것

**정확성이 올라가고 확정률도 올랐다.** 보통은 하나를 얻으면 하나를 잃는데 이번은
아니었다 — 사용자가 답할 수 없던 것(*"8개 은행에서 동시에 주거래"*)을 묻지 않게 되면서
**"아니오" 가 유도로 채워지고, "아니오" 는 결정적**이기 때문이다.

잃은 것 셋을 적는다.

```
질문이 늘 수 있다        거래 은행이 3곳이면 은행권 20개(지금 15개)다. 거래가 없거나
                     1~2곳이면 오히려 줄어든다(10·15·16개)
"모름" 경로가 나쁘다     목록에 모른다고 답하면 예산 12개 시점이 옛 동작보다 못하다
                     (폭 평균 0.432 vs 0.185). 남은 일이다
"거래해 본" 을 우리가     정의하지 않는다(§4). 계좌만 만들고 안 쓴 것을 거래로 볼지는
정의하지 않는다          사람마다 다르고, 그것을 우리가 정하면 추측이 된다
```
