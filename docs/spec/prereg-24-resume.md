# prereg-24 · 이어하기(D9) — 이어받은 화면은 원 화면과 같아야 한다

> 작성 2026-09-04 (**고치기 전**) · 이슈 [#67](https://github.com/hyos0415/fineprint/issues/67) ·
> 근거 `0026` D3(피로는 이어하기·순서·문구로 다룬다 · 질문 수로는 안 다룬다) · `0040`(무상태 · 이어하기는
> 클라이언트 보관으로 공짜) · 로드맵 §D D9

## §1 없으면 어떻게 되나

질문이 은행권 86개 · 저축은행 71개다. `0026` 은 질문 수를 줄이지 않기로 정했고 그 대신 **멈췄다가 이어서
답하는 길**을 약속했다. 지금은 CLI 를 닫으면 세션 로그만 남고 다시 시작하면 1번부터고, 웹은 화면을 닫으면
`state` 가 폼 hidden 과 함께 사라진다(`prereg-21` 이 3런 기록을 사람이 `state_json` 을 붙여 줘서 복원한 것이
그 증거다). 약속한 길이 없는 상태다.

## §2 무엇을 만드나

- **CLI** — `ask_loop.py --resume <ask_session_*.json>`. 로그의 스냅샷·권역·기간·스코프·선호·`state` 를 이어받아
  **다음 질문부터** 묻는다. 로그에 스코프(`company`·`kinds`)와 선호 원문(`prefs_arg`)이 없어 먼저 넣는다 —
  그 전 로그는 스코프 없이 이어지므로 경고를 낸다. 이어받은 세션의 로그에는 `resumed_from` 을 적는다
- **웹** — 화면 아래 **"이어하기 코드"**: 스냅샷·권역·기간·스코프·선호·정렬·답 전부를 담은 JSON 한 덩이를
  `<textarea readonly>` 로 보인다. 0단계 폼의 "이어하기 코드" 칸에 붙여 넣고 제출하면 그 자리에서 이어진다.
  코드는 서버가 만들고(`app.py`) 템플릿은 꽂기만 한다(`0043`). **JS 없이 돈다**
- **하지 않는 것** — 서버 세션 · 쿠키 · 계정 · `localStorage`(`0040` · `0026` 반증 조건 "저장·계정 기능을 만드는
  순간 다시 본다"). 코드는 **사용자가 든다.** 화면에 그렇게 적는다 — *"이 코드는 서버에 남지 않습니다. 이어서
  답하려면 보관해 두세요"*. 다운로드 링크를 만들지 않는다 — 복사가 되는 텍스트 상자로 충분하고, `0040` 반증
  조건이 "잃으면 파일 내려받기부터" 라고 순서를 적어 뒀다

## §3 예측 — 고치기 전에 적는다

기준 출력은 고치기 전에 받아 뒀다 — `--auto 예`(은행권 전체) 와 `--company 우리 --kind 적금 --answers 예,아니오,모름,예`
(4개 답한 뒤 대본이 떨어져 중단).

```
P1  CLI 동일     4개 답한 로그로 --resume 하고 바로 '그만' 하면, 그 세션의 3단계 화면(문자열)이 원 세션의
                3단계 화면과 같다 · 남은 질문 수도 같다
P2  웹 동일      어떤 state 의 화면을 정상 경로(답을 하나씩)로 만든 HTML 과, 그 화면의 이어하기 코드를 0단계 폼에
                넣어 만든 HTML 이 **같다**
P3  코드 크기    "전부 답한" state 의 이어하기 코드 — 은행권(86답)·저축은행(71답) 둘 다 **10KB 미만** (`0040` 임계)
P4  잘못된 코드   JSON 이 아닌 코드 · 모르는 조건 키 · 후보에 없는 은행 이름 → **0단계 폼에 문장으로** 오류가 난다
                (날 JSON 이 아니다 — `0040` 의 에러 계약)
P5  계약 무변동   A1~A17 두 권역 통과 그대로 · 0단계 폼(새 칸 포함) A14 통과
P6  CLI 회귀 0    --auto 예 출력이 기준과 같다 (세션 파일 이름 줄만 다르다)
```

## §4 판정 조항

```
P1·P2 가 틀리면  이어받기가 state 밖의 것(스코프·선호·정렬)을 빠뜨린 것이다. 무엇이 빠졌는지 적고 코드에 넣는다
P3 이 틀리면     `0040` 반증 조건 1 이 발동한다 — A 안(서버 세션)을 다시 본다. 여기서 정하지 않는다
P4 가 틀리면     HTML 경로의 감싸기가 새 입력을 안 덮은 것이다. 고친다
P5 가 틀리면     A14 면 새 문구의 낱말이다 — 문구를 고친다. 다른 코드면 이 변경과 무관한 회귀다
P6 이 틀리면     run() 시그니처 변경이 기본 경로를 건드렸다. 되돌린다
```

## §5 결과 (2026-09-04 · 고친 뒤)

**여섯 예측이 전부 맞았다 — P1 은 한 번 틀렸다가 §4 대로 고친 뒤 맞았다.**

```
P1  맞음(수정 뒤)  '없음,예' 두 답 뒤 대본이 떨어진 로그를 --resume 하고 '그만' → 3단계 화면 문자열 동일 · 남은 1 = 1.
                 **첫 시도는 한 줄이 달랐다** — 성과 줄의 "(폭 1.18 → 0.08%p)" 가 이어받은 세션에서 사라졐다.
                 폭 변화의 기준(첫 화면 `start`)이 세션 안에만 있었다. 로그에 `start`·`top1_start` 를 남기고
                 이어받게 했다 — 폭 변화는 사용자의 여정에 대한 말이고 여정은 원 세션에서 시작했다
P2  맞음         정상 경로로 3개 답한 화면 HTML 과, 그 이어하기 코드를 폼에 넣어(다른 칸은 일부러 저축은행·36개월로)
                 만든 HTML 이 **바이트 동일** — 코드가 폼의 다른 칸을 덮는다
P3  맞음         가장 긴 경로(목록 "모름" · 전부 예) — 은행권 80답 4,016 B · 저축은행 68답 3,757 B. 10KB 의 40%
P4  맞음         JSON 아님 · 모르는 조건 키 · 후보에 없는 은행 → 전부 400 과 한국어 문장 (HTML 경로가 감싼다)
P5  맞음         A1~A17 두 권역 · 두 정렬 통과 · 0단계 폼(새 칸) A14 통과
P6  맞음         --auto 예 출력이 기준과 같다 (세션 파일 줄 제외)
```

**옛 로그는 스코프 없이 이어진다.** 이 변경 전 로그에는 `company`·`kinds` 가 없어 `--resume` 이 경고를 내고
전체 후보에서 이어진다 — 스코프를 `--company`·`--kind` 로 다시 주면 맞다. 옛 로그의 `state` 자체는 그대로 쓸 수 있다.

**측정에서 배운 것 하나** — 첫 질문이 목록 질문인 스코프(우리 적금)에서 대본 `예` 는 "읽을 수 없는 답" 이라 0개
답하고 멈춘다. 기준 로그를 그렇게 만들어 놓고 P1 이 "같다" 고 나온 것을 한 번 믿을 뻔했다(빈 상태는 뭘 해도
같다). 대본의 첫 답을 `없음` 으로 바꿔 다시 잰 것이 위 결과다.

결정은 [`0054`](../decisions/0054-the-user-holds-the-resume-code.md).
