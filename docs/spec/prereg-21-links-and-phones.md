# prereg-21 · 홈페이지 링크 · 대표전화(F3) — 링크가 열리고, 숫자는 안 바뀌고, 고지는 하나다

> 작성 2026-09-04 (**구현 전**) · 이슈 [#60](https://github.com/hyos0415/fineprint/issues/60) ·
> 근거 `0037`(링크만 주고 가입은 받지 않는다) · `prereg-20` §5(기관 97곳 100% · 스킴 없음 10곳) ·
> `0039`·`0043`(뷰 모델이 정하고 렌더러는 꽂는다) · 로드맵 §F F3

**사람이 스킴을 정했다** (2026-09-04): *"붙이든 안 붙이든 눌러서 열리게"*. 이 문서는 그 결정을
화면에 옮기면 무엇이 달라져야 하고 무엇이 달라지면 안 되는지를 **고치기 전에** 적는다.

## §1 없으면 어떻게 되나

사유 문장 셋(`조건불명`·`뜻없음`·`추첨`)이 전부 *"은행에 확인해 보세요"* 로 끝나는데 화면에 갈 곳이
없다. 사용자는 상품 이름을 복사해 검색해야 하고, 그 검색 결과 첫 줄이 기관 공식 페이지라는 보장이
없다. 재료는 있다 — `prereg-20` 이 기관 97곳의 홈페이지·대표전화를 100% 받아 뒀다.

## §2 무엇을 만드나

- `src/analysis/companies.py` — 두 권역 최신 `company_*.json` 을 읽어 `{fin_co_no: {홈페이지, 전화}}` 를
  만든다. 상품 행의 `co_no` 로 짝짓는다(이름으로 짝짓지 않는다 — `prereg-20` P4 가 코드 짝을 확인했다)
- `view.display()` 에 **`홈페이지`·`전화` 두 칸**을 더한다. 웹 표와 CLI 줄이 같은 칸을 읽는다
  (`0039` 반증 조건 1 — 한쪽만 쓰는 칸을 만들지 않는다). 웹은 `<a href>` 와 `tel:` 링크, CLI 는 상품
  줄 아래 한 줄이다
- **스킴 보정** — `homp_url` 이 `http://`·`https://` 로 시작하지 않을 때만 **화면에 낼 때** `https://` 를
  붙인다. 그 밖에는 API 값 그대로다(파라미터가 붙은 2곳도 그대로 · `0037` D2). 저장 데이터는 안 고친다
- **전화는 API 값 그대로다** — 숫자만 온다(8~10자리). 하이픈을 우리가 넣지 않는다. 대신 `tel:` 링크로
  눌러서 걸리게 한다 — 스킴 결정과 같은 태도다(표기를 지어내지 않고 동작만 보장)
- 고지(`calculate.NOTICE`)에 *"여기서 가입 신청을 받지 않습니다"* 를 더한다(`0037` D4). 상수는 하나이고
  CLI·웹·리포트·`/api/health` 가 그것을 읽는다 — 사본을 만들지 않는다
- 화면 계약 **A17** — (가) 목록의 모든 상품에 홈페이지·전화가 화면에 있다 (나) 화면 URL 은 API 값과
  같거나 `https://` + API 값이다 — 우리가 붙인 파라미터가 없다 (다) 전화는 API 값 그대로다.
  모델 겹(`check_model`)과 렌더 겹(CLI·웹) 둘 다 건다
- `fetch_companies.py --open` — 화면에 나갈 URL 97개를 실제로 열어 응답 코드를 센다. **집계만** 낸다
- **하지 않는 것** — 가입 흐름 · 추적 파라미터 · 제휴 코드(`0037` D1~D3). 스코프 밖 상품(A7 줄)에는
  링크를 안 붙인다 — 그 줄은 "밖에 무엇이 있나" 이고 목록이 아니다. 리포트(F1)에도 안 붙인다 — 리포트는
  "왜 이 금리인가" 이고 갈 곳은 목록에 있다

                 우리가 https:// 를 붙인 상품의 기관은 정확히 10곳이고 전부 저축은행이다
P3  숫자 무변동   빈 상태 뷰 모델 JSON 이 구현 전과 **같다** — 달라지는 것은 meta.고지 한 칸뿐이다.
                 (products 의 net_lo·net_hi·tier·caveats · questions · notices 전부 동일)
P4  계약         A1~A16 통과 그대로 · A17 위반 0 — 두 권역 × 두 정렬(hi·lo) × 페르소나 3 + 시드 30
P5  고지 하나    고지 문장이 코드에 한 곳(`calculate.NOTICE`)뿐이고 A13 이 CLI·웹·리포트에서 통과한다.

P6  내부 이름    A14 새 위반 0 — "홈페이지"·"전화" 는 우리가 지은 낱말이 아니다

## §4 판정 조항

```
P1 이 틀리면   안 열리는 기관은 링크를 **빈 칸**으로 낸다 — 다른 URL 을 찾아 채우지 않는다(추측 금지 ·
              `0016`). 몇 곳인지와 어떤 응답인지를 §5 에 적고 `0037` 반증 조건에 기록한다
P2 가 틀리면   빈 칸을 빈 칸으로 낸다(prereg-20 §4 와 같다). 짝이 안 되는 기관 코드를 §5 에 적는다.
              보정 수가 10 이 아니면 `--check` 와 화면이 다른 규칙을 쓰는 것이다 — 규칙을 한 곳으로 모은다
P3 이 틀리면   표시를 더하면서 계산을 건드린 것이다. **구현을 되돌리고** 어디서 새는지 먼저 찾는다
P4 가 틀리면   A17 이 잡은 것은 렌더러 누락이다(고친다). A1~A16 이 새로 걸리면 P3 와 같은 자리다
P5 가 틀리면   사본이 생긴 것이다 — `0035` 가 찾은 실패의 재현. 사본을 지우고 상수를 읽게 한다
P6 이 틀리면   A14 목록과 새 라벨이 겹친 것이다. 라벨을 고친다 — 목록은 안 고친다
```

## §5 결과 (2026-09-04 · 구현 뒤)

**여섯 중 넷이 맞았고 P1·P2 가 틀렸다. 그리고 A17 이 예측에 없던 것을 잡았다** — 저축은행 행의
절반이 **코드와 이름이 다른 기관**이다(아래).

```
P1  틀림   97곳 중 95곳 열림. 안 열린 둘의 사유가 다르다
             페퍼저축은행  파이썬 urllib 가 인증서 검증 실패(자체 서명 인증서가 체인에) · **curl 은 200**.
                          도구(파이썬 인증서 저장소)의 실패이고 브라우저는 OS 저장소를 쓴다 — 열린다고 본다
             JT저축은행    403 — 파이썬·curl·브라우저 UA 전부 403. 스크립트를 막는 WAF 로 보이지만
                          **브라우저로 열리는지는 확인하지 못했다.** 사람이 눌러 보는 것이 남았다
P2  틀림   빈 칸 0 (맞음). 보정 수는 틀렸다 — "기관 10곳" 은 상품 스냅샷 기관 97곳 기준이고 12개월 화면에는
           그 중 6곳(은행 0 · 저축은행 6)만 나온다. 규칙은 하나다 — `--check` 도 `companies.link()` 를 읽게
           바꿔 두 수가 같은 규칙에서 나온다는 것을 확인했다(전체 기관 기준 10 = 10)
P3  맞음   빈 상태 뷰 모델 JSON 이 두 권역 모두 `meta.고지` 한 칸만 다르다
P4  맞음   은행권 · 저축은행 × hi·lo × 페르소나 3 + 시드 30 — A1~A16 통과 · A17 통과
           (**코드-이름 대조를 더하기 전** 값이다. 더한 뒤 저축은행은 아래처럼 A17 불통과)
P5  맞음   옛 문장 grep 코드 0곳 · A13 CLI·웹·리포트 통과
P6  맞음   A14 새 위반 0
```

**판정 조항대로 하지 않은 것 하나 — 투명하게 적는다.** §4 는 P1 이 틀리면 안 열리는 기관의 링크를
빈 칸으로 내라고 했다. JT저축은행에 그것을 적용하지 않았다. 403 은 "스크립트에 안 열린다" 이고
사람이 브라우저에서 여는 것과 같은 질문이 아니라서, 빈 칸으로 만들려면 기관 제외 목록(사람이
관리하는 사전)을 새로 만들어야 한다. **사람이 브라우저로 한 번 열어 보고** 정하는 것이 맞다 —
안 열리면 §4 대로 빈 칸 처리 · 열리면 §3 의 "열린다" 정의를 브라우저 기준으로 고친다(이슈 #60).
페퍼저축은행은 curl 200 이라 열린다고 봤다. `--open` 은 실패 사유를 그대로 적게 고쳤다.

**사람이 확인했다 (2026-09-04 · 같은 날).** JT저축은행 홈페이지는 브라우저에서 열린다. 따라서 **97곳
전부 사용자 브라우저에서 열린다** — P1 이 재려던 것은 그것이었고, §3 의 "GET → 2xx/3xx" 는 도구
기준을 사용자 기준으로 잘못 적은 것이다. 정의를 **"사용자 브라우저에서 열린다"** 로 고쳐 적는다
(측정 뒤에 고치는 것이므로 여기 그대로 남긴다 · `0051` 반증 조건 2). `--open` 은 1차 선별 도구로
남고, 거기서 안 열린 곳은 사람이 브라우저로 본다. 빈 칸 처리는 없다.

### A17 이 잡은 것 — 링크가 이름과 다른 은행으로 간다 (저축은행)

링크는 `co_no`(금리 행의 기관 코드)로 가고 화면 이름은 행의 `company` 다. 둘이 같은 기관인지
대조를 A17 모델 겹에 더했더니 **저축은행에서 3,444건**이 걸렸다.

```
저축은행 12개월   행 297 중 160 · 메인 층 106 중 25 · 화면 상품 71 중 12 가 코드 ≠ 이름
은행권            0
예                코드 0010378(바로저축은행)의 금리 행에 하나저축은행 `1Q 비대면정기예금` 의 이름·조건
```

원인은 F3 가 아니라 **추출의 행 짝짓기**다 — `extract_llm.load_pairs()` 가 옵션을 상품에 붙일 때
상품코드만 키로 써서, 코드가 겹치는 기관(예금 52 · 적금 29 코드)에서 마지막 기관의 이름·조건이
이긴다. 금리는 A 것, 이름·조건·채널은 B 것인 행이다. 바로잡으면 추출 파일에 없는 문구 쌍이
**111개** 나온다(앞쪽 기관 문구는 한 번도 추출되지 않았다). **저축은행으로 잰 것 전부가 재측정
대상**이다. 여기서 고치지 않는다 — 이슈 [#61](https://github.com/hyos0415/fineprint/issues/61)
(`blocking`)으로 뺐고 `prereg-22` 를 먼저 쓴다.

**F3 의 상태** — 은행권 화면은 A17 까지 전부 통과다. 저축은행 화면은 #61 이 닫혀야 A17 을 통과한다.
링크를 이름 기준으로 바꿔 통과시키는 길은 **가지 않는다** — 그러면 금리와 링크가 다른 기관이 된다.
검사는 사실만 말하고, 사실은 행이 틀렸다는 것이다.
