# prereg-27 · R2 자연어 → 스코프 + 조건 답 후보 — 안전(잘못 채운 답 0)과 가치(질문이 몇 개 주나) 두 축

> 작성 2026-09-07 (**측정 전 · 모델 내려받는 중**) · 이슈 [#73](https://github.com/hyos0415/fineprint/issues/73) · `0057` ·
> 정답표 [`r2-sample-sentences.md`](./r2-sample-sentences.md)(합성 20문장 · 사람 검토 뒤 고정) · `0042`(로컬 · 원문 폐기)

## §1 왜 재나

사람 관점에서 R2 는 이 서비스의 핵심 기능이다 — *"자연어로 폼을 채울 수 있는 부분까지는 채워줘야 내가 원하던 서비스"*.
그리고 이 프로젝트에서 LLM 이 사용자와 직접 만나는 유일한 자리다. 그래서 두 축을 같은 무게로 잰다.

```
안전   모델이 채운 답이 사용자의 말과 다른 것이 **0 개**여야 한다 — 하나라도 있으면 과대 진술이 되는 자리
가치   사용자의 말로 조건 답이 몇 개 채워지고, 그 결과 질문이 몇 개 주는가 — 0 에 가까우면 만들 이유가 없다
```

기각 조건은 둘이다. 안전이 안 나오면 기각, 안전하지만 가치가 없어도 기각. **둘 다 결론이다**(`0057` D4).

## §2 무엇을 만드나 (측정용 최소)

- **서빙** — llama.cpp `llama-server`(b10830 · CUDA 13.3 · Windows) · OpenAI 호환 `/v1/chat/completions` · 모델은 한 번에 하나
- **후보 모델 셋** (GGUF · 8GB 안) — `Qwen3.5-4B Q5_K_M`(3.1GB) · `EXAONE-3.5-7.8B-Instruct Q4_K_M`(4.4GB) · `Qwen3.5-9B Q4_K_M`(5.3GB).
  Qwen3.5 는 `enable_thinking: false` 로 부른다(`CLAUDE.md`)
- **파서** `src/analysis/r2_parse.py` — 문장 하나 → JSON. **출력을 스키마로 강제**한다(`response_format: json_schema`):
  ```
  scope    group ∈ {bank, savingsbank, null} · banks: [기관 이름 enum] · kinds ∈ {예금, 적금, null} · term_months: int|null ·
           amount_deposit: int|null · amount_monthly: int|null
  traded   banks: [기관 이름 enum] | "없음" | null        (목록 질문 `_거래은행`)
  answers  [{type ∈ CONDITION_TYPES(17), bank ∈ 기관 이름 enum | null, value ∈ {예, 아니오, 모름}, evidence: 문장 조각}]
  ```
  기관 이름은 **두 권역 공시 이름 55개의 enum** 이라 없는 은행이 나올 수 없다. 코드가 `type_key(type, bank)` 로 상태 키를
  만들고 **후보 집합(`question_plan`)에 없는 키는 버린다** — 문구 `#` 키는 스키마에 없다(추출 시점 형식 제한 · `0057` D1).
  **원문은 반환 뒤 즉시 폐기** — 측정 스크립트도 정답표의 문장만 다시 읽고 모델 입출력을 파일에 남기지 않는다(합성 문장이라
  남겨도 개인정보는 아니지만, 운영과 같은 규칙으로 잰다)
- **측정** `src/analysis/measure_r2.py` — 20문장 × 모델 3 → 아래 지표. 프롬프트는 **한 벌**로 시작하고, 고치면 몇 번째
  판인지와 무엇을 고쳤는지를 §6 에 적는다(최대 2번 · `0057` 반증 조건 1)
- **이 사전등록에는 화면이 없다.** 확인 화면(A19)은 관문을 넘은 뒤의 일이다

## §3 지표 정의

문장마다 정답표의 `조건 답` 집합 L = {(키, 값)} 과 모델 출력 P = {(키, 값)} 을 비교한다. 정답표가 "둘 다 맞다" 로 둔 것
(첫거래 예 ↔ 거래 은행 `[]` · 모름 ↔ 비움)은 어느 쪽이든 맞은 것으로 센다.

```
잘못 채운 답     P 에 있는데 L 에 없는 (키, 값)  — 키가 맞고 값이 다른 것 · 문장이 말하지 않은 조건을 채운 것 · 무관한 정보를 넣은 것
빠뜨린 답       L 에 있는데 P 에 없는 것
스코프 정확도    권역·은행·상품군·기간·금액 다섯 칸을 칸 단위로 맞음/틀림 (비워야 할 칸을 채우면 틀림)
거래 은행       목록이 집합으로 같으면 맞음
지연           문장 하나의 왕복 초 (첫 토큰이 아니라 완료까지)
가치 (모델 무관)  정답표의 답을 그대로 state 에 넣었을 때 그 스코프의 "전부 답하면" 질문 수가 얼마나 주나 —
               라벨 기준이라 모델과 무관하게 **자연어 선채움의 상한**을 말한다
```

## §4 예측 — 재기 전에 적는다

```
P1  적재     세 모델 전부 8GB 에 올라가고 스키마 강제로 20/20 유효 JSON. 컨텍스트 4096 에서 VRAM 7GB 아래
P2  안전     첫 판 프롬프트에서 **어느 모델도 잘못 채운 답 0 이 아니다** (1~3개 · 틀리는 자리는 시제 — "옮길 생각 없어" 를
            예로, 무관 정보 넣기 — 12번 문장, 기관 붙이기 — 17번). 최고 모델은 ≤ 2. 두 번째 판에서 최고 모델이 0 에 닿을지는
            **반반** — 닿으면 관문 통과, 안 닿으면 기각
P3  재현     최고 모델의 빠뜨린 답 ≤ 30% (라벨 답 총수 기준). 크기 순 — 9B ≥ EXAONE 7.8B ≥ 4B
P4  스코프    다섯 칸 정확도 ≥ 90% (금액·기간이 가장 잘 맞고, 권역은 "저축은행" 낱말이 없으면 은행으로)
P5  지연     문장 하나 완료 < 5초 (GPU · 4096 ctx · 출력 200 토큰 안)
P6  가치     답이 있는 문장 14개에서 라벨을 state 에 넣으면 질문 수 중앙값 **-3 이상** (스코프가 좁은 문장은 -1~-2 · 거래
            은행 목록이 있는 문장은 F6 유도로 -5 이상). 답이 없는 문장 6개는 0
P7  회귀     자연어 상자를 비우면 화면·CLI 출력이 지금과 글자 하나 다르지 않다 (이 사전등록 단계에는 화면 변경이 없어 자명 ·
            화면을 붙일 때 다시 잰다)
```

## §5 판정 조항

P2 가 맞으면   (0 이 아님) 예측대로. 두 번째 판까지 고치고 §6 에 무엇을 고쳤는지 적는다. 두 번째 판에서도 최고 모델이 0 이 아니면

### 틀린 자리의 모양 — 다음 결정의 재료

- **뒤집힘**(가장 위험) — "거긴 처음이야 · 첫 거래야" 를 첫거래 **아니오**로(4B v1 · 2건 · 둘 다 필터가 걸러 화면엔 안 갔다).
  v2 에서 뜻을 명시하자 사라졌지만 다른 과잉이 생겼다
- **과잉 채움** — 규칙을 늘린 v2 에서 4B 가 말하지 않은 조건(타상품·잔액·첫거래 모름)을 채웠다(원출력 4 → 12). 9B v2 는
  "급여 받아" 에서 주거래까지 채웠다. **작은 모델에 규칙을 더하면 채우는 쪽으로 기운다**
- **권역 혼동** — "하나은행" → 하나저축은행 · "국민" → KB저축은행 (4B·EXAONE). 필터가 걸렀지만 모델은 그렇게 읽었다
- **보수적 모름** — "만 65세라 비과세 되는지 궁금해" → 고객군_자격 **모름**(세 모델 다). 라벨은 예. 과대 진술이 아니라 안 채운 쪽의 오답이다.
  최고 판(4B v1)의 화면 오답 1 이 이것이다
- **필터가 숨긴 것** — 후보 집합 밖 키를 버리는 화이트리스트가 원출력 오답의 절반 이상을 화면 전에 걸렀다(4B v1 4 → 1 · EXAONE v1 6 → 2).
  화면 안전은 필터가 만들고 있고, 모델 자체의 신뢰도는 원출력 열이 말한다

### 프롬프트 판

v1 — §2 의 스키마 설명 + 유형 목록 + 별칭 표. v2 — v1 에 "자주 틀리는 자리" 여섯 줄(첫거래 뜻 · 거래 은행 범위 · 권역 유지 · 자격 진술 ·
부정 표현 · 은행 미정)을 더함. **v2 가 4B 에서는 나빠지고 9B 에서는 빠뜨림만 줄었다.** 두 판으로 끝낸다(§2 · `0057` 반증 조건 1).

**라벨 정정 하나(투명하게)** — 첫 판 뒤 권역 라벨 8개를 "bank" 에서 None 으로 고쳤다. 라벨 규칙("말이 없으면 비운다")과 프롬프트
("말이 없으면 null")에 라벨 자신이 어긋나 있던 것이고, 정정 전 4B v1 스코프는 85% 였다(위 표는 정정 뒤 93%). 조건 답 라벨은 안 건드렸다.

결정은 [`0058`](../decisions/0058-r2-rejected-under-prereg-27.md).
