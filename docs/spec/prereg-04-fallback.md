# 사전 등록 04 — 분모 수정 + 폴백 구조 판정

> 등록일 2026-08-26 · 상태: **예측만 있음 (은행권 B 실행 전)** · 이슈 #5 후속
>
> `prereg-03` §10이 넘긴 두 가지를 한 문서에서 다룬다 — **분모 수정**과 **표본 확대**.
> 여기에 `E1`(폴백 구조 재측정)을 합친다. 셋이 같은 데이터를 쓰기 때문이다.
>
> **[정정 2026-08-26, 은행권 실행 전]** §9 참고표의 저축은행 폴백 값에 규칙 버전이
> 섞여 있었다. A 는 v3(115)로 적었는데 폴백은 v2 기준 146(80.2%)을 옮겨 적었다.
> **v3 기준은 144(79.1%)다.** §8이 v3 고정이므로 v3 값이 맞다.
> **은행권 예측(§6)에는 영향이 없다** — 그 기준선은 v3로 잰 75.8%다.

## 0. 답하는 질문 두 개

> **(1) 분모를 고치면 추출기 성능이 어떻게 보이는가?**
> `prereg-03`은 "우대조건이 있는 행"을 분모로 썼는데, 그중 저축은행 83.3%가
> 최고금리 = 기본금리였다. 그 행에서는 어떤 추출도 맞을 수 없다(`0006`).
>
> **(2) "규칙 먼저 → 못 닫으면 LLM" 이 둘 중 어느 하나보다 나은가?**
> 저축은행에서 80.2%를 관측했지만 **사후에 합친 값**이다. 사전등록하고 다시 잰다.

## 1. 정직하게 먼저 적을 것 — 무엇이 이미 알려져 있나

**저축은행 폴백 80.2%는 이미 계산했다.** 그 데이터를 다시 돌리면 같은 값이 나오고,
그건 새 측정이 아니다. 그래서 **확증 대상은 은행권**이다.

```
저축은행    A·B 를 각각 돌렸고 폴백을 사후에 합쳤다      → 이미 아는 값. 예측이 아니다
은행권      B 를 아직 안 돌렸다 (연기 테스트 4쌍만)      → 처음 재는 데이터. 여기서 판정한다
```

**은행권은 A의 개발 집합이다.** 규칙 파서가 그 253행을 여덟 라운드 보면서 만들어졌으므로
A가 유리하고, **폴백 이득은 저축은행보다 작을 것으로 예상한다.** 그 방향을 미리 적어둔다.

## 2. 분모를 고친다

```
prereg-03 의 분모     우대조건이 있는 행
prereg-04 의 분모     우대조건이 있는 행  +  공시 최고금리 > 기본금리
```

**폭 = 0 행을 버리지 않는다.** 분모에서 빼고 **별도 층으로 보고한다** —
조건문에 우대금리가 적혀 있는데 공시에 반영되지 않은 상태이고, 사용자에게
"은행에 확인이 필요하다"고 알려야 할 정보다(`../decisions/0011` · `problem.md` §5).

### 실측 — 분모를 고치면 이렇게 된다

| | 조건 있는 행 | 폭 > 0 (새 분모) | 조건문 종수 | 호출 쌍 |
|---|---:|---:|---:|---:|
| 은행권 `20260826` | 253 | **236** (93.3%) | 77 | 219 |
| 저축은행 `20260825` | 1,090 | **182** (16.7%) | 46 | 109 |

**저축은행은 분모가 1,090 → 182로 줄어든다.** 6분의 1이다. 검정력이 크게 떨어지므로
은행권 236행이 주 판정 대상이 된다.

## 3. 방향별로 잰다 — 권역마다 실패 방향이 반대다

`prereg-03`의 닫힘률은 절댓값만 봤다. 부호를 나누자 이것이 나왔다.

| A 규칙 v3 · 폭>0 기준 | 맞음 | 넘침 (더 뽑음) | 모자람 |
|---|---:|---:|---:|
| 은행권 236행 | 179 (75.8%) | 16 | **41** |
| 저축은행 182행 | 115 (63.2%) | **38** | 29 |

**은행권은 모자람이 주된 실패, 저축은행은 넘침이 주된 실패다.** 절댓값으로 묶으면
이 차이가 보이지 않는다. 그래서 아래 모든 지표를 **방향별로 보고한다.**

## 4. 폴백 규칙 — 실행 전에 고정한다

```
1. A(규칙 파서 v3)를 돌린다
2. |A 합계 − 폭| <= 0.06 이면 A 결과를 채택하고 끝낸다
3. 아니면 B(제한 스키마 LLM)를 돌린다
4. |B 합계 − 폭| <= 0.06 이면 B 결과를 채택한다
5. 둘 다 안 맞으면 **B 결과를 채택하고** "계산불가" 층으로 라벨한다
```

**5번에서 B를 택하는 이유**: 구조가 더 풍부하다. B는 `condition_type`을 갖고 있어
사용자별 계산에 쓸 수 있고, A는 금리만 있어 쓸 수 없다. 닫힘률에는 영향이 없다
(둘 다 실패한 행이므로).

**게이트는 검사이지 예측이 아니다.** "이 문장은 어려워 보인다"로 고르지 않고,
싼 것을 먼저 돌려 산수가 맞는지 보고 넘긴다(`design.md` §3).

## 5. 지표 — 주·부

**주 지표: 맞음 비율 (분모 = 폭 > 0 행)**

```
맞음 = |뽑은 합계(상한 적용) − (최고금리 − 기본금리)| <= 0.06%p
```

**부 지표 — 전부 함께 보고한다**

| 부 지표 | 왜 |
|---|---|
| **방향별 분해** (넘침 / 모자람) | 권역마다 방향이 반대다(§3). 절댓값은 이걸 감춘다 |
| **진짜 과다 추출** | 넘침에서 폭 0 행을 뺀 값. 폴백이 A보다 **늘면 손해다** |
| **항목 0개 비율** | 회피 방지. B가 A보다 5%p 이상 높으면 우위 불인정 |
| **LLM 호출 비율** | 폴백의 비용 근거. 낮을수록 좋다 |
| `기타` 비율 (B) | 열거값 17종이 이 데이터를 덮는지 |
| 공시미반영 층 크기 | 분모에서 뺀 행. 사용자에게 알릴 정보라 세어 둔다 |

## 6. 예측과 임계 (은행권 B 실행 전에 고정)

기준선: **A 규칙 v3 = 75.8%** (179/236, 은행권 폭>0).

| | 예측 | 판정 |
|---|---|---|
| **폴백 맞음 비율** | **83.8% 이상** (+8%p) | 79.8%(+4%p) 미만이면 **A가 강한 곳에서 폴백은 값어치 없다** |
| **B 단독** | A와 ±5%p 이내 | A의 개발 집합이므로 B가 크게 이기면 오히려 이상하다 |
| **진짜 과다 추출** | 폴백이 A(16건) **이하** | 늘면 실패 — B를 태워 넘침을 만든 것이다 |
| **항목 0개** | A와 ±5%p 이내 | B가 5%p 이상 높으면 우위 불인정 |
| **LLM 호출 비율** | 30% 이하 | A가 75.8%를 닫으므로 24% 근처가 기대값이다 |

**+8%p 근거**: A가 못 닫는 57행(넘침 16 + 모자람 41) 중 B가 절반을 잡으면 +12%p다.
저축은행에서 B는 A가 놓친 것의 상당 부분을 잡았지만(+17%p), 은행권은 A의 홈그라운드라
남은 57행이 더 어려울 것으로 본다. 절반의 3분의 2 수준을 기대해 +8%p로 잡는다.

**하한 +4%p 근거**: 57행 중 10행 미만이면 폴백을 유지할 근거가 약하다. LLM 호출 비용과
복잡도를 감당할 값어치가 없다.

## 7. 저축은행 재측정 — 판정에 쓰지 않는다

같은 파이프라인을 저축은행에도 돌려 **분모 수정 효과**를 본다. 다만 폴백 값은 이미
알고 있으므로 **판정에 쓰지 않고 참고로만 보고한다.**

## 8. 실행 조건 (고정)

- **B 모델**: `claude-haiku-4-5-20251001` · `temperature 0` · `max_tokens 4096` ·
  재시도 없음 · 쌍당 1회 (`prereg-03` §6과 동일)
- **프롬프트·스키마**: `prereg-03` §6.1 그대로. **수정하지 않는다**
- **규칙 파서**: v3 고정. 이 실험을 보고 고치지 않는다
- 스냅샷: 은행권 `20260826` · 저축은행 `20260825`
- 은행권 B 호출 219쌍(폭>0에 속한 쌍) — 전체 234쌍을 돌리고 폭>0만 채점한다

## 9. 결과 — 비어 있음

| | 은행권 236행 (판정) | 저축은행 182행 (참고) |
|---|---|---|
| A 규칙 v3 | 75.8% (179) | 63.2% (115) |
| B 제한 스키마 | — | 71.4% (130) |
| **폴백** | — | **79.1%** (144, 사후 계산 · v3) |
| 방향별 A (넘침/모자람) | 16 / 41 | 38 / 29 |
| 방향별 폴백 | — | — |
| 진짜 과다 추출 A / B / 폴백 | 16 / — / — | 38 / 23 / **13** |
| 항목 0개 A / B / 폴백 | — | 11.5% / 3.3% / **3.3%** |
| LLM 호출 비율 | — | **36.8%** (67/182) |
| McNemar (B만/A만) | — | 29 / 14 · p = **0.0315** |

**저축은행 참고 결과 요약** (v3 기준 · 판정에 쓰지 않음)

```
              맞음          넘침   모자람   항목0개
A 규칙 v3     115 (63.2%)    38     29     21 (11.5%)
B 제한스키마    130 (71.4%)    23     29      6 ( 3.3%)
폴백          144 (79.1%)    13     25      6 ( 3.3%)

폴백 − A  +15.9%p     폴백 − B  +7.7%p     LLM 호출 36.8%
```

**진짜 과다 추출이 38 → 13으로 줄었다.** 폴백이 넘침을 만들지 않고 오히려 줄인다 —
§6의 "늘면 실패" 조건과 반대 방향이다.

**부수 관측 — v3가 폴백에서는 v2보다 낮다.**

```
v2 기준   A 114 (62.6%)  ·  폴백 146 (80.2%)
v3 기준   A 115 (63.2%)  ·  폴백 144 (79.1%)
```

규칙을 깎아 A는 1행 올랐는데 **폴백은 2행 내려갔다.** v3가 A에서 새로 맞힌 행보다,
v2가 실패해서 B에게 넘겨 맞혔던 행을 v3가 "성공"으로 가로챈 뒤 틀린 경우가 더 많다는
뜻이다. **규칙을 깎는 것이 폴백 구조에서는 손해일 수 있다** — `0007`이 이슈 #6을 닫은
판단을 뒷받침하는 별개 근거다. 은행권에서도 같은지 확인한다(§9에 v2 행을 함께 적는다).

판정: — (§6 임계 적용)

## 10. 반증 조건

- **폴백이 79.8% 미만이면** → A가 강한 곳에서 폴백은 값어치가 없다. 그러면 폴백을
  "규칙이 약한 권역에서만" 쓰는 조건부 구조가 되고, 어느 권역인지 판별하는 문제가
  새로 생긴다
- **진짜 과다 추출이 A보다 늘면** → B가 넘침을 만든 것이다. 폴백 5단계(둘 다 실패 시
  B 채택)를 A 채택으로 바꿔야 한다
- **B 단독이 A를 5%p 이상 이기면** → A의 개발 집합에서도 B가 낫다는 뜻이고, 규칙 파서를
  1차로 두는 근거가 약해진다. `0007`의 판단을 다시 봐야 한다
- **은행권에서도 넘침이 모자람보다 많으면** → §3의 "권역마다 방향이 반대"가 틀린 것이다.
  방향 차이는 권역이 아니라 다른 요인이다
- **LLM 호출 비율이 40%를 넘으면** → A가 실제로 닫는 비율이 예상보다 낮다는 뜻이고,
  비용 계산을 다시 해야 한다
