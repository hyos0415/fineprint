# prereg-32 · 교차판매 조건의 모양 — 그래프가 필요한가를 구조를 짓기 전에 잰다

> 작성 2026-09-09 (**재기 전**) · 사람 제안 — *"공시 내에 카드 관련 부분이 많았잖아 … 이걸 하면 그래프 구조가 확실히 필요해질 거 같다"* ·
> 사람 결정 — **1번 실측을 먼저 · 그 뒤 카드 데이터 존재 확인** · 관련 `0002`(사슬 순회 폐기 · 사슬 4건) · 결정 README D2(조건 구조 표현) · D5(그래프 백엔드 · 게이트 통과 뒤) ·
> D7(확인 불가능한 외부 조건) · `CLAUDE.md` 1번(선행 조건 안 채워진 부품을 먼저 만들지 않는다)

## §1 묻는 것

예적금 우대조건 중 **다른 상품을 가리키는 것**(카드 실적 · 펀드·청약·보험·대출 보유 · 다른 예적금 가입)이 얼마나 있고 **어떤 모양**인가.
그래프가 값을 내는 조건은 둘이다 — (가) 노드에서 노드로 **두 홉 이상** 따라가는 질의가 있다 (나) 한 상품이 외부 상품 **여럿을 동시에**(AND) 요구해 조합이 생긴다.
둘 다 작으면 표(역인덱스)로 끝나고, 그래프 백엔드(D5)는 열지 않는다.

```
E  임계             카드실적에 금액·횟수 임계가 적힌 비율 (있어야 "채우면 얼마" 가 계산된다)
F  역인덱스 크기     조건 유형 → 그 조건으로 오르는 상품 수 · %p 합 (카드실적 · 타상품 각각) — "이 조건을 채우면 어디가 오르나" 의 값
```

## §3 예측 — 재기 전에 적는다

```
P1  A   은행권 외부 참조 15~20% (앞선 눈대중 7% + 12%) · 저축은행 5% 미만
P2  B   부류 6종 이상 · 카드(일반)가 최다 · 특정 카드명은 10건 미만(대부분 NH채움카드)
P3  C   AND 조합(외부 참조 2개 이상 동시 요구) 문구 10개 미만 — 은행권 234문구 기준 5% 미만
P4  D   두 홉 **0~4건**. `0002` 가 사슬 4건을 봤다. 그 이상이면 놀랄 일이다
P5  E   카드실적 임계 있는 비율 30~50%
P6  F   카드실적 역인덱스 — 은행권 상품 40~55개가 오르고 %p 는 대체로 0.1~0.5
```

## §4 판정 조항 — 임계를 미리 적는다

```
그래프(D5)를 연다      D(두 홉) ≥ 10 건 **또는** C(AND 조합) ≥ 20 문구. 둘 다 아니면 열지 않는다 — 표와 역인덱스로 충분하다
역인덱스 화면 후보     F 에서 오르는 상품이 20개 이상이고 임계(E)가 절반 이상 있으면 "이미 쓰는 카드가 있으면 여기가 오른다" 화면을 다음 사전등록 후보로 올린다.
                    **"만들면"** 으로 묻지 않는다 — 카드 비용(연회비·소비 조건)을 우리 데이터가 모르는데 이득만 말하면 권유가 된다(`0037`)
다음 단계             결과가 무엇이든 **2번(카드 데이터 원천 확인)** 을 한다. 재료가 없으면 구조가 맞아도 짓지 않는다
```

```
P1  A     은행권 19.1% ✓ (15~20)  · 저축은행 5.4% ✗ (5% 미만 예측 · 근소)
P2  B     7부류 ✓ · 카드(일반) 최다 ✓ · 특정 카드명 10 ✗ (10 미만 예측 · 경계 · NH채움 한 문구가 기간 셋으로 불렸다)
P3  C     동시 요구 고유 문구 7 ✓ (10 미만) — 쌍으로 세면 19 라 예측을 넘는 것처럼 보인다. 단위를 미리 못 박지 않은 것이 이 사전등록의 구멍이다
P4  D     고유 4 ✓ (0~4) — 그리고 넷이 전부 **2쌍의 상호 참조**다. `0002` 의 "사슬 4건" 과 같은 크기

          "카드 조건이 많다" 는 감은 항목 수(52 · 기간별 반복)에서 왔고, 상품 수로는 은행권 79개 중 17개(22%)다
```

### §4 판정 — 그래프는 열지 않는다

- **D(두 홉) 4 < 10 · C(AND) 7 < 20 → 그래프(D5)를 열지 않는다.** 교차판매 조건은 다섯에 하나지만 모양이 전부 **한 홉 + 임계**다. 두 홉처럼 보인 것은
  예금·적금 짝상품의 상호 참조 2쌍이고, 이건 "함께 가입" 플래그 하나로 표현된다. 표와 역인덱스로 충분하다 — `0002` 의 결론(사슬 순회 폐기)이 세 번째로 재확인됐다
- **역인덱스 화면 후보 — 열지 않는다.** F 에서 오르는 상품 17 < 20 · 임계 35% < 50%. "이미 쓰는 카드가 있으면 여기가 오른다" 는 지금 질문 루프가 이미 하는 일
  (카드실적 질문에 예라고 답하면 그 17개가 오른다)과 같아서 새 화면이 더할 값이 작다
- **다음 단계(2번 · 카드 데이터 원천 확인)는 조항대로 한다.** 다만 이 결과로 그 조사의 무게가 바뀐다 — 구조가 필요 없으니, 카드 데이터가 있어도 쓸 자리는 "카드실적 임계
  (월 30만원 등)를 채울 수 있나" 를 사용자에게 더 정확히 묻는 것 정도다. 큼직한 기능이 아니라 질문 문구 정밀화다

### 이 실측이 말하는 것 한 줄

**교차판매 조건은 많지만(19%) 구조는 평평하다(한 홉 · 상호참조 2쌍).** 그래프가 필요해지는 자리는 우리 데이터 안에 없다. 필요해질 때는 카드·펀드 쪽 데이터가 **들어와서**
홉이 이어질 때이고, 그때 다시 잰다(반증 조건 — 외부 상품 데이터가 결합돼 두 홉 고유 10건 이상이 생기면 D5 를 연다).
