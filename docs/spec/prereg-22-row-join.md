# prereg-22 · 행 짝짓기를 기관코드+상품코드로 — 저축은행 행 절반이 남의 조건을 달고 있었다

> 작성 2026-09-04 (**고치기 전**) · 이슈 [#61](https://github.com/hyos0415/fineprint/issues/61) `blocking` ·
> 잡은 곳 `prereg-21` §5 (F3 의 화면 계약 A17 — 링크가 가는 기관과 이름의 기관이 다르다) ·
> 근거 `0031`(상품코드는 기관을 넘어 유일하지 않다 — 이미 적어 두고도 짝짓기에는 안 썼다)

## §1 무엇이 틀렸나

`extract_llm.load_pairs()` 가 옵션 행(금리)을 상품(이름·기관·우대조건 문구·가입 채널)에 붙일 때
**상품코드만** 키로 쓴다.

```python
base = {b["fin_prdt_cd"]: b for b in payload["baseList"]}     # 같은 코드면 마지막 기관이 이긴다
product = base.get(opt["fin_prdt_cd"])
```

저축은행은 코드가 겹친다(예금 52 · 적금 29 코드가 두 기관 이상에). 그래서 **금리와 `co_no` 는 기관 A
것, 이름·조건·채널은 기관 B 것**인 행이 만들어졌다. 은행권은 코드 겹침이 없어 영향이 0 이다.

**이미 알던 사실이었다.** `0031` 이 *"하나저축은행 세 법인이 전부 상품코드 240001 을 쓴다"* 고 적었고
그래서 상품을 (기관코드, 상품코드)로 세게 고쳤는데, **세는 자리만 고치고 붙이는 자리는 안 고쳤다.**
링크가 없을 때는 이름과 금리가 다른 기관 것이어도 화면에서 보이지 않았다 — F3 가 붙인 링크가
드러냈다(`0051`).

## §2 고치기 전에 아는 것 (결정적 — 추출 없이 계산됨)

고친 짝짓기로 행을 다시 만들면 이렇게 된다. 예측이 아니라 **계산 결과**이고, 고친 뒤 같은 수가
나오는지 P1 로 재확인한다.

저축은행 12개월 행     297         196
상품(기관+코드) 전체   188         137      (`0031` 의 183 은 12개월 · 그것은 133 이 된다)

이슈 #61 본문의 "111개" 는 조건없음 필터 **전** 수다. 필터 뒤는 85 다.

## §3 무엇을 고치나

- `load_pairs()` 의 키를 `(fin_co_no, fin_prdt_cd)` 로 — 한 줄이다
- `extract_llm.py --reuse <옛 파일>` — 옛 결과를 **(문구, 기간)** 으로 재사용하고 새 쌍만 부른다. 같은
  입력에 같은 호출(temperature 0)이고, "같은 쌍은 재사용한다" 는 원래 설계다(§호출 단위). `pair_id` 는
  자리 번호라 소비자 8곳이 그 번호로 읽으므로, 번호가 새로 매겨진 **완전한 새 파일**을 만든다.
  옛 파일은 `extract_llm_savingsbank_20260825_before-61.json` 으로 옮겨 보존한다(git 제외)
- 실행 조건은 `prereg-03` §6 그대로 — Haiku 4.5 · temperature 0 · 재시도 없음
- **하지 않는 것** — 추출 프롬프트·스키마·판정 규칙을 건드리지 않는다. 은행권은 다시 부르지 않는다

### P7 — 저축은행의 새 기준선 (12개월 · `measure_per_institution.py 20260825 --group savingsbank`)

**이 표가 말하는 것** — 옛 저축은행 값은 틀린 행 위에서 나온 것이라 비교가 아니라 **교체**다.

```
                          #61 이전 (틀린 행)          #61 이후 (새 기준선)
행 · 기관                  297행 · 30곳               196행 · 38곳
게이트 (메인 층 / 행)       106/297 = 35.7%            **126/196 = 64.3%**
전부 예                    확정 82/106 (77.4%) · 폭 0.396 · 3.170%    확정 95/126 (75.4%) · 폭 0.398 · 3.203%
거래 1곳 중앙값             84.0% · 3.130 · 질문 9       84.1% · 3.162 · 질문 10
예산 12개 (0·1·2·3곳)      86.8·86.8·85.8·82.1%        86.5·82.5·82.5·82.5%
                          폭 0.115·0.115·0.116·0.371   폭 0.128·0.333·0.333·0.333
목록 "모름"                68.9% · 0.420               66.7% · 0.412
화면 상품 수                71                          92
```

**게이트가 35.7% 에서 64.3% 로 간 것은 개선이 아니다.** 옛 분모 297 에는 "조건없음" 상품에 남의 조건이
붙은 행 101 개가 들어 있었고, 그 행들이 메인 층에 못 들어가 비율을 끌어내렸다. `0018` 의 저축은행 기준선
36.7%(109/297)와 이슈 #10 의 *"저축은행 게이트 불통과"* 는 **이 결함의 산물**이다. 기준선을 어디에
둘지는 사람이 다시 정한다(#10 에 적었다).

**옛 값이 적힌 문서** — `prereg-15`·`16`·`18`·`19` 의 저축은행 값, `0018`·`0031`·`0045`·`0047` 의 저축은행
숫자. 기록이라 고치지 않고 머리에 "#61 이전" 표시를 달았다. 은행권 값은 전부 그대로 유효하다.

결정은 [`0052`](../decisions/0052-join-rows-by-institution-and-product.md).
