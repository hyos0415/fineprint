# 사전 등록 11 — 후보 집합(스코프)을 넣는다

2026-08-28 작성 · **재기 전에 커밋한다** · 이슈 [#15](https://github.com/hyos0415/fineprint/issues/15)

앞선 기록: `decisions/0028`(스코프 결정) · `0014`(묶는 축은 기관) · `0017`(좋은 상품을
묻지 않는다) · `0018`(예산·게이트) · `0024`(P2·R2 계약) · `0026`(질문 수 불가침) ·
`0027`(문구 단위 질문) · `prereg-09`(화면 계약 A1~A6) · `prereg-10` §7(사람 세션)

## 0. 무엇을 만드나

```
0단계 축      기관 · 상품군(예금/적금) · 기간 · 납입액        ← 기관·상품군이 새로 들어간다
질문 생성     후보 집합에서만                             (`0028` S2)
지표          카탈로그 전체 고정                          (`0028` S3)
화면          스코프 밖 최고 금리를 항상 표시               (`0028` S4 · 새 assert A7)
```

`kor_co_nm`(기관명)은 원천 데이터에 이미 있고 `rows`에 안 담고 있었을 뿐이다.

> **정정 (2026-08-28, 구현 중)** — 처음 이 문서에 *"저축은행 원천은 파일 구조가 달라
> 기관명 매핑을 아직 못 붙였다"* 고 적었는데 **틀렸다.** 저축은행 원천에도 `kor_co_nm`
> 이 있고 기관 30곳이 그대로 나온다. 처음 못 붙인 것은 매핑을 **은행권 파일에서** 읽는
> 임시 스크립트를 썼기 때문이다. 판정 기준이 아니라 사실 서술의 오류이므로 지운 것이
> 아니라 정정으로 남긴다. §6-2 도 같이 정정한다.

## 1. 두 층을 분리한다 — 이게 이 사전등록의 핵심이다

지금까지 코드는 "사용자 화면"과 "평가 지표"를 같은 집합에서 계산했다. 그래서 사용자
화면에 카탈로그 질문 39개가 나왔다.

| 층 | 집합 | 무엇을 위해 |
|---|---|---|
| 화면 | 후보 집합 (스코프 적용) | 사용자가 답할 질문은 자기 후보에 걸린 것뿐이어야 한다 |
| 지표 | **카탈로그 전체 고정** | 스코프로 확정률·커버리지를 좋게 만드는 도피를 막는다 (`0018`) |

**기준선·게이트·예산 12개는 카탈로그 전체에서만 잰다.** 스코프별 숫자는 참고로 찍되
기준선과 비교하지 않는다.

## 2. 새 화면 계약 A7 — 스코프 밖 최고 금리

```
A7  스코프가 걸린 화면에는 **스코프 밖 최고 금리**가 있어야 한다
    (스코프 안 최고와 같거나 낮으면 표시하지 않아도 통과 — 숨길 것이 없다)
```

**왜 assert 인가** — 좁히면 금리를 잃는다. 은행권 실측으로 기관별 격차 **중앙값
2.41%p**, 16곳 중 15곳이 1.0%p 초과다. 이걸 안 보여주면 `0017`이 막은 실패("좋은 상품이
묻힌다")를 스코프에서 되살린다. A1~A6과 같은 급의 계약이므로 검사에 넣는다.

## 3. 예측 — 재기 전에 적는다

| | 예측 | 근거 |
|---|---|---|
| 우리은행 · 적금 12개월 질문 수 | **7개** | 이미 셌다 (유형 6 + 문구 1) |
| 스코프별 질문 수 (은행권 16곳) | **전부 20개 이하** | 상품이 가장 많은 기관이 7개다 |
| 지표 (카탈로그 기준) | **한 자리도 안 변한다** | 확정 37/67 · 85/106 · 폭 0.185 · 0.386 · 커버리지 84.8% · 35.7% |
| 화면 계약 A1~A7 | **전부 통과** | A7은 새로 만드는 것이므로 첫 실행에서 위반이 나오면 구현 실패다 |
| 스코프 밖 격차 (기관 평균) | **1.0%p 이상** | 실측 중앙값 2.41%p |

**지표가 한 자리라도 움직이면 스코프가 지표 층에 새어 들어간 것이다.** 그때는 구현을
되돌리고 그 사실을 먼저 적는다 — 이 사전등록에서 가장 중요한 판정이다.

## 4. 회피 방지

| 가드 | 기준 |
|---|---|
| 지표에 스코프를 쓰지 않는다 | `ask_budget.py`·기준선·게이트는 스코프 인자를 받지 않는다 |
| 스코프로 커버리지를 올리지 않는다 | 게이트는 카탈로그 79/297 분모 고정 (`0018`) |
| 질문 수 감소를 개선으로 주장하지 않는다 | 39 → 7 은 **다른 집합을 재는 것**이다. `0026`의 "질문 줄이기" 와 구분해 적는다 |
| 스코프를 우리가 추측하지 않는다 | 사용자가 말한 것만. 뽑은 스코프는 화면에 보여주고 고칠 수 있어야 한다 (`0028` S5) |
| 조건 답을 스코프에서 유도하지 않는다 | "우리은행 주거래" → 급여이체 예 로 채우지 않는다 (`0024` P2) |

## 5. 무엇을 재나

```
M5  스코프별 질문 수 — 은행권 16개 기관 × (예금/적금) 전수. 20개 넘는 곳이 있는지
M6  지표 무변동 — 카탈로그 기준 확정률·폭 평균·커버리지가 소수점까지 같은지
M7  화면 계약 A1~A7 — 페르소나 3 + 시드 0~199, 스코프 없음/기관 스코프 두 조건에서
M8  스코프 밖 격차 — 기관별로 (전체 최고 − 그 기관 최고). 이미 한 번 쟀고 재현되는지
```

M5·M6·M7·M8 전부 코드가 한다. **사람 세션은 이 사전등록의 범위가 아니다.**

## 6. 이 사전등록이 정하지 않는 것

1. **상위 N 후보 자동 좁힘**(`0028` 대안 B) — 답할수록 후보가 바뀌면 질문이 다시 생겨
   `0024` P4를 깰 수 있다. **별도 사전등록으로 다룬다**
2. ~~**저축은행 기관명 매핑** — 원천 파일 구조가 달라 별도 작업이다~~
   → **정정: 저축은행도 그대로 된다** (기관 30곳). 위 §0 참고
3. **R2 구현** — 자연어 → 스코프 추출은 이 사전등록의 범위가 아니다. 지금은 CLI 플래그로
   받는다(`--company`). R2 를 만들 때 추출 정확도를 따로 사전등록한다
4. **스코프를 기억할 것인가** — 세션 간 저장은 개인정보 최소수집(`0026` 반증 조건)과
   맞물린다. 지금은 저장하지 않는다

### M6 — 스코프가 지표 층에 새지 않았다

이 사전등록의 주 판정이다. 스코프를 넣은 뒤 `ask_budget.py` 를 다시 돌려 **소수점까지
같은 값**을 확인했다. 스코프 인자는 `ask_budget.py` 에 아예 없다(`prereg-11` §4 가드).

### M5 미달 — 웰컴저축은행 23개

```
웰컴저축은행   상품 14개 · 질문 23개 (유형 8 + 문구 15)
```

**기관 축이 이 한 곳에서는 문제를 못 풀었다.** `0028` 의 반증 조건 2가 예고한 실패
모양 그대로다 — *"스코프를 걸어도 질문이 20개를 넘으면 기관 축이 문제를 못 푼 것"*.

다만 규모를 적어 둔다 — 저축은행 30곳 중 **2건(웰컴 전체·웰컴 적금)**이고, 나머지
28곳은 질문 중앙값 **3개**다. 은행권은 17곳 전부 20개 이하(최대 제주은행 17개)다.
**기관 축을 버릴 근거는 아니고, 상품이 많은 기관에 두 번째 축이 필요하다는 신호다**
(상품군·기간으로 이미 더 좁힐 수 있고, `0028` 대안 B(상위 N)는 별도 사전등록이다).

### M8 — 좁히는 대가가 크다. A7의 근거다

은행권 격차 중앙값 **2.41%p** 로 처음 측정과 같은 값이 재현됐다. 저축은행은 **8.62%p** 로
더 크다(전체 최고 11.84%). 한국스탠다드차타드은행처럼 메인 상품이 하나도 없는 기관은
격차가 5.92%p(=전체 최고)로 찍힌다 — 스코프를 걸면 **볼 수 있는 상품이 없다**는 뜻이고,
그것도 사용자에게 알려야 한다.
