**관측 다섯**

1. **문서가 짧다** — 3~7쪽 · 4~6천 글자. 통째로 컨텍스트에 들어간다. 조항은 전부 "2 거래 조건" 표 안의 `중도해지이율` · `만기 후 이율` 행이다. **찾을 필요가 없다 → RAG(R) 불필요.** `prereg-32` §6 의 결론이 여기서도 선다
2. **모양은 다르지만 스키마는 하나다** — 구간(경과기간 · 월 또는 일 기준) → 이율 = `고정 %` **또는** `기준이율 × 비율 × (경과/계약)` · 최저 이율. 네 기관이 전부 이 두 형태 안에 있다.
   다른 것은 (가) 구간 경계(1·3·6·9·11개월) (나) 비율(50~90%) (다) 경과 단위(일수 vs 월수) (라) **기준이율의 정의** — 우리·농협은 가입 시점 기본이율, 신한은 "차감률" 표 별도, 만기 후는 세 곳 다 **만기 시점 일반정기예금 기본이율**(우리 상품 금리가 아니다)
3. **기준이율 정의가 계산의 함정이다** — 만기 후 이율은 "만기일 당시 일반정기예금 기본금리" 라 지금 공시의 그 상품 금리로 계산하면 틀린다. 화면은 이 구간을 숫자 대신 **"만기 시점 일반정기예금 기본금리의 50%"** 로 말해야 한다(숫자를 지어내지 않는다 · `0019` 의 태도)
4. **설명서 URL 이 기관마다 다르고 상품 코드로 예측되지 않는다** — 우리 `download.jsp?...PLM_P010002491_...pdf` · 신한 `img.shinhan.com/sbank2016/seol/{날짜난수}.PDF` · 농협 `file/ebank/product/guide/{코드}_pi.pdf` · KB 는 최신판을 웹 검색으로 못 찾았다(2021 판만). **79개 상품의 설명서를 모으는 것이 이 과업의 병목**이지 읽는 것이 아니다. `0056` 이 상품 상세 페이지에서 본 것과 같은 모양이다
5. **판(version)이 있다** — 준법감시인 심의필 번호와 유효기간이 적혀 있다(신한 2024.09.02~2025.09.01 · 농협 2025.09.01~2027.08.31). 설명서는 공시 스냅샷과 **날짜가 다르다** — 짝을 맞출 때 유효기간을 봐야 한다

## §2 무엇을 만들 것인가 (사람이 확정하면)

- **원천** — 상품별 설명서 PDF (은행권 79개 먼저). 수집은 기관별 손 작업 + 스크립트 혼합이 될 것이다
- **추출 스키마** — `{구간: [{from_m, to_m, 단위(일|월), 형태(고정|비율), 값, 기준이율_정의, 최저}], 만기후: [...], 출처: 쪽·문장}`. 추출은 지금 추출기와 같은 방식(Haiku · 스키마 강제 · 홀드아웃 채점)
- **계산** — 코드. 경과 개월 → 구간 → 이율 → 세전·세후 금액. 기준이율이 "만기 시점 일반정기예금" 인 구간은 **숫자를 내지 않고 정의를 문장으로** 낸다
- **화면 하나** — 가입 상품 · 가입일 · 해지 시점 → 구간별 금리 가로 바(0·1·3·6·9·11·12·이후) · 세후 금액 · 근거 조항 문장. JS 없이 CSS 바. 화면 계약 **A20** — 만기 전 어느 구간도 만기 값을 넘지 않는다 · 구간마다 근거 문장이 있다 · 못 찾은 구간은 빈칸이 아니라 "설명서 확인 필요"
- **하지 않는 것** — 설명서 전체를 검색 인덱스로 만드는 것(필요 없음 · 관측 1) · 기관 코드로 URL 을 추측하는 것(관측 4 — 없는 URL 을 만든다)

## §3 예측 — 수집 전에 적는다 (다음 단계는 "79개 설명서를 모을 수 있나")

```
P1  수집 가능률   은행권 79개 상품 중 최신 설명서 PDF 를 **공식 사이트에서** 찾는 비율 60~80%. 못 찾는 쪽은 KB 처럼 검색에 안 잡히거나 앱 전용 상품
P2  기관 편차    17개 기관 중 URL 규칙이 일정해 스크립트로 받을 수 있는 곳 5곳 이하 · 나머지는 사람이 한 장씩
P3  스키마 적합   모은 설명서의 중도해지 조항이 §1 의 두 형태(고정 · 기준×비율×경과)로 표현되는 비율 ≥ 90%. 안 되는 것은 계단식 표(KB 별지형)
P4  기준이율     만기 후 이율의 기준이 "만기 시점 일반정기예금" 인 비율 ≥ 70% — 즉 화면의 마지막 구간은 대부분 숫자가 아니라 정의로 나간다
P5  유효기간     설명서 유효기간이 현재(2026-09)를 포함하는 비율 ≥ 80% · KB 2021 판처럼 지난 것이 섞인다
P6  RAG 불필요   조항 위치는 전부 "거래 조건" 표 안 · 정규식 `중도해지이율|만기\s*후\s*이(자)?율` 로 100% 찾힘 — 검색 인덱스는 만들지 않는다
```

## §4 판정 조항

```
P1 < 50%    수집이 병목 — 화면을 만들지 않는다. 대신 "설명서 링크 + 중도해지는 설명서에서 확인" 을 F3 옆에 붙이는 것으로 끝낸다 (`0056` 과 같은 결론)
P3 < 90%    스키마를 넓히기 전에 안 맞는 모양을 기록하고 사람에게 묻는다 — 스키마를 관측 뒤에 늘리지 않는다
P6 틀림     그때 처음으로 R 이 필요해진 것이다 — 기록하고 새 사전등록
어느 쪽이든  결과는 결정 문서 하나 (착수 / F3 링크로 대체 / 보류)
```
