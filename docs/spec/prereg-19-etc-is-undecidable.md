# prereg-19 · `기타` 는 판정 불가로 둔다 — 뜻이 공시에 없는 조건은 묻지 않는다

> **#61 이전 (2026-09-04 표시).** 이 문서의 **저축은행** 값은 추출 행 절반이 다른 기관의 이름·조건을 달고 있던 때의 값이다(`decisions/0052` · `prereg-22`). 저축은행 숫자는 비교가 아니라 교체 대상이고 새 기준선은 `prereg-22` §6 이다. 은행권 값과 결정의 논리는 그대로 유효하다.

> 작성 2026-09-03 (**구현 전**) · 이슈 [#56](https://github.com/hyos0415/fineprint/issues/56) ·
> 근거 `prereg-18` §2.2 · `0019`(뜻을 모르는 남의 낱말에 뜻을 지어내지 않는다) · `0016`(추측하지 않는다)

**사람이 A 로 정했다** (2026-09-03). 이 문서는 그 결정이 무엇을 바꾸는지 **고치기 전에** 적는다.

## 왜 A 인가 — 세 선택지가 실제로 하는 일

`기타` 로 남은 항목은 넷이고 실제로 질문이 되는 것은 둘이다.

```
국민은행  KB내맘대로적금       "소중한 날"                 +0.10%p · 배타그룹 g1 · 다른 조건 8개
세람저축은행 내가디자인하는적금  "올해의 띠"                 +0.10%p · 배타그룹 g1 · 다른 조건 7개
SBI저축은행 정기예금(1년변동금리) "금리변동주기우대금리 : 연0.1%"  이미 `조건불명` 으로 갈려 안 묻는다
```

**답이 금리를 바꾸는 경우가 하나뿐이다.** 다른 조건에 "예" 가 하나라도 있으면 배타그룹 밴드
(`0022`) 때문에 `기타` 의 예/아니오/모름이 숫자를 전혀 안 바꾼다. 다른 조건을 **전부 아니오**
한 사람에게만 확정 2.24 / 확정 2.16 / 범위 2.16~2.24 로 갈린다 — 세후 0.085%p 다.

```
A  판정 불가 취급    묻지 않는다. "전부 아니오" 사람에게 두 상품이 확정 대신 0.085%p 범위로 남는다.
                    3런에서 사람이 "모름" 을 눌러 이미 이 결과가 나왔다
B  기관 상대로 유도   거래 없는 기관은 "아니오" 로 채운다. 그 사람이 "소중한 날" 대상일 수 있으므로
                    모르는 것을 아니오로 채우는 것이다 — 확정 2.16 을 만드는데 사실이 아닐 수 있다.
                    `0016` 이 막은 추측이다
C  그대로           두 사람에게 뜻 없는 질문 하나가 마지막에 나간다. 사람은 "모름" 을 답했다
```

## §1 무엇을 고치나

- `기타` 를 **판정 불가**로 다룬다 — 질문을 만들지 않고, 그 %p 는 범위의 위쪽에 남긴다.
  `UNDECIDABLE` 과 같은 경로지만 **사유는 따로 둔다.** 판정 불가의 사유 문장은 *"추첨·랜덤으로
  주는 우대금리"* 라서 `기타` 에 붙이면 거짓이다. 새 사유 `뜻없음` 을 두고 문장은 *"어떤 경우에
  받는지 공시에 설명이 없는 우대조건이 있어 그 부분은 확정하지 않습니다. 해당되는지는 은행에
  확인해 보세요"* 로 끝난다 (화면 라벨 *"은행 확인이 필요한 조건"* — 낱말은 사람이 2026-09-04 에
  정했다. "뜻이 없다" 는 공시를 탓하는 말로 읽혀서 사용자에게는 할 일을 앞세운다) — `조건불명` 과 같은 태도(막다른 길에 세워두지 않는다).
- **`기타` 라벨과 추출 스키마는 안 바꾼다.** 추출기가 내는 값이고 세션 로그의 키다(`0031`).

## §3 판정 조항

```
Q1·Q2·Q5·Q7 중 틀리면    구현이 규칙과 다르다. 고쳐서 다시 잰다
Q3 이 틀리면              기타 가 밴드 밖에서도 숫자를 바꾸고 있었다 — 원인을 적고 사람에게 묻는다
Q4 가 어느 칸에서든 반대면  묻지 않은 것이 다른 질문 순서를 나쁘게 바꿨다 — 원인을 적고 사람에게 묻는다
Q6 이 틀리면              이 변경과 무관한 회귀다. 별도로 잡는다
```

## §4 이 측정이 못 하는 것

- "소중한 날" 대상인 사람이 잃는 것 — 그 사람은 두 상품을 0.085%p 범위로 본다. 은행에 확인하라는
  문장이 그 자리를 채운다. 사람 완주에서 그 문장을 읽는지는 다음에 본다.
- `기타` 가 9월 공시에서 늘어나면 이 결정의 비용도 늘어난다. 월 갱신 뒤 `기타` 수를 다시 센다.

## §5 결과 (2026-09-04 · 구현 뒤)

**일곱 예측이 전부 맞았다.** 고친 것은 `calculate.py` 두 자리(`기타` 를 `UNDECIDABLE` 에 넣고
`caveats_for` 가 `뜻없음` 을 낸다)와 사유 표·라벨 표·`ask_loop.HARD_CAVEATS` 다. 판정 규칙은
그 밖에 손대지 않았다.

```
Q1  맞음   질문 총수 87 → 86 · 62 → 61 (유형+문구+목록 · `question_plan` 으로 셌다)
Q2  맞음   은행권 9·14·15·19 · 저축은행 8·8·10·14 — 모든 페르소나에서 정확히 하나 줄었다
Q3  맞음   은행권 58.2% · 0.172 · 2.975 · 저축은행 77.4% · 0.396 · 3.170 소수점까지 같다.
           거래 1곳 중앙값(76.1%/2.727 · 84.0%/3.130)과 과대 진술 열도 전부 그대로다
Q4  맞음   저축은행 네 칸 · 은행권 1·2·3곳 · 목록 모름 — 소수점까지 같다.
           **은행권 0곳만 움직였고 좋아진 방향이다** — 확정 52→53 (77.6→79.1%) · 폭 0.089→0.076.
           `기타` 자리에 들어온 다음 질문이 상품 하나를 확정으로 옮겼다
Q5  맞음   전부 아니오 페르소나에서 딱 두 상품 — KB내맘대로적금 확정 2.157 → 범위 2.157~2.242 ·
           내가디자인하는적금 확정 3.215 → 범위 3.215~3.299. 둘 다 사유 `뜻없음`(+ 원래 있던
           `중복우대불명`). 두 권역의 사유 합계에서 `뜻없음` 은 1·1 이고 `추첨` 은 0·0 이다.
           SBI 정기예금(1년변동금리)은 예측대로 `조건불명` 그대로다
Q6  맞음   첫거래·주거래 동시 수령 모든 페르소나 0개
Q7  맞음   화면 계약 A1~A16 — 은행권(최대순·확정순) · 저축은행(최대순·확정순) · 선호 켠 상태
           (A10·A11 포함) 전부 위반 0건 · 세션 203개씩. API·화면 대조도 전부 통과.
           A3 가 `CAVEAT` 전부를 보므로 `뜻없음` 문장이 최종 화면에 있는지도 여기서 검사됐다
```

**측정 도구 두 가지를 적어 둔다.** Q1·Q5 는 `measure_per_institution.py` 가 안 내는 값이라
`question_plan` 크기와 "목록 빈 채 · 유형·문구 전부 아니오" 상태를 직접 넣어 셌다(고치기 전에
먼저 돌려 기준값 87·62·2.157·3.215 가 §2 와 같은 것을 확인한 뒤 고쳤다). 화면 계약 검사는
`.venv` 의 파이썬으로 돌려야 한다 — 시스템 파이썬에는 `jinja2` 가 없어 웹 렌더 겹에서 죽는다.
