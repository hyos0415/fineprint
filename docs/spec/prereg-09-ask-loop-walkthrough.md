# 사전 등록 09 — 중단해도 화면이 정직한가

2026-08-28 작성 · **재기 전에 커밋한다** · 이슈 [#13](https://github.com/hyos0415/fineprint/issues/13)

앞선 기록: `decisions/0024`(되묻기 흐름) · `decisions/0025`(질문 루프) ·
`decisions/0026`(질문 수는 협상 대상이 아니다) · `design.md` §화면이 지켜야 할 계약

## 0. 사람이 정한 방향 — 편의와 정직 사이에서 타협하지 않는다

이 문서의 첫 판은 *"사람이 22개를 완주하는가"*를 재려고 했다. 사람이 그 전제를 기각했다.

> 사용자 편의성을 위해 질문을 줄인다? 이건 그냥 과대광고랑 똑같은 맥락이잖아.
> 진짜 필요한 정보는 다 수집을 해야 한다고 보거든?? 은행원이 하는 일을 똑같이 해야
> 하는 거라고 보는데. 나는 이거 전혀 사용자의 편의성과 정직한 정보 제공 트레이드 오프
> 타협할 생각이 없거든?

그래서 **완주율·중단률은 이 사전등록의 지표가 아니다.** 기록만 하고 판정에 쓰지 않는다.
사유는 `decisions/0026`에 있다 — 안 물은 조건은 `모름`이 되고 `모름`은 `hi`에 남으므로,
질문을 줄이는 것은 **최고 금리를 그대로 둔 채 확인만 건너뛰는 것**이다.

**그러면 무엇을 재는가.** 중단은 시스템이 지원하는 상태다(안 물은 것은 범위 + `미응답`
사유). 위험은 사용자가 멈추는 것이 아니라 **멈춘 상태에서 우리 화면이 단정하는 것**이다.

## 1. 왜 이것이 실재하는 위험인가 — 이미 한 번 일어났다

`0019`가 찾은 사례다. 사용자는 아무 잘못도 하지 않았다.

```
부산은행 "부산이라 좋다 Big적금" 의 조건문은 이 한 줄이 전부다
   *우대이율 6개월 미만 최대2.00%, 6개월 이상 2.20%

무슨 조건인지 한 글자도 없는데 무조건_특판_이벤트(항상 충족)로 분류돼 있었다
   사용자 입력 0개 상태에서 6개월 상품이 4.80% 로 보였다
```

**사용자가 답을 왜곡할 걱정은 하지 않는다.** 조건을 부풀려 답하면 못 받는 금리를 보게
되므로 본인 손해로 직결되고, 사용자도 그것을 안다. 이 사전등록이 막는 것은 **우리
코드가 사용자의 침묵을 확정으로 바꾸는 것**이다.

## 2. 재는 것 넷 — 셋은 사람이 필요 없다

| | 무엇 | 누가 |
|---|---|---|
| M1 | **화면 계약 전수 검사** — 모든 중간 상태에서 아래 A1~A5를 assert | 코드 |
| M2 | **남은 질문 수 단조 비증가** — A4. 답 조합을 섞어 전수로 | 코드 |
| M3 | **"모르겠다" 비율** — 질문이 답할 수 있는 형태인가(`0024` P1) | 사람 1회 |
| M4 | 상태바 둘째 숫자가 보이는가 — 자기보고 2문항 (§4) | 사람, 약한 증거 |

`design.md` 화면 계약이 *"화면 코드에 assert를 박는다"*고 이미 적어 둔 것이 M1이다.

## 3. 판정 기준 — assert 다섯 개를 지금 정의한다

각 중간 상태의 `evaluate()` 결과와 렌더 문자열에 대해 검사한다. **하나라도 위반하면
불통과**이고, 위반 건수·상품·상태를 그대로 기록한다.

```
A1  net_lo != net_hi 인 상품을 단일 숫자로 렌더하지 않는다
    (범위는 범위로 — 화면 계약 1번)

A2  tier == "확정" 이면 net_lo == net_hi 여야 한다
    "확정" 라벨이 폭이 남은 상품에 붙으면 사용자의 침묵을 단정한 것이다

A3  caveats 가 비어 있지 않으면 사유 문장이 화면 문자열에 있어야 한다
    특히 `미응답`·`모름`·`이행필요` — 화면 계약 4번

A4  질문에 답할 때마다 "남은 질문 수" 가 늘어나지 않는다 (`0024` P4)

A5  net_hi 가 공시 최고금리(세후)를 넘지 않는다
    상한이 모든 중간 상태에서 살아 있어야 한다
```

**A6을 나중에 추가했다** (2026-08-28 · `decisions/0028`). §6의 회피 방지는 *"assert를
느슨하게 고치지 않는다"* 인데 A6은 **더 엄격하게** 만드는 것이므로 추가한다. 사유를
적는다 — 사람 세션에서 화면이 **11개 답한 사용자에게 "답한 질문 22개" 라고 표시**했다.
`전체 - 남은` 을 답한 수로 계산했기 때문이다(`"아니오"`·`"모르겠다"` 는 딸린 문구
질문까지 지운다). 화면의 숫자가 사실이 아닌 것은 A1~A5와 같은 종류의 실패다.

```
A6  화면의 "답한 질문 N" 이 실제로 답한 횟수와 같다
    줄어드는 것은 분모(전체)여야 한다 — 39 → 36 → 28
```

**A7·A8도 나중에 추가했다.** A7 은 스코프(`0028`)가 생기면서, A8 은 성과 줄이 "내 금리
범위" 로 바뀌면서(`0029`) 필요해졌다. 둘 다 **더 엄격하게** 만드는 방향이고, 사유는
같다 — **화면에 숫자를 하나 더 올리면 그 숫자가 거짓말할 자리가 하나 더 생긴다.**

```
A7  스코프가 걸린 화면에는 스코프 밖 최고 금리가 있어야 한다      (`0028` S4)
A8  성과 줄의 범위가 실제 1위 상품의 net_lo~net_hi 와 같아야 한다  (`0029`)
```

**A2의 예외를 미리 적는다.** 공시 최고금리 = 기본금리인 행(`gap == 0`)은 우대조건이
금리에 영향을 못 주므로 답을 안 받아도 폭이 0이다. 이 경우 `확정`은 정당하다 —
A2는 `net_lo == net_hi`를 요구하므로 자동으로 통과한다. **예외 조항을 따로 두지 않는다.**

## 4. 표본 — 중간 상태를 어떻게 만드는가

전 조합(3²²)은 못 돈다. **결정론적 전 구간 + 무작위 혼합**으로 정한다.

| | 무엇 | 개수 |
|---|---|---|
| P1 | 세 페르소나(전부 예 · 전부 아니오 · 전부 모름)의 **모든 단계** | 은행권 3 × 23 = 69 상태 |
| P2 | 시드 고정 무작위 혼합 세션 — 매 질문 예/아니오/모름/숫자를 무작위 | 200 세션 × 각 단계 |
| P3 | 위를 저축은행(27개 질문)에서 반복 | 같은 규모 |

시드는 `0`부터 `199`로 **지금 못 박는다**. 결과를 보고 시드를 고르는 것을 막는다.

**사람 세션(M3·M4)은 은행권 1회다.** 첫 세션이 기록이고, 여러 번 돌리면 전부 남기고
판정은 첫 세션으로 한다. 답을 미리 준비하지 않고, 모르면 "모르겠다"로 답한다.

자기보고 문항도 미리 고정한다.

```
Q1  답을 이어가는 동안 어느 숫자를 보고 있었나 — 남은 질문 수 / 확정 상품 수 / 둘 다 / 안 봤다
Q2  "모르겠다" 를 골랐을 때 그 대가(확정이 안 늘어난다)가 화면에서 보였나 — 예 / 아니오
```

| 가드 | 기준 |
|---|---|
| 시드·표본을 결과 보고 고르지 않는다 | §4에 시드 0~199를 못 박았다 |

| 지표를 바꾸지 않는다 | 질문 예산 12개·우선순위 규칙(`0018`)은 이 측정에서 안 건드린다 |

## 7. 이 사전등록이 정하지 않는 것

1. **이어하기(`--resume`)를 만들 것인가.** `0026`이 피로를 다루는 자리로 지목했지만
   설계는 안 정했다. 이 측정과 독립이다
2. **자기보고 결과로 상태바를 바꿀 것인가.** M4는 약한 증거다. 바꾸려면 별도 근거가 필요하다
3. **법·규제 근거.** 금융상품 광고에서 최고금리 단독 표기를 제한하는 규제가 실재한다고
   보지만 **조문을 확인하지 않았다.** 확인 전에는 인용하지 않는다 (`0026` §남은 것)
4. **개인정보 최소수집 원칙과의 관계.** 전부 묻는 것이 수집 최소화와 부딪치는지 —
   `0026`의 반증 조건에 적었다. 답을 서버에 저장하지 않는 지금 구조에서는 안 부딪친다고
   보지만, 저장을 시작하면 다시 봐야 한다

## 7.1 기준선 재등록 예고 — 고치기 **전에** 적는다 (2026-08-28)

전수 검사가 **A2 위반**을 찾았다(예측은 0건이었다). 고치면 확정률이 내려가므로
`CLAUDE.md` 3번에 따라 **수정 전에** 사유·편향 방향·완화 조치를 여기 적는다.
`prereg-06` §2.3(1)이 `0019`에서 한 것과 같은 절차다.

### 무엇이 틀렸나

```
evaluate()   tier = "범위" if rng["unknown"] else "확정"      ← 밴드 폭을 안 본다
```

`0022`가 배타 그룹을 **범위로** 처리하기로 정했는데(`lo` = 그룹 최댓값 · `hi` = 합산)
**층 라벨만 그 결정을 따르지 않았다.** 조건을 전부 답해 `unknown`이 0이 되면, 밴드
폭이 남아 있어도 `확정`이 붙는다.

```
아이행복적금        4.02 ~ 5.71%   폭 1.69%p   층 = 확정   남은 조건 0개
우리SUPER주거래적금  2.75 ~ 3.26%   폭 0.51%p   층 = 확정   남은 조건 0개
```

**상태바 둘째 숫자가 과대 진술을 한다.** "금리가 정해진 상품"이 안 정해진 상품을 센다 —
전부 예로 답했을 때 은행권 64개 중 **14개**, 저축은행 100개 중 **7개**. `0024` P4가
*"확정 상품 수가 '모르겠다'의 대가를 정확히 가른다"*고 한 그 숫자다.

### 어떻게 고치나

```
폭이 남아 있으면(lo != hi) unknown 이 0 이어도 `범위` 다
```

`0022`를 층 라벨에 적용하는 것뿐이고, 새 규칙을 만들지 않는다.

### 편향 방향 — 확정률이 내려간다

**유리한 방향이 아니다.** 그래서 재등록의 정당성이 있다.

| | 지금 | 고친 뒤 |
|---|---|---|
| 은행권 확정 (예산 12) | 39/67 = 58.2% | **37/67 = 55.2%** |
| 저축은행 확정 (예산 12) | 88/106 = 83.0% | **85/106 = 80.2%** |
| 폭 평균 | 0.176 · 0.277%p | **안 변한다** (라벨만 바뀐다) |
| 커버리지 | 84.8% · 35.7% | **안 변한다** (`확정`·`범위` 둘 다 메인이다) |

**폭 평균·커버리지가 조금이라도 움직이면 예상 밖이다** — 그러면 이 수정이 라벨 말고
다른 것을 건드린 것이고, 그 사실을 먼저 적는다.

### 완화 조치

- 옛 값(58.2% · 83.0%)은 **버그가 있던 코드의 값**이라고 `START-HERE`에 명시한다
- 전수 검사를 회귀 가드로 남긴다 — A2가 다시 깨지면 즉시 잡힌다
- `0022`의 `중복우대불명` 사유 문장은 그대로다. 사용자 화면에서 달라지는 것은
  **`확정` 라벨이 빠지고 `범위`가 되는 것**뿐이다

| 커버리지 | 84.8% · 35.7% | 안 변한다 | **84.8% · 35.7%** |

페르소나 실측도 같은 방향이다 — 전부 "예" 의 확정이 **64 → 50**(밴드 폭이 남은 14개가
`범위` 로 갔다), 전부 "아니오" 65 · 전부 "모름" 4는 **안 움직였다**(밴드는 조건을 다
충족했을 때만 폭을 만든다).

### A3 — 사람이 "문장도 보여준다" 를 골랐다

3단계 화면이 사유 문장을 여섯 코드만 냈고 `미응답`·`수치필요`는 상품 줄의 코드로만
나갔다. §5에서 이 위반을 예고했고, 사람이 골랐다.

> 나도 가가 맞다고 보네 (가 = 두 문장도 항상 보여준다)

**두 블록으로 나눴다** — `CAVEAT` 자체가 두 종류이기 때문이다.

```
답하면 없어지는 사유      미응답 · 수치필요
되물어도 못 채우는 사유    조건불명 · 중복우대불명 · 추첨 · 단계불명 · 모름 · 이행필요
```

### 남은 것 — M3·M4

사람이 은행권 1회를 답해 "모르겠다" 비율과 자기보고 2문항을 채우는 일이 남았다.
**M1·M2가 통과했으므로 그 세션에서 무엇을 보든 화면은 정직하다** — 중단해도 범위와
사유로 나가는 것을 8,000여 개 중간 상태에서 확인했다.
