# prereg-26 · 공시에 뜻이 없는 낱말은 어디에 정의돼 있나 — G 코퍼스의 출처 조사

> 작성 2026-09-04 (**조사 전**) · 에픽 [#20](https://github.com/hyos0415/fineprint/issues/20) ·
> 근거 로드맵 §G(*"코퍼스를 어디서 얻나부터 조사한다"*) · `0011`(상품설명서에도 설명 안 되는 금리가 있다) ·
> `0019`(뜻을 모르는 남의 낱말에 뜻을 지어내지 않는다) · `0050`(`기타` 는 판정 불가) · `prereg-14` §7(탑스 · 소중한 날)

## §1 왜 조사하나

사람 완주에서 **공시 안에 답이 없는 낱말**이 나왔다(탑스 · 소중한 날). 우리는 뜻을 지어내지 않고(`0019`) 판정 불가로
두고 *"은행에 확인해 보세요"* 라고 쓴다(`0050`). 그 낱말들의 뜻이 **공개된 어디엔가 있다면** 그것이 G(검색)의
코퍼스다. 사람이 국민은행 상품설명서를 직접 봤는데 "소중한 날" 이 없었으므로, 상품설명서(A2)가 코퍼스라는 전제는
이미 무너졌다. 그럼 어디인가 — 이 문서는 그것을 **찾기 전에 예측한다.**

## §2 표본 — 지금 데이터에서 판정 불가로 남은 낱말·조건

```
낱말 (뜻없음 · 기타)     탑스           제주은행    제주Dream 정기예금        "③탑스, 주거래 고객"
                        소중한 날       국민은행    KB내맘대로적금            "… 주택청약종합저축, 소중한 날"
```

낱말 4 · 조건불명 상품 5. 전부 12개월 화면에 실제로 나오는 것이다.

## §3 어디를 보나 — 순서를 고정한다

기관마다 같은 순서로 본다. 한 곳에서 찾으면 다음은 **참고로만** 본다.

```
1  기관 공식 홈페이지의 상품 상세 페이지 (A7 이 받은 `homp_url` 에서 출발)
2  상품설명서 PDF (상품 상세에서 링크되는 것)
3  기관 서비스·이벤트 소개 페이지 (상품 페이지 밖)
4  금융감독원 금융상품통합비교공시 화면 (API 와 같은 원천이라 있을 리 없다 — 확인용)
5  그 밖(뉴스 · 블로그) — **출처로 인정하지 않는다.** 있었다는 사실만 적는다
```

## §4 예측 — 찾기 전에 적는다

```
P1  낱말 4개 중 기관 **공식** 웹 어딘가(1~3)에 뜻이 있는 것 ≥ 2. 전부는 아니다 — 하나 이상은 앱 안에만 있거나 어디에도 없다
P2  상품설명서 PDF(2)에서 뜻이 나오는 낱말 0 (`0011` · 사람의 KB 확인과 같은 결과)
P3  조건불명 5개 중 상품 상세 페이지(1)에 조건이 적혀 있는 것 ≥ 3 — 공시 `spcl_cnd` 가 요약이고 상세는 웹에 있다
P4  출처의 **모양이 기관마다 다르다** — HTML 상품 페이지 · PDF · 이미지(배너) · 앱 전용이 섞인다. 단일 크롤 규칙으로
    받을 수 있는 출처가 아니다 → 코퍼스는 기관별 수집이고 그 비용이 G 의 선행이 된다
P5  뜻을 찾은 낱말도 **판정에 넣지 않는다** — 찾은 것은 "출처가 있다" 는 사실이지 우리가 그 뜻으로 사용자 답을 판정할
    권한이 아니다(`0019`). 화면에 할 수 있는 최대는 "이 낱말의 설명은 기관 페이지 X 에 있습니다" 링크다
```

## §5 판정 조항

```
P1 이 틀리면(0~1)   공식 웹에도 없다 — 코퍼스가 존재하지 않는다. G 는 계속 대기고 화면은 지금 문장 그대로다
P1 이 틀리면(4)     전부 있다 — 기관 웹이 코퍼스다. A2(상품설명서)가 아니라 **A2'(상품 상세 페이지)** 를 수집 항목으로 연다
P2 가 틀리면        `0011` 의 결론을 다시 본다 — 설명서가 낱말은 설명한다는 뜻이다
P3 이 틀리면        조건불명은 웹에도 없다 — 은행에 전화하라는 지금 문장이 맞다
P4 가 틀리면(단일)   크롤 규칙 하나로 받을 수 있다 — 수집 비용이 예상보다 작다. A2' 이슈를 바로 판다
P5                 예측이 아니라 다짐이다. 조사 결과가 무엇이든 지킨다
```

### 예측 대조

```
P1  부분   공식 웹에 뜻이 있는 낱말 — 확정 1(소중한 날) · 그룹사 페이지 1(탑스) · 없음 1(올해의 띠) · 미확인 1(손하나로).
           "≥ 2" 는 탑스를 기관 공식으로 치면 맞고 아니면 틀리다. **하나 이상은 어디에도 없다** 는 뒷문장은 맞았다(올해의 띠)
P2  맞음   설명서 PDF 에서 뜻이 나온 낱말 0 (읽을 수 있는 PDF 가 없었고, 사람의 KB 확인이 그 자리를 채운다)
P3  미확정  조건불명 5 중 상세 페이지에서 확인된 것 2(페퍼 둘 — "조건 없음" 이 답) · 3 은 도구가 못 읽음. "≥ 3" 은 사람 확인 뒤 판정
P4  맞음   모양이 다 다르다 — 정적 HTML(국민·세람·페퍼) · JS 렌더(부산·SBI) · 접속 거부(제주) · PDF 특약(국민) · 그룹사 페이지(탑스).
           단일 크롤 규칙은 없다. 헤드리스 브라우저 없이는 반을 못 읽는다
P5  지킴   찾은 뜻을 판정에 넣지 않았다. 코드는 한 줄도 안 바뀌었다
```

### 이 조사가 말하는 것

1. **코퍼스는 상품설명서가 아니라 "기관 상품 상세 페이지" 다** — 소중한 날의 정의는 설명서에 없고 웹 페이지에 있다.
   페퍼의 "기본 우대" 도 웹 페이지가 답했다. `0011` 이 금리에서, 사람이 용어에서 본 것과 같은 방향이다
2. **그래도 다 있지는 않다** — 올해의 띠는 기관 공식 웹 어디에도 뜻이 없다. 이런 낱말은 지금처럼 판정 불가 + "은행에 확인"
   이 맞다(`0050`). 코퍼스가 생겨도 이 문장은 남는다
3. **수집 비용이 균일하지 않다** — 정적 HTML 은 요청 한 번, JS 렌더는 브라우저가 필요, 제주는 도구 접속이 막혔다.
   기관 97곳을 같은 방법으로 받을 수 없다. G 를 열려면 **어느 기관까지 받을지**가 먼저 정해져야 한다
4. **"조건불명" 의 일부는 "조건 없음" 이다** — 페퍼 0.1%p 는 누구나 받는다. 공시 `spcl_cnd` 가 "우대" 라고만 쓴 것을 우리가
   조건불명으로 둔 것인데, 이 사실을 판정에 넣으려면 웹 페이지를 근거로 쓰는 결정이 필요하다 — **여기서 정하지 않는다**(P5)

**사람 확인 4건은 하지 않기로 했다 (2026-09-04 · 사람 결정).** *"니가 못 찾았는데 내가 찾을 확률이 낮을 거 같아서 …
그냥 은행 안내가 필요한 항목 정도로 처리하면 안 되려나"*. 그것이 이미 `0050` 의 동작이다 — 뜻 없는 낱말은 판정 불가 ·
라벨 "은행 확인이 필요한 조건" · *"해당되는지는 은행에 확인해 보세요"*. 새로 만들 것이 없다. P1 은 "확정 1 · 그룹사 1 ·
없음 1 · 미확인 1" 로, P3 은 "5 중 2 확인" 으로 **그대로 닫는다.** 결정은 [`0056`](../decisions/0056-no-corpus-yet-undefined-words-stay-bank-check.md).
